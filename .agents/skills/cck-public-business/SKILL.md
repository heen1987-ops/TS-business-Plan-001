# 공공 사업 통합 진입점

먼저 [공통 계약](../_shared/contract.md)을 읽고 기관, 기관의 역할, 사업, 사업유형, 계약/협약 방식, 공고·정정 차수, 기준일을 기록한다. 기관 이름만으로 유형이나 규정을 선택하지 않는다.

1. 사용자가 공고 대응·기술제안·연구개발계획서·발표·평가 대응을 원하면 [cck-proposal](../cck-proposal/SKILL.md)로 이동한다.
2. 체결된 계약/협약의 착수·계획·산출물·일정·변경·보고·검수·정산 준비를 원하면 [cck-project-management](../cck-project-management/SKILL.md)로 이동한다.
3. 공식 자료 정리·규정 적용·근거 충돌 해결이 중심이면 [cck-public-evidence](../cck-public-evidence/SKILL.md)를 적용한 후 위 업무로 돌아온다.
4. 새 기관을 추가하거나 실제 교육청/사업유형이 정해지지 않았으면 [cck-agency-onboarding](../cck-agency-onboarding/SKILL.md)으로 프로필을 만든다.

기관 프리셋은 [agency-profiles.json](../_shared/agency-profiles.json)을 읽는다. IITP/KEIT도 일반 구매·용역과 R&D 지원을 구분한다. EDU는 특정 교육청으로 치환해야 하는 템플릿이며 병원은 향후 별도 온보딩 대상이다.

입력이 부족할 때는 이미 확인된 범위로 공통 작업을 진행하고, 분기에 꼭 필요한 기관/공고/단계만 확인한다. 기존 세션에서 명확한 값을 반복해서 묻지 않는다. “제안서와 사업관리 모두”라면 하나의 근거 원장을 두고 두 산출물 세트를 만든다. 제안 자료를 승인된 수행 기준선으로 자동 전환하지 않는다.

출력: 업무 범위 표, 선택한 분기와 이유, 확인된 자료/미확인 목록, 다음 스킬과 필요한 입력. 외부 제출·메시지·실제 시스템 상태 변경은 사용자의 권한과 실행 환경에 따라 별도 처리한다. 이 패키지를 읽었다고 연결·설치·운영이 완료됐다고 보고하지 않는다.
