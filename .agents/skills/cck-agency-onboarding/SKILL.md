# 기관 확장

[공통 계약](../_shared/contract.md), [근거 규칙](../_shared/evidence-rules.md), [기관 프로필](../_shared/agency-profiles.json)을 읽는다. 기관 프로필은 해당 기관 모든 사업의 규정·양식·권한이 검증됐다는 선언이 아니다.

1. 실제 기관 명칭·식별자·공식 도메인과 발주/전문/수요/수행 역할을 확인한다. 교육청이면 어느 교육청·교육지원청·학교인지 기록한다. EDU와 HOSPITAL 같은 분야 이름을 실제 기관 ID로 쓰지 않는다.
2. 사업유형과 계약/협약 방식을 구분하고 지원 가능한 분기를 지정한다. IITP/KEIT라고 항상 R&D는 아니다. 하나의 기관 프로필 아래 여러 사업유형과 공고별 적용 프로필을 허용한다.
3. 공식 가이드·규정·공고·정정·양식·평가표·계약/협약 자료의 탐색 경로를 등록한다. 제목·발행기관·URL·판본·확인일·열람 수준·미확인을 남긴다. 내부 규정이나 원문을 읽지 못했으면 확보했다고 표시하지 않는다.
4. 실제 공고가 선택되면 `기관 → 사업유형 → 공고/차수 → 계약·협약 → 판본` 범위로 적용성 표를 만든다. 기존 프로필과 다른 공고의 기한·자격·서식·승인을 승계하지 않는다.
5. 새 프로필은 DRAFT로 만들고 검토 상태와 실행 상태를 분리한다. 명시적인 검토 근거 없이 PROJECT_REVIEWED로 승격하지 않는다. 기관 공식코드는 확인된 경우에만 별도 필드에 기록한다.
6. 합성 자료로 기관/공고 불일치, 원문 누락, 판본 충돌, 제안 주장 승격 금지를 시험한다. 실제 사업 자료 검증과 설치/호출/운영 결과는 별도 기록한다.

출력: 기관 프로필 초안, 공식 자료 등록표, 공고별 적용표, 공통/기관별 추가 항목, 미확인·충돌, 검증 시나리오. 프로필 ID가 새롭다는 이유로 실행 환경 권한이나 데이터 연결을 만들지 않는다.

병원은 우선 구매·자산·품질/인증·교육·사고 후속 등 행정 업무의 별도 프로필을 설계한다. 환자 관련 데이터는 승인된 환경과 최소 범위를 먼저 정한다. 이 패키지에 EMR/EHR 연계나 임상 판단 기능이 구현돼 있다고 가정하지 않는다.
