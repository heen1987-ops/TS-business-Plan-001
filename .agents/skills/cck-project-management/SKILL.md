# 사업관리

[공통 계약](../_shared/contract.md)과 [근거 규칙](../_shared/evidence-rules.md)을 읽는다. 계약/협약 방식과 실제 효력 자료를 먼저 확인한다. 제안서 초안을 승인 계획으로 취급하지 않는다.

## 입력

계약/협약과 부속서, 승인된 수행/연구계획·WBS·산출물 목록·테일러링, 변경 승인 자료, 현재 산출물·회의·이슈·제출·수락 증거. 기관/사업/공고/계약·협약/판본을 구분한다. 이전 사업 템플릿을 사용하면 빈 구조만 재사용하고 이름·기한·승인 상태를 복사하지 않는다.

## 절차

1. 기준선 원장을 만든다: 범위/요구 ID, 산출물 ID·판본, 일정·비용 기준, 승인 주체·일시·원문 위치, 효력 시작, 변경 이력. 승인 증거 미확인 항목은 PROPOSED 또는 UNKNOWN에 둔다.
2. 정보화 조달은 해당 계약의 착수·설계·구현·시험·검수·인계 조건에, R&D는 해당 협약의 목표·연차/단계·보고·변경·연구비 증빙 조건에 연결한다. 기관 이름으로 획일적 필수 서식이나 기한을 생성하지 않는다.
3. 산출물 추적표에 `계획 / 작업중 / 작성 / 검토 / 제출 / 수락`과 각 증거를 별도 보존한다. 문서 최신판, 승인판, 현재 작업판을 구분한다. 파일 저장만으로 완료·검수 통과로 변경하지 않는다.
4. 변경요청은 기존 기준선과 별도 큐에 적고 범위/일정/비용/품질/보안 영향을 분석한다. 승인 근거가 연결되기 전 기준선에 반영하지 않는다. 증거 연결도 권한 있는 승인 여부의 실제 검토를 대체하지 않는다.
5. 보고서·WBS·회의록·산출물·제출 기록을 대사한다. 날짜·버전·진척·책임·요구 누락 충돌을 이슈로 만들고 원문 위치와 해소 주체를 남긴다. 추정 진척률이나 존재하지 않는 회의/승인 기록을 생성하지 않는다.
6. 다음 행동, 담당, 근거 있는 예정일, 미확인/미승인 항목을 제시한다. 보고서 초안과 실제 시스템 변경을 분리해 실행 여부를 기록한다.

## 산출물

승인 기준선/미확인표, 요구·산출물·검증 추적표, 일정/진척 보고, 변경요청·승인대사표, 이슈 큐, 검수/정산 준비 증거 목록. 실제 검수 통과·대금 지급·연구비 적정성은 증거와 결정 주체 확인 없이 확정하지 않는다.

## 기존 TS 자산

기존 TS 7업무 스킬은 TS 전용 어댑터 자산이다. 이 공통 패키지는 TS의 실제 산출물 카탈로그·WBS·내부 양식·인사정보를 포함하지 않는다. TS 어댑터를 사용해도 같은 출처·판본·승인·변경 계약을 적용하며 다른 기관에 TS 날짜나 서식을 강제하지 않는다.
