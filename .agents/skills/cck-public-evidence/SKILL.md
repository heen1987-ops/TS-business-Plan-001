# 공통 근거 확인

[공통 계약](../_shared/contract.md)과 [근거 규칙](../_shared/evidence-rules.md)을 먼저 읽는다. [공식 출처 레지스트리](../_shared/source-registry.json)는 탐색 출발점이며 적용 판정 결과가 아니다.

1. 사업 범위를 식별하고 원문 목록을 만든다. 공고 미선택 상태라면 기관 일반 자료와 실제 사업 자료의 빈칸을 구분한다.
2. 사용 가능한 공식 연결 도구·브라우저·제공 파일로 원문을 읽는다. 검색 발췌, 첨부 목록, 메타데이터만 확인한 경우 그 수준을 그대로 적는다. 권한 없는 자료를 찾았다고 접근권한을 가정하지 않는다.
3. 판본과 기준일을 고정해 조항을 읽고 적용 사실을 대조한다. 공고 정정·협약·특칙·과업 변경을 놓치지 않는다. 원문이 없으면 보편적인 제안이나 검토 질문은 만들되 법적 필수로 단정하지 않는다.
4. 근거 원장과 충돌 원장을 만들고 요구사항·평가기준·산출물에 연결한다. “가이드에 있음”, “이 사업에 적용”, “승인됨”, “이행 완료”를 별도 판단한다.
5. 출처 미확인, 표 추출 손실, 판본 충돌, 기관·공고 불일치와 후속 확인을 보고한다. UNKNOWN을 삭제해 문서를 완결된 것처럼 보이게 하지 않는다.

출력: 출처/판본 목록, 적용성 표, 충돌 표, 요구·산출물 연결표, 미확인 목록. 중요한 주장 바로 옆에 실제로 읽은 원문 위치를 붙인다. 기존 정보화 가이드의 금액 경계나 조건을 재서술할 때 원문 대조 없이 바꾸지 않는다.

구조화 입력이 있으면 `node ../_shared/inspect-request.cjs <request.json>`을 이 스킬 폴더 기준으로 실행할 수 있다. 검사는 파일 본문이나 법령을 검증하지 않으며 결과 `READY_FOR_DRAFT`도 원문 검토를 대체하지 않는다. 실행하지 않았다면 실행 결과를 만들지 않는다.
