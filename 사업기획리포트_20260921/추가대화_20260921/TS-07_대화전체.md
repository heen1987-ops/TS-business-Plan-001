# TS-07. 지역 교통안전 특별실태조사·개선 이행

## 사업컨셉: 지역의 교통위험 개선권고를 실제 조치와 확인으로 연결하는 협업지원 서비스

**교통안전 조사에서 확인한 문제를 지자체·경찰·시설관리자 등의 실행과제로 연결하고, 계획한 개선이 실제로 이행됐는지 근거로 확인하도록 지원하는 사업입니다.** 새로운 위험지도나 보고서를 만드는 것이 아니라, **“이 위험을 해결하려면 누가 무엇을 결정하고 실행해야 하며, 어디까지 확인됐는가”를 연결하는 서비스**로 구성합니다.

기존 TS-07의 범위인 **특별실태조사 → 개선권고 → 기관협의 → 이행계획 → 이행 확인**을 하나의 사업컨셉으로 유지합니다. 원래 문서에서도 실제 문제 발생과 규모는 검증 전 가설로 관리하고 있습니다. :chatgpt-content-reference{index="0"}

## 3. 해결하려는 문제는 세 가지

### ① 조사에서 확인한 문제와 실행계획이 같은 내용을 가리키는지 확인하기 어려울 수 있음

**문제 가설**

> 조사보고서의 위험요인, 개선권고의 대상, 지자체 사업계획의 공사·운영 범위가 서로 다른 표현과 단위로 작성되면, 실행계획이 원래의 위험을 해결하는지 다시 대조해야 할 수 있다.

예를 들어 ‘보행환경 개선’이라는 권고가 여러 시설사업으로 나뉘거나, 여러 권고가 한 사업에 묶일 수 있습니다. 이때 필요한 것은 문장 요약보다 **권고와 실제 사업의 대응관계**입니다.

기존 원장도 권고에 위치·이용조건·변경사항이 충분하지 않을 때 발생할 수 있는 재검토와, 권고가 사업계획에 어떻게 반영됐는지 추적하는 문제를 구분했습니다. :chatgpt-content-reference{index="7"} :chatgpt-content-reference{index="8"}

**확인할 질문**

> “이 사업계획의 어떤 항목이 원래 권고한 어떤 위험을 해결하는지, 자료를 다시 만들지 않고 설명할 수 있습니까?”

단, 상세설계가 별도 과업인 경우까지 조사보고서에 모든 설계정보가 없다는 이유로 문제라고 판단하지 않습니다.

### ② ‘협의 중’이라는 상태만으로는 다음 행동을 알기 어려울 수 있음

**문제 가설**

> 여러 기관이 참여하는 개선과제에서 기관 이름과 진행상태만 기록되면, 실제로 누구의 어떤 결정·자료·승인·일정을 기다리는지 확인하기 어려워 재문의가 반복될 수 있다.

이 경우 ‘협의 중’을 다음처럼 구체화하는 것이 필요합니다.

**도로관리자의 설계검토 대기인지, 교통운영 관련 협의인지, 예산 확정인지, 현장 여건 확인인지**를 구분해야 합니다.

기존 원장도 결정주체·결정사항·선행조건을 구분하는 것을 목표로 두며, 필수 심의·예산절차에 따른 대기를 시스템 오류로 취급하지 않도록 명시합니다. :chatgpt-content-reference{index="9"}

**확인할 질문**

> “현재 멈춰 있는 과제는 누가 무엇을 확인하거나 결정하면 다음 단계로 진행할 수 있습니까?”

이 질문에 답이 없다면 협업정보의 문제일 수 있습니다. 답이 명확하고 필요한 절차를 정상적으로 수행 중이라면, 단순한 지연으로 분류하지 않습니다.

### ③ 계획 반영·시행완료 보고·실제 이행확인이 혼재할 수 있음

**문제 가설**

> 계획서에 반영된 상태, 집행기관이 완료했다고 보고한 상태, 현장 확인을 마친 상태가 구분되지 않으면, 아직 남은 작업이 있는데도 과제가 끝난 것으로 이해될 수 있다.

또는 반대로, 이미 충분히 확인한 사항을 다른 기관이나 담당자가 다시 검토하면서 불필요한 재확인이 발생할 수 있습니다.

**확인할 질문**

> “완료로 표시된 과제에서 실제로 확인한 것은 계획 반영, 공사·운영 완료, 현장상태, 개선효과 중 어디까지입니까?”

기존 원장도 **계획 반영·시행보고·이행확인·효과관찰을 별도로 관리**하도록 정의했습니다. 이 구분은 그대로 유지합니다. :chatgpt-content-reference{index="10"}

### TS-07 통합 문제정의

> **교통안전 특별실태조사에서 도출한 개선과제를 관계기관이 실행하는 과정에서, 조사근거·권고·사업계획·기관별 결정·실제 이행결과의 연결이 충분하지 않아 재검토·협의대기·확인 누락이 발생하는지 검증한다. 기존 체계로 해결되지 않는 부분이 확인되면, 같은 개선과제를 기준으로 필요한 자료와 다음 행동을 연결하는 지원기능을 구성한다.**

## 4. 서비스는 어떻게 구성하는가

큰 흐름은 다음과 같습니다.

**위험사실·근거 확인 → 개선권고 구체화 → 기관별 결정·실행 연결 → 계획과 시행결과 대조 → 이행 확인 → 잔여사항 관리**

세부 과업을 별도 사업으로 쪼개지 않고, 다음 세 가지를 **TS-07의 구성요소**로 묶습니다.

| 구성요소 | 서비스가 지원할 내용 | 확보하려는 결과 |
|---|---|---|
| **① 개선과제의 근거·범위 연결** | 조사에서 확인한 사실, 위치·대상, 권고, 사업계획을 연결하고 불일치·누락 후보 제시 | 어떤 위험을 해결하는 과제인지 관계기관이 같은 기준으로 이해 |
| **② 기관별 실행·협의 지원** | 요청·회신·회의결과에서 결정사항, 미결사항, 선행조건을 구조화 | 누가 무엇을 확인해야 다음 단계로 가는지 파악 |
| **③ 계획·결과 이행검증** | 최초·변경계획, 시행보고, 확인자료를 대조하고 잔여사항 정리 | 완료보고와 실제 확인범위가 일치하는지 검토 |

### 관리의 중심은 ‘문서’가 아니라 ‘하나의 개선과제’

제안하는 정보 연결은 다음과 같습니다.

> **어느 장소의 어떤 위험인가 → 어떤 근거로 확인했는가 → 무엇을 바꾸기로 했는가 → 어떤 기관이 결정·수행하는가 → 무엇이 변경됐는가 → 어떤 증거로 확인했는가**

이 관계가 있어야 서로 다른 기관의 공문·회의록·계획서·현장자료를 하나의 과제로 묶을 수 있습니다.

**일반 일정관리 도구와의 차이는 문서의 내용을 대조한다는 점**입니다. ‘계획서 제출 완료’를 표시하는 것을 넘어, 계획서가 원래 권고를 반영했는지, 변경된 범위가 어떤 확인사항을 남겼는지 검토하도록 지원합니다.

단순 담당자·기한 관리만으로 문제가 해결된다면, 새로운 AI 엔진이 필요한 이유는 약해집니다.

## 5. 대표 적용 예시: 통학로 보행위험 개선과제

다음은 실제 지역의 문제나 조치결과가 아닌 **설명용 상황**입니다.

특별실태조사에서 한 통학로의 보행자 시야 확보와 횡단 동선에 관한 추가 검토가 필요하다고 확인했다고 가정합니다.

| 단계 | 서비스 지원 | 실제 판단·실행 주체 |
|---|---|---|
| **문제 확인** | 조사시점·위치·관찰내용·주민 의견을 구분해 근거 연결 | 조사전문가와 현장 관계자가 사실과 원인 가설 확인 |
| **권고 검토** | 권고가 해결하려는 위험과 필요한 추가 확인사항 정리 | 권한 있는 담당자가 대안과 검토범위 판단 |
| **기관별 협의** | 시설·교통운영·학교 이용상황 등 확인할 항목을 관계자에게 연결 | 해당 시설관리자·교통운영 담당·학교 등 실제 관계기관 |
| **실행계획 확인** | 권고와 계획의 반영·제외·통합·변경 관계 비교 | 계획·설계·집행 담당자가 변경사유와 실행조건 확정 |
| **이행 확인** | 보고내용과 대상 위치·시점·수행증거를 대조 | 정해진 확인자가 자료·현장 상태를 검토 |
| **후속 확인** | 아직 확인되지 않은 사항과 유지관리 조건 정리 | 해당 운영·유지관리 주체가 추가 확인 |

이때 AI가 횡단보도를 어디로 옮기거나 신호시간을 얼마로 변경하라고 독자 결정하지 않습니다. **도로·교통공학적 검토와 공식 결정은 해당 전문가·권한자에게 남깁니다.**

> **‘무엇을 시행했는가’와 ‘어떤 위험이 얼마나 달라졌는가’를 분리해서 설명하는 것이 핵심입니다.**

주민에게 정보를 제공하는 기능은 후속 확장으로 검토할 수 있습니다. 다만 **기관이 공개를 승인한 진행상태·시행내용·다음 확인사항만 제공**하고, 내부 검토안이나 미확정 완료일을 주민과의 약속처럼 안내하지 않도록 설계합니다.

## 9. 어떤 사업으로 만들 것인가

조사 전체를 CCK가 대신 수행하는 구조보다, **교통안전 전문기관이 조사·판단을 맡고 CCK가 자료 연결·검토·협의 지원을 제공하는 결합형 사업**을 우선 검토합니다. 실제 수행자와 계약방식은 별도로 확인해야 합니다.

**B를 사업컨셉의 중심으로 두되, A로 충분히 해결되면 기존 운영 개선에 편입합니다.** 처음부터 전국 지자체가 공동 사용하는 대형 플랫폼을 전제하지 않습니다.

**업무·자료 관계 정의 → 기존 시스템 연계 → 권고·계획·증빙 검증 기능 → 기관별 화면·권한 설정 → 현장 검증·운영지원**

구체적인 기간·예산은 아직 산정하지 않습니다. 대상 과제량, 과거자료 상태, 기존 시스템의 기능, 관계기관 참여와 운영책임이 먼저 확인되어야 합니다.

## 10. 효과와 사업성은 무엇으로 확인할 것인가

| 평가영역 | 확인할 결과 | 주의할 점 |
|---|---|---|
| **문제-계획 연결** | 권고가 어느 사업에 반영됐는지 정확하게 찾는가 | 표현이 비슷하다는 이유만으로 같은 과제로 연결하지 않음 |
| **협의 명확성** | 실제 미결사항·결정주체·선행조건을 파악하는가 | 정당한 심의·예산절차를 불필요한 지연으로 분류하지 않음 |
| **변경 추적** | 계획변경이 원래 권고와 확인조건에 미치는 영향을 설명하는가 | 변경 자체를 잘못으로 취급하지 않음 |
| **이행 확인** | 완료보고와 실제 증거의 차이를 발견하는가 | 자료 부족과 실제 미이행을 구분 |
| **전체 업무부담** | 근거 재구성·재문의가 줄고 신규 입력·검수 부담보다 편익이 큰가 | 관리도구 입력량이 늘어난 것을 성과로 계산하지 않음 |
| **공공적 결과** | 확인된 위험에 필요한 조치와 잔여사항을 놓치지 않게 됐는가 | 보고서 처리량을 안전성과로 대체하지 않음 |

검증에서는 정상적으로 완료된 과제뿐 아니라 **계획이 바뀐 과제, 미완료 과제, 자료만 부족한 과제**를 함께 봅니다. AI가 잘 처리하기 쉬운 자료만 골라 효과를 산정하지 않습니다.

특히 다음 상태는 분리합니다.

> **계획에 반영됨 / 시행했다고 보고됨 / 정해진 방법으로 이행 확인됨 / 이후 효과를 관찰함**

실제 사고감소를 평가하려면 별도의 관찰기간·교통량·다른 사업의 영향 등을 고려한 분석계획이 필요합니다. 이번 모듈은 우선 **개선과제의 실행·확인 신뢰성**을 검증하며, 공사 완료나 단기 사고건수 변화만으로 AI의 안전효과를 확정하지 않는 설계입니다.

### 첫 현업 확인질문

> **“최근 특별실태조사에서 제시한 권고 하나를 골라, 어떤 기관의 어떤 사업에 반영됐고, 무엇이 바뀌었으며, 현재 어디까지 확인됐는지 기존 자료만으로 보여주실 수 있습니까?”**

이 질문을 따라가며 **조사보고서, 권고문, 기관별 회신, 최초·변경 이행계획, 결과보고, 현장 확인자료**를 연결합니다. 자료를 다시 만들거나 다른 담당자에게 재문의해야 했던 지점과 이유를 기록합니다.

현재 확인한 것은 법정 업무범위, 지역 협업사례, 기존 정보·협업기능과 관련 부서의 공개 연결입니다. **실제 이행지연·확인누락 사례, 내부 시스템의 상세 기능, 기존 용역의 전체 과업범위와 추가 구매수요는 확인되지 않았으므로 신규사업성을 확정하지 않습니다.**

### TS-07 사업컨셉 핵심 문장

> **본 사업은 지역 교통안전 특별실태조사에서 도출한 개선권고를 관계기관의 결정·실행계획·수행결과와 연결하여, 필요한 안전조치의 이행과 확인을 지원하는 것을 목적으로 한다. 조사근거와 권고의 대응관계, 기관별 선행조건, 계획변경 사유, 수행증거 및 잔여사항을 추적하고, 계획 반영·시행보고·이행확인·효과관찰을 구분한다. 기존 조사·협의·사업관리체계를 활용하되, 해당 체계로 해결되지 않는 내용 검토와 연결 부담이 확인된 범위만 추가 구축한다.**

**TS-07의 차별점은 ‘지역 안전보고서를 작성하는 AI’가 아니라, ‘그 보고서에서 나온 개선과제가 어느 기관의 어떤 행동으로 이어졌고 무엇이 아직 남았는지 근거로 보여주는 AI’입니다.** 다음 순번인 **TS-08 전세버스 교통안전정보 공시**는 이미 진행 중인 사업과 겹치므로, 신규 도입안이 아니라 **기존사업 제외범위와 추가로 남는 문제의 유무**를 중심으로 정리합니다.
