TS 국민 편의와 안전 AX 요구사항 명세서 
버전  0.1   2026 -09 -10   발주  전 검토안  
기능 28 건과 데이터·보안·성능·품질·관리 등 15 건, 총 43 건의 검토 명세다. 각 수치 기준은 발주 전 협의할 
초안이며 CCK 제품의 측정 성능이 아니다. 
명세 읽기와 공통 계약 
입력과 사전조건은 처리 문장 및 데이터 항목에, 정상·예외 처리는 요구 본문에, 기대 결과는 검수 기준에 
명시한다. 모든 T 요구 ID 는 해당 요구를 Given 사전조건 / When 정상 또는 오류 주입 / Then 검수 기준으로 
시험하는 추적 ID 다. 구현 단계에서 세부 테스트 번호를 확장한다. 
외부 URL 과 실제 API 명세가 미제공이므로 아래 API ID 는 설계 계약 식별자다. 운영 URL·스키마가 이미 
존재한다고 의미하지 않는다. 사례별 인증·데이터·원천 기준을 확보한 후 구현한다.

시험 계획과 판정 책임 
단위 시험은 규칙·구조화·상태 전이를, 계약 시험은 API 스키마·오류·버전·타임아웃을, 통합 시험은 공식 
상태·권한·복구를 검증한다. X01 의 선점과 중복, X02 의 허위 완료, X03 의 사실 변조, X04 의 잘못된 증빙 수리, 
X05 의 자격 오판을 필수 실패 시나리오로 둔다. 
AI 평가의 분모는 완료된 업무 사례다. 한 사례의 여러 모델 호출·같은 사례의 반복 실행을 독립 표본으로 늘려 
세지 않는다. 개발 중 선정한 어려운 사례는 반례 시험으로 보고하고 운영 실패율 추정에 사용하지 않는다. 
전문가 불일치와 유보를 유지하며 자동 평가의 통과 사례도 사람이 검토한다. 
개발팀은 시험을 수행하고 QA 는 결과·재현성을 검토한다. 발주기관 업무 책임자는 의미·규칙·공식 상태를, 
보안 담당자는 개인정보·권한을, 운영 담당자는 인수·복구를 판정한다. 본 명세의 작성과 문서 QA 는 이 실제 
인수검사를 대신하지 않는다. 
지원 모드 변경 
공식 API 와 개인정보 처리 근거를 확보하지 못한 업무는 승인된 표본 기반 준비 모드로만 검증한다. 실시간 
조회나 실제 실행을 납품한 것으로 표시할 수 없다. 준비 모드·조회 모드·실행 모드는 검수 항목과 가격을 다시 
합의하여 구분한다.
