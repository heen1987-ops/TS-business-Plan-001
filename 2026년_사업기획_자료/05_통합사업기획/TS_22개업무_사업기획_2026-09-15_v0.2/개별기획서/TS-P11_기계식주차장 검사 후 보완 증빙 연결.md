## 0. 기구축 기반의 CCK AI 적용·중복 재판정

2026-09-15 사용자 정정에 따라 기존 시스템·업무·안내·AI 사업의 후속 적용도 기획 대상에 포함했다. 이전의 **기존 후보 구체화**를 **기구축 업무 AI 적용**로 재판정했다. 이번 기획 판정이며 제품 동작·계약 중복을 확정한 결과는 아니다.[^49]

**판정 이유:** 기존 검사 업무에 CCK AI 보완 검토를 추가하고 TS-BIZ-005와 연결.

## 1. 실제 업무와 기획 대상

**확인된 업무:** 설계서 안전도 심사, 사용·정기·정밀안전검사와 교육. [^14][^7][^31]

**수행 근거와 경계:** 공식 안내의 주차장법상 안전도 심사·사용/정기/정밀안전검사 확인. 개별 시행본·수탁 범위 대조 전. 업무의 존재와 새 AI 과업의 발주 필요성은 별도 판단이다. 페이지의 법령 인용은 조사 출발점이며 현행 법령·위탁·사무분장을 모두 대조한 법률 검토 결과가 아니다.

**공식 업무 중 이번 초기 범위:** 검사 종류 1개·시설 1개 시범, 지적/보수/재확인 문서 3종, 조회 1개. 나머지 세부 업무는 이번 최소 구축 범위에 넣지 않고 동일 묶음의 후속 검토로 둔다.

## 2. 국민·현업 문제와 WHY

- 문제의 근거 수준: 검사 지적과 보수 설명·재확인 자료의 대응을 추적하기 어렵다는 가설.
- 설명용 상황: 관리자가 보수를 완료했다고 제출했지만 지적된 장치와 작업 내용이 일치하는지 문서에서 불명확한 상황. 실제 관찰·면담 결과로 일반화하지 않는다.
- 국민 가치: 잘못된 안내·보완 누락·처리 실패를 줄이고 근거를 확인할 수 있게 한다. 안전 업무에서는 검토의 질을 높이는 경로를 검증하며 사고 감소를 직접 보장하지 않는다.
- 공공 개입 이유: 법정 절차·공공 안전서비스에서 이용자의 정보 격차와 업무 실패를 줄일 필요가 있다.
- 왜 AI인가: 시설별 보수 체크리스트와 기존 검사 관리시스템만으로 해결되지 않는 자유 서술의 조건 해석·근거 연결이 있는지 비교한다. 같은 효과가 나면 AI 개발 범위를 줄이거나 제외한다.
- 수요 확인: 실제 지적·보수·재확인 기록과 현행 검사 기능.

## 3. 현재 흐름과 변경할 행동

현재 업무는 공식 안내에서 확인했지만 실제 화면 조작·처리시간·오류 발생률은 현장 확인 전이다. 아래 변경 흐름은 제안이다.

1. 시설·검사·지적 식별자를 연결.
2. 보수 설명의 작업 항목을 지적사항과 대조.
3. 증빙 부족·재확인 필요 항목을 표시.
4. 검사관이 현장 확인 결과와 함께 종결 여부 판단.

최종 산출물은 **보수 대응표와 추가 확인 질문**이다. LLM의 자연스러운 답변이나 문서 생성 자체를 업무 완료로 표시하지 않는다.

## 4. 서비스 범위와 요구사항

| 요구사항 ID | 수행할 기능 | 수용기준 초안 |
|---|---|---|
| TS-P11-F1 | 시설·검사·지적 식별자를 연결 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P11-F2 | 보수 설명의 작업 항목을 지적사항과 대조 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P11-F3 | 증빙 부족·재확인 필요 항목을 표시 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P11-F4 | 검사관이 현장 확인 결과와 함께 종결 여부 판단 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |

- 핵심 입력: 시설ID·검사 결과·지적사항·보수 기록·공식 재확인 결과.
- 결과: 보수 대응표와 추가 확인 질문.
- 초기 물량: 3개 문서 유형, 1개 규칙·지침 묶음, 1개 조회 인터페이스, 0개 처리·인계 인터페이스를 상한 가정으로 견적 확인한다. 실제 API 개수나 제공 사실이 아니다.
- 제외: 비전·OCR·STT·TTS·센서·차량제어·검사설비, 자동 법적·안전 판정, 기관 간 원본 데이터의 포괄 통합.
- 입력 제한: 텍스트 전자문서·승인된 정형 결과만 사용한다. 스캔·사진 필수자료는 기존 공식 제출경로에서 사람이 확인하며 전체 제출절차를 AI가 완결했다고 표시하지 않는다.

## 5. 데이터·NOA·SI 및 책임

| 계층 | 역할·범위 | 확보 상태 |
|---|---|---|
| 데이터 | 시설ID·검사 결과·지적사항·보수 기록·공식 재확인 결과 | 담당부서 허용·표본·품질·용도 확인 전 |
| NOA·로컬 LLM | 입력 서술의 구조화·검색·근거 설명·보수 대응표와 추가 확인 질문 초안 | 공급사 설명과 내부 대장 참고; TS 버전·실행·사용권 검증 전 |
| 업무 규칙·SI | 시설/검사/보수 이력 관계·관리자 권한·검사시스템 조회 | 인터페이스·권한·변경 협조 미확정 |
| 사람 | 사실 정정, 보완·적격·안전·공개·발송의 최종 확인 | 주차안전 업무부서·검사 담당자와 실제 분장 협의 필요 |
| CCK 주관 범위 | 요구사항·NOA 구성·업무 모듈·연계·검수·운영 인수 총괄 | 담당 인력·가용률·납품계약 확인 전 |

NOA 공개 소개는 폐쇄망·업무 연결·감사·사람 검토를 설명한다. 특정 기능이 현재 TS 설치물에서 동작한다는 증거와는 다르다. 내부 대장의 기재와 현재 정정도 원 코드·사용권·실행 시험을 대신하지 않으므로, NL2SQL·승인 중단/재개·자동 재실행을 기본 보유 기능으로 확정하지 않는다.[^33][^44][^45][^46]

기존 운영사에는 시설/검사/보수 이력 관계·관리자 권한·검사시스템 조회의 계약·인터페이스 협조를 요청하는 역할안을 둔다. 협력사 확보나 기관 협조가 완료됐다는 뜻은 아니다. 초기에는 조회·검토 결과 생성까지 제한하며 기존 시스템의 결정·상태 변경은 담당자가 수행한다.

## 6. 대안·중복과 현재 판정

| 대안 | 범위·효과 가설 | 비용·기간 영향 | 판단 |
|---|---|---|---|
| 현행 유지·운영 개선 | 시설별 보수 체크리스트와 기존 검사 관리시스템 | 신규 구축 최소; 반복 문제 잔존 여부 확인 | 유효한 비교 기준 |
| SI·규칙 개선 | 입력·식별자·상태·원문 검색 정비 | 연계·데이터 정비 필요, LLM 운영 부담 없음 | 같은 목표를 달성하면 우선 적용 |
| NOA+SI | 보수 대응표와 추가 확인 질문와 검토 흐름 | 문서 정비·AI 평가·연계·운영 비용 추가 | 기구축 업무 AI 적용 |

**중복 대조:** TS-BIZ-005, H02, 주차장 AI 상담, L04 증빙 기능과 공통화; 기구축 업무의 존재는 제외 사유가 아니며 기존 기능 재사용과 추가 AI 적용분을 구별. 비교 단위는 업무·대상자·입력 데이터·기능·산출물·성과다. SFR-001~009 정리자료에는 공통 기반·직무 특화·민원·전세버스 AI 요구가 기재되어 있다. 동일 납품 기능은 기존 계약 이행·재사용으로 묶고, 새 적용 업무·변경 기능·연계·지식 정비·평가 등 추가 수행분을 사업 범위로 산정한다. 기구축 또는 같은 업무라는 이유로 적용 대상을 제외하지 않는다.[^43][^31]

**현재 판단:** 기구축 업무 AI 적용 — 기존 검사 업무에 CCK AI 보완 검토를 추가하고 TS-BIZ-005와 연결. 이번 판정은 CCK AI 적용 검토 방향이다. 최종 계약의 추가 범위·제품·수요·견적을 확인한 뒤 실제 발주·수행 범위를 확정한다.
