# R&D·정보화 통합보기 설계

## v0.2 현재 범위·수용기준

현재 추진사업 외 AX 전환·디지털전환+AI+정보화 기획으로 전환한다. 기본 목록은 검토대상 5건, 유보 2건·제외 1건은 별도 필터로 보존한다. scope_review와 transformation을 기준으로 모든 상세·직접 링크에 판정·이유·AS-IS/TO-BE·디지털전환·AI·구축/연계·운영·제외 경계를 표시한다. 초기화는 검토대상으로 돌아간다. 모바일 범위·성격 선택은 전체 폭으로 보여 판정 문구가 잘리지 않게 한다. 독립 R&D는 대상에서 제외하고 필요한 기술 검증만 세부 과업으로 둔다. 변경 전 자료는 버전 보존했으며 화면·단일 원장·상세 조사 상태를 함께 검증한다.

## v0.1 초기 설계 이력

2026-09-09 · 사용자 요청: 기관·법령 조사를 바탕으로 R&D와 정보화사업 등을 전체적으로 볼 수 있게 한다.

## 목적·가정

- 독자: TS 사업기획 담당자·검토자. 기획 검토용 로컬 화면이며 외부 운영 시스템이 아니다.
- 규모 M / 위험 Medium. Stage-Gate와 근거 추적, BDD를 적용한다.
- 가정: 기존 사업 1개는 파생 문서의 설명을 기준으로 표시한다. 신규 8개는 법정업무와 아카이브에서 도출한 탐색 가설이다. 실제 공고·사업 선정·예산 확보를 의미하지 않는다.
- 목표: 한 후보의 국민 문제, R&D 연구범위, 정보화·AX+SI 구축범위, 실증·운영·확산 조건, 법적 근거, 기존 사업 중복, 다음 확인을 함께 비교한다.
- 제외: 실제 AI 서비스 구현, 법률 전수검증, 모든 정부 R&D·조달 공고 수집, 예산·일정·투자 우선순위 확정, 외부 배포.

## 분류와 대안

R&D와 정보화는 과업 성격이며 AX+SI는 도입 방식이다. 실증·운영·확산은 추진 과정이다. 동일 후보가 R&D와 정보화를 포함할 수 있고 모든 정보화사업이 R&D를 거칠 필요는 없다. 연구와 구축의 과업·비용·성과를 나누고 중복 계상하지 않는다.

대안 A는 문서 표만 제공하는 방식으로 유지가 쉽지만 근거 탐색이 불편하다. 대안 B는 기존 관계도에 모든 기획 필드를 넣는 방식으로 법적 사실과 사업 가설이 혼재하기 쉽다. 대안 C는 별도 통합보기와 단일 JSON 원장을 만들고 관계도를 연결하는 방식이다. C를 적용해 법적 사실과 가설의 상태를 보존한다.

## 데이터와 화면

- 입력: 기존 프로젝트 맥락, 기관법령 관계원장, TS 15개 검토 관계, 공개 정책·통계 페이지.
- 편집 원본: `사업포트폴리오.json`. 법정업무는 기존 `D_TS_…` ID로 참조한다.
- 생성 결과: `사업기획_통합보기.html`, `사업포트폴리오_요약.md`, `사업유형_판단기준.md`와 과제 관리대장의 생성 구간.
- 화면 UI-01: 기존 사업 요약 → 후보 비교표 → 선택 후보 상세 → 심의·공고 확인 경로. 관계도와 왕복 이동한다.
- 흐름: 후보 전체 확인 → 사업 성격/이슈 검색 → 후보 선택 → WHY·연구/구축/실증 비교 → 법정업무 관계도 이동 → 원문 확인 → 기획 미결사항 기록.
- 데스크톱은 비교표, 모바일은 같은 내용을 세로 카드로 재배치한다. 자세한 근거는 접을 수 있는 상세로 제공한다.
- 권한/API: 읽기 전용. 네트워크 API, 로그인, 저장·승인 기능, 분석 로그, 개인정보 입력 없음. 원문 링크만 사용자가 열 수 있다.
- 화면 상태: 기본 선택, 조건 변경 성공, 검색 결과 없음, 미확인 근거·공고 미연결, 데이터 오류, JavaScript 비활성, 오프라인 조회. 외부 출처는 네트워크 필요. 로컬 즉시 데이터로 별도 로딩·타임아웃 UI는 불필요하다.
- 접근성: WCAG 2.2 AA 목표, 한국어 문서, 네이티브 버튼·입력·select·details, 키보드·포커스·상태 안내, 360px와 1440px 확인. 실제 스크린리더·종합 WCAG 인증은 별도 미검증으로 기록한다.

## 사전 검토와 변경 통제

사전 QA 관점에서 가장 큰 오류는 후보를 공고 사업으로 오인하거나 모든 AI 기능을 R&D로 분류하는 것이다. `탐색 후보`, `연구 필요성`, `공고 연결`, `선정 상태`, `예산 미정`을 별도 필드로 두어 통제한다. 후보 화면 작성은 진행 가능하며 실제 사업 착수 판단은 근거가 충족된 뒤 수행한다.

기존 관계원장은 변경하지 않는다. 기존 관계도는 통합보기 링크와 검증된 ID의 직접 이동만 추가하고 회귀검사를 실행한다. 생성 파일을 수정하는 대신 원장·화면 원본을 수정한다. 복구는 이번 링크·직접 이동 추가분을 되돌리고 기존 관계도 생성기를 실행하는 방식이다. Git push·배포·원본 삭제는 수행하지 않는다.

독립 평가위원이나 외부 법률 검토자가 검토한 결과로 표시하지 않는다. 이번 구현·자료 QA와 사업 선정 승인을 구별해 완료 보고한다.
