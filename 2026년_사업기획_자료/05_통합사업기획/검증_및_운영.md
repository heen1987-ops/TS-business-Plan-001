# R&D·정보화 통합보기 검증 및 운영

## v0.2 범위 정정 — 최신

현재 추진사업 외 신규 AX·디지털전환+AI+정보화만 기획하도록 정정했다. 기존 8개 ID·사례·출처를 보존하고 검토대상 5건·유보 2건·제외 1건으로 분리했다. 신규 검토대상도 비중복 미확정이다. 단순 이름 변경을 방지하기 위해 업무·데이터 전환, AI, 구축·연계, 운영, 진행사업과의 제외 경계를 필수 필드로 두었다.

문서·근거 검사 261개, 재생성 보호 3개가 통과했다. 화면 검사는 범위 필터·집계·직접 링크 상태·AS-IS/TO-BE·기관법령 연결·키보드·모바일을 확인했다. 실행별 최종 수치는 화면_검증결과.json과 심층리서치 검증결과.json을 따른다. 데스크톱과 모바일 캡처를 직접 확인해 모바일 선택값 잘림을 수정했다. 실제 사용자 인터뷰·독립 평가위원·계약상 비중복 확정은 미실시다.

변경 전 원장은 2026-09-09_범위정정_변경전, 새 조사 버전은 2026-09-09_v0.2에 보존한다. 아래의 원장 미변경·R&D 분류·검사 수치는 v0.1 당시 이력이며 현재 상태로 사용하지 않는다.

## v0.1 검증 이력

2026-09-09 · 사용자 요청에 따른 대화 중 작업. 예약 자동화 실행 결과가 아니다.

## 결론과 적용 범위

[사업기획 통합보기](사업기획_통합보기.html)에서 기존 사업 맥락 1건과 신규 탐색 후보 8건을 전체 비교할 수 있다. R&D·정보화 연계 후보 6건과 정보화 중심 후보 2건을 구별하고, 법정업무 12개·확장 검토기관 9개를 기존 관계도에 연결했다.

화면과 기획 초안 정리는 완료했다. 실제 사업 선정, 예산·공고 매칭, 계약 경계·데이터 권한, 기관별 법률 적용, 국민 수요·효과는 미확정 또는 미검증이다. 이 8개 후보가 대한민국의 전체 공공 R&D·정보화 사업을 포괄한다는 뜻은 아니다.

## 문제·가정·방법

- 문제: 기관·법령 조사 결과만으로는 연구할 부분과 정보화로 구축할 부분, 기존 사업과의 중복, 실증·확산 조건을 함께 비교하기 어렵다.
- 가정: 기존 사업 설명은 파생 문서의 맥락이며 최종 계약 확인이 아니다. 신규 후보는 탐색 가설이다.
- 방법론: M 규모 Standard Loop, Stage-Gate, 근거 추적, BDD. 요구사항 → 기존 구조 확인 → 분류·화면 설계 → 생성 → 검사 → 결함 수정 → 재검증 → 운영 연결을 수행했다.
- 상세 설계·수용기준: [통합보기 설계](통합보기_설계.md)의 INT-01~08, T01~08.
- 생략: 실제 AI 시스템 개발, 이미지 생성, 외부 호스팅·배포, 예산 산정 확정. 이번 범위에는 필요하지 않다.

## QA·사용자 관점·평가

- 국민 문제와 법적 역할을 먼저 읽고 R&D·정보화 범위를 비교하도록 구성했다. AI 기능에는 비AI 대안을 나란히 뒀다.
- 별도 R&D 필요성이 확인되지 않은 튜닝·드론 안내 후보와 가능규정의 실제 수탁 확인이 필요한 교통약자·위험물 운송 후보를 구별했다.
- 후보·법적 근거·확장기관을 실제 화면에서 선택하고 원문 링크와 관계도 이동을 확인했다. 모바일에서는 열을 카드로 재배치했다.
- 자체 QA 판정: **조건부 합격 — 내부 기획 탐색·조회 용도**. 필수 화면 결함은 수정했다. 실제 사업 착수·선정 판단은 보류한다.
- 독립 평가위원·법률전문가의 판정은 받지 않았다. 이를 기관 승인 또는 독립 평가 완료로 표시하지 않는다.
- 실제 국민·현업 인터뷰, 스크린리더 낭독, 종합 WCAG 검증은 미실시다. 키보드·반응형 확인만으로 전체 접근성 인증을 주장하지 않는다.
- 시각 점검은 실제 화면 캡처로 수행했다. 생성 이미지·참조 이미지 편집을 사용하지 않아 이미지 생성용 점수표는 적용하지 않았다.

## 운영·복구·다음 조사

1. `사업포트폴리오.json`의 후보 ID와 출처·확인일·미확인 상태를 유지한다. 예산·일정·목표값의 null을 0 또는 확정으로 바꾸지 않는다.
2. 원장 변경 후 `생성_통합보기.py`를 실행해 화면·요약·과제 관리대장의 생성 구간을 함께 갱신한다. 생성 구간 밖의 기존 기록은 보존한다.
3. 법적 사실이 바뀌면 기관·법령 원장과 해당 업무를 먼저 검토한 뒤 후보를 갱신한다. 파생 산출물을 최신 근거로 자동 승격하지 않는다.
4. 분류·상태·직접 이동·화면을 변경하면 해당 검사와 연결된 관계도 회귀검사를 실행한다. 새로운 선정·예산·공고 단계로 확대할 때는 데이터뿐 아니라 표시 문구·검증 범위도 함께 갱신한다.
5. 복구는 이전 원장·화면 원본을 복원해 재생성하는 방식이다. 기존 관계도는 통합보기 링크·직접 이동 추가 부분을 되돌려 복구할 수 있다. 원본 아카이브 삭제·변경은 필요하지 않다.
6. 기존 평일 오전 9시 리서치 운영 문서에 포트폴리오 갱신 절차를 연결했다. 이번 변경은 예약 실행을 실제 수행했다는 뜻이 아니다.
7. 다음 조사: TS-BIZ-001·002·003의 기존 자산·실제 수요·중복과 TS-BIZ-004·007의 실제 위탁·대행을 우선 확인한다. 이후 다른 기관의 법정업무·사회문제·공고를 비교한다. 이는 조사 효율을 위한 제안이며 사업 우선순위 확정은 아니다.

후보별 다음 입력은 공식 문제 통계, 실제 사용자 요구, 계약·자산·데이터 권한, R&D 선행과제·차별성, 정보화 사전계획, 공고·재원·심의 적용성이다. 현행 기능·운영비·효과를 검증한 뒤 선정과 추진 계획을 구체화한다.
