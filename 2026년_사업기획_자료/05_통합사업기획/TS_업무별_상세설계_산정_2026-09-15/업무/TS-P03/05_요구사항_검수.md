# TS-P03 요구사항·검수

위험물질 운송계획·점검 인계 문서 일치 확인

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P03-HF01 | 승인본 선택 / 계획 개정 이력이 있으면 점검 시점의 적용본을 선택한다. | 최신 파일이라는 이유만으로 당시 계획을 덮어쓰지 않는다. / TS-P03-HT01 |
| TS-P03-HF02 | 차량·물질 상충 / 명칭 유사도와 공식 식별값 대조를 분리한다. | 식별값 불일치는 같은 물질·차량으로 자동 합치지 않는다. / TS-P03-HT02 |
| TS-P03-HF03 | 인계 항목 확인 / 조치 내용·수신기관·회신 책임을 초안에서 점검한다. | 수신기관이 미확정이면 자동 발송 대상에 배정하지 않는다. / TS-P03-HT03 |
| TS-P03-HF04 | 수신 상태 추적 / 발송과 수신 확인을 원천 상태로 구분한다. | 전송 완료만으로 수신 완료를 표시하지 않으며 마지막 확인 시각을 표시한다. / TS-P03-HT04 |
| TS-P03-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P03-HT05 |
| TS-P03-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P03-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 위험물 운송 업무 유형 1개, 계획/점검/인계 문서 3종, 조회 1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
