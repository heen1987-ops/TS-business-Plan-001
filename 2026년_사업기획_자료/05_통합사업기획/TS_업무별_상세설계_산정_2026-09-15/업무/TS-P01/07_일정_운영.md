# TS-P01 추진 일정·운영

운수회사 안전점검 개선조치 증빙 검토 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 추진 전제·책임

TS 점검부서가 종결·보완 사례와 기준 버전을 제공하고 COSAS 운영자가 점검키·기관별 권한을 확인한다.

CCK가 분석·NOA/LLM 구성·화면/연계·검증·운영 인계를 주관한다. TS는 자료·권한·규칙·정답·검수·공식 업무 결정을 맡는다. 원 시스템 공급사 변경 작업은 별도 책임과 범위를 확정한다.

## 단계·종료 조건


| 단계 | 수행 | 종료·책임 |
| --- | --- | --- |
| G0 범위 | 운수회사 한 업종, 점검 유형 1개, 전자문서 3종, 기존 기록 조회 1개 | 자료·API·계약·검토자 확인 / TS+CCK |
| G1 설계 | 지적·증빙 키와 정답 사례 정의 | 요구·화면·데이터·권한·평가셋 승인 / TS |
| G2 구현 | 점검 유형 1개에서 지적·증빙 대조와 보완 초안을 제공하고 담당자가 기존 화면에서 처리 | 정상·예외 흐름 시연 / CCK |
| G3 검증 | P17을 통해 검토 이력 연계; 종결 반영은 상태 충돌·승인 검증 후 별도 활성화 | 기능·권한·근거·성능·복귀 시험 / CCK+TS |
| G4 시범·인계 | 승인 사용자·물량으로 제한 적용 | 현업 인수·운영 교육·복귀 확인 |
| 후속 | 새 점검 유형은 기준팩과 평가 사례를 추가하고 대조 엔진은 재사용 | 효과·자원·추가 물량 검토 후 결정 |


## 일정·인력 환산 가정

증분 중간 공수 32인일을 평균 2명·주 5일로 단순 환산하면 약 4주다. 자료·권한·현업 검토 대기 4주를 별도 가정한 참고 기간은 **약 8주**다. 공통 기능·선행 업무·조달·보안 심의 기간은 포함하지 않았다. 22개를 이 기간에 모두 수행한다는 계획이 아니다.

분석→구성→연계→시험의 의존성을 지킨다. 독립 자료 정리·화면 설계만 병행하고 실제 팀은 직무 겸임·병행을 조정한다.

| 위험 | 대응 | 책임 |

| 자료·기준 변경 | 관련 결과를 재확인 상태로 전환하고 승인 후 갱신 | 자료 소유자 |

| 연계 오류 | 대상·기간 불일치 → 보완 요청 | 원 시스템 운영부서 |
| 효과 미달 | 원인·피드백·범위 수정 후 재평가 또는 중단 | 사업 책임자 |


## 운영·성과 환류

- 월별 지식 갱신·오류·권한 변경·실패 호출·응답 시간·수정량 검토
- 규칙·지식·프롬프트 변경 시 회귀 사례 재실행과 이전 승인 버전 보관
- 업무 지표: 중요 보완 누락 건수·잘못된 충족 표시·건별 검토시간
- 인수인계: 설치 구성·권한표·지식 목록·연계 계약·장애·복귀 절차·제약 전달



## 준비 상태

문서 설계·기획 산정 초안 단계다. 자료권한·연계·견적·제품 시험·현업 승인·운영 반영은 미완료다. 이 문서는 배포 승인이나 확정 사업계획을 의미하지 않는다.
