# TS-P19 요구사항·검수

DRT 이용 조건·예약 완료 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P19-HF01 | 장소·조건 확인 / 자유 입력 장소를 공식 위치 후보로 바꾸고 이용자가 확인한다. | 동명 정류장·지역 경계는 임의 선택하지 않는다. / TS-P19-HT01 |
| TS-P19-HF02 | 지역 규칙 적용 / 지자체·운송모델에 해당하는 운영 구역·시간 규칙을 적용한다. | 다른 지역 규칙을 혼용하거나 조회 불가를 운행 없음으로 표시하지 않는다. / TS-P19-HT02 |
| TS-P19-HF03 | 선택 후 요청 / 제시한 출도착·시간·조건을 이용자가 확인한 뒤 기존 시스템에 요청한다. | 시간·정류장 변경이 생기면 재동의를 받고 요청 중복을 방지한다. / TS-P19-HT03 |
| TS-P19-HF04 | 접수·배차·취소 구분 / 공식 상태코드로 접수와 배차·취소 완료를 구분한다. | 접수 응답만으로 차량 도착을 확정하지 않고 취소 실패도 숨기지 않는다. / TS-P19-HT04 |
| TS-P19-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P19-HT05 |
| TS-P19-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P19-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 지자체 1곳·운송모델 1개, 텍스트 또는 직원 입력 보조, 조회·예약 각 1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
