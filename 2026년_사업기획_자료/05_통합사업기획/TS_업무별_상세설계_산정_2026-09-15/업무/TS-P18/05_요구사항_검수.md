# TS-P18 요구사항·검수

K-패스 이용 등록·처리결과 이해 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P18-HF01 | 본인 정보 한정 / 조회 동의와 본인확인 범위의 상태만 가져온다. | 대화에 다른 사람 이름이 있어도 그 사람의 상태를 조회하지 않는다. / TS-P18-HT01 |
| TS-P18-HF02 | 상태 구분 / 등록 완료·카드 연결·처리 대기의 원천 코드를 각각 표시한다. | 카드를 발급받았다는 진술을 등록 완료 상태로 바꾸지 않는다. / TS-P18-HT02 |
| TS-P18-HF03 | 사유 설명 / 공식 사유코드와 해당 기간 규칙에 따라 이유를 설명한다. | 빈 사유코드를 소득·자격 문제로 추정하거나 환급액을 임의 계산하지 않는다. / TS-P18-HT03 |
| TS-P18-HF04 | 정정·문의 인계 / 사용자 확인 후 기존 경로로 넘기고 접수 상태를 확인한다. | 문의 페이지 열림을 처리 완료로 표시하지 않는다. / TS-P18-HT04 |
| TS-P18-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P18-HT05 |
| TS-P18-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P18-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 등록 완료 확인 또는 미지급 상태 설명 중 1개 흐름, 조회 1개·인계 1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
