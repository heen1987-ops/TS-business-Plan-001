## 2. 현행 기반과 고도화 목표

배달업 이륜차 강사교육·승인 교안을 이용하는 업무에 이륜차 콘텐츠팩·교안 검토 규칙·강사 화면 설정 항목을 추가한다. 현행 내부 화면·소요시간·API를 직접 시험한 것은 아니다. 아래 흐름과 오류 처리는 **제안 설계**이며 현업 워크숍에서 실제 절차와 대조한다.

대표 상황: 강사가 신규 입사자의 질문을 실제 교육 사례로 바꾸되 위험한 요령을 섞지 않아야 하는 상황

| 현행 기반 활용 | 고도화할 처리 | 유지할 공식 책임 |
| --- | --- | --- |
| 배달업 이륜차 강사교육·승인 교안 | P21의 공통 교육 기능에 이륜차 배달 상황·수칙·강사 교안을 추가하는 전문 콘텐츠 모듈 | 기존 업무의 자격·검사·예약·지급·공개·안전 판단 권한 |
| 공통 교안·강사 가이드·검증된 상황문답 템플릿 | 이륜차 상황에 맞는 문답·교안 보완·안전수칙 대조 | 원천 데이터·적용 기준의 승인과 검토자 확인 |


국민에게 기대하는 가치는 정확한 다음 행동과 보완 필요를 더 빨리 이해하거나, 담당자의 검토 누락을 줄이는 것이다. 다음 지표를 측정해 확인한다: 위험한 요령 생성·근거 없는 설명·교안 수정 부담·교육생 이해. 업무시간 절감을 감축 인원으로 환산하지 않는다. 사고 감소·무사고를 이 기능만으로 입증했다고 주장하지 않는다.

## 4. 처리 흐름과 화면

이륜차 모듈 선택 → 상황 입력 → 교재 대조 → 교안·문답 초안 → 강사 수정 → 교육 책임자 승인 → 사용. P21 공통 상태·승인 기능을 그대로 사용한다.

| 순서 | 사용자·시스템 동작 | 처리 책임 |
| --- | --- | --- |
| 1 | 학습목표와 교재를 이륜차 모듈로 고정한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 2 | 배달 사례를 교재 수칙과 대조해 상황 문항을 만든다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 3 | 문항·정답·해설·근거를 개별 수정하고 변경을 기록한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 4 | 교육 책임자가 승인한 버전만 사용 목록에 올린다. | 사용자/현업 확인 후 공식 시스템의 권한 유지 |


화면 TS-P22-S01은 **입력·조건 → 근거를 포함한 결과 → 사용자/담당자 확인 → 다음 처리** 순서로 구성한다. 원문 위치와 적용본은 결과 옆에서 확인하고, 확인 전 초안과 확정된 원천 상태를 구분한다. 모바일은 입력·결과·확인을 세로로 배치하며 조건을 잃지 않는다.

| 화면 상태 | 필수 동작 |
| --- | --- |
| 대기·조회 중 | 입력을 보존하고 진행 단계 표시; 확정 버튼 중복 실행 방지 |
| 자료 없음·일부만 확인 | 없는 항목과 미확인 사유, 가능한 다음 행동 표시 |
| 권한 거부 | 자료 내용을 노출하지 않고 권한 요청 또는 기존 창구 안내 |
| 오류·시간 초과 | 현재 처리 결과를 확정하지 않음; 원 상태 재조회 후 재시도 |
| 정상 결과·확인 대기 | 근거·적용본·한계를 읽고 사용자가 선택 또는 담당자가 수정 |
| 이관·확정·반려 | 공식 응답이나 담당자 결정 이력으로 상태 구분 |


화면 상세 디자인과 API 실주소는 별도 구현 단계에서 확정한다. 키보드 입력·오류 초점·상태 읽기와 모바일 조건 유지가 제품 인수 시험 대상이다.

## 5. 데이터·출력 계약

아래 필드명은 **논리 설계 예시**다. 실제 원 시스템 필드·API가 존재한다는 뜻이 아니다. 필드별 필수 여부·보존기간·마스킹·추출 가능성을 원천 담당자와 매핑표로 확정한다.

| 입력 논리 항목 | 연결·검증 규칙 |
| --- | --- |
| course_module / learner_role | 강사 양성 또는 신규입사 교육 중 1개 |
| motorcycle_material / version | 승인 이륜차 교재·수칙 |
| delivery_scenario | 배달 시간압박·교차로 등 텍스트 상황 |
| question / answer / rationale | 문항·정답·근거 해설 |
| instructor_edit / approval | 강사 수정과 교육 책임자 승인 |
| used_version / feedback | 사용 교안 버전·수정 의견 |


출력은 다음 항목을 묶고 각 항목에 원문 참조·버전·확인 상태를 붙인다.

- 배달 상황별 문항·해설 초안
- 교재 근거와 안전상 금지 사항
- 강사 진행용 질문·지도 메모
- 교육 책임자 승인 교안
- 기각·수정된 문항 이력

공통 메타데이터: case_id, source_refs, source_version, retrieved_at, rule_version, model_config_version, review_status, reviewer_action. 여기의 review_status는 제안 기능의 상태이며 법정·업무 처분 상태를 대신하지 않는다.

초기 외부 시스템 연계 0개. P21의 교안·승인·배포 관리 모듈을 사용하며 이륜차 자료·문항·강사 역할 설정만 추가한다. 개인 운행데이터 존재를 가정하지 않는다.

자료가 없으면 승인된 파일 반입·공개 지식만으로 가능한 1단계까지 수행한다. 개인 데이터 조회·쓰기 연계가 필요한 후속 단계는 실제 인터페이스와 권한이 확인돼야 개발 범위를 확정한다.

## 8. 데이터 주권·안전·운영

교육 엔진·강사 화면을 P21과 P22에 각각 견적할 위험. P22는 이륜차 규칙·콘텐츠·평가·설정 비용만 산정한다.

- 자료 원본·검색 인덱스·모델 호출·로그·백업·라이선스 경로를 기존 서버 환경에서 점검한다. 로컬 배치라는 이유만으로 외부 전송이 없거나 보안이 충족됐다고 단정하지 않는다.
- 문서 안의 명령·외부 링크는 근거 데이터로 취급하고 실행 지시로 사용하지 않는다. 인용 권한은 검색과 원문 열람 모두에서 검증한다.
- 기준·문서 변경과 접근 철회 시 결과를 재확인 대상으로 전환하고 인덱스 갱신·삭제 전파 방법을 검증한다. 보존기간과 삭제 권한은 TS 정책 확인 후 설정한다.
- 기존 업무 화면을 복귀 경로로 보존하고 AI 기능만 비활성화할 수 있게 한다. 쓰기 도입 시 요청 식별자·상태 재조회·승인·중복 방지·복구 담당을 계약에 명시한다.

법정업무 확인 범위: 2026년 전문강사 양성 공고로 업무 확인. 공고 내 신청연도 2025 표기는 다른 2026 일정과 불일치해 현행 접수 근거로 사용하지 않음. 실제 현행 조문·위탁 관계·개인정보 처리 근거의 최종 적용 검토는 착수 전 확인 항목이다.

P21 공통 교육 엔진에 이륜차 과정·강사 권한·평가 사례를 추가 P21의 문답 엔진·승인 기능 비용은 이 보고서 견적에서 제외한다.
