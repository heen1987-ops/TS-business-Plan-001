발주 전환의 입력

사업의 필요성이 검토되었다고 즉시 공고할 수 있는 것은 아니다. 승인 범위·예산 근거·집행 시기·수행조건·계약 절차를 해당 권한자가 확인한 뒤 발주 검토용 초안을 만든다. 이 패키지는 실제 공고를 수행하지 않는다.

기획 항목 발주 문서로 전환 검토 규칙
국민·직원의 미해결 문제 추진 배경·사업목적 공개 가능한 근거만 사용, 기대효과를 사실처럼 쓰지 않음
선택한 정책·사업 대안 과업 범위·구축 대상 승인된 범위만 포함, 운영 개선도 필요하면 과업으로 분리
실행 기능 기능·데이터·연계 요구사항 입력·처리·출력·예외·권한·수용기준 명시
측정할 결과 산출물·시험·검수기준 모호한 품질 표현을 측정방법·책임자·임계값으로 구체화
비용·일정 사업기간·인력·인수조건·예산 참조 비용 항목의 기능과 발주 요구사항이 서로 일치
제약·기존 환경 재사용·연계·보안·운영 조건 실제 제공되는 자산·이용권·API만 환경으로 명시

요구사항 변환 예 — 가상 기획 사례

기획 표현: 예약 가능한 날짜를 찾는 과정의 화면 왕복을 줄인다.

발주 검토용 요구사항: 승인된 예약 조회 인터페이스가 제공되는 경우, 입력한 차량·희망일·지역 조건을 유지하며 검사소별 예약 가능 상태를 비교하도록 제공한다. 조회 시각·실패·정보 미제공 상태를 표시한다. 검수는 고정 시험 데이터에서 조건 유지, 상태 일치, 타임아웃 처리 및 키보드 흐름을 확인한다.

이는 현재 API 존재나 가용상태를 확인했다는 의미가 아니다. API가 없으면 제공 범위·비용·효과를 다시 판단한다. 이 개별 사업의 구현이 P23 플랫폼 개발비에 포함되는 것도 아니다.

공고 준비 시 사람이 확정할 필드

계약 방식, 적용 계약규정, 참가자격, 입찰·제출 일정, 평가방법·배점, 계약기간, 예정가격 관련 처리, 공동수급·하도급 조건, 제출서류, 보안·개인정보·접근성 요건, 문의처를 계약·법무·업무 담당자가 확인한다. 빈값을 그럴듯한 통상 문구로 채우지 않는다. 해당없음도 판단 근거를 남긴다.

RFP 구성안은 일반적인 발주 문서 설계이며, TS의 현행 표준 RFP·계약규정·공고양식을 모두 확보·검증한 결과가 아니다. 관련 지침은 현행 적용 버전의 본문과 실제 발주처 서식을 추가 확인한다.

공급사와 기능의 구분

CCK가 NOA·로컬 LLM·문서 자동화·SI를 결합해 주사업자로 수행하는 기획이다. 다만 실제 공공 RFP 초안은 기능·성과·보안·연계 요구 중심으로 작성한다. 특정 공급사의 선정이 확정되었다고 쓰지 않으며, 기존 NOA 연계 조건은 실제 보유 환경과 재사용 필요성이 확인될 때만 반영한다.

변경 관리와 공개본

예산이 30% 줄었다면 문서의 금액만 바꾸지 않는다. 요구사항·자료량·양식 수·일정·검수 범위를 재검토 대상으로 표시하고 담당자가 조정안을 선택한다. 영향을 받는 사업설명자료·RFP·공고 인계서의 이전 승인 상태도 재확인한다.

공개본에는 허용된 근거 요약만 넣고 민원 개인식별정보·기관 내부 검토의견·비공개 예산자료는 공개 적합성을 확인한다. 내부 원문 접근권한이 공고문 공개 권한을 뜻하지 않는다.
