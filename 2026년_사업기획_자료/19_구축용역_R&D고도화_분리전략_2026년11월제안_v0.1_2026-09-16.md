# 선도입·운영 기반 기술고도화 전략 — 구축용역(A권)·R&D고도화(B권) 분리

## 0. 이 문서의 위치

사용자가 `18_전체구조_재구성_마스터인덱스` §3.1이 제시한 "D트랙을 본안으로, N-08B를 참고자료로"라는 단순 화해안 대신, **"같은 서비스 안에서 용역으로 완성할 범위와 도입 후 R&D로 고도화할 기술을 구분한다"**는 더 정교한 전략을 직접 제시했다. 이 문서는 그 전략을 (1) 법령·제도 사실관계 검증, (2) 이 프로젝트 기존 자산과의 매핑, (3) 연결표 골격, (4) 지금부터 확인해야 할 재원경로 체크리스트로 구체화한다.

**18번 §3.1과의 관계**: 18번의 화해안("D트랙 본안, C트랙 참고자료")은 **틀린 것은 아니었으나 구조가 더 단순했다** — "두 문서 중 무엇을 쓸지"였다면, 이번 전략은 "같은 서비스 안에서 어디까지가 용역이고 어디부터가 R&D인지"를 기능 단위로 가른다. D트랙(AUD-F01~10)과 C트랙(N-08B 10단계 검사모델)의 1:1 대응 관계(18번 §3.1에서 확인)는 **그대로 유효한 근거자산**이며, 이번 A권/B권 분리 작업의 출발점이 된다.

**이 프로젝트 기존 문서와의 정합성 갱신 필요**: `03_R&D기반_사업기획_기조_재정립` §7(예타 대응 기조)이 "국가재정법(500억)/공운법(2,000억)" 예타 기준을 R&D를 포함한 일반 사업에 함께 적용되는 것처럼 서술하고 있는데, **이제는 구분해야 한다**:
- **일반(비R&D) 정보화·건설 등 사업**: 기존 국가재정법 §38(500억)/공운법 §40(2,000억) 예타 기준이 **그대로 유효**(이번 개정은 R&D 특칙만 건드림) — T2(대형전환) 같은 비R&D 트랙에 계속 적용.
- **국가연구개발사업(B권이 해당할 가능성)**: 이제 예타가 아니라 **연구형/구축형 이원화 사전점검**(대형기준 1,000억)을 따른다 — B권이 1,000억 근처 규모가 아니라면 이 절차 자체가 적용 안 될 가능성이 높고, 그 경우 소속 부처(국토부)의 **기존 R&D 사업 내 신규과제 공모** 경로(사용자 §7-①의 네 번째 행)를 확인하는 것이 현실적이다.

이 갱신은 `03_R&D기반_사업기획_기조_재정립` §7에도 반영 필요 사항으로 남긴다(이번 문서에서는 지식만 정리, 원문 수정은 사용자 확인 후).

## 2. A권·B권 정의 (사용자 원문 그대로 채택)

| 구분 | A. Noa 기반 AX 서비스 구축 용역 | B. 도입·운영 기반 AI Agent 엔진 고도화 R&D |
|---|---|---|
| 핵심 질문 | 현재 확보한 기술로 어떤 국민·기업 문제를 해결할 것인가? | 도입된 서비스의 어떤 기술적 한계를 새로운 방법으로 넘어설 것인가? |
| 산출물 | 운영서비스·연계기능·업무별 스킬·운영검수자료 | 개선 엔진·알고리즘·평가자료·비교실험 결과 |
| 평가 기준 | 계약상 기능·성능·보안·운영 요건 충족 | 기존 엔진·대안 대비 기술적 개선과 재현 가능성 |
| 미달 시 | 계약상 보완 | 검증 안 된 결과는 운영 미반영 |
| 독립성 | **R&D 선정·성과와 무관하게 독립 성립** | **용역의 미완성 기능을 대신 완성하는 사업이 아님** |

**판별 절차(OECD R&D 기준 채택)**: 신규성·창의성·결과의 불확실성·체계성·이전/재현 가능성 5개 기준으로 "일반 고도화(용역 범위)"와 "R&D 후보"를 가른다. 계약 결함(문서가 안 열림, 상태가 사라짐, 승인 없이 제출됨)은 **R&D가 아니라 용역 하자보수**로 즉시 분류.

## 3. 4개 기술영역 × 이 프로젝트 기존 자산 매핑

사용자가 제시한 4개 기술영역을 이 프로젝트가 이미 만들어둔 산출물에 직접 대응시켰다. **"이미 상당 부분 설계돼 있다"**는 것이 이번 매핑의 핵심 발견이다 — 완전히 새로 시작하는 게 아니라, D트랙·N-08B·22개업무·N-코드 전부가 이미 이 네 영역 어딘가에 해당하는 기능을 다뤄왔다.

| 기술영역 | 구축(A권)에서 완성할 기준기능 | 운영 후 고도화(B권) 후보 | 이 프로젝트의 기존 근거자산 |
|---|---|---|---|
| **① 문서 구조·의미 이해** | 합의된 문서유형 구조화·항목추출, 원문연결, 인식실패 표시 | 복합 표·주석·첨부관계 있는 신규 문서배치에서 의미연결 성능 저하 여부 | N-03(전세버스 안전공시 AI판별, SFR-008), N-20(튜닝승인 사전판정), N-08B_06 M01(문서 구조화), D트랙 1차PMS "산출물과 검토"(원문·버전 관리) |
| **② 근거·요건 관계 검증** | 승인된 기준검색, 대상자료 대조, 기준일·출처 표시, 미확인사항 사람검토 | 다수 문서·개정이력이 얽힐 때 상충·영향관계 탐지 성능 | **가장 두터운 자산** — N-09(법령-위탁업무 정합성 진단), D트랙 AUD-F02·F05(기준팩·발견사항), N-08B_06(AI감리엔진 5개호 매핑), 17번 문서 후보A(교환·환불 증거지원)·B(기술검토 요건증빙)·C(철도 운영변경 안전증빙) 전부 이 영역 |
| **③ 업무계획·실행** | 승인된 워크플로우, 실행상태 저장, 재시도·중복방지, 권한확인·사람승인 | 사전 미정의 복합 예외상황에서 안전한 업무 재구성 | N-08(A) PMS 이행관리(즉시 착수 INCUBATE), D트랙 1차PMS 전체(사업·일정·회의·인수인계), P23(정책기획 8단계 워크플로우), N-08B_02 RFP초안의 Project Workflow |
| **④ 추론·자원관리** | 합의된 동시사용·처리시간 충족하는 배포·설정 | 업무난도·문서량 변화 시 품질 유지하며 자원사용 절감(적응형 추론) | **이 프로젝트에서 가장 얕은 영역** — 09-15 대화에서 다룬 GPU 인프라(H200×2세트+RTX Pro 6000×1세트, 용량산정 문서 없음)가 유일한 관련 논의. N-08B_12 §5가 "NoA Core 변경범위 미확정"이라 밝힌 것도 사실상 이 영역의 공백 |

**관찰**: ②(근거·요건 관계 검증)가 압도적으로 두텁고, ④(추론·자원관리)가 가장 비어 있다. **B권(R&D)의 가장 방어하기 쉬운 후보는 ②의 "다수 문서·개정이력 얽힘" 시나리오**(이미 D트랙·N-08B·17번이 세 번 독립적으로 이 문제를 다뤄왔다는 것 자체가 "반복되는 공통 기술문제"라는 사용자 §4의 요구조건과 정확히 부합), **④는 아직 구체적 문제 사례가 없어 지금 시점엔 근거가 가장 약하다.**

## 4. 구축–운영–R&D 연결표 (골격 + 예시 1건)

사용자가 요청한 8단계 체인(국민·기업 문제→구축 요구사항→납품·검수 기능→운영 기준선→관측된 기술적 한계→R&D 목표→개선 엔진→재검증·적용조건)의 템플릿과, ②영역에서 가장 근거가 두터운 사례(17번 문서 후보B, 기술검토 요건-증빙)로 채운 예시 1건이다. 나머지 항목은 A권·B권 본문 작성 시 동일 형식으로 채운다.

| 단계 | 예시(후보B: 자동차 기술검토 요건-증빙 준비 Agent) |
|---|---|
| 국민·기업 문제 | 제작·수입기업이 제품 적용요건과 제출자료 입증범위를 맞추기 어려워 반복보완 발생(가설, 규모 미검증) |
| 구축 요구사항 | 제품자료 구조화, 요건-증빙 연결표 생성, 불일치 표시(①·②영역 조합) |
| 납품·검수 기능 | 지정 문서유형에 대해 요건 후보 확인 + 증빙 연결 + 사람 최종검토 화면 |
| 운영 기준선 | 도입 시점의 반려율·재제출 횟수·검토 소요시간(계약 검수조건으로 사전 정의) |
| 관측된 기술적 한계(운영 후 확인 대상) | 제품군이 다양해지며 서술형 기술설명과 요건의 의미 연결 정확도가 저하되는지 |
| R&D 목표 | 다수 개정이력·제품군 간 의미관계 검증 기술 — 기존 검색·규칙 대비 개선 여부 비교 |
| 개선 엔진 | 관계기반 근거검증 엔진(②영역 공통기술, D트랙 AUD-F02/F05 + N-08B M01~M02 재사용) |
| 재검증·적용조건 | 같은 표본에서 기존방식·개선엔진 비교, 개선 확인된 모듈만 반영 |
