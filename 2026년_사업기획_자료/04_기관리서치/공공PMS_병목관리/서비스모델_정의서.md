# Public AI-PMS 서비스모델 정의서

2026-09-10 · 서비스모델 v0.1 · 설계 검토안

**공공서비스를 만드는 정보화사업의 누락·재작업·관리 단절을 줄여, 국민이 이용하는 서비스의 품질과 연속성을 높이는 것을 목표로 한다.**

국민 효과는 검증할 가설이다. 직접 사용자는 발주기관·수행사·감리원이며, 대상 공공서비스에서 실제로 어떤 장애·이용 불편이 줄어드는지 연결해 확인한다.

현재 작업은 **서비스 정의·업무 설계**에 한정한다. 2026-09-10 사용자의 “구현은 하지 말고 설계와 서비스모델을 명확히”라는 정정을 우선한다. 기존 HTML·API 초안은 참고 이력으로 유지하며, 새 기능·화면·코드·시제품을 구현하지 않는다. 본 문서를 서비스 범위와 도입·운영 모델의 우선 검토 문서로 삼는다.

## 1. 서비스 정의

### 서비스명

Public AI-PMS — 공공 정보화사업 이행관리·검증 지원 서비스.

### 한 문장 정의

**발주기관과 수행사가 같은 사업공간에서 기준·일정·산출물·검토·보완을 함께 관리하고, AI와 전문가의 검토를 통해 확인된 결과를 인수인계·유지관리·기업 수행이력·다음 사업에 연결하는 서비스다.**

### 서비스가 약속할 가치

| 대상 | 사용자가 얻는 변화 | 서비스에서 제공할 결과 |
|---|---|---|
| 발주기관 담당자 | 지금 누가 무엇을 처리해야 하는지, 무엇이 막혀 있는지 파악 | 역할별 처리 목록·대기 원인·근거가 연결된 검토·미결 사항 |
| 수행사 PM·실무자 | 제출 기준과 완료조건을 알고 사전에 보완하며 공식적으로 소명 | 합의 기준·자체점검·제출 기록·보완과 소명의 처리 이력 |
| 부서장·최종 책임자 | 진행률 숫자와 함께 중요한 미결·판단 사유 확인 | 쟁점·변경·위험·승인 필요사항과 확인 근거 |
| 감리원·전문가 | 자료를 다시 모으는 부담을 줄이고 검증할 항목과 증거 확인 | 검사 대상·원문·시험증거·차이점·시정 및 재검증 기록 |
| 후임·운영 담당자 | 과거 결정과 현재 책임·지원기간을 이어 파악 | 상시 인수인계 자료·운영 책임·미결 장애·차기 계약 준비 |
| 기관의 기획·평가 담당자 | 다음 판단에 실제 수행·성과·정정된 이력 활용 | 역할별 레퍼런스·다면평가·개선 수요·후속 요구의 근거 |

서비스의 성공은 화면 수나 AI 답변 수가 아니라 **기관과 수행사가 실제 업무를 끝내고, 그 결과와 판단 근거가 다음 담당자·사업에도 이어지는가**로 판단한다.

## 2. 무엇이 문제인가

현행 문제는 사용자 경험에서 도출한 가설이며 모든 공공기관의 실태로 확정한 사실은 아니다.

| 현행 문제 가설 | 왜 비용과 위험이 생기는가 | 서비스로 바꿀 행동 |
|---|---|---|
| 계약·RFP·계획·지침을 반복해서 찾음 | 기준 해석과 과업 범위 확인이 반복됨 | 착수에 적용 기준·책임·완료조건을 함께 확인 |
| 기관과 수행사가 별도 일정·파일로 관리 | 제출, 검토, 승인 중 어디서 기다리는지 모호함 | 양측 업무와 선행조건·다음 행동을 같은 흐름으로 관리 |
| 파일 제출과 과업 완료가 혼동됨 | 검토·보완·시험증거의 누락을 뒤늦게 발견할 수 있음 | 제출·검토·보완·재검증·승인 상태를 구분 |
| 검토의견·보완·소명이 메일·전화에 분산 | 같은 내용을 재확인하고 정정이 다음 판단에 반영되지 않음 | 지적마다 근거·응답·재확인·확정 상태를 연결 |
| 담당자 변경·사업 종료 후 관리가 끊김 | 결정 이유·지원 책임·다음 발주 준비를 다시 찾음 | 서비스·사업·계약의 관계를 유지하고 미결 책임을 인계 |
| 업체 평가는 담당자의 인상에 좌우될 수 있음 | 실제 역할·기여·환경·개선 결과가 생략될 수 있음 | 수행 사실·전문 검토·역할별 의견과 정정 이력을 함께 제공 |

## 3. 고객·참여자·비용 부담

**기준안은 기관이 구매하고 사업 참여자들이 함께 이용하는 모델이다.** 실제 계약형태·가격·기관 도입은 미확정이다.

| 구분 | 기준안 | 책임과 관계 |
|---|---|---|
| 도입 고객 | 정보화사업을 발주·관리하는 공공기관 | 기관 내 적용 사업과 이용 목적 결정 |
| 비용 부담 주체 | 도입 기관 | 도입·이용·기술운영·기관별 적용 비용 부담을 기본 가정 |
| 기관 내 서비스 책임자 | 기관이 지정한 사업관리·정보화 총괄 조직 | 운영규칙·역할·참여 사업·평가 목적·이용권한 관리 |
| 직접 이용자 | 사업 담당·검토·결재·업무부서, 수행사 PM·실무자 | 각자 맡은 업무와 관찰 범위의 기록·판단 |
| 전문 이용자 | 배정된 감리원·감리법인·분야 전문가 | 정해진 범위의 독립적 검토와 전문 판단 |
| 서비스 제공·기술운영자 | CCK를 주관 제공자로 검토 | 서비스 설계·기관 적용·교육·기술운영·오류 대응·품질 개선 |
| 최종 수혜자 | 해당 공공서비스를 이용하는 국민 | 실제 서비스 품질·접근성·연속성 개선 여부를 별도 확인 |

수행사는 해당 사업의 참여자로 이용하도록 한다. 제출·소명·정정·자체점검 등 기본 참여에 별도 유료 등급을 두는 모델은 기준안에 포함하지 않는다. 평가 대상 기업의 유료 구매 여부가 평가·노출·점수에 영향을 주지 않도록 한다.

CCK의 주관 수행은 기획상의 역할 배분이다. 실제 인력·기술자산·재사용권·운영 능력·원가·협력사 확보가 검증됐다는 의미는 아니다. TS는 첫 적용 가능성을 검토할 기관이며 도입·신규사업 선정이 확정된 고객이 아니다.

## 4. 서비스의 기본 단위

기관이 여러 사업을 관리하고, 각 사업에 수행사·감리·업무부서가 참여한다. 사업 종료 후에도 그 사업이 만든 서비스·시스템의 운영과 후속 계약은 이어진다.

    기관
      └ 관리 대상 서비스·시스템
          ├ 구축 사업·계약
          ├ 운영·유지관리 사업·계약
          └ 고도화 사업·계약
              └ 각 사업의 기준·과업·제출·검토·조치·평가·미결 책임

구축·운영·고도화 계약은 동시에 존재할 수 있다. 종료된 사업을 다음 계약으로 덮어쓰지 않고, 무엇을 어느 계약·업체가 책임지는지 관계와 기간을 유지한다.

기관 간 확장은 동일한 서비스 방식의 재사용으로 본다. 여러 기관이 기업 평가와 원문을 자동으로 통합하는 데이터 공유 모델을 전제하지 않는다.

## 5. 제공 서비스 여섯 가지

| 서비스 영역 | 사용자가 하려는 일 | 서비스가 지원하는 처리 | 남길 결과 |
|---|---|---|---|
| S1 공동 사업관리 | 기준을 맞추고 사업을 진행 | 착수 기준 합의, 기관·수행사 공동 일정, 요청·회의·변경·대기 원인 관리 | 사업 기준서·책임·현재 상태·다음 행동 |
| S2 산출물 검토·보완 | 제출자료가 요구에 맞는지 확인 | 제출 전 점검, 공식 제출, 근거 대조, 보완·소명·재확인 | 제출·검토·보완·확정 기록 |
| S3 감리 검사 지원 | 전문 검증을 지속적으로 수행 | AI 검사와 감리사 검토, 차이점 확인, 시정·재검증 | 검사 범위·근거·전문 판단·시정 결과 |
| S4 주기적 평가·수행이력 | 실제 수행과 경험을 공정하게 기록 | 역할별 평가, 확인 사실·의견 구분, 통지·소명·정정 | 기업×사업×역할×기간의 레퍼런스 |
| S5 인수인계·유지관리 | 담당자·계약이 바뀌어도 업무를 이어감 | 목적·결정·미결·지원기간·책임·차기 계약 준비 연결 | 인수인계 자료·운영 책임·후속 조치 |
| S6 성과·차기 사업 환류 | 반복 문제를 개선하고 다음 요구를 정함 | 운영 성과·사용자 경험·개선 대안 검토, 차기 RFP의 근거 정리 | 개선 후보·채택/보류 사유·후속 요구 초안 |

여섯 영역은 공통의 사업 기록을 사용한다. 평가·감리를 위해 동일 자료를 다시 입력하게 만드는 방식은 피하고, 현재 업무에서 남긴 기록을 확인·재사용하도록 설계한다.

## 6. 핵심 서비스 이용 흐름

| 단계 | 이용자의 행동 | 제공자가 지원할 일 | 다음 단계로 넘어가는 기준 |
|---|---|---|---|
| ① 적용 준비 | 기관이 적용 사업·목적·담당 역할을 정함 | 기존 업무·시스템·자료와 중복 입력 점검, 운영규칙·교육 지원 | 사용할 범위·권한·공식 기록의 위치가 명확 |
| ② 기준 합의 | 기관·수행사가 계약·요구·기한·완료조건을 확인 | 근거 추출·정리, 상충·모호한 항목 제시 | 권한자가 기준을 확정하고 쟁점의 처리 방향 결정 |
| ③ 공동 수행 | 양측이 자료 제공·과업·제출·검토 요청을 처리 | 역할별 할 일·대기 원인·제출 전 점검 제공 | 해당 제출본·시점·증거가 접수됨 |
| ④ 검토·감리 | 담당자·전문가가 AI 후보와 실제 증거를 확인 | 기준·원문·차이·미확인 범위 연결 | 확인·추가 증거·보완·전문검토 중 필요한 조치 결정 |
| ⑤ 보완·소명·확정 | 수행사가 보완 또는 소명하고 검토자가 재확인 | 원 지적·응답·수정·판단 근거 연결 | 해결·유지·철회·유보를 권한자가 확정 |
| ⑥ 평가·운영·환류 | 관련자가 경험을 평가하고 후임·운영자가 인수 | 확정 이력·다면평가·미결·지원 책임·개선 후보 제공 | 다음 담당자·사업에서도 정정된 근거와 책임을 확인 가능 |

주기적 평가는 마지막에만 실행하는 절차가 아니다. 착수에 평가 계획을 정하고 정기 점검·주요 산출물·시험·종료·운영 시점에 연결한다.

### 설명 사례 — 가상 정보화사업

공공 예약서비스 구축사업을 가정한다. 착수 때 기관과 수행사가 시험조건·제출자료·완료조건을 확인한다. 수행사는 시험결과서를 제출하고, AI는 결과 수치에 대응하는 원시 로그가 확인되지 않는다고 알린다.

기관 검토자는 자료 부족인지 실제 시험 문제인지 확인한다. 수행사는 다른 첨부에 있는 로그로 소명하거나 필요한 시험·자료를 보완한다. 검토자는 현재 자료로 지적의 해결·유지·철회를 확정한다. 담당자가 바뀌면 이 결정과 남은 조치를 인계받는다.

이 과정에서 평가할 대상은 실제로 확인된 품질·대응·협업이다. AI가 처음 지적했다는 사실만으로 수행사에 불이익을 주지 않는다. 국민이 예약을 더 안정적으로 완료하게 됐는지는 실제 서비스 운영 결과로 따로 측정한다.

## 7. AI·기관·감리·제공자의 역할

| 주체 | 맡을 일 | 확정할 수 있는 것 |
|---|---|---|
| AI | 텍스트·전자문서의 기준 후보, 누락·불일치·증거 부족, 근거 탐색·요약·후속 행동 제안 | 분석 후보와 처리 상태. 법적 책임·기업 귀책·계약 승인으로 확정하지 않음 |
| 기관 담당·검토자 | 업무 맥락·적용 기준·자료의 타당성·보완 필요 검토 | 배정 권한 안의 검토의견·조치 |
| 기관 승인권자 | 기준·변경·업무상 승인·미결 처리 결정 | 기관의 전결·계약 절차에 따른 결정 |
| 감리원·전문가 | 범위별 전문검사·현장 확인·추가 증거·시정 확인 | 해당 제도·계약에서 맡은 전문 판단·감리의견 |
| 수행사 | 이행·제출·자체점검·보완·소명·위험 공유 | 수행 사실의 제출과 의견. 기관 승인·평가를 대신 확정하지 않음 |
| CCK 기술운영 | 서비스 제공·교육·오류 복구·기준팩 관리 지원·품질 개선 | 기술 처리·변경 이력. 기관의 평가·귀책·감리의견을 임의 수정하지 않음 |

AI와 사람의 의견이 같아도 정확성이 입증된 것은 아니다. 의견 차이·양측이 놓친 항목·추가 전문검토를 확인할 수 있어야 한다.

로컬 LLM과 CCK 자산을 활용하는 것을 프로젝트의 기술 방향으로 반영한다. 입력은 텍스트가 있는 전자문서·승인된 구조화 기록을 중심으로 한다. 스캔·사진만 존재하면 기존 검증된 전자화 결과나 텍스트 원본 확보가 선행 조건이다. 모델·장비·구현 방식의 선정은 현재 문서의 범위가 아니다.

## 8. 주기적 다면평가와 레퍼런스 모델

### 누가 무엇을 평가하는가

| 평가자 | 관찰 가능한 영역 |
|---|---|
| 직접 사업 담당자 | 합의 일정·요청 대응·협업 |
| 산출물·기술 검토자 | 요구 충족·시험 근거·보완 품질 |
| 중간관리자 | 쟁점 공유·위험 대응·의사결정 지원 |
| 최종 결재자·책임자 | 사업목적·확정 성과·중요 의사결정 |
| 관련 업무부서 | 업무 적합성·요구 반영·전환·교육 |
| 실제 서비스 사용자 | 사용 편의·접근성·문제 해결 경험 |
| 감리원·전문가 | 검증 범위의 적합성·증거·시정 확인 |

평가 계획에는 대상·항목·관찰 기간·평가자 역할·이용 목적·공개 범위·소명 절차를 먼저 정한다. 모든 사람이 모든 항목을 평가하거나 직급만으로 가중하지 않는다.

### 레퍼런스 한 건의 구성

기업명 + 사업 맥락 + 실제 역할·기간 + 확인된 성과·이행 + 확정 지적·개선 결과 + 역할별 평가 + 자료 충분성 + 소명·정정 상태.

수행 사실, 검사·감리 결과, 사람의 만족도는 구분해 제시한다. 협업 만족도·산출물 만족도·공공서비스 만족도·PMS 사용 만족도를 동일 점수로 합치지 않는다.

### 우수·미흡 수행과 신규기업의 처리

- 우수 수행은 확인된 결과·기여·근거를 긍정적 레퍼런스로 남긴다.
- 미흡 수행은 확정된 내용·영향·실제 책임·소명·개선 결과를 함께 남긴다.
- 내부 점수 증감이 필요하면 먼저 항목별 기준·예외·집계·이의 처리·정정 규칙을 정한다. 현 단계에서는 단일 종합점수나 가중치를 확정하지 않는다.
- AI 후보 수·지연 일수·보완 횟수·위험 신고 건수를 그대로 벌점으로 전환하지 않는다.
- 신규기업의 이력 없음, 미응답·관찰 불가는 미평가·자료 부족으로 표시한다.
- 신규기업도 명확한 과업 기준·제출 전 점검·보완 지원·소명 기회를 이용한다.
- 후속 사업의 담당자는 사업·역할·난이도·기간을 함께 검토한다. 비교 가능한 범위와 자료 충분성을 확인한다.
- 공식 입찰의 가점·감점·제재·기관 간 제공은 적용 근거와 절차를 별도 확인해야 할 활용 영역이다.

### 평가 신뢰를 유지하는 운영

결과 고지 → 소명·추가 근거 → 배정된 재검토 → 확정·정정 → 후속 조회 반영의 경로를 둔다. 최초 평가자와 다른 검토자를 지정할지, 어느 수준에서 상향 검토할지는 기관의 운영규칙으로 정한다.

CCK 또는 협력사가 평가 대상 사업의 수행사이기도 하면 이해관계를 표시하고 판단·정정·권한 변경 책임을 기관과 독립 검토자에게 분리하는 조건을 검토한다. 제공자의 사업 이해가 평가를 좌우하지 않도록 하는 것이 서비스 신뢰의 조건이다.

## 9. 도입·제공 방식

### 비교할 모델

| 모델 | 제공 단위 | 적합성을 확인할 상황 | 비용·운영상 쟁점 |
|---|---|---|---|
| A 기관 단위 도입 | 기관별 독립 업무공간과 여러 사업의 공통 운영 | 담당자 교체·복수 계약·장기 운영 이력이 중요한 경우 | 초기 업무 정리·연계·교육, 기관 운영 책임 필요 |
| B 단일 사업 적용 | 특정 사업·계약 기간의 관리·검토 지원 | 최초 실증으로 흐름과 부담을 확인할 경우 | 사업 종료 후 기록 인계·유지관리 연속성을 별도 설계 |
| C 여러 기관의 공동 운영 | 운영 주체가 정한 기관별 이용 공간 | 공통 운영주체·이용 근거·기관별 권한과 운영 조건 확보 시 | 데이터 공유·비용 배분·사고 책임·규칙 차이 검토 필요 |

**서비스의 기본 모델은 A, 최초 검증 범위는 B의 크기로 잡는다.** 기관 단위의 연속성을 유지할 수 있는 구조에서 한 사업의 업무를 먼저 검증한다. C는 기관별 도입 경험과 운영 근거가 확보된 후 검토한다.

기관 단위 도입은 반드시 특정 서버 설치나 특정 구매계약을 의미하지 않는다. 로컬 LLM 실행·기관의 자료 통제·운영 조건을 충족하는 제공 환경을 이후 도입 설계에서 정한다.

## 10. 수익·비용 모델 — 가격 확정 전의 구조

기준안은 **기관 도입·적용 대가 + 기관별 이용·운영 대가 + 선택 모듈·추가 적용 대가**다. 실제 가격·계약기간·구매방식·수익률은 조사·견적 전이다.

| 구분 | 대가를 받는 가치 | 원가·범위 산정 기준 |
|---|---|---|
| 초기 도입·기관 적용 | 현행 업무와 연결해 실제 사용 가능한 운영체계 정착 | 기존 기능 재사용, 기관별 규칙·연계·이관·교육·검증 범위 |
| 기본 이용·운영 | 여러 사업의 공동 업무와 이력을 안정적으로 유지 | 운영기관·활성 사업 수, 문서 처리 규모, 보존·지원 수준 |
| 감리 검사 모듈 | 검사기준과 전문 검토 지원을 지속 제공 | 검사 범위·기준팩 유지·분석량·검증·지원 비용 |
| 평가·환류 확장 | 누적 이력을 활용하는 기관별 모델 제공 | 평가 운영 설정·정정 관리·성과·후속 기획 범위 |

참여 인원이 늘 때마다 기본 협업이 불리해지지 않도록 기관·사업 단위를 우선 검토한다. 최종 과금 단위는 운영원가와 실제 이용 행태로 결정한다. AI 지적 건수·업체 감점·평가 순위·선정 결과에 연동한 수익모델은 채택하지 않는다.

원가에는 도입·설정·연계·이관·교육, 로컬 추론 환경·라이선스, 기술지원·자료 보존·복구, 기준 업데이트·전문 검토, 오류 확인·재검증·정정 운영을 포함한다.

기관별 적용 공수가 계속 늘어 공통 기능 재사용 이익을 상쇄하면 제품형 서비스의 수익성이 약해진다. 공통 제공 범위와 별도 유상 변경 범위를 사전에 구분하고, 계약 종료 시 기관의 자료·이력 인계와 열람 조건을 명확히 한다.

## 13. 기대효과·정량 편익 모델

### 결과를 판단할 세 층

| 층 | 기대하는 변화 | 측정 대상 |
|---|---|---|

### 산정식

- 순확보 시간 = 비교 가능한 현행 업무시간 − 도입 후 업무시간. 도입 후에는 추가 입력·AI 오탐 확인·보완·정정 시간을 포함한다.
- 직접 시간가치 = 업무별 순확보 시간 × 해당 역할의 적용 단가 × 같은 기간의 실제 업무량.
- 비용 반영 결과 = 직접 시간가치 + 별도 입증된 비중복 편익 − 같은 기간의 도입·이용·운영·추가 검토 비용.

업무량은 건당 시간을 측정했을 때만 곱한다. 이미 한 기간의 전체 시간을 측정했다면 업무량을 다시 곱하지 않는다. 추가 검토시간을 순시간에서 차감했다면 같은 인건비를 비용에서 다시 차감하지 않는다.

시간가치는 확보된 업무 역량의 가치다. 실제 지출이 감소한 현금 절감액과 구분하며 감축 인원으로 바꾸지 않는다. 외부 감리대가·재작업·지연 비용이 실제로 줄었는지는 별도 증거를 확인한다.

기존 설명자료의 가상 시간·감소율·가격은 이 서비스의 실측 효과나 확정 편익으로 채택하지 않는다. 시장 전체 금액에 임의 개선율을 곱하지 않는다.

### 도입 판단을 위한 질문

1. 기존 PMS·업무규칙 개선으로 해결할 수 있는 부분과 AI가 추가로 해결하는 부분은 무엇인가?
2. 기관과 수행사의 전체 업무시간이 줄었는가, 다른 참여자에게 입력 부담이 이동했는가?
3. 검토시간이 줄면서 중요한 누락·불리한 오판·소명 부담이 늘지는 않았는가?
4. 담당자가 바뀌어도 결정·미결·지원 책임이 이어지는가?
5. 확인된 이력이 다음 판단과 공공서비스 개선에 실제 활용되는가?
6. 기관별 설정·운영 원가를 포함해 반복 제공할 수 있는가?

결과를 보기 전에 비교 업무·기간·표본·허용 오류·최소 개선 기준을 정한다. 사업 성공률·공정성·카르텔 감소를 이미 달성한 성과로 표시하지 않는다.

### 문서 검토 기록

검토 방식: 사용자 요구와 이전 설계의 범위·참여자·연차를 대조하고, 서비스 정의→고객 가치→이용 흐름→운영 책임→대가·비용→성과의 연결을 자체 검토했다. 담당자 편의와 공정성, 수행사의 지원·소명, 기본 평가의 1차년도 수집, 감리의 독립 판단을 유지했다.
