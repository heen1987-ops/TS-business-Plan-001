# CCK 기술 기반 TS 사업 확장 검토

2026-09-10 · v1.0 · 현재 사용자 요청 U-CCK-03

[설명 HTML](CCK_TS_기술기반_확장검토.html) · [편집 Markdown](CCK_TS_기술기반_확장검토.md) · [공식 출처원장](출처원장.json) · [문서 검사 결과](검증/검증결과.json)

기존 조사 A/B/C를 5개 사업군으로 연결했다. 예약·신청 실행, 결과 후속 행동, 위험·결함 보고, 조치증빙 대조, 신청 준비·보완이다. 기준 변경과 이용 피드백은 우선 보조 기능으로 두었다. 각각의 CCK 재사용 자산, 추가 개발, 직접·협력 책임, 납품물, 비AI 비교, 실패 처리와 확산 조건을 명시했다.

## 근거와 해석

- CCK 파생 기술대장 K01의 TA-01·02·03·20 구조·주의사항과 TA-23의 계획 단계 표기를 확인했다. K02는 기존 열람을, K03은 이번 재열람을 참조했다. 실제 제품 코드·데모·권리·로컬 모델·성능은 검증하지 않았다.
- TS 공식 업무소개 9건을 선별 열람했다. 리콜센터의 대상·조치여부 조회, COSAS의 기존 분석·진행관리 기능을 신규 기능으로 제안하지 않도록 반영했다.
- 출처원장은 기존 기관 ID ORG-0001에 연결한 이번 문서의 출처 범위다. 정식 사업 원장·전체 기관 모집단의 완료 수에 더하지 않았다.
- X01~X05는 검토 식별자다. 기존 A/B/C와 비교 주제를 새 이름으로 중복 집계하지 않았다. 심층리서치 1~6 결과 본문은 여전히 미열람이다.

## 제작·검증

작업 유형: M 규모 사업기획 확장, 위험도 Medium. 근거 확인 → 설계 → 문서 구현 → 검증의 Standard Loop를 적용했다. 별도 제품 구현·배포·장편 화면설계서는 이번 설명자료 범위에 필요하지 않아 만들지 않았다.

수용기준: 5개 사업군에 근거·기술·추가 개발·납품·책임·검증을 연결하고, 실제 보유와 제안 기능을 구분하며, 연계 조건별 납품 경계가 동일한 HTML·Markdown에 표현돼야 한다. 문서는 한국어·반응형·키보드·인쇄·JavaScript 미사용 시 열람을 지원한다.

- 상세 확장 문서: **31/31 통과**. 5개 사업군·9개 출처, HTML/Markdown 일치, 로컬 링크, 연계 수준 3종, 키보드 상세 열람, 768·390·320px, 200% 확대, 인쇄·상태 복원·JavaScript 미사용 동작을 확인했다.
- 기존 설명자료 v1.3: **52/52 통과**. 기술 확장 요약·상세 링크와 기존 기능 회귀 검사를 수행했다.
- 두 검사에서 외부 HTTP 요청·JavaScript 오류 0건. 실제 CCK·LLM·업무 API는 실행하지 않았다.
- 데스크톱 첫 화면, X04 카드, 모바일 연계 선택 화면을 직접 열어 제목·본문·표·선택 동작의 배치를 검토했다. 표는 작은 화면에서 독립 스크롤을 제공한다.
- 자동 axe, 실제 스크린리더·사용자·독립 평가위원, 실제 인쇄물 전체 조판은 검증하지 않았다. 문서 검사 통과는 WCAG 전체 적합성이나 제품 수행 가능 인증이 아니다.

문서 자체 QA는 합격이다. 기획 확장 초안은 조건부 적합이며, 사업 선정은 수요·비중복·제품·인력·연계·견적 근거 확보 전 보류다. 이는 독립 심사 결과가 아닌 자체 검토다.

## 갱신·보존

`기술확장_내용.json`과 `제작_기술확장.py`에서 두 형식을 생성한다. 생성 파일을 직접 바꾸면 해시 검사로 덮어쓰기를 중단한다. `검증_기술확장.cjs`는 번들 Node.js·Playwright·Edge로 로컬 문서를 확인한다.

기존 설명자료 v1.2는 `../설명자료_2026-09-10/이력/v1.2_기술확장전`에 보존했다. `연결_기술확장.py`는 한 번 실행한 보존·연결 기록이며 재실행용이 아니다. 후속 검증은 기존 Q01~Q11과 추가 Q12를 이어간다.

다음 입력은 X02의 공식 결과 표본, X04의 지적사항-조치 문서 쌍, X01의 API 규격과 운영사 협조, X03의 제도별 보호·서식, X05의 실제 보완 사례·계약 대조다. 인력·납기·원가와 회사 수행 가능성은 별도로 확인한다.
