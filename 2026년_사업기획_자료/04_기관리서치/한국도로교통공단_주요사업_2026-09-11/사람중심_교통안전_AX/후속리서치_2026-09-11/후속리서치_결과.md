# 사람 중심 교통안전 AX 후속 리서치

조사 기준일: 2026-09-11. 대상 기관: 한국도로교통공단(KoROAD). CCK 사업기획 검토용이며 기관의 발주계획이나 승인 문서가 아니다.

## 1. 이번 조사로 달라진 판단

**H01은 고령운전자 정책의 근거 검토를 주제로 구체화하고, H03은 현장 조건과 제품 증빙을 대조하는 작은 기능부터 검토한다. H02는 기존 제도·교육·관리 기능과 실제 업무 권한을 확인할 때까지 개인별 관리 사업의 확정을 보류한다.** 이는 기획 판단이며 사업성·효과 검증 결과가 아니다.

가장 큰 변화는 공단의 내부 생성형 AI가 이미 서비스 개시 단계에 있다는 사실이다. 2026-03-30 공식 발표는 내부망 LLM·RAG, 업무 질의응답, 감사문서 요약·법령 추천, 보도자료 초안을 설명한다. 따라서 범용 지식검색·요약만으로 신규성을 주장하기 어렵다. 본 세 후보의 차별점은 근거의 적용 조건, 불일치, 담당자 검토와 후속 조치를 연결하는 업무에 있다. 다만 해당 기능이 기존 서비스에 없는지는 승인 요구사항·실제 화면과 대조해야 한다. [공식 발표·E25](https://www.koroad.or.kr/main/board/6/306421/board_view.do?bdNoticeYn=N&bdOpenYn=Y&cp=2&listType=list&pageSize=3)

이 발표는 전체 교통AI플랫폼의 모든 기능이 완료됐다는 증거가 아니다. 내부 GPU 보유는 CCK의 사용권·잔여 용량·모델 탑재 허용을 뜻하지 않는다. 발표의 보안·환각 방지 표현을 무오류 보증으로 받아들이지 않으며, 사전 만족도와 자기보고 시간절감 수치를 이 세 후보의 성과로 전용하지 않는다.

가정(Assumptions): 독자는 CCK 기획자와 기관의 정책·교육·안전·디지털 담당자다. CCK 로컬 LLM과 기관이 승인한 기존 서버를 사용하며 신규 인프라 투자 0원 조건을 유지한다. 사업규모·예산·납기는 미정이다. 연구는 공개 자료와 기존 검토문서에 한정했다.

작업 유형은 후속 사업 리서치, 규모 M, 위험도 Medium이다. 근거 기반 Discovery와 중복·권한 검토를 적용했다. 업무 연결·출처 추적·범위·미검증 사항을 품질게이트로 삼았다. 구현·UI·운영 배포 요청이 아니므로 화면설계서, 코드, 배포계획은 작성하지 않았다.

## 4. H01 — 신체나이보다 정책 적용 조건을 비교

기존 검토의 핵심은 유지한다. 세대별 일반 기능이 개선됐다는 연구와 고령 연령집단에서 운전 관련 기능 저하가 관측됐다는 연구는 다른 질문을 다룬다. 국내 연구의 표본·관측시기·성별, 해외 면허체계·이동환경을 함께 봐야 한다. 기존 국내외 근거는 [사업구상서 2절](../사업구상서.md)과 [출처 E02~E07](../출처원장.md)에 정리돼 있다. 이번 회차에서 새 임상 근거를 추가하거나 신체기능 임계값을 산출하지 않았다.

**사업 과업 제안:** 정책 담당자가 ‘고령운전자 관리기준 보완’을 검토할 때, 연구에서 관측한 기능과 제도에서 사용하는 기준이 어떤 관계인지 대조하고 국내 추가 검증 과제를 남긴다.

| 검토 질문 | AI가 비교할 정보 | 담당자가 판단할 내용 |
|---|---|---|
| 같은 나이의 기능이 세대별로 달라졌는가 | 출생집단, 관측연도, 측정영역·표본, 결과와 불일치 | 한국 운전자에 대한 적용 가능성 |
| 실제 운전과 관계있는 기능은 무엇인가 | 시각·주의·반응·운동 기능과 운전 결과를 연결한 근거 | 평가 항목의 적합성·전문가 검증 |
| 나이 기준을 보완할 대안은 무엇인가 | 현행 유지·평가 보완, 조건부 운전의 해외 운영 조건, 이동지원 | 국내 적용·법령 개선·비용·지역 형평성 |
| 연구가 정책 제언에 충분한가 | 표본 편향·누락·인과해석 제한, 반대 근거 | 채택·보류와 국내 실증의 우선순위 |

납품 가능한 업무 묶음은 근거카드·조건 비교표·검토 이력·근거 변경 시 영향 알림이다. 알림은 향후 제품 기능안이며 이번 대화에서 자동조사를 설정한 것이 아니다. 법령 최신성은 시스템 외부의 승인된 갱신 경로와 반입 책임이 필요하다. 망분리된 로컬 LLM이 스스로 최신 웹자료를 계속 확보한다고 가정하지 않는다.

비AI 비교안은 담당자의 기존 검색·문헌관리 도구·표준 검토서다. 같은 자료 묶음과 같은 정책 질문을 주고 출처 오류, 조건 누락, 보완 질문의 유용성, 검토시간을 비교한다. 현재 표본·목표값·평가자와 실험 결과는 없다. 정책 채택·이동권·안전 성과는 문서 생성시간과 별도로 추적해야 한다.

## 5. H02 — 기록의 존재보다 조치 검토의 빈틈 확인

이번에 확인한 음주교육 연구는 상습 운전자 자료와 교육 개선을 다룬다. 방지장치 도입·운영도 별도 사업실명제로 공개돼 있다. 따라서 ‘상습 음주운전자 이력 시스템이 없다’거나 ‘재범예방 제도가 없다’고 제안서를 쓰지 않는다. [E27](https://www.koroad.or.kr/main/research/res_basic_list.do?cp=2&listType=list&sc=2026), [방지장치 사업 게시·E26](https://www.koroad.or.kr/main/board/16/306454/board_view.do?bdNoticeYn=N&bdOpenYn=Y&cp=1&listType=list)

공개된 연구계획을 보유했다는 사실은 그 안의 개인자료를 사용할 권한이 아니다. 기존 구상서의 법률 대조와 개인정보 활용 조건을 유지한다. 개인별 적용은 사건의 시점·사실관계·개별 법령과 담당 기관 확인이 필요하다.

**합성 예시로 검토할 기능안:** ‘재교육 출석 확인 요청’에 ‘예약 완료’ 문서만 제출됐을 때 AI는 완료나 미이행을 판정하지 않고, 출석 증빙을 추가 확인할 필요가 있음을 원문 위치와 함께 표시한다. 예약일·기한·대상 판정은 검증된 규칙이 처리한다.

- 기대 결과: 의무·권고·참고를 구별하고 요청과 증빙의 차이를 설명한다.
- 금지할 결과: 문서 미확보를 미이행 확정으로 바꾸기, 임의의 법정기한 생성, 재범위험 점수·자동 제재.
- 비교안: 규칙 기반 체크리스트와 기존 담당자 검토. 정형 규칙만으로 같은 결과를 얻으면 AI 추가 범위를 줄인다.
- 다음 필수 근거: 현업이 겪은 반복 사례의 익명 설명, 기존 기능 목록, 실제 기록 처리 근거·보유기간·접근권한·위탁 범위. 실제 개인기록은 이번에 수집하지 않았다.

이 예시는 작성한 기능 설명이며 모델을 실행한 성능 시험이 아니다. 재범 감소를 입증하지 않는다.

## 6. H03 — 실제 등록기술로 살펴본 추천의 함정

### 기존 예시 조건에 적용한 수동 검토

가정한 현장: ‘비 오는 야간, 고령 보행자가 많은 비신호 횡단보도. 전원·공사·유지관리 부담을 줄이고 싶다.’ 실제 특정 지역의 현장조사 결과는 아니다.

| 판단 | 근거 | 추가 확인 |
|---|---|---|
| 바로 도입할 추천으로 확정할 수 없음 | 등록된 주 기능이 보행신호 연장·감응과 연결되며 예시 현장은 비신호임 | 신호 없이 쓸 수 있는 독립 기능·별도 모델이 있는지, 신호 신설 전제인지 |
| 우천·야간 적합성 미확인 | 공개 설명만으로 해당 조건의 성능·시험 범위를 확인하지 못함 | 같은 모델의 환경별 시험조건·결과·오류·고장 시 동작 |
| 유지관리 조건 미확인 | 전원·통신·토목공사·보수 범위의 구체 문서가 확보되지 않음 | 설치 구성, 기존 설비 연동, 전력·정기보수·교체 비용 |
| 시험·검사 필요성은 장치 유형별 검토 | KICS는 보조장치·검지기 등의 구분과 조건을 안내 | 적용 장치 분류, 증빙 종류, 모델·버전·유효기간 일치 |

공단 검사 안내에는 보조장치 5종의 세부기능검사, 옵션보드 조건, 검지기 용도 구분 등이 제시돼 있다. 그러므로 모든 제품에 같은 인증 체크리스트를 붙이면 안 된다. 원문 기준의 해당 장치·용도·버전을 기술 담당자가 확인해야 한다. [KICS 안내·E28](https://kics.koroad.or.kr/intro/system.do)

위 표는 공개 자료에 대한 기획자의 수동 조건 검토다. 해당 제품이 부적합하다는 인증 판정도, LLM 성능 검증도 아니다. **발굴 대상 제품에 영상 AI가 쓰여도 CCK가 구현할 기능은 기술문서·규격·증빙의 텍스트 비교**다. 영상 인식·신호 제어·장치 제작은 CCK 사업 범위에 넣지 않는다.

### 바로 사용할 수 있는 실증용 프롬프트

> 현장 조건과 허용된 등록부 자료만 사용해 기술 후보를 검토해 줘. 각 후보마다 제품 ID·모델·출처·확인일을 표시하고, ‘맞는 조건 / 충돌 가능 조건 / 정보가 없는 조건’을 나눠 줘. 설치 전제, 기존 신호·전원·통신, 시험성적서 범위와 유효기간, 유지보수 조건을 확인해 줘. 등록 설명·인증서·현장 효과평가를 구분하고 자료가 없으면 확인 질문으로 남겨 줘. 비신호 현장에 신호 연동형 기능을 추천할 때는 추가 설비 전제를 먼저 밝혀 줘. 전수검색이나 성능 보증을 주장하지 말고, 구매·설계·인증 판정을 대신하지 마.

초기 검증 범위는 한 등록부·한 현장문제·확정한 기준일이다. 이번 확인은 목적에 따라 찾은 샘플 1건이므로 검색 재현율·제품 누락률·시장 규모를 계산할 모집단이 없다. 목록 다운로드 버튼은 확인했지만 다운로드 완결성과 이용조건, 전체 제품 건수는 검증하지 않았다. 정적 화면의 ‘0건’을 실제 등록제품 수로 쓰지 않는다.
