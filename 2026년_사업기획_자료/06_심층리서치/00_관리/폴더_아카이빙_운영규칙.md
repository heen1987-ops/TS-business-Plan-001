# 폴더 관리와 아카이빙 운영규칙

현재 적용 v0.2: [신규사업 범위 기준](../../00_기획지침/신규사업_범위와_중복배제.md)을 우선한다. 조사 이력 8건은 보존하되 검토대상 5건·유보 2건·제외 1건을 분리한다. TS-BIZ-001은 제외, 003·008은 중복 경계 확인까지 유보한다. AX·디지털전환+AI+정보화의 AS-IS/TO-BE·AI·구축/연계·운영을 상세화하며, 독립 R&D 조사·공고를 신규사업으로 우선 추진하지 않는다.

버전 v0.1 / 2026-09-09. 대상은 TS 사업기획의 조사 자료다. 기관의 법정 기록물관리 기준이나 보존연한을 대신하는 규정이 아니다.

## 1. 폴더별 책임

```text
[TS] 사업기획/
├─ 00_자료목록/             기존 TS 자료의 위치·맥락·검토 기록
├─ 00_기획지침/             P01~P07 기준
├─ 01_기획과제/             과제 관리대장
├─ 02_사업기획서/           선정 후 작성할 사업기획서
├─ 03_검토결과/             사업 검토·피드백
├─ 04_기관리서치/           기관·법령·업무 관계의 기준 원장
├─ 05_통합사업기획/         포트폴리오·유형·선정·예산 상태의 기준 원장
└─ 06_심층리서치/
   ├─ README.md            조사 시작점
   ├─ 00_관리/             운영규칙·설계·대기열·변경·생성·검증
   ├─ 01_후보별/
   │  ├─ 후보분석_원장.json
   │  └─ TS-BIZ-번호_고정주제/
   │     ├─ README.md
   │     ├─ 01_문제정의.md
   │     ├─ 02_연관솔루션.md
   │     ├─ 03_국내외사례.md
   │     ├─ 04_사업화_실증.md
   │     └─ 05_근거_미확인.md
   ├─ 02_공통솔루션/        솔루션원장.json·SOL-번호.md
   ├─ 03_도입사례/          사례원장.json·CASE-번호.md
   ├─ 04_출처아카이브/
   │  ├─ 출처원장.json
   │  ├─ 검토노트/          DRS-번호.md — 분석한 내용과 한계
   │  └─ 원문/DRS-번호/취득일/해시.html.txt
   ├─ 05_종합분석/          종합보고서·비교표·추적원장
   ├─ 90_템플릿/            새 후보·사례·출처·조사 기록
   └─ 99_버전보관/          날짜_버전/문서원장.zip·스냅샷목록.json
```

기관·법령은 `04`, 사업 선정·예산·기본 성격은 `05`, 상세 가설·솔루션·사례·출처는 `06`에서 고친다. `06`에 표시한 기관 유형이나 업무 근거가 바뀌면 먼저 `04` 원장과 출처를 대조하고 관련 후보를 재검토한다. 폴더가 늘어도 같은 사실의 기준 원장은 하나로 유지한다.

## 2. 식별자와 단일 기준 원장

| 대상 | 규칙 | 변경 원칙 |
|---|---|---|
| 후보 | TS-BIZ-001, … | `05`에서 부여한 ID 재사용, 재번호 금지 |
| 문제 | PRB-001, … | 원인·범위 변화는 버전 기록, 별도 문제는 새 ID |
| 솔루션 | SOL-01, … | 특정 공급사 제품과 구분, 기능·경계 관리 |
| 사례 | CASE-001, … | 같은 운영주체·서비스의 단계 변화는 같은 ID |
| 출처 | DRS-001, … | 같은 문서·페이지의 개정은 같은 ID와 추가 취득 버전 |
| 업무·법령 | 기존 D_TS_*, 관계원장 ID | 신규 이름을 임의로 만들어 중복 관계 생성 금지 |

폴더 이름의 주제는 경로 안정성을 위해 유지하고 실제 변경된 이름은 원장의 `name`에 기록한다. 이동이 불가피하면 기존·신규 경로 매핑과 모든 내부 링크를 함께 갱신하고 이전 경로에는 안내문을 남긴다. 확인하지 않은 법령·시설·사례를 수량 목표 때문에 만들지 않는다.

생성 문서의 기준 입력은 다음 네 JSON이다.

- `01_후보별/후보분석_원장.json`: 문제·원인·반대 가설·측정·범위·연결 ID.
- `02_공통솔루션/솔루션원장.json`: 공통 기능·SI 기준안·AI 선택지·수용 조건.
- `03_도입사례/사례원장.json`: 운영주체·지역·시점·단계·AI·효과 한계.
- `04_출처아카이브/출처원장.json`: 서지·관련 본문·한계·취득 파일·해시.

자동 생성된 Markdown을 직접 수정하지 않고 원장 또는 생성 문구를 고친다. `종합보고서.md`와 이 운영 문서 등 수동 작성 문서는 생성 대상이 아니므로 별도 편집한다. 원장을 바꿔도 종합보고서의 분석이 저절로 갱신되지는 않는다.

## 3. 원문 취득과 검토 수준

1. 제목·공식 주소·발행주체·게시/갱신일·조사일·본문 위치를 등록한다. 게시일이 없으면 `null`이며 조회일로 대체하지 않는다.
2. 공개 접근이 허용된 자료만 취득한다. 로그인·권한 제한·차단을 우회하지 않는다. 같은 문서의 합법적인 공식 원문이 별도로 제공되면 출처와 경로를 명시한다.
3. 실제 받은 응답 바이트의 SHA-256·크기·취득 UTC 시각·콘텐츠 유형·최종 URL을 기록한다. 다른 날짜·해시 응답은 별도 파일로 두고 이전 파일을 덮어쓰지 않는다.
4. 제목만 있는 페이지·오류 응답·검색 요약을 본문 확보로 집계하지 않는다. 저장 파일의 제목과 관련 본문 적합성을 따로 대조한다. PDF는 사용한 페이지·표·각주를 확인한다.
5. 주장·근거·적용 판단·반대 근거·미확인 항목을 노트에 적는다. 자료의 설명과 우리의 TS 적용 판단을 구분한다.

`archived_path`는 실제 파일의 위치이고 `web_review_status`는 열람 범위다. `claim_verified`는 기록한 제한된 내용의 확인 여부이며 ‘현재 가동’, ‘한국 법적 적용’, ‘독립 성과 검증’을 뜻하지 않는다. 효과는 사례의 `independent_effect_verified`에서 별도 관리한다. 링크 존재와 서비스 본문도 구분한다.

HTML은 `.html.txt`로 저장해 로컬에서 스크립트가 실행되지 않게 한다. 원문 응답에 연결된 이미지·첨부파일까지 모두 보존한 것은 아니다. 새 첨부파일을 받으면 하위 파일 목록과 해시를 별도로 남긴다. 파생 번역·요약은 `검토노트`에 저장하며 원문과 동일하다고 표시하지 않는다.

수집 실패에는 오류·확인일·후속 행동을 남긴다. 이번 DRS-018·019는 직접 본문 미확인, DRS-004는 검색·직접 응답 불일치, DRS-027은 검색 표 확인과 원문 미보존을 구분했다. 이런 한계를 빈칸으로 지우지 않는다.

## 4. 개정과 재검토

새 자료는 먼저 동일 URL·제목·운영주체·기존 ID를 검색해 중복을 확인한다. 같은 출처가 개정되면 `observations` 또는 `versions`에 종전 확인일·해시·판단을 유지하고 최신 관련 본문을 다시 검토한다. 시행일·발행일·확인일을 각각 적는다. 단순 재생성을 최신 조사로 집계하지 않는다.

`원문_보존.py`는 초기 미수집 자료의 취득 보조 도구다. 이미 보존된 자료를 건너뛰므로 최신 버전 수집기나 예약 전체 실행기로 사용하지 않는다. `초기출처_구성.py`와 `초기분석_구성.py`는 최초 구성 기록이며 초기화·롤백 도구가 아니다. 현재 JSON이 우선한다.

변경 발생 시 `05_종합분석/추적원장.json`의 들어오는 관계를 역추적한다. 출처 변경 → 사례 사실 확인 → 솔루션 적용 판단 → 후보 문제·실증·법적 경계 → 종합보고서·포트폴리오의 순서로 영향을 검토한다. 변경이 없는 링크까지 의미 없이 다시 작성하지 않는다.

자료 상태는 ‘탐색 단서 → 본문 관련 부분 검토 → 업무 적용 검토 → 활용/유보/대체’로 구별한다. 사례의 도입단계·효과 검증은 별도로 유지한다. 후보를 `확정`하거나 예산을 확보로 바꾸는 작업은 사용자 결정 증거가 있을 때만 수행한다.

## 5. 생성·검증·버전 보존

프로젝트 Python 환경에서 아래 파일을 순서대로 실행한다. 실행 작업 경로가 달라도 스크립트 자신의 위치를 기준으로 동작한다.

```powershell
python .\06_심층리서치\00_관리\생성_리서치문서.py
python .\06_심층리서치\00_관리\검증_리서치.py
python .\06_심층리서치\00_관리\스냅샷_보존.py --version v0.1 --date 2026-09-09
```

새 조사에서는 원장의 기준일과 문서 버전·생성기의 조사 기준일을 함께 바꾸고, 본문 검토가 끝난 자료만 확인일을 갱신한다. `스냅샷_보존.py`에 새 날짜·버전을 지정한다. 기존 날짜·버전을 덮어쓰지 않는다.

생성기는 `생성파일_원장.json`의 이전 해시와 현재 파일을 비교한다. 수동 변경을 발견하면 쓰기 전에 중단한다. 그 내용을 원장 또는 수동 문서로 옮겨 검토하고, 변경 문서를 별도 버전으로 보존한 후에만 생성 대상 복구를 진행한다. 해시 원장을 임의로 바꾸어 보호를 우회하지 않는다.

검증은 ID·참조·필수 필드·각주·문서 링크·파일 해시와 미확인 상태를 확인한다. 검증 통과가 법률·현장·효과의 승인을 뜻하지 않는다. 주요 변경은 과제→사례→원문 경로를 실제로 열어보고 발표 시점과 현재 적용성을 확인한다.

스냅샷에는 문서·JSON·스크립트와 각 파일 해시를 보존한다. 원문 파일은 `04_출처아카이브/원문` 한 곳에 두고 스냅샷 목록에 원문 해시를 연결한다. 따라서 스냅샷 ZIP만 별도로 복사하면 원문까지 복구되는 것은 아니다. 전체 이전은 해당 원문 폴더도 필요하다.

복구할 때는 현재 변경을 먼저 별도 보존하고 ZIP을 임시 새 폴더에 푼 뒤 해시·경로를 검증한다. 필요한 파일만 검토해 복구하며 기존 원문이나 사용자 문서를 일괄 삭제·덮어쓰지 않는다. 대체·오류 자료는 폐기 사유를 표시해 남기고 자동 삭제 규칙을 두지 않는다.

## 6. 지속 조사와 보안·권리

월~금 오전 9시(Asia/Seoul) 기존 예약 리서치가 `04_기관리서치/리서치_운영.md`와 이 구조를 함께 읽고 대기열을 이어간다. 공휴일 제외는 별도 설정되지 않았다. 신규 근거가 없으면 반복 알림을 보내지 않으며 중요한 법령·사례·기획 판단 변경을 알린다. 이번 문서는 예약 실행 성공의 증거가 아니다.

기존 TS 원본은 읽기 전용 참조한다. 비공개 계약·개인정보·인증정보를 공개 검색이나 외부 서비스로 보내지 않는다. 조사 폴더에도 불필요한 개인 식별 정보·토큰을 넣지 않는다. 문서·웹 응답의 이용 조건을 출처별로 유지하며 외부 공개·재배포·학습 사용은 별도 범위를 확인한다. 서울 자료의 공공누리 제4유형과 같은 제한을 일반적인 ‘공공자료 무료 사용’으로 바꾸지 않는다.

이번 버전은 로컬 기획자료다. 외부 공유·Git 반영·배포는 실행하지 않는다. 원문 변경 감지나 새로운 자료 확보 없이 자동 재생성한 결과를 새 연구 성과로 보고하지 않는다.
