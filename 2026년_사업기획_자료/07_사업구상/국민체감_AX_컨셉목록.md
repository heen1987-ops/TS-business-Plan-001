# 국민체감형 TS AX 컨셉 목록

상태: 컨셉 보관·문제 발굴 단계. 실제 사업 선정·기존 과업 비중복·수행 권한·기능 구현은 확정하지 않았다. 사용자는 상담 연결 컨셉을 우선 보관하고 다음 컨셉으로 진행하도록 요청했다. 아래에는 구현·예산 설계를 추가하지 않는다.

## 01. 용건을 알아듣고 연결하는 AI 상담 접수

2026-09-10 최신 결정: 사용자가 전화기·전화망 입구의 소형 엣지 장치 방향을 너무 국소적이라고 평가하여 해당 장치안을 유보하고 다른 사업 조사로 전환했다. 아래 상담 컨셉은 이력으로 보존하며 장치 도입을 선정안으로 취급하지 않는다.

**WHY: 어디로 연결해야 할지 몰라도, 같은 설명을 반복하지 않고 담당 상담사와 이야기한다.**

사용자가 정정한 흐름:

전화 접수 → 용건 음성 수집·STT → AI가 용건·담당 업무 판단 → 연결 정보·요약 전달 → 상담사 연결 → 상담사가 맥락을 알고 상담 시작.

AI가 상담 전에 용건을 파악해 전달하는 컨셉이다. 상담사가 먼저 내용을 읽고 AI에 검색을 요청하는 구조로 바꾸지 않는다. AI가 민원을 최종 판단·처리하거나 예약까지 자동 완료하는 범위는 이번 컨셉에 포함하지 않는다. 분류가 불확실하거나 이용자가 원하면 공통 상담·상담사 연결이 가능해야 한다.

예: “검사 예약이 계속 꽉 찼다고 나와요.” → 자동차검사 예약 불편으로 분류·요약 → 담당 상담사는 “예약이 안 돼서 전화하셨군요”로 상담 시작.

상태: **사용자 지시에 따라 컨셉만 보관.** 녹음·개인정보 처리, 실제 연결 규칙·가용 상담사, 기존 콜센터 과업의 중복 범위는 후속 검토다.

이 컨셉은 [민원 완결 AX 확장 구상](고령자_민원완결_AX_구상.md)과 구별한다. 이전 문서의 예약 실행·결제·완료 지원은 장기 확장 가설이며 현재 사용자가 정리한 1차 컨셉의 확정 범위가 아니다.

## 02. 실제 가능한 검사 일정 연결 — 다음 논의 초안

**WHY: 예약 정보 때문에 검사 기회를 놓치거나 여러 검사소를 다시 찾아다니는 일을 줄인다.**

사용자의 “예약 화면은 마감인데 현장은 여유로워 보인다”는 경험에서 출발한다. 실제 가용 여부와 표시가 어긋나는 원인은 미확인이다.

희망 지역·기간·검사 조건 전달 → 실제 예약 가능한 일정 확인 → 적합한 선택지 제시 → 자리가 없으면 동의한 취소 자리 연결.

잔여석 반영 오류는 기본 업무·정보화 정비로 해결해야 한다. AI는 이용자 조건을 이해하고 실제 가능한 후보를 찾는 데 어떤 추가 효과가 있는지 검토한다. 대기 예측을 확정된 빈자리로 취급하지 않는다.

상태: **다음 논의를 위한 제안. 사용자 선택·확정 전.** 국민 불편과 해결 가설만 정리하며 상세 설계는 진행하지 않는다.

## 03. 방문 전 준비 확인 — 두 번 방문 줄이기

**WHY: 필요한 준비를 몰라 방문한 뒤 다시 돌아오는 일을 줄인다.**

문제 가설: 이용자가 예약은 했지만 자신의 업무·차량·신청 조건에 맞는 준비사항을 이해하지 못해 현장에서 처리가 지연되거나 재방문하는 경우가 있는지 확인한다. 실제 발생 사례·규모는 아직 조사하지 않았다.

예약·신청 내역 확인 → 이용자가 받은 안내나 준비 내용을 말·사진으로 전달 → 해당 업무의 공식 요건과 대조 → 빠진 내용만 짧게 질문·알림 → 방문 준비 확인.

예: “내일 검사받으러 가는데 이대로 가면 되나요?” → 동의한 예약 내역과 전달한 안내를 확인 → 해당 업무에서 필요한 준비 중 확인되지 않은 항목만 안내.

AI는 어려운 안내문과 이용자의 일상어·제출 사진에서 필요한 정보를 추출하고, 빠진 내용을 쉽게 확인하는 역할을 검토한다. 준비 요건은 공식 기준에 따르며 AI가 임의로 추가하지 않는다. 준비 확인을 검사 합격·안전 승인·최종 접수 가능 보장으로 표시하지 않는다.

전화로 확인을 마칠 수 있도록 하고 사진·스마트폰 사용을 필수로 요구하지 않는다. 일반 체크리스트·간소화 안내로 충분하면 AI의 추가 필요성을 재검토한다. 기존 민원 안내·직무 지원 과업과 실질적으로 중복되는지도 후속 확인한다.

상태: **컨셉 제안·사용자 선택 전.** 준비 미비로 인한 재방문·처리 지연 감소를 검증할 가설이며 상세 설계·구현은 하지 않는다.

## 04. 검사 결과에서 필요한 조치까지 — 검사 후 막막함 줄이기

**WHY: 검사 결과를 받고도 무엇을 고쳐야 하고 다음에 무엇을 해야 하는지 몰라 헤매는 일을 줄인다.**

문제 가설: 검사 결과의 전문용어와 후속 절차를 이해하기 어려워 필요한 조치를 미루거나 반복 문의하는 이용자가 있는지 확인한다. 실제 발생 빈도와 피해 규모는 미검증이다.

예: “검사에서 부적합이라는데, 이제 뭘 해야 해요?”

본인 확인·동의 후 검사 결과 확인 → AI가 결과와 이용자의 질문을 연결해 쉬운 말로 설명 → 공식 결과에 근거한 조치·후속 절차 확인 → 원하는 경우 후속 일정 알림·상담 연결.

전화로도 설명을 듣고 다음 행동을 확인하는 흐름을 검토한다. AI는 항목별 용어를 풀어 주고 이용자의 이해 여부에 따라 추가 질문을 조절한다. 진단·수리 방법·비용·주행 가능 여부·합격 가능성을 임의로 판단하지 않으며 전문 판단이 필요한 내용은 담당자에게 연결한다.

TS 자동차검사 결과 전달·후속 안내와 연결하는 기획 가설이다. 세부 수행 근거, 결과 데이터 이용 권한, 기존 검사·민원 과업과의 중복은 후속 검증한다. 단순 결과 설명이 기존 과업에 포함되거나 쉬운 표준 안내만으로 충분하면 독립 신규사업으로 선정하지 않는다. 국민 성과는 결과 이해도, 후속 조치 누락과 반복 문의 감소로 검증한다.

상태: **컨셉 제안·사용자 선택 전.** 앞선 방문 전 준비 확인과 구별하여 검사 후 행동을 다룬다. 소규모 컨셉 발굴(S·Low)로 문제→흐름→미검증 사항을 기록했으며 상세 설계·구현·효과 검증은 진행하지 않았다.
