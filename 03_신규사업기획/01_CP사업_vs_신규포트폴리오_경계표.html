여기 나온 것과 "같은 문제·같은 사용자"면 신규사업이 아니다

영역내용
AI 서비스 6종검색·코딩지원·번역·법령·보고서생성·운수지도지원 — 공단 직원용 대화형/입력형 도구
추가 제안(① 사업 범위)비식별화 2지점, DMZ 외부망 격리, MCP 플러그인 허브, 직무특화 3종(자동차검사 Q&A봇·상시감사 지원 어시스턴트·보도자료 생성), 평가기준 외부화(스키마화)

2

포트폴리오 A — 대국민 교통안전·이동서비스

사용자 자체가 다르다: 공단 직원 → 일반 국민

신규 확인

상황별 교통안전 이해·실천 지원서비스

① CP에 있는 것내부 직원 대상 검색 AI, 법령 AI. 대국민 접점 없음
신규가 다룰 것일반 국민(고령자·어린이·사업용 운전자)이 실제 상황에서 겪는 이해 오류를 시나리오 학습으로 진단·재평가
겹치지 않음 — 사용자·문제·전달 채널이 전부 다르다. CP의 어떤 화면에도 국민 직접 접점이 없다는 것을 실제 관찰로 확인했다.
3

포트폴리오 B — 공공 AI·개인정보 처리의 신뢰성 검증

여기가 진짜 조심할 지점 — 이름이 CP와 비슷하게 들릴 수 있다

이름 주의

B-1. AI 자동시험·한계검증 엔진

① CP에 있는 것 — "AI 학습데이터관리"원문 문서 → Q&A 쌍 자동 생성 → 사람이 검수. 목적: 지식을 더 채워 넣기. 실패 시 일반 오류 메시지만 노출(원인 로그 없음) — 직접 화면으로 확인함
B-1이 다룰 것이미 만든 AI/SKILL이 요구사항대로 동작하는지 재시험. 합격기준 구성 → 합성 시나리오 → 시험 실행 → 계측·증거 → 실패 재현 → 회귀시험. 목적: 이미 배포된 것을 검증하기
"학습데이터 검수"와 "요구사항 시험"을 같은 것으로 오인하면 CP의 유지보수(원칙7: 계약상 기능 미충족 시 해당 계약 보완)를 R&D로 잘못 청구하게 된다. 제안서에는 반드시 "CP의 학습데이터 검수는 콘텐츠 품질 확인이고, B-1은 시스템 동작 재현성·회귀 검증으로 계층이 다르다"는 문장을 넣어야 한다.
이름 주의

B-2. 개인정보 처리 실증검증 엔진

① CP에 있는 것 — 비식별화 2지점입력 배치 비식별화 + 출력 실시간 마스킹을 실행하는 기능(제안 단계, 아직 계약 이행 증빙 없음)
B-2가 다룰 것그 마스킹이 실제로 정책·설계대로 동작했는지 로그·설정·저장소를 대조해 증거로 확인. 예: 원문 삭제 후 검색색인에 잔존정보가 남는지 검사
계층이 다르다 — CP는 "처리자", B-2는 "검증자". 다만 B-2를 팔려면 CP의 비식별화가 실제로 구현·검수 완료됐는지부터 확인해야 한다(현재 [제안] 등급, 이행 증빙 없음) — 아직 있지도 않은 기능을 검증하겠다고 팔 수는 없다.
이름 주의

참고: 직무특화 "상시감사 지원 어시스턴트" (① 사업 제안 범위)

① CP 제안 범위감사처 직원이 규정-법령 상충 조항을 검색·질의하도록 돕는 상담형 도구
B-1/B-2와의 관계이건 "감사 업무자를 돕는 도구"이지 "AI 시스템 자체를 감사하는 도구"가 아니다 — B-1·B-2(AI/개인정보 처리를 검증)와 대상이 다르다
겹치지 않음. 다만 두 개를 한 문장에서 같이 설명하면 혼동을 부르니 제안서에서 명확히 분리 서술할 것.

정리 — 공통전략서에 바로 쓸 문장

"① 사업은 공단 직원이 조직 지식을 활용하도록 돕는 6종 AI 서비스와 그 운영 기반(비식별화·플랫폼 격리·직무특화 도구)을 다룬다. 신규 포트폴리오는 ① 사업과 겹치지 않는 두 축이다 — (A) 국민을 직접 사용자로 하는 서비스와 (B) ①사업을 포함한 공단 내 AI·개인정보 처리 전반이 실제로 요구사항·정책대로 동작하는지 사후 검증하는 독립 제품이다. B는 ①사업의 산출물을 검증 대상으로 삼을 수 있다는 점에서 연계되지만, ①사업 자체의 유지보수·확장과는 계약·비용·검수 기준이 분리된다."
이 표는 화면 관찰(2026-09-15)과 9/17 전략문서만을 근거로 하며, ①사업 실제 이행 범위는 검수 시점에 재확인이 필요하다. B-1·B-2는 아직 "가설" 단계(9/17 문서 자체 표기)이며 이 표가 그 가설을 검증한 것은 아니다.
