기획 판단

CCK가 주관·총괄 수행사로 책임질 수 있는 범위를 기획한다. 핵심은 CCK 기술·로컬 LLM이며, 비전·영상인식·신규 센서 중심 사업은 제외한다.

기술의 기준 / 사용자 정정 U-CCK-01

CCK 기술로 무엇을 해결할 수 있는가?

CCK의 핵심 솔루션과 로컬 LLM을 바탕으로 주관 수행할 납품 범위를 정의한다. 아래 자산은 제품 성능 보증이 아닌 재사용·연계 검토안이며 인력·일정·원가·검수 근거를 함께 확인한다.

사업 수행의 기준 / 사용자 정정 U-CCK-02

CCK가 주관해서 납품할 수 있는가?

핵심 기술·전체 설계·통합·검수·운영을 CCK가 책임지는 사업을 찾는다. 모든 구성요소를 직접 개발할 필요는 없지만, 협력사가 담당할 부분도 CCK가 품질과 납품을 관리할 수 있어야 한다.

구분책임·조건
CCK 핵심 책임로컬 LLM·지식검색·검토·업무 흐름의 핵심 구현, 전체 설계·통합·품질·검수·운영 총괄
협력으로 보완 가능UI·시스템 연계·인프라 등 분담 후보. 업체·인력·계약·산출물·인수 기준 확보 여부는 별도 확인
기관·기존 운영사 협조공식 데이터·업무규칙·API·인증·변경 권한과 검토 책임. 협조가 없을 때 실제 납품 범위를 축소
이번 범위 밖핵심 가치가 비전·센서·차량 제어·물리적 진단에 있는 사업. 협력사에게 맡긴다는 이유로 다시 포함하지 않음

주관 수행 검증 전 → 근거 확보 후 CCK 주관 후보 / 협력 조건부 주관 후보 / 범위 축소·보류·제외. 현재 후보 수·선정 상태는 이 문서 수정으로 바꾸지 않는다.

기술 기반 확대 / U-CCK-03

기술을 조합해 5개 사업군으로 확대

확장 가치가 큰 지점은 여러 문서의 근거를 연결하고, 빠진 조건을 확인하고, 사람이 승인한 다음 실제 처리 상태까지 이어주는 구간이다. 텍스트 자료만으로 시험 가능한 검사결과·시정조치 검토를 먼저 구체화하고, 예약은 공식 API 확보를 병행하는 것이 현재 근거에서의 검증 순서 제안이다.

    T11~T17 / 계획·요청 확인

    8단계 연구 계획으로 확장

    8단계 연구 계획과 1~6차 시작 요청을 확인했다. 반환 기록에는 해당 연구 보고서 본문이 없다.

  7. 07

    U-CCK-01 / 현재 사용자 정정

    CCK 기술·로컬 LLM으로 범위 명확화

    현재 작업에서 사용자가 CCK 솔루션 기술을 바탕으로 하며 로컬 LLM을 사용하고 비전은 사용하지 않는다고 정정했다. 참조 대화의 발언 ID와 구별한다.

  8. 08

    U-CCK-02 / 현재 사용자 정정·문맥 해석

    CCK 주관 수행 가능성을 필수 조건으로

    현재 사용자 정정을 주관·총괄 수행사 관점으로 해석했다. CCK가 핵심 솔루션·통합·품질·검수·운영을 책임질 수 있는 사업인지 확인한다.

02 / 조사할 출발 사례

어디에서 다음 행동이 막히는가?

3개 조사안은 CCK 주관 수행 가능성을 확인할 출발 사례다. 핵심 자산·직접/협력 수행·연계·인력·납기·원가·검수 근거가 확보되기 전에는 수행 가능이나 선정으로 판정하지 않는다.

편의 중심 · T05~T10

A. 예약 대안 탐색

사용자 경험 기반

설명용 요청 예시

“다 마감이면, 내가 갈 수 있는 다른 날짜나 검사소를 찾아줘.”

희망 예약이 마감되면 이용자가 날짜와 검사소를 바꾸며 가능한 대안을 반복 탐색한다.

경험·문제 가설

검사소 선택 → 날짜 확인 → 마감 → 돌아가기 → 반복

개선 가설

조건 전달 → 실제 가용 후보 확인 → 바뀌는 조건 비교 → 선택

AI가 도울 일

로컬 LLM이 필수·선호 조건을 해석하고 필요한 확인 질문과 대안 설명을 지원한다. CCK의 지식·실행 자산과 예약 조회 API를 연결할 수 있는지 검증한다.

시스템·사람이 확인할 일

차량·검사 조건, 공식 검사기간, 실제 빈자리와 예약 확정은 업무시스템·규칙으로 확인한다.

가장 먼저 확인할 것

표시·탐색 불편, 조회·갱신 문제, 실제 공급 부족을 분리한다. 가능한 대안이 있었는데 찾지 못했는지 본다.

측정할 결과

  • 유효 후보 탐색시간
  • 화면 왕복·조건 재입력
  • 탐색 포기·기간 내 실제 수검

오류와 비교 기준

조회 실패를 마감으로 표시하거나, 갈 수 없는 시간을 유효 후보로 추천하는 오류.

달력·검색 결과·조건 유지 개선만으로 충분한지 비교한다.

편의·안전 연결 · T09~T10

B. 검사결과 후속 조치

잔여 문제 검증 전

“내 검사결과에서 꼭 해야 할 일과 권고사항을 나눠줘.”

설명을 받은 뒤에도 필요한 조치를 구분하거나 실행하기 어려운 경우가 있는지 확인한다.

경험·문제 가설

결과 통보 → 이해의 어려움 또는 실행 여건 부족 → 조치 지연 가능

개선 가설

공식 결과 확인 → 필수·권고·미확인 구분 → 행동 → 완료 근거 확인

AI가 도울 일

이미 제공된 공식 검사결과의 텍스트·구조화 항목과 근거를 검색해 용어·절차를 설명하고 누락된 확인사항을 찾는다. 사진·영상·센서 진단은 수행하지 않는다.

시스템·사람이 확인할 일

판정·기한·정비 판단은 공식 결과와 전문가가 담당한다. 이용자 완료 보고와 공식 확인을 구별한다.

가장 먼저 확인할 것

이해·절차·시간·이동·비용·기록 중 어느 요인이 조치를 어렵게 하는지 정상 이행 사례와 비교한다.

측정할 결과

  • 필수·권고 구분 정확도
  • 조치 누락·지연
  • 확인된 후속 조치 이행

오류와 비교 기준

결과에 없는 정비 진단, 근거 없는 안심, 중요한 조치 누락.

쉬운 결과표·체크리스트·절차 안내와 비교해 추가 효과를 본다.

안전 중심 · T10

C. 위험상황 자율보고

잔여 문제 검증 전

설명용 요청 예시

“방금 본 위험한 상황을 사실대로 보고할 수 있게 정리해줘.”

항공·철도 이용자나 종사자가 보고 작성과 정보 전달에서 겪는 부담·누락이 있는지 확인한다.

경험·문제 가설

위험 경험 → 무엇을 적을지 고민 → 누락 또는 작성 중단 가능

개선 가설

상황 서술 → 중립적 확인 → 사실·추정 구분 → 작성자 확인 → 공식 절차

AI가 도울 일

사용자가 텍스트로 서술한 관찰과 추정을 구분하고 필요한 사실을 중립적으로 확인한다. CCTV·영상으로 위험상황을 감지하는 과제는 제외한다.

시스템·사람이 확인할 일

항공과 철도의 보고 대상·접수·보호·의무보고 경계를 각각 확인한다. 전문가는 위험을 검토한다.

가장 먼저 확인할 것

작성 중단, 추가 확인, 핵심정보 누락과 그 원인을 비식별 사례·서식·이용자 경험으로 확인한다.

측정할 결과

  • 작성 부담·중단
  • 관찰 사실의 보존
  • 위험 검토에 필요한 정보

오류와 비교 기준

사실 창작, 유도질문, 신원 노출, 보고 제도의 잘못된 분류.

기존 서식 개선·항목 안내와 비교한다. 보고 건수 증가만으로 안전 효과를 주장하지 않는다.

  • 조회 범위와 결과를 명시
  • 조건 밖 후보는 구별
  • 바뀌지 않은 조건은 재입력 없이 유지

  • 가능·마감·확인 불가 구분
  • 조회 시점·불확실성 표시

조회되지 않은 빈자리나 예약번호를 생성하지 않는다.

01

출발점

국민이 서비스를 이용하고 안전조치를 수행하다 막히는 순간을 찾습니다. 이 중 CCK 기술과 로컬 LLM의 언어·지식·절차 처리로 바꿀 수 있는 문제를 고릅니다.

02

해결할 변화

텍스트로 전달한 상황과 조건을 이해하고, 공식 근거와 데이터를 찾아 대안·조치를 설명합니다. 정확한 조회·계산·확정은 기존 시스템·규칙·사람이 담당합니다. 비전·센서 진단은 이번 범위에서 제외합니다.

03

선정 전 확인

CCK가 주관사로 무엇을 직접 만들고 무엇을 협력할지, 어떤 제품·인력·연계 근거로 일정과 원가 안에서 납품할지 확인합니다. 최소 납품물과 검수·운영 책임이 설명되는 범위로 사업을 구체화합니다.

대화 출처·버전·열람 범위 +

참조 대화·사용자 정정·CCK 파생 기술대장을 반영했다. v1.3 기술 확장 검토에서 공식 TS 업무소개 9건을 선별 열람했고 범위·위치는 별도 출처원장에 기록했다. CCK 기능·성능·로컬 모델 호환성을 실행 검증하지 않았으며 법령 현행 원문·실제 API·심층리서치 결과 본문은 미검증이다.
