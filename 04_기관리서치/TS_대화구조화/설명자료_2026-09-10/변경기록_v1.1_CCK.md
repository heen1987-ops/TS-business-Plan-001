# CCK·로컬 LLM 범위 반영 기록

2026-09-10 · 설명자료 v1.1 · 기준: 현재 사용자 정정 U-CCK-01.

## 결론과 적용 방법

CCK 솔루션의 기술을 바탕으로 로컬 LLM이 처리할 언어·지식·업무 문제를 기획하도록 설명자료와 공통 기획 기준을 수정했다. 비전·영상인식·신규 센서·장비를 핵심으로 삼는 제안은 제외한다. Standard Loop로 범위·출처 확인, 공통 데이터 수정, 생성, 브라우저 검사, 시각 자체 검토를 수행했다.

## 반영한 내용

- 첫 화면에 CCK·로컬 LLM과 비전 제외 범위 표시.
- CCK 기능군, 확인 수준, 로컬 실행 조건과 8개 메가이슈별 적용·제외 경계 추가.
- 예약 대안, 검사결과 후속 조치, 위험보고를 텍스트·공식 결과 중심으로 수정.
- DR01~08의 복사 문구에 동일한 기술 범위 적용. DR06은 CCK 적합성·로컬 실행·데이터 검토로 구체화.
- 공통 기획 기준과 후속 확인 Q10에 자산·버전·권한·실행 검증 조건 반영.
- 기존 14개 대화 턴은 보존하고 새로 반환된 4~6차 연구 시작 요청만 T15~T17로 추가. 총 17개 사용자 발언·11개 AI 답변이며 연구 결과 본문은 반환되지 않았다.

## 자료와 제품 기능의 구분

CCK 보유기술 대장 K01, ASEF 설명 K02, Capability Fit 지침 K03을 읽었다. 파생 기술대장에 RAG·지식DB, Argus·Keeper·Nexus 설명이 있음을 확인했으며, 원 코드·실행환경·성능·최종 계약을 검증한 것으로 기록하지 않았다. K01의 NL2SQL 계획 단계, 승인 중단/재개 근거 부족, 일부 제품명 불확실성도 반영했다. 기존 OCR·VLM 자료가 존재하더라도 이번 범위에 도입하지 않는다.

자료별 원본 경로·버전·읽은 범위·한계는 [CCK 적용 기준](../../../00_기획지침/CCK_로컬LLM_적용범위.md)에 있다. G:의 CCK·TS 원본은 수정하지 않았다.

## 검증 결과와 판정

[검사 결과 JSON](검증/검증결과.json): **49/49 통과**.

- 기술 범위의 첫 화면 표시, 8개 연구 복사문, HTML·Markdown·실제 다운로드 내용 일치 확인.
- 조사안·상황 선택, 키보드, 복사 실패 대안, 320·390·768·1440px 및 200% 확대, 인쇄·상태복구 확인.
- 외부 HTTP 요청 0건, JavaScript 오류 0건. 로컬 CCK 엔진·LLM·업무 API는 실행하지 않았다.
- 기술 범위의 데스크톱·모바일 스크린샷을 직접 열어 확인했다. 번호가 줄바꿈되는 부분은 고정 너비·줄바꿈 방지로 수정한 뒤 재검증했다.
- 최초 실행에서는 새 details 영역 3개로 인해 기존 검사 선택자가 모호해 중단됐다. 기존 근거 영역을 정확하게 선택하도록 고쳤다. 제품 동작 실패로 숨기거나 검사 자체를 제거하지 않았다.

자체 문서 QA 판정: **합격**. 독립 평가위원 심사, 현업·실제 이용자 평가, WCAG 전체 준수 인증, CCK 제품 적합성 판정은 수행하지 않았다. axe 패키지가 없어 axe 자동 검사는 미수행이며 CSS 대비·키보드·반응형 범위만 확인했다.

## 보존·잔여 작업

이전 생성물·원본 데이터·생성기·검사기·검증 산출물은 `이력/v1.0_CCK범위반영전`에 보존했다. 정식 후보 원장·선정 상태·자동화 설정은 변경하지 않았다.

다음 검증 입력은 Q10의 CCK 실제 기능·버전·로컬 모델 호환성·RAG·도구 실행·승인/재개·재사용 권한이다. 이번 수정은 문서의 기획 경계를 확정한 것이며, 후보 사업의 비중복·제품 구현·성능·실증 완료를 의미하지 않는다.

재발 방지: 기술 경계를 기획 기준에 연결하고 모든 연구 복사문의 CCK·로컬 LLM·비전 제외 문구를 회귀 검사에 포함했다.
