## 3. 상위 문제정의와 두 성과축

## 5. 예약 구상의 정확한 구조

### 5.1 원인과 해결 가설

| 원인 가설 | 확인해야 할 증거 | 대응 가설 |
|---|---|---|
| 표시·탐색 불편 | 실제 빈자리가 있는데 날짜별 상태를 확인하기 위해 화면 왕복 | 상태를 미리 표시하고 날짜·검사소 비교와 조건 유지 |
| 갱신·조회 문제 | 실제 상태와 표시의 불일치, 조회 실패가 마감처럼 보이는 사례 | 조회·갱신·오류 구분, 조회 시점 표시 |
| 실제 공급 부족 | 방문 가능 조건에 맞는 빈자리가 실제로 없음 | 바꿀 수 있는 조건을 확인한 후 대안 제시, 별도 운영 검토 |

세 원인은 미확인이고 함께 발생할 수 있다. 사용자의 “마감이 반영이 안 된다”는 표현만으로 데이터 연동 장애를 확정하지 않는다. 다른 프로젝트 문서의 “현장은 여유로워 보인다”는 경험 문구는 이 참조 대화의 사용자 발언에서 확인되지 않았으므로 이 대화의 인용으로 사용하지 않았다.

### 5.2 이용자가 원하는 흐름

T07~T08의 요구와 당시 설계 제안을 다음처럼 정리할 수 있다.

**자연어 요청 → 필수·선호 조건 확인 → 실제 예약 가능 정보 조회 → 상황별 대안 비교 → 바뀐 조건만 재조회 → 사용자 선택 → 허용된 예약 경로로 연결**

예시 프롬프트는 실제 조회 요청·결과가 아닌 구상 설명용이다.

> “내가 갈 수 있는 자동차검사 일정을 찾아줘. 토요일 오전이 좋고 가까운 곳이 마감이면 다른 검사소도 비교해줘. 검사기간과 내 방문 가능 일정을 확인해서, 여유가 없으면 갈 수 있는 가장 빠른 대안을 보여줘.”

“우회 안내”는 예약 제한을 우회한다는 뜻으로 해석하지 않는다. T07 문맥에서는 **날짜·위치 등 변경 가능한 조건을 조정해 대안을 찾는 것**을 뜻한다.

### 5.3 상황별 추천 원칙

아래는 T07~T09의 설계안을 정리한 것으로 실제 검사기간·업무규칙은 아직 검증하지 않았다.

| 상황 | 비교 순서 | 보존할 조건 |
|---|---|---|
| 방문 기회가 충분함 | 가까운 위치·선호 시간 중심 | 공식 검사기간, 검사 가능한 차량·검사소 조건 |
| 특정 날짜에만 방문 가능 | 날짜를 유지하고 다른 검사소 비교 | “토요일만 가능” 등 고정 조건 |
| 방문 가능한 기회가 적음 | 실제 방문 가능한 후보 중 빠른 일정 | 갈 수 없는 시간대를 유효 대안으로 표시하지 않음 |
| 현재 조건에 유효 후보가 없음 | 바꿀 조건과 바뀌는 불편을 명시 | 사용자 동의 없이 거리·시간 한도를 완화하지 않음 |
| 조회 실패 또는 기간 미확인 | 확인 불가를 표시하고 재조회·추가 확인 | 확인 불가를 마감이나 안전함으로 바꾸지 않음 |
| 공식 긴급 조치·이용제한이 제공됨 | 해당 지시의 적용 확인을 우선 | 검사기한의 여유를 안전상 여유로 해석하지 않음 |

“여유”는 남은 날짜 수와 개인의 실제 방문 기회를 함께 보는 개념이다. “촉박함”의 수치 기준은 대화에서 정해지지 않았다. AI가 차량의 안전성을 진단하거나 법정 기한을 임의로 계산·연장하는 근거가 아니다.

### 5.4 후속 검증에 쓸 시나리오 초안

| ID | Given / When | Then — 확인할 기대 동작 |
|---|---|---|
| R01 | 토요일만 가능 / 평일에만 빈자리가 있음 | 평일을 조건 충족 후보로 추천하지 않음 |
| R02 | 날짜 조정 가능 / 같은 검사소가 희망일 마감 | 유효 기간 내 다른 날짜와 검사소를 구분해 비교 |
| R03 | 방문 기회가 적음 / 빠른 슬롯을 찾음 | 실제 방문 가능 조건을 충족한 후보 안에서 빠른 일정 제시 |
| R04 | 조회 실패 / 결과 목록을 표시 | 마감·후보 없음과 다른 확인 불가 상태로 설명 |

R01~R05·R07은 대화 내 제안을 검증 문장으로 변환했다. R06은 실시간 상태 변화에 대비해 이번 구조화에서 추가한 확인 항목이다. 모두 **실행하지 않은 검증 초안**이다.

## 6. 기존 기능·기관 근거에 대한 확인 수준

T01은 TS를 설립법에 근거한 국토교통부 산하 위탁집행형 준정부기관으로 설명하고, 자동차·도로·철도·항공·드론·시설·모빌리티 등의 업무를 법령과 연결했다. **이는 참조 답변의 조사 결과를 요약한 것이며 이번 작업의 현행 지정·조문 확인 결과가 아니다.** 이번 문서에서 개별 조문의 위탁 권한이나 현재 수행조직을 새로 확정하지 않는다.

## 9. 다음 확인 순서와 완료 기준

구체적인 항목은 [후속확인 대기열](후속확인_대기열.md)에 Q01~Q09로 기록했다. 자동화 일정·우선순위를 변경하거나 외부 기관에 자료를 요청한 것은 아니다.

1. 대화의 외부 주장과 기존 기능을 원문·현재 화면으로 확인한다.
2. A는 실제 예약 탐색을 재현하고 표시/조회/공급 원인을 분리한다.
3. B·C는 잔여 문제의 존재와 정상 완료 사례를 함께 확인한다.
4. 최종 계약·업무 권한·자료 접근·비AI 대안을 대조한다.
5. 증거가 확보된 주제만 문제정의·기획서·실증 계획으로 발전시킨다.

이번 문서 정리의 수용기준은 ① 10개 턴의 추적 연결 ② T04·T06~T09의 정정 보존 ③ T10의 3개 조사안과 4개 비교 주제 포함 ④ 외부 주장과 검증의 구분 ⑤ 기존 집계·유보·제외 상태 유지 ⑥ 후속 확인 연결이다.

검증 결과(2026-09-09): JSON 파싱 후 대화 ID, 10개 턴·추적 ID의 순서와 고유성, 사용자·AI 본문 존재, 반환 상한, 후속 페이지 상태, 보고서의 턴 연결, 최종 방향, 대기열 9개, 미실행 시나리오 7개, 외부 검증 전 표기, 인용 표식 분리, 문서 링크를 확인했다. **구조·정합성 검사 14개 통과**, 신규 Markdown 문서 2개와 연결 README 2개의 **로컬 링크 57개 유효**. 외부 URL의 유효성 검사는 포함하지 않았다.

내부 문서 검토 판정: **합격 — 대화 구조화의 수용기준에 한정.** 사용자 정정과 AI 제안의 구분, 기존 범위와의 충돌, 독자의 추적 경로를 검토했다. 독립 평가위원 심사·실제 사용자 검증·법률 검토·업무시스템 시나리오 R01~R07은 미실시다. 외부 사실 검증과 사업 선정은 별도 후속 단계로 남긴다.

방법론: S급 Micro Loop — 맥락 확인 → 최소 문서화 → 정합성·연결 점검. 개발·UI·배포가 없으므로 구현 설계서·화면 목업·테스트 코드·릴리즈 문서는 만들지 않았다. 내부 문서 점검은 독립 평가위원 심사나 실제 사용자 검증을 대신하지 않는다.
