@@ASIS@@

왜 AI가 필요한가

서로 다른 문서 표현과 요구사항·시험증거를 연결하고 상충·누락 후보를 찾는 데 활용합니다. 일정 계산·권한·승인은 명확한 규칙과 업무 절차로 처리합니다.

무엇과 비교해야 하는가

현행 방식, 기존 PMS의 설정·연계, 규칙 기반 검토, AI 지원을 같은 자료로 비교합니다. 기존 기능과 겹치는 부분은 재사용하고 AI 오탐 때문에 늘어나는 확인업무도 계산합니다.

육하원칙으로 보는 사업 정의

WHY · 왜관리 단절·재작업·판단 근거 부족을 줄여 공공서비스의 품질과 연속성을 지원합니다.

WHAT · 무엇을공동 업무관리와 기준·증거·검사·보완·수행이력을 연결합니다.

WHO · 누가기관 담당·검토·승인자, 수행사 PM·실무자, 감리원과 운영 담당자가 사용합니다.

WHEN · 언제착수의 기준 확정부터 수행·검수·유지관리·차기 발주까지 연결합니다.

WHERE · 어디서기관이 허용한 업무환경에서 기존 PMS·계약·전자결재와 연계합니다.

HOW · 어떻게공통 검사 엔진에 분야별 기준을 적용하고 AI 후보를 사람이 검토·확정합니다.

업무 상태

작성·제출·검토·보완·재검증·승인. 누가 무엇을 기다리는지 기록합니다.

AI 처리 상태

대기·분석 중·완료·일부 추출·실패. 분석 실패로 정상 제출을 취소하지 않습니다.

공식 계약 절차

검사·인수·변경 승인 등은 해당 권한과 시스템의 확정 기록에 연결합니다.

일정·책임·인수인계가 연결되는 규칙

날짜 4개: 최초 계획일, 현재 승인일, 예상일, 실제 이행일을 분리합니다. 예상 지연이나 변경 요청이 승인 기한을 덮어쓰지 않습니다.

대기와 책임: 기관 검토·자료 제공, 업체 보완, 외부 선행조건을 구별합니다. 대기시간 자체를 업체 귀책이나 벌점으로 자동 변환하지 않습니다.

기간과 미결: 하자·운영·라이선스·기술지원의 기산 사건과 종료일을 나눕니다. 시작 사건이 불명확하면 기간도 미확정으로 두고, 만료됐어도 장애를 자동 종결하지 않습니다.

공동관리와 권한: 공유 업무는 함께 보되 기관 내부 메모·업체 미제출 초안·타 기업 영업자료는 분리합니다. 후임자는 현재 권한과 미결 업무를 인수하고 과거 행위자는 기록에 남습니다.

04
AI + 감리사

같은 증거를 보되,
판단 경로는 독립적으로

AI의 상시 검사 지원과 감리사의 전문·현장 검토를 연결하는 후속 모듈입니다. AI 검사를 법정 감리 수행이나 독립된 감리의견과 동일하게 표시하지 않습니다.

공유 가능한 적용기준 · 산출물 · 시험증거 · 변경이력
TRACK A · 검사 지원

AI

  • 분석 가능한 문서·요구사항을 지속 대조
  • 누락·불일치·증빙 부족 후보 제시
  • 추출 실패·미검토·권한 제한 구간 표시
  • 이전 지적과 보완자료의 차이 연결
TRACK B · 독립 전문검토

감리원·감리법인

  • 사업 맥락·중요도·적용 범위 판단
  • 현장·시스템 확인과 인터뷰
  • AI 후보 검증 및 추가 전문검사
  • 감리의견과 시정 확인을 책임 있게 결정
차이점 검토 → 보완·시정 → 재검증 → 권한 있는 주체의 확정

두 결과가 다르면 근거와 의견 차이를 보존합니다. AI와 사람이 동의했다는 사실만으로 정확성을 증명하지 않습니다.

전수 대상과 검증 완료를 구별

등록된 모든 항목을 검사 대상으로 삼을 수 있어도, 추출 실패·미확보 증거·전문 판단까지 자동 검증됐다고 보고하지 않습니다.

감리품질도 근거로 검토

후속 장애만으로 감리 부실을 단정하지 않습니다. 당시 점검 범위·확인 가능성·근거와 시정 확인을 대조합니다.

05

아키텍처 SVG 다운로드기존 상세 설계 문서

기준·증거의 위치를 보존

원본·버전·문단·표·셀과 근거를 연결합니다. 모든 적용 요구사항에 검토 상태를 남겨 검색 누락이 통과로 바뀌지 않게 합니다.

업무와 분석의 실패를 분리

접수 기록 후 분석을 비동기로 처리합니다. 재시도·중복 요청·동시 수정·구버전 승인을 제어합니다.

권한은 화면 밖까지 적용

API·파일·검색·캐시에 같은 권한을 적용합니다. 계약·결재 등 필드별 공식 원본을 정하고 임의의 외부 전송을 막습니다.

엔진 데이터 객체와 실제 구현 전 확인

STANDARD → CONTROL → OBJECT → EVIDENCE → TEST → FINDING → REVIEW → ACTION → RETEST → CONCLUSION

각 항목은 기준·세부조건·검사대상·증거·방법·발견사항·사람 검토·조치·재검증·결론입니다. 하나의 서비스에 여러 사업·계약이 연결될 수 있습니다.

기존 계정·검색·문서·LLM 기반의 재사용권과 실제 API를 먼저 확인합니다. 파일 저장과 업무 DB의 정합성 보정, 분석 이력·권한 철회·복구 절차는 구현 설계에서 확정합니다.
