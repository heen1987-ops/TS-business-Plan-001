# Public AI-PMS 요구사항 분석서

2026-09-10 · v0.1 · 서비스모델 기반 설계 검토안

**기관과 수행사가 기준·일정·산출물·보완을 함께 관리하면서 검증 가능한 이행근거를 만들고, 그 근거를 감리·평가·인수인계·유지관리·차기 사업에 재사용하는 서비스의 요구사항을 정의한다.**

현재 범위는 요구사항 분석과 명세다. 상세 요구와 수용기준은 검토안이며 계약·개발·도입의 확정을 의미하지 않는다.

## 1. 문서 목적·독자·사용 방법

| 항목 | 정의 |
| --- | --- |
| 분석 대상 | CCK 검사·검증 역량을 공공 정보화사업에 적용하는 Public AI-PMS |
| 대상 독자 | 기관 기획·사업·계약·평가 담당자, 수행사 PM, 감리 전문가, CCK 서비스·기술 책임자 |
| 분석서 역할 | 왜 필요한지, 누가 사용하는지, 제공 범위·우선순위·책임·미결 조건이 무엇인지 설명 |
| 명세서 역할 | 무엇을 제공해야 하는지, 어떤 입력·결과·업무규칙·예외·수용기준이 필요한지 정의 |
| 성공기준 | 기존 요구 33개를 누락 없이 처리하고, 상세 요구 58개의 출처·연차·역할·검증 조건을 추적 가능하게 작성 |
| 시간축 | Y1~Y3는 착수 이후 상대적 제공 연차. 실제 착수일·예산·기관 일정 미확정 |
| 현재 수준 | 검토 가능한 요구사항 초안. 현업 인터뷰·법령 적용·실측·가격·제품 검증은 별도 확인 필요 |
| 방법론 | M 규모·문서 작성 위험도 Low. 요구사항 분석 + DDD의 업무 경계 + BDD + 요구 추적. 공공업무의 판단 영향은 별도 검토 |
| 적용 단계 | 맥락 확인 → 범위·모델 분석 → 요구 정의 → 문서 정합성 자체점검 |
| 생략 항목 | 제품 코드·API 경로·물리 DB·고충실도 UI·프로토타입·실행 시험·배포. 현재 사용자 범위에 포함되지 않음 |

함께 사용하는 문서:

- [요구사항 명세서](요구사항_명세서.md): 상태·자료·권한·품질 조건과 상세 요구.
- [요구사항 추적표](요구사항_추적표.md): 원요구 ↔ 상세 요구 ↔ 업무·자료·수용기준.
- [요구사항 원장](요구사항_원장.json): 문서 간 연결을 유지하는 구조화 원장.
- [문서 검토 결과](문서검토_결과.md): 문서 점검 결과와 미검증 범위.

## 2. 근거와 해석의 경계

분석 기준은 [서비스모델 정의서 v0.1](../서비스모델_정의서.md), [기존 대화 요구 원장](../대화_요구사항원장.json), [추가 대화 반영 자료](../설명자료_2026-09-10/설명자료_데이터.json)다. 21개 사용자 발언을 반영한 로컬 정리본에서 원요구 33개를 추적했다. 이번 명세 작성에서 참조 대화의 최신 변경을 다시 조회한 것은 아니다.

| 구분 | 이번 문서에서의 취급 |
| --- | --- |
| 사용자 의도 | 공동 PMS, CCK 검사 중심, 정보화사업 감리, 주기적 다면평가, 좋은/미흡 이력, 신규기업 기회, 연속성, 정량 편익, 연차 구분 |
| 현장 문제 | 사용자 경험에서 나온 문제 가설. TS 공식 조사나 공공기관 전체 실태로 일반화하지 않음 |
| 서비스모델 | 기관 구매·공동 이용·CCK 주관·6개 영역·3개년은 기획 검토 기준. 실제 계약/도입과 구분 |
| 상세 요구 | 분석을 통해 구체화한 제안. “해야 한다”는 향후 요구 조건을 뜻하며 사용자가 세부값까지 승인했다는 의미가 아님 |
| 과거 AI 설명·예시 | 참고 이력. 시제품 성능·감리 적합성·법적 결론·시장 수치의 새로운 검증 근거로 승격하지 않음 |
| 외부 법령·수치 | 이번 작업에서 새로 조사·검증하지 않음. 적용 원문·시행일·조사일·판단은 TBD-03/09에서 확인 |
| 최신 범위 정정 | “구현은 하지 말고 설계와 서비스모델을 명확히”가 과거 구현 예시 요청보다 우선 |

## 3. 해결할 문제와 도입 가치

**핵심 문제는 기준·제출·검토·결정·책임이 서로 연결되지 않아 업무의 대기 원인과 완료 근거를 다시 확인해야 한다는 것이다.** 이는 사용자 의견에서 도출한 가설이며 첫 기관에서 현행 업무 표본으로 검증한다.

| 목표 | 현행 As-Is 가설 | 제공할 To-Be | 직접 결과·연결 요구 | 확인할 효과 |
| --- | --- | --- | --- | --- |
| G01 기준 해석·탐색 부담 완화 | 원문을 반복 검색하고 완료조건이 다르게 이해됨 | 적용 기준·원문·책임·완료조건을 착수 시 함께 확인 | S1 / SFR-003~006 | 기준 탐색시간, 해석 재확인 건수 |
| G02 누락·재작업·대기 감소 | 접수와 승인 혼동, 기관/수행사 병목 불명확 | 제출→검토→소명→재검증→확정의 상태·다음 행동 연결 | S1·S2 / SFR-007~018 | 처리 순시간, 대기시간, 재보완율, 중대한 검토 누락 |
| G03 검증 근거·감리 품질 지원 | 기준·시험증거를 감리 때 재수집 | 기준별 검사범위와 AI·전문가 판단·시정 확인 기록 | S3 / SFR-019~022 | 증거 수집시간, 미검사율, 재검증 완료율 |
| G04 공정한 수행이력 확보 | 인상·단일 점수 중심일 가능성 | 역할·관찰기간·실제 근거·우수/미흡/개선·정정 제시 | S4 / SFR-023~028 | 근거 연결률, 정정 반영률, 무실적 부당 분류 여부 |
| G05 업무·지원 연속성 확보 | 교체·사업 종료 때 결정과 책임 재탐색 | 상시 인계·미결 책임·지원기간·후속 계약 준비 연결 | S5 / SFR-029~031 | 인계 파악시간, 책임 미지정 건수, 지원 공백 |
| G06 공공서비스 개선과 재정 타당성 | 후속 사업 요구가 실제 문제·성과와 분리 | 성과→문제→대안 비교→다음 요구의 근거 연결 | S6 / SFR-032~036, BMR-003 | 이용 불편·장애·접근성 지표, 비중복 투자, 순편익 |

G01~G06은 측정할 목표다. “카르텔 감소”, “사업 성공률 상승”, “국민 편익 증가”를 이미 달성한 효과로 기재하지 않는다.

## 4. 고객·이용자·판단 권한·대가

**기준 서비스모델은 기관이 구매하고 발주기관·수행사·배정된 전문가가 공동으로 이용하는 방식이다.** TS는 첫 적용 검토 후보이며 확정 고객이 아니다.

| 주체 | 필요와 이용 장면 | 결정/책임 | 대가 관계 |
| --- | --- | --- | --- |
| 도입 기관 | 여러 사업을 관리하고 담당자 교체에 대응 | 적용 사업·계약·역할·기준·자료 이용·운영 정책 | 도입·이용·기관 적용·기술운영 비용 부담을 기본 가정 |
| 사업 담당·검토·승인자 | 다음 행동·근거·미결 확인 | 맡은 범위의 검토·변경·승인 | 기관 소속 이용 |
| 수행사 PM·실무자 | 합의 기준에 따른 제출·자체점검·소명 | 맡은 과업 수행·증거 제출·보완 | 해당 사업 기본 참여; 소명/정정의 유료 등급 없음 |
| 감리원·전문가 | 검사범위·증거·판단 차이·시정 확인 | 계약·제도상 정해진 독립 판단 | 감리 계약과 플랫폼 이용/기술운영 대가 구분 |
| 다면평가 참여자 | 자신의 관찰 범위에 관한 의견 제공 | 역할·시점별 응답, 미관찰 명시 | 구매 여부와 평가 영향 분리 |
| 후임·운영 담당자 | 미결·지원·갱신 준비 인수 | 승계된 책임과 계속 관리 | 기관/운영계약에 따른 참여 |
| CCK | 서비스 제공·기관 적용·기술운영·지원 | 기술 품질·오류 대응·범위 설명 | 도입/운영/선택 모듈 대가; 자기 회사 평가 확정권 없음 |
| 국민 | 대상 공공서비스의 품질·연속성 | 서비스별 피드백·실제 이용 효과의 관찰 주체 | 플랫폼의 기본 직접 구매자로 가정하지 않음 |

한 사람이 여러 역할을 가질 수 있다. 담당자·중간관리자·최종결재자 등의 평가 역할과 업무 승인 권한은 별도다. CCK가 시스템을 운영한다는 사실이 기관의 계약 판단·감리 판단·평가 확정권을 뜻하지 않는다.

## 5. 전체 구조와 서비스 경계

업무의 공통 흐름은 **기준 → 증거 → 검사/검토 → 사람의 판단 → 조치 → 재검증 → 이력 → 후속 관리**다.

| 서비스 | 제공 결과 | 핵심 상세 요구 |
| --- | --- | --- |
| S1 공동 사업관리 | 합의된 기준과 다음 행동·책임·일정 | SFR-001, SFR-002, SFR-003, SFR-004, SFR-005, SFR-006, SFR-007, SFR-008, SFR-009, SFR-010 |
| S2 산출물 검토·보완 | 제출부터 검토·소명·재검증·승인까지 연결된 기록 | SFR-011, SFR-012, SFR-013, SFR-014, SFR-015, SFR-016, SFR-017, SFR-018 |
| S3 검사·감리 지원 | 검사범위·Finding·독립 전문 판단·시정 확인 | SFR-019, SFR-020, SFR-021, SFR-022, IFR-003 |
| S4 다면평가·수행 레퍼런스 | 역할별 관찰·확인된 수행·소명·정정 이력 | SFR-023, SFR-024, SFR-025, SFR-026, SFR-027, SFR-028 |
| S5 인수인계·유지관리 | 후임이 이어받는 미결 책임·지원기간·계약 준비 | SFR-029, SFR-030, SFR-031 |
| S6 성과·고도화·차기 발주 | 실제 문제와 비교 대안에 근거한 후속 요구 | SFR-032, SFR-033, SFR-034, SFR-035, SFR-036 |

공통 품질·자료·연계·운영 요구는 위 6개 서비스 전체에 적용한다. CCK 검사 역량을 공통화하되 분야별 기준·판단자·책임은 별도다.

| 범위 구분 | 이번 기준 |
| --- | --- |
| 핵심 제공 범위 | 기관·서비스·사업·계약 연결, 공동 기준·일정·증거·검토·소명·승인, 주기적 평가 수집, 수행이력, 인계·지원기간 |
| 후속 연차 | 정보시스템 감리 검사엔진, 다면평가 분석, 레퍼런스 고도화, 성과·RFP 환류, 기관별 반복 적용 |
| 조건부 기능 | 컨소시엄 역량 탐색, 계정/조직·계약/결재/PMS·외부 시험 결과의 실제 시스템 연계 |
| 별도 근거 확인 | 공식 입찰 평가 활용, 기관 간 평가/개인정보 공유, 특정 사업 법정 감리 적용, 제품지원/하자 기간 |
| 현재 제외 | 자동 법적 판정·낙찰/배제·기업 벌점, 감리원 대체, 회계감사/건설 등 타 감리 실제 제공, 신규 OCR·영상/VLM·센서·실시간 제어, 외부 LLM 자동 전송 |
| 현재 작업 제외 | 제품 구현, 시제품, UI 코딩, API 경로·물리 DB 확정, 시스템 연계 실행, 배포 |
| 기존 시스템 관계 | 원천의 공식 기록을 확인해 연결. 전자결재·계약·기존 PMS를 일괄 대체한다고 전제하지 않음 |

### 서비스 제공 대안

| 대안 | 효과 | 비용·기간 가정 | 위험·선행조건 | 판단 |
| --- | --- | --- | --- | --- |
| A. 단일 사업 전용 | 한 사업의 흐름을 빠르게 확인하기 쉬움 | 상대적으로 작으나 연속 운영비 별도 | 종료 후 이력·지원 연속성 약화 가능 | 기관 도입 전 실증 단위로 활용 |
| B. 기관 단위 서비스 + 사업별 적용 | 인수인계·유지관리·복수 계약 연결 | 기관 운영·권한 설계가 필요 | 서비스 책임자·자료/규칙·기술운영 비용 확인 | 서비스모델 기준안. 최초 적용은 제한된 사업에서 검증 |
| C. 다기관 통합·공동 평가 | 공통 기능 반복 활용 가능 | 제도·보안·운영 협의 부담 큼 | 자료 공유 근거·평가 절차·운영 책임 미확정 | 후속 검토. 초기 계약 범위에 일괄 포함하지 않음 |

비용·기간은 상대적 판단이며 견적이나 확정 일정이 아니다.

| 일정·접수·승인 | 상태·기한·권한·알림·이력 | 설명·요약 보조 | 기본 흐름 자체는 AI 없이도 성립해야 함 |

| 산출물 검토 | 필수항목·참조·버전 검사 | 요구와 내용의 대응·불일치 후보 | 독립 검토 기준, 오탐/미탐, 증거 연결 정확성 |
| 인계·후속 요구 | 연결된 기록 조회 | 미결 요약·문제별 근거 취합 | 누락·오해·수정 부담, 실제 판단에 쓰이는 정도 |

AI 적용 범위는 검증 결과에 따라 줄이거나 사람/규칙 기반으로 유지할 수 있다. AI 도입 자체를 편익으로 계산하지 않는다.

## 6. 제공 연차와 우선순위

| 최초 적용 | 상세 요구 수 | 제공할 범위 | 확정 전에 확인할 조건 |
| --- | --- | --- | --- |
| Y1 | 46 | 공동 AI-PMS·기초 검토·다면평가 수집·기본 레퍼런스·소명·인계·유지관리·공통 운영 | 기관·업무·권한·자료·품질·원가·측정 기준 |
| Y2 | 5 | 요구 단위 검사·Finding·정보화사업 감리·독립 판단 연결 | 감리 대상·기준·독립성·실제 증거·검사 성능 |
| Y3 | 7 | 다면평가 분석·레퍼런스 고도화·성과/대안/RFP·기관 재적용·조건부 역량 탐색 | 유효 이력·정정·비교 가능성·정보 이용 근거·효과 |

- Y1 요구는 Y2·Y3에도 유지한다. 연차는 각각 별개의 서비스 수명이 아니다.
- 1년차 AI는 기준 후보·기초 검토 지원이다. 2년차 감리 검사엔진의 완전한 검증 능력을 미리 약속하지 않는다.
- 다면평가·만족도·우수/미흡 수행 근거는 1년차부터 수집한다. 3년차는 분석·활용의 고도화다.
- 업무단계 B1(기준 설정)·B2(공동 수행/증거)·B3(검사/검토)는 한 사업 안에서 반복된다. B1=Y1, B2=Y2, B3=Y3가 아니다.

M은 해당 연차 범위가 채택될 경우 필수로 제안하는 요구이며 구현 승인 표시가 아니다. C는 권한·계약·자료·상대 시스템을 확인한 뒤 채택할 조건부 요구다. 현재 M 54개, C 4개다.

### 핵심 이용 예: 시험결과서 하나의 승인

1. 기관·수행사가 요구사항과 시험 완료조건을 확인하고 기준 버전을 확정한다.
2. 수행사는 결과서·시험 증거를 연결하고 제출 전 자체점검 후 공식 제출한다.
3. 시스템은 접수 기록을 남긴다. AI 분석은 별도 상태로 진행하며 오류가 나면 미검사 범위를 알린다.
4. AI가 미대응 요구·증거 부족 후보를 내면 검토자가 원문을 확인해 보완 여부를 정한다.
5. 수행사가 소명하거나 새 버전을 제출하면 지적·기준·증거·재검증을 연결한다.
6. 권한자가 해당 버전을 확정한다. AI 후보만으로 기업 미흡 이력을 만들지 않는다.
7. 후임은 승인 근거와 남은 운영 책임을 이어보고, 감리는 자신의 범위에서 추가로 독립 검증한다.

순편익의 기본 산정 구조는 다음과 같다.

- 노동시간가치 = 업무별 순절감시간 × 해당 역할의 확인된 시간가치. 이미 기간 총시간을 썼으면 건수를 다시 곱하지 않는다.
- 연간 순경제가치 = 노동시간가치 + 별도로 입증한 비중복 회피 비용 − 추가 운영 비용.
- 초기 도입·교육·이관 비용은 별도 포함한다. 여러 해를 비교할 때는 평가기간·가격 기준·할인 방식부터 확정한다.
- 오탐 확인시간을 도입 후 업무시간에 포함했다면 다시 비용으로 차감하지 않는다.
- 실제 예산 절감은 계약·지출 감소 자료로 따로 확인한다. 절감시간을 감축 인원으로 바꾸지 않는다.
- Y2 감리·Y3 고도화 편익은 해당 기능 적용 이후의 효과로 계산한다. 시장 총액의 임의 비율이나 일반 AI 연구 효과를 실현 편익으로 대입하지 않는다.

평가 설계는 [연구 평가 원칙](C:/Users/김희섭/.agents/instructions/RESEARCH-EVALUATION.md)을 적용한다. 같은 사업의 반복 버전·여러 채점은 독립 표본으로 부풀리지 않는다. 서열형 응답·다중 지표·평가자 차이·소수 표본·오류가 관측되지 않은 경우의 불확실성을 고려한다. 전문가 대조 자료는 AI 지적 사례와 통과 사례를 함께 확인하며, 최소 유의미한 개선과 판정 규칙은 결과를 보기 전에 정한다.
