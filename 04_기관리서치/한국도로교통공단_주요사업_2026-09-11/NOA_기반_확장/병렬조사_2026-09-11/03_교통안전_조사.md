2026 교통AI플랫폼 구축계획 [R01](https://www.koroad.or.kr/main/board/16/306460/board_view.do?bdNoticeYn=N&bdOpenYn=Y&cp=1&listType=list)이 확인되어 모든 후보는 기존 사업 범위 대조 후 구체화한다. 계획 공시를 구축 완료·가용 서버 확보로 간주하지 않는다.

### N03 안전개선 조치·증빙 대조

판단: 안전축 조건부 우선 검토

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 권고와 조치보고의 표현이 달라 이행 근거를 반복 대조해야 할 수 있다. 부실 종료·누락의 발생률은 미확인이다. |
| 현행 기능·중복 | 조치보고·합동점검·보고 절차와 TEMS 장비 관리가 이미 있다. 새 대장·일정·사후관리 도입으로 설명하지 않는다. |
| 최소 납품 범위 | 한 개선 업무의 권고–조치 대조표, 관련 문장·미확인 부분·추가 질문. 현행 대장의 완료 상태를 자동 변경하지 않는다. |
| 필요한 데이터 | 확정 권고, 비식별 조치보고, 사람이 확인한 현장 점검 결과의 텍스트, 장소·업무 식별자. |
| CCK 재사용 후보 | NOA 근거 연결·검토 이력과 Grantee·Accio 대응/비교 패턴을 응용한다. |
| 추가 개발 | 권고–조치–증빙 스키마, 부분 대응 표현, 원문 대조 UI, 검토 의견·출력, 기존 상태 읽기 어댑터. |
| LLM·코드·사람 역할 | LLM: 의미상 대응·누락 후보 / 규칙: ID·장소·일시·중복 / 도로관리기관: 실제 조치·원천 증빙 / 공단·권한 기관: 현장 확인·종료. |
| 비AI 대안·검증 지표 | 표준 조치 양식·체크리스트와 같은 실제 문서 비교. 미확인 조치 발견, 잘못된 지적, 확인 소요와 수정 부담을 평가한다. |
| 사업화 선행조건 | 현행 조치 관리 기능, 확정 권고/보완 사례, 기관 간 자료 접근권, 증거 인정 기준·검토 책임자. |
| 축소·유보 조건 | 주원인이 공사비·일정·기관 권한이거나 증빙이 사진뿐이면 현재 LLM 범위로 해결하지 못한다. |
| 대표 검수 시나리오 | 복합 권고 중 일부만 조치, 다른 장소의 증거, 같은 증거 중복 연결, 상충 회신, 현장 확인 필요를 구별. |

### N05 상황별 안전교육·이해 확인

판단: 국민 체감 검증 후보

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 역할별 상황을 자기 말로 설명할 때 드러나는 오해를 보충 설명할 수 있다. 현행 이해 실패 규모는 미확인이다. |
| 현행 기능·중복 | 법정교육·마이크로러닝·교재·학습관리와 인증 후 매년 사후교육이 있다. LMS·퀴즈·정기교육 신설은 중복이다. |
| 최소 납품 범위 | 한 역할·한 안전 주제의 승인 텍스트 보충학습. 예: 통학버스 동승보호자의 승하차 수칙. 법정 수료와 분리한다. |
| 필요한 데이터 | 가공 권한이 확보된 텍스트 교재·상황 사례·정답 해설·버전·금지 설명, 최소 질문·응답. |
| CCK 재사용 후보 | NOA 지식 연결·근거 설명·검토 흐름을 교육용으로 구성한다. |
| 추가 개발 | 역할별 시나리오, 자유서술 피드백, 강사 검토 UI, 읽기 쉬운 설명, 허용된 LMS 연계. |
| LLM·코드·사람 역할 | LLM: 승인 범위 재설명·확인 질문 / 규칙: 과정·버전·수료 연계 / 강사: 교육 내용·모호한 답변 검토 / 공식 체계: 수료. |
| 비AI 대안·검증 지표 | 짧은 사례+객관식+정답 해설과 비교. 새 상황의 이해, 잘못된 안전 설명, 강사 수정 부담과 이용 접근성을 평가한다. |
| 사업화 선행조건 | 기존 LMS 개인화·문답 기능, 교재 권리·승인자, 기존 교육 연구 범위, 기존 서버·대민 경로. |
| 축소·유보 조건 | 음성·영상이 필수인데 텍스트만으로 대상 접근성을 충족할 수 없으면 대상 조정·유보. 건강·인지·운전능력 진단 제외. |
| 대표 검수 시나리오 | 모호한 답변은 재질문·강사 전환. 긴 대화 강요 방지. 미승인 설명 억제. 주행 중 상호작용을 유발하지 않음. |

### N06 TBN 원고 확인·정정 지원

판단: 내부 연계·연구 중복 확인 후

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 사건의 최신 기록과 원고 사이 지점·방향·통제 상태·시각의 불일치를 찾는 검토 가설이다. 실제 오류 사례는 미확보다. |
| 현행 기능·중복 | TBN 방송 업무와 2026 돌발정보관리체계 개선연구Ⅱ가 있다. 공개 수집건수 통계는 사건 원문 피드가 아니다. |
| 최소 납품 범위 | 한 편집 조직·한 사건 유형의 종료 사건 텍스트와 원고를 대조하는 도구. 이후 검토자 보조로만 운영한다. |
| 필요한 데이터 | 기관이 확인한 사건 텍스트, 사건ID·출처·확인/유효시각, 편집 원고·정정 기준. 원시 음성·영상 제외. |
| CCK 재사용 후보 | NOA 근거 연결·검토 이력, 문서 비교 패턴을 사건·원고 대조에 응용한다. |
| 추가 개발 | 사건 버전 스키마, 만료·충돌 상태, 원고 대조·정정 초안 UI, 기존 텍스트 공급 어댑터. |
| LLM·코드·사람 역할 | 규칙: 사건ID·시간·만료·필수 항목 / LLM: 의미 불일치 후보 / 방송 조직: 출처 충돌 해결·편집·정정·송출. |
| 비AI 대안·검증 지표 | 사건ID 템플릿+필수 필드+만료 알림과 비교. 의미 오류 탐지, 오탐, 편집 지연과 수정 부담을 측정한다. |
| 사업화 선행조건 | 내부 확인된 사건 텍스트, 정정 기록, 편집 시스템·피드 계약, 2026 연구와 플랫폼의 실제 납품 범위. |
| 축소·유보 조건 | 새 관제·영상·STT/TTS·자동 송출을 요구하면 제외. 정보 지연이 주원인이면 데이터 공급 개선부터 진행한다. |
| 대표 검수 시나리오 | 다른 사건을 합치지 않음. 출처 충돌·만료·입력 지연은 확인 필요로 유지. LLM이 미확인 원천정보의 정답을 고르지 않음. |

### N07 TAAS 공식 통계 질의·설명

판단: API 한 종류 기술 검증

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 질문을 적절한 대상·연도·지역·통계 정의에 연결하고 결과를 이해하도록 돕는다. 현행 조회 실패 규모는 미확인이다. |
| 현행 기능·중복 | TAAS 검색·GIS·전후비교·보고서·OpenAPI가 있다. 새 통계 플랫폼 또는 기존 NL2SQL 제품으로 설명하지 않는다. |
| 최소 납품 범위 | 지자체별 대상 교통사고 통계 API 1종과 승인 질의 유형. 외부 연결이 없으면 승인 반입 집계표와 반입 시점으로 제한한다. |
| 필요한 데이터 | 공식 API 응답·코드/분류·정의·기준시점·출처. 공개 통계와 개인 사고 원자료를 혼합하지 않는다. |
| CCK 재사용 후보 | NOA 근거 설명·도구 실행 패턴. 로컬 모델 어댑터와 통계 커넥터는 실제 기능 확인 후 추가 개발한다. |
| 추가 개발 | 질의 스키마·지역코드, 승인 파라미터 호출, 응답 검증·계산, 출처 카드, 실패·정의 불일치 처리. |
| LLM·코드·사람 역할 | LLM: 모호함 확인·조건 설명 / API: 공식 수치 / 코드: 검증·합계·비율 / 담당자: 정책 해석. |
| 비AI 대안·검증 지표 | 쉬운 필터+용어 설명+정형 보고서와 비교. 조건 오류·결과 해석·완료 시간·LLM의 추가 비용을 확인한다. |
| 사업화 선행조건 | 인증 호출, 사용 가능한 연도·지역·분류·페이지·오류·한도, 기존 AI 분석 기능, 실제 이용 질문. |
| 축소·유보 조건 | 질문이 소수 정형 유형이고 폼이 더 경제적이면 폼으로 제공. 기술 접점이 명확하다는 이유로 독립 사업 우선순위를 높이지 않는다. |
| 대표 검수 시나리오 | 조회 실패·데이터 없음≠사고 0. 다발지역 미선정≠안전 보증. 다른 정의·분모·지역을 무조건 비교하지 않음. |
