# 범용서비스_조사

2026-09-11 · KoROAD · 공개자료 병렬조사

공통 제약: 기존 로컬 서버·신규 인프라 투자 0원·텍스트/구조화 데이터·CCK NOA 기반. 제품·수요·기존 계약 중복·실행은 미검증.

2026 교통AI플랫폼 구축계획 [R01](https://www.koroad.or.kr/main/board/16/306460/board_view.do?bdNoticeYn=N&bdOpenYn=Y&cp=1&listType=list)이 확인되어 모든 후보는 기존 사업 범위 대조 후 구체화한다. 계획 공시를 구축 완료·가용 서버 확보로 간주하지 않는다.


## A · 범용 공공업무·국민서비스

### N01 방문 준비·상담 인계

판단: 연계·수요 확인 후

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 디딤돌 지원을 받으려는 국민이 준비조건과 방문 전 상담 내용을 유지하기 어려울 수 있다. 실제 누락·재방문 빈도는 미확인이다. |
| 현행 기능·중복 | 디딤돌 원스톱 지원과 은행 앱의 벌점조회·교육예약 연결이 이미 있다. 예약 연결 자체를 신규로 세지 않는다. |
| 최소 납품 범위 | 한 지원센터 업무의 준비목록·확인 질문·상담 인계 카드. 공식 API 없이는 접수 완료를 표시하지 않는다. |
| 필요한 데이터 | 승인된 대상·준비 안내, 센터 정보, 국민이 제공한 최소 조건. 탐색 단계에서 증명서 원문을 요구하지 않는다. |
| CCK 재사용 후보 | NOA의 업무 맥락·근거 연결·검토 이력 패턴. 대국민 화면과 공식 상태 연계는 추가 개발이다. |
| 추가 개발 | 조건 스키마, 단계형 접근성 UI, 상담 카드, 본인/대리인 권한, 허용된 조회·접수·상태 어댑터. |
| LLM·코드·사람 역할 | LLM: 자유로운 표현을 조건과 질문으로 정리 / 규칙: 대상·기한·필수 입력 / 공식 시스템: 접수 상태 / 담당자: 자격·상담·접수 결정. |
| 비AI 대안·검증 지표 | 현행 안내·단계형 폼과 같은 준비 과업으로 비교한다. 준비 누락·재입력·도움 없이 마친 비율·재방문을 본다. |
| 사업화 선행조건 | 실제 상담 실패 사례, 현재 포털 기능, 기존 AI사업 범위, 본인확인·망·접수 API 및 처리 권한. |
| 축소·유보 조건 | 기존 기능과 동일하거나 접수 권한 없이 완료를 약속해야 하면 제외. TS 자동차검사 예약 경험을 KoROAD 수요로 일반화하지 않는다. |
| 대표 검수 시나리오 | 조건이 불명확하면 추가 질문. 조건 변경 시 준비목록 갱신. 접수 API가 실패하면 준비 상태를 보존하고 접수 실패로 표시. |

### N02 시험검사 신청자료 사전점검

판단: 보완 사례 확보 후 소규모 실증

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 신청서와 설명자료의 누락·모델명·날짜·서술 불일치가 보완 왕복을 만들 수 있다. 실제 보완 자료는 미확보다. |
| 현행 기능·중복 | 공식 검사 접수·현장검사·성적서 발급 절차가 있다. 통합시험검사 관련 구축 기능과 중복을 확인해야 한다. |
| 최소 납품 범위 | 검사 유형 1종의 텍스트 전자자료 대조, 원문 근거와 보완 목록 출력. 시험 합격·성적서 진위 판단은 하지 않는다. |
| 필요한 데이터 | 비식별 신청서·설명서·성적서의 전자 텍스트, 승인 체크리스트, 기준 버전. 스캔 파일은 미검토로 구분한다. |
| CCK 재사용 후보 | Grantee의 규정–증빙 대응과 Accio의 비교 패턴, NOA 검토 흐름. 교통 문서 파서가 완성돼 있다는 뜻은 아니다. |
| 추가 개발 | 문서 유형별 텍스트 추출·원문 위치 매핑, 명칭 사전, 규칙표, 비교 화면, 보완 양식·검토 이력. |
| LLM·코드·사람 역할 | LLM: 서술·증빙 대응 후보 및 설명 / 규칙: 유무·식별자·날짜·버전 / 담당자: 보완 필요·접수·시험 결과 확정. |
| 비AI 대안·검증 지표 | 체크리스트·정확 일치 규칙과 비교. 부당한 보완 요구, 놓친 불일치, 원문 찾기·검토 시간을 함께 측정한다. |
| 사업화 선행조건 | 정상·보완·예외 실제 사례, 체크리스트 소유자, 처리 형식, 기존 시스템 기능표와 문서 권한. |
| 축소·유보 조건 | 단순 필수 항목 검사만 필요하면 SI로 편성. 스캔·도면 판독이 핵심이고 텍스트로 한정할 수 없으면 유보. |
| 대표 검수 시나리오 | 유사 모델명, 제출했으나 잘못 분류된 문서, 구·신 기준 혼재, 빈/손상 파일, 서술상 같지만 다른 표현을 구분. |

### N04 기준 변경의 업무 반영 관리

판단: 공개 사례로 요구 구체화

| 검토 항목 | 조사·설계 결과 |
| --- | --- |
| 국민·업무 문제 가설 | 같은 버전명 아래 재배포된 파일과 서로 다른 시행시점을 관리하고 연결 문서의 적용 여부를 확인해야 한다. 실제 미반영 피해는 미확인이다. |
| 현행 기능·중복 | KoROAD는 기준 제개정과 재배포 공지를 운영한다. 공지·diff·검색과 업무 문서 반영 확인을 구분한다. |
| 최소 납품 범위 | 기준집 1종과 관리 문서 집합의 변경 영향 후보·반영 확인표. 공개 사례로 설계하고 실제 업무 자료로 가치를 검증한다. |
| 필요한 데이터 | 승인 기준·공지·재배포 이력, 파일/조항 식별, 연결 안내·검토표·교재, 문서 소유자·적용시점. |
| CCK 재사용 후보 | Accio의 버전 비교 패턴과 NOA 근거·승인 흐름. 시점 지식그래프는 기보유로 산정하지 않는다. |
| 추가 개발 | 파일 해시·내용 버전, 공포/배포/재배포/시행 상태, 조항 식별, 영향 연결, 적용제외 사유·반영 이력. |
| LLM·코드·사람 역할 | 코드: 정확한 변경·날짜·상태 / LLM: 의미상 영향 후보·수정 설명 / 기준·문서 소유자: 적용 해석·반영 승인. |
| 비AI 대안·검증 지표 | 단순 diff+문서검색과 비교. 구기준 잔존·잘못된 영향 제안·반영 누락·검토 부담을 구분한다. |
| 사업화 선행조건 | 권위 있는 기준 버전, 관리 문서 목록·소유자, 실제 오류·반영 사례, 기존 AI사업의 지식관리 범위. |
| 축소·유보 조건 | 관리 문서 목록이나 승인 책임자가 없거나 단순 파일 비교만으로 해결되면 범위를 축소한다. |
| 대표 검수 시나리오 | R02 표기가 같아도 다른 파일 검출. 재배포일≠시행일. 예고안≠시행본. 승인 뒤 원문 변경 시 재검토. 영향 없음의 사유 보존. |
