# AI 브라우저와 승인 기반 업무 실행

## 문제와 제공 결과

**문제 가설:** 담당자가 여러 시스템의 조회·대사·초안 작성을 반복하며 인계와 완료 확인을 따로 수행한다는 가설.

**제공 결과:** 공식 API를 우선 검토하고 부족한 구간에 승인된 브라우저 도구를 적용하여 조회·초안·인계의 실행 증거를 남기는 업무 지원.

분류는 대표 실증 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 공식 브라우저 도구 문서는 화면 읽기와 상호작용 기능을 설명함. 이는 TS 시스템에 대한 접근·전송 허용이나 업무 효과의 확인이 아님.

**현장 검증 필요:** 조회·복사·초안 반복이 많은 시스템, API 지원 여부, 이용조건과 화면 변경 빈도, 기존 RPA 성능을 실제 업무로 대조.

### TS 검토 시나리오와 전환 과제

담당자가 내부 시스템에서 사업 상태를 조회해 보고 초안을 작성하던 중 로그인 만료와 화면 항목 변경을 만나는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 업무 수행자, 중요한 행동 승인자, 시스템 운영자 |
| 입력 | 업무 목적, 허용 도구·계정, 사건 ID, 읽기 범위, 입력 스키마·승인 조건 |
| 행동·전환 과제 | API 가능성을 먼저 확인 → 조회·초안 계획 제시 → 허용 도구 실행 → 반환값을 사건 원천과 대사 → 사람이 초안을 확인 → 필요한 인계만 승인 후 수행. |
| 산출물 | 조회 근거·검토 가능한 초안·도구 호출 순서/인자/결과·실행 후 원천 상태 |
| 예외·인계 | 로그인 만료·화면 변경·도구 오류 시 재시도 전에 중복 실행 여부 확인. 승인 후 목적·대상·금액 등이 바뀌면 기존 승인 재사용 금지. |
| 완료 판단 | 정확한 대상의 공식 상태를 확인하고 검토자가 산출물 또는 수동 인계를 수락한 상태. 클릭 성공만으로 완료하지 않음. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 API·RPA의 오류·예외·기록 보강 | 미지원 화면에 제한적 조회·초안 도구 | 승인된 쓰기는 중복·재승인·복구 시험 통과 후 |
| 지식 아카이브 | 기존 업무 매뉴얼을 입력·완료·예외 규칙으로 정리 | 시스템별 도구 계약·반환값·허용 상태 원장 | 다단계 계획 변경은 상태·권한 전이 검증 후 |
| 업무서비스 | 담당자의 조회·대사·초안 흐름 개선 | 사람 확인이 포함된 업무 실행 지원 | 여러 시스템 실행은 각 책임자·보상/취소 절차 확보 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 반복 업무를 관찰해 API/RPA/브라우저 대안과 현행 소요·재작업 측정.
- **2027**: 읽기·초안 한 흐름에서 대상 오인·로그인 만료·화면 변경·수동 전환 시험.
- **2028**: 검증된 흐름에 한해 제한적 쓰기를 별도 승인·중복 방지·실행 후 대사로 검증.
- **2029**: 여러 시스템의 일부 성공·실패에서 책임·상태·취소 가능성을 시험한 후 연결.
- **2030**: 유지보수 시간과 실사용 효과를 재평가해 취약한 화면 연계는 API 또는 수동 방식으로 전환.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 읽기·초안 중심 실행 도구와 승인 확인 | 중복 방지·화면 변경·재시도·수동 대체 | 공식 API 우선, 부족 구간의 허용 브라우저 |
| 지식 아카이브 | 허용 도구·입력 항목·승인 조건·업무별 예외·공식 완료 증거 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 요청 → 권한·계획 확인 → 조회·초안 → 사람 승인 → 허용 실행 → 공식 결과 대사 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 시스템 이용조건, 테스트 계정·환경, 허용 작업 목록, 재시도·중복 방지와 수동 복귀를 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반 인수 후 대표업무 1~2개 선정 시 최소 범위만 실증. 현행 방식과 같은 조건으로 비교.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

조회·초안부터 검증. 외부 전송·접수·승인·결제는 별도 권한과 검증 없이 수행하지 않음. 화면 성공 문구만으로 완료 판정 금지.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
