# 야간 품질평가와 오류 조치 운영

## 문제와 제공 결과

**문제 가설:** 응답은 남지만 당일 질문·근거·도구 실행과 실제 처리 결과를 묶어 오류 원인을 확인하기 어렵다는 가설.

**제공 결과:** 업무시간 외에 당일 기록을 취합해 평가 후보를 만들고 관리자가 확인·배정·수정·재검증·종결하는 운영 흐름.

분류는 대표 실증 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 추적 기록 취합·야간 평가·이슈 연결 | 중요 오류 실시간 통제·평가 실패 재처리 | 서비스 로그·공식 처리 결과·관리자 조치 |
| 지식 아카이브 | 동결 평가 기준, 사람 정답·이견, 오류 유형·원인·수정 버전 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 추적 기록 취합 → 일반 품질 야간 평가 → 사람 확정 → 이슈 배정 → 조치·회귀 시험 → 종결 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 질의·응답·근거·도구 호출 ID/순서/명칭/인자/결과와 공식 업무 결과의 연결, 보존·마스킹 기준을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반 인수 후 대표업무 1~2개 선정 시 최소 범위만 실증. 현행 방식과 같은 조건으로 비교.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

LLM 점수는 확정 오류가 아님. 평가 실패를 정상으로 처리하지 않음. 권한 위반·중요 오처리는 실시간 통제하고 야간 평가로 미루지 않음.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
