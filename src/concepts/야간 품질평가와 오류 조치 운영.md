# 야간 품질평가와 오류 조치 운영

## 문제와 제공 결과

**문제 가설:** 응답은 남지만 당일 질문·근거·도구 실행과 실제 처리 결과를 묶어 오류 원인을 확인하기 어렵다는 가설.

**제공 결과:** 업무시간 외에 당일 기록을 취합해 평가 후보를 만들고 관리자가 확인·배정·수정·재검증·종결하는 운영 흐름.

분류는 대표 실증 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 공식 평가 문서는 운영 기록 평가, 고정 데이터셋 평가와 도구 실행경로 평가를 구분. 사람 피드백으로 평가자를 보정하는 방법이 존재함.

**현장 검증 필요:** TS 대화·근거·도구 이력과 실제 처리 결과의 연결 여부, 누락 로그, 마스킹, 평가 비용·운영자의 처리 가능량은 확인 필요.

### TS 검토 시나리오와 전환 과제

주간에는 정상처럼 보인 안내에서 구판 인용이 발견되고 도구는 잘못된 사건을 조회한 경우를 야간 평가에서 찾는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 품질 운영자, 업무 검토자, 개발·지식 담당, 서비스 책임자 |
| 입력 | 질문·응답·근거판본·trace ID·호출 ID·순서·도구명·인자·결과·공식 상태·평가셋 버전 |
| 행동·전환 과제 | 당일 기록의 완전성 확인 → 규칙/정답/모델 평가를 분리 → 의심 사례와 평가 실패를 별도 대기열에 등록 → 사람이 원인을 확정 → 수정·동일 사례 회귀시험. |
| 산출물 | 근거가 붙은 이슈, 심각도·영향 업무·담당·기한, 수정 버전과 재시험 결과 |
| 예외·인계 | 권한 위반·중요 오처리는 실시간 차단·인계. 기록 누락 또는 평가 도구 실패는 품질 정상으로 집계하지 않고 원인 복구 후 재평가. |
| 완료 판단 | 오류 확정 또는 비오류 판정의 근거가 남고 조치·재검증·잔여 위험을 책임자가 수락. 야간 점수 산출만으로 종결하지 않음. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 로그의 연결·마스킹·실시간 위험 탐지 보강 | 야간 취합·평가 실패 대기열·이슈 연결 | 자동 우선순위는 오탐·미탐과 운영 부하 검증 후 |
| 지식 아카이브 | 기존 정답·오류 유형·근거판본 정비 | 오류→원인→조치→회귀사례 지식 | 변경 영향별 평가 선택은 중요 누락 시험 통과 후 |
| 업무서비스 | 기존 장애·문의 처리에 품질 이슈 인계 | 관리자 확인·담당 배정·재검증 업무 | 자동 수정은 배포 승인·회수·독립 시험 경로 확보 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 기록 연결률·현행 오류 분류·운영 인수 절차와 사람 평가 기준선 확보.
- **2027**: 대표업무에 최소 S04를 적용해 규칙·사람·LLM 판정 차이, 평가 실패 처리와 재검증을 시험.
- **2028**: 운영 기록 평가와 동결 회귀셋을 분리하고 반복 오류의 수정시간·재발을 정례 측정.
- **2029**: 다기관 인계 이슈는 원천 접근권·책임·공유 가능한 최소 증거를 합의 후 연결.
- **2030**: 확정 오류 감소와 검사·조치 비용을 함께 평가해 평가 항목·주기·표본을 조정.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 추적 기록 취합·야간 평가·이슈 연결 | 중요 오류 실시간 통제·평가 실패 재처리 | 서비스 로그·공식 처리 결과·관리자 조치 |
| 지식 아카이브 | 동결 평가 기준, 사람 정답·이견, 오류 유형·원인·수정 버전 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 추적 기록 취합 → 일반 품질 야간 평가 → 사람 확정 → 이슈 배정 → 조치·회귀 시험 → 종결 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 질의·응답·근거·도구 호출 ID/순서/명칭/인자/결과와 공식 업무 결과의 연결, 보존·마스킹 기준을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반 인수 후 대표업무 1~2개 선정 시 최소 범위만 실증. 현행 방식과 같은 조건으로 비교.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

LLM 점수는 확정 오류가 아님. 평가 실패를 정상으로 처리하지 않음. 권한 위반·중요 오처리는 실시간 통제하고 야간 평가로 미루지 않음.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
