# IT 장애 분석과 AIOps 검증 후보

## 문제와 제공 결과

**문제 가설:** IT 장애 로그·변경 이력·복구 기록을 연결하면 원인 탐색을 줄일 수 있다는 가설이며 TS 현장 규모·원인은 미확인.

**제공 결과:** 장애 유형과 관측 범위를 먼저 정의하고 승인된 로그로 원인 후보·추가 확인·수동 복구 지원의 가능성을 비교.

분류는 선행조건 확인 전 보류. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** AIOps는 기존 후보에서 별도 보류 주제로 분류. 서비스 답변 품질평가와 IT 인프라 장애 원인분석은 다른 문제임.

**현장 검증 필요:** TS 장애 발생량·원인 기록·구성/변경 데이터·현행 관제/ITSM 기능, 로그 접근권과 운영 수요가 미확인.

### TS 검토 시나리오와 전환 과제

배포 직후 여러 서비스의 지연 경보가 동시에 발생했지만 공통 원인과 개별 증상이 섞인 경우의 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | IT 운영자, 변경 승인자, 시스템 소유자 |
| 입력 | 시간 동기화 로그·구성·배포·경보·장애 티켓·복구 조치·실제 원인 |
| 행동·전환 과제 | 관측 누락·시계 차이 확인 → 변경과 경보의 관계를 후보로 제시 → 운영자가 원인 확인 → 승인된 수동 복구 → 재발·복구시간 비교. |
| 산출물 | 원인 후보와 반증·추가 관측, 장애·변경·복구의 사건 기록 |
| 예외·인계 | 상관 경보를 원인으로 확정하지 않음. 로그 공백은 정상으로 해석하지 않으며 자동 재시작·설정 변경은 범위 밖. |
| 완료 판단 | 운영자가 원인 또는 미확인 범위·복구 결과를 기록하고 잔여 장애의 소유자를 지정. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 관제·로그의 시간·구성 연결 개선 | 승인된 로그 분석 시험환경 | 자동 복구는 별도 변경권·복구안·오판 시험 후 |
| 지식 아카이브 | 기존 장애·변경·복구 원인 분류 정비 | 구성요소·변경·장애 영향 관계 | 원인추론은 실제 정답 사건·오탐 비용 검증 후 |
| 업무서비스 | 기존 장애 초기분류·추가 관측 개선 | 원인 후보 확인·복구 검토·사후분석 | 운영 자동화는 담당 수용성과 현행 도구 대비 편익 확인 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 장애·로그·기존 관제 도구의 수요와 자료권리 확인.
- **2027**: 보류 유지; 충분한 사건이 확보되면 타당성·단순 규칙 비교만 수행.
- **2028**: 과거 장애의 시간 분리 시험으로 원인 탐색·오경보·관측 공백 평가.
- **2029**: 실증 통과 시 한 운영환경의 읽기·분석 지원만 제한 적용.
- **2030**: 복구시간·운영자 검토부담·도구 유지비를 비교해 확대·축소·중단 결정.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 승인된 IT 로그·변경 이력 시험 연결 | 원인 후보의 오탐·관측 결손 분석 | 기존 관제·변경관리·복구 기록 |
| 지식 아카이브 | 로그·구성·변경·장애 시점·복구 조치·재발 여부 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 장애 기준선 → 관측자료 대사 → 원인 후보 → 운영자 확인 → 승인된 복구 → 효과 재평가 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 장애 발생량·로그 권리·현행 관제 도구와 실제 운영 수요, 오탐 비용을 확보한 뒤 착수. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 소관·수요·자료·예산 경로가 확인될 때에만 사전 타당성 검토. 연도 도래만으로 구축 착수하지 않음.
- **2028:** 타당성·비교시험을 통과한 하위 범위만 제한 검증. 미충족이면 이월 또는 중단.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

일반 LLM 답변 품질운영·모델 검토와 IT 장애 예측을 혼동하지 않음. 운영환경 자동 변경·재시작은 별도 승인·검증.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
