# 카카오톡 교통안전 안내와 공식처리 연결

## 문제와 제공 결과

**문제 가설:** 국민이 검사·자격·리콜·피해상담의 처리 기관과 준비물을 반복해서 탐색한다는 가설. 기존 챗봇과 문자 안내의 실제 이용·실패 구간을 먼저 확인.

**제공 결과:** 질문 목적을 확인하고 적용 조건·준비물·처리 가능한 기관과 공식 링크를 안내하며 해결되지 않은 건을 상담원에게 인계.

분류는 대표 실증 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** TS는 2026-01-21 보도자료에서 이륜차 정기검사 카카오톡 전자문서 사전안내와 검사소·예약 연결의 시행을 밝힘. 행안부는 2026-03-16 자료에서 카카오 대화로 증명서를 안내·발급하는 AI 국민비서 시범서비스를 설명함.

관련 공식 근거: [TS 이륜차 검사 카카오톡 전자문서 안내](https://main.kotsa.or.kr/portal/bbs/report_view.do?bbscCode=report&bbscSeqn=18778&menuCode=05010200), [행안부 AI 국민비서 시범서비스](https://www.mois.go.kr/video/bbs/type019/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000255&nttId=124399), [자동차리콜센터 리콜대상·조치여부 확인](https://www.car.go.kr/ri/recall/list.do), [자동차리콜센터 리콜알리미](https://car.go.kr/ri/ntcn/list.do).

**현장 검증 필요:** TS 기존 안내 이후의 재문의 이유·목적 오분류·검사소 선택 실패·상담 인계 부담은 미측정. 타기관의 시범 범위와 TS 연계 승인은 별도 확인.

### TS 검토 시나리오와 전환 과제

‘검사 안내를 받았는데 리콜도 있다. 근처 어디로 가야 하나’라는 질문에 검사와 제조사 시정조치를 나눠 설명하는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | TS 채널 이용자, 상담원, 업무별 지식 소관자, 채널 운영자 |
| 입력 | 채널 1:1 질문, 이용자가 선택한 지역·업무 목적, 검사소 제공업무, 제작사 공식 정비망·리콜 링크의 갱신일 |
| 행동·전환 과제 | 검사/리콜 목적을 나눔 → 처리 가능한 시설 종류를 설명 → 각각의 공식 링크·준비물을 제공 → 불명확한 사건은 상담원에게 질문·확인내역을 인계. |
| 산출물 | 목적별 다음 행동·공식 조치처·유효한 링크와 미해결 상담 인계 묶음 |
| 예외·인계 | 리콜 조치여부는 제작사 분기 보고 기반으로 이전 분기까지 표시될 수 있고 시간외 조회 제한이 있을 수 있음. 조회 실패·갱신 지연을 미조치·대상 아님으로 해석하지 않음. 환경부 리콜은 해당 공식 조회에서 조치여부가 제공되지 않으므로 제작사 등 적정 확인 경로로 인계. |
| 완료 판단 | 이용자가 선택한 공식 경로가 제공되고 미해결은 상담원이 인수한 상태. 외부 예약·리콜 수리 완료는 공식 처리 결과가 있을 때만 별도 표시. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 채널·전자문서의 링크 실패·상담 인계 보강 | 목적 확인과 응답을 연결하는 승인된 채널 스킬 | 본인업무 상태 조회는 동의·연계권·오인 통제 통과 후 |
| 지식 아카이브 | 검사·리콜·항공·피해구제 소관과 갱신 주기 정비 | 조치처의 실제 처리 가능업무·예외 지식 | 기관 간 상태 설명은 출처별 시차와 책임 합의 후 |
| 업무서비스 | 기존 일방 안내 뒤 반복 질문·상담 연속성 개선 | 공개정보에 한정한 목적별 대화·다음 행동 안내 | S02 증빙·신청 지원은 공개안내 실증과 별도 진입 심사 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 기존 카카오 전자문서·챗봇·문자·상담 경로의 실제 기능과 추가 수요 대조.
- **2027**: 공개안내 한 업무에서 질문의 공식 소관·처리 가능한 시설·링크의 정확도와 상담 인계 누락 측정.
- **2028**: 검증된 질문군과 접근성 지원 확대; 링크 변경·정보 지연·외부 장애 회귀시험 정례화.
- **2029**: 기관·제작사 연계는 협약·응답 시차·개인동의·상담 책임이 확보된 조회부터 제한 검증.
- **2030**: 재문의·경로 이탈·처리처 오안내·상담 부담을 재평가하고 채널 중복과 운영 범위를 조정.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 카카오톡 수신·응답·상담 인계의 추가 연결 | 문맥·링크 만료·실패 안내·접근성 | 기존 TS 채널·공식 처리처·승인된 메시지 |
| 지식 아카이브 | 업무 소관, 검사 종류, 조치 가능 시설, 공식 링크와 갱신일 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 질문 → 목적·조건 확인 → 근거 안내 → 공식 경로 이동 → 미해결 상담 인계 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 기존 TS 챗봇·국민비서·문자 기능과 다른 추가가치, 링크 유지 담당, 상담 인계 경로를 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반 인수 후 대표업무 1~2개 선정 시 최소 범위만 실증. 현행 방식과 같은 조건으로 비교.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

TS 카카오톡 채널의 1:1 대화를 대상으로 수신·답변하는 설계이며 개인 대화나 단체방 수집은 범위에 포함하지 않음. 2027은 공개안내 실증. 예약·접수·결제·허가·배차 완료를 채팅 응답으로 확정하지 않음. 항공자격/비행승인, 리콜/제작사 조치, 중고차 피해/신차 중재를 구분.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
