# NPU·GPU와 폐쇄망 모델 운영 연구

## 문제와 제공 결과

**문제 가설:** 같은 품질·지연 조건에서 NPU·GPU 배치와 전환·복구가 총비용을 낮출 수 있다는 연구 가설.

**제공 결과:** 장비·SDK·모델 호환, 같은 부하의 품질·지연·전력·운영비와 장애전환을 비교해 채택 또는 보류 근거를 제공.

분류는 순증 연구 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** v1.1은 RD-05를 동일 품질 조건의 자원 배치·전환·복구 연구로 정의함. 실제 가용 NPU·GPU와 호환 모델이 확인됐다는 뜻은 아님.

**현장 검증 필요:** 칩·SDK·연산자·모델 형식·폐쇄망 운영·메모리와 실제 계측 가능한 비용 항목을 확인.

### TS 검토 시나리오와 전환 과제

평상시 경량 추론은 NPU에서 가능하지만 긴 문서나 미지원 연산에서 GPU 전환이 필요한 상황을 시험하는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 추론·인프라 연구자, 모델 평가자, 운영·보안 담당 |
| 입력 | 실제 장비·SDK·모델버전·업무셋·부하·품질 기준·전력·지연·메모리·장애 기록 |
| 행동·전환 과제 | 호환성 선별 → 같은 모델·업무·부하 시험 → 전환 전후 결과 비교 → 장애·복구 재현 → 운영공수 포함 총비용 비교 → 제한 편입 심사. |
| 산출물 | 호환 표, 품질·지연·전력·비용 결과, 전환 실패·복구 조건과 채택/보류 사유 |
| 예외·인계 | 미지원 연산·메모리 부족·성능 저하는 숨기지 않음. 전환 중 중복 실행·결과 누락을 확인하고 현행 환경으로 복귀. |
| 완료 판단 | 비교 결과·실패 조건·비용이 재현되고 채택 또는 보류 판단을 책임자가 수락하면 연구 완료. 제한 운영 편입은 품질·복구 기준을 통과한 경우에만 별도 승인. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 현행 GPU 실행·비용·장애 계측 개선 | NPU 호환·전환·복구 연구환경 | 혼합 운영은 품질·장애·총비용 실증 통과 후 |
| 지식 아카이브 | 기존 모델·장비·라이선스·SDK 원장 정비 | 업무별 호환·실패·성능 시험 지식 | 배치 추천은 실제 부하 변화와 회귀 검증 후 |
| 업무서비스 | 기존 모델 운영의 장애·비용 비교 보강 | 장비 적합성 심사·제한 편입 업무 | 운영 서비스화는 실행권·지원인력·인수 조건 확보 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 실제 장비·SDK·모델 실행권·비교 GPU와 계측 항목 확인.
- **2027**: 호환성과 같은 품질 조건의 소규모 비교 연구; 특정 칩 구매를 전제하지 않음.
- **2028**: 긴 입력·동시부하·미지원 연산·장애전환의 재현 시험.
- **2029**: 검증을 통과한 업무만 폐쇄망 제한 운영, 복구·지원 공수를 포함해 재평가.
- **2030**: 모델·SDK 변경과 장비 수명·지원비를 반영한 총비용으로 유지·전환·중단 결정.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 장비 호환·자원배치 연구 시험환경 | 장애 전환·품질 유지·총비용 비교 | 실제 가용 NPU/GPU·폐쇄망 모델·계측 |
| 지식 아카이브 | 장비·SDK·모델버전·시험조건·성능·오류·장애복구·비용 원장 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 가용 장비 확인 → 호환 시험 → 같은 조건 비교 → 장애·복구 실험 → 총비용 판단 → 제한 편입 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 실제 가용량·실행권, 모델 호환·폐쇄망 조건, 계측·운영 인력과 비교 GPU 기준을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 순증 연구 가설·기존 과제 차이·시험권을 확인한 경우에만 기준선 비교연구. 납품과 별도 관리.
- **2028:** 타당성·비교시험을 통과한 하위 범위만 제한 검증. 미충족이면 이월 또는 중단.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

하드웨어 구매·특정 칩 채택을 선결론으로 두지 않음. 청구서·협약을 가동·성능 증거로 쓰지 않음. 통과 전 운영 납품과 분리.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
