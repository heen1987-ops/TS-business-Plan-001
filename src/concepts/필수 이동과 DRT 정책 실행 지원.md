# 필수 이동과 DRT 정책 실행 지원

## 문제와 제공 결과

**문제 가설:** 이동 건수만으로 주민의 필수 이동 미충족과 실제 이용 실패를 설명하기 어렵다는 가설.

**제공 결과:** 지역별 수요·대기·실패·정책 조건을 대사한 대안 검토와 공식 교통서비스 안내를 지원.

분류는 선행조건 확인 전 보류. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** PS 공개 재설계는 최소서비스·DRT 필요지역·필수노선 판단 근거를 대조하는 정책 지원을 제안. 전국 배차나 예산 배분의 자동화 실적은 아님.

**현장 검증 필요:** 지역별 필수 이동의 정의, 거절·대기·취소 사유, 기존 노선 대체 가능성과 운영자의 실제 조정 권한을 확인.

### TS 검토 시나리오와 전환 과제

병원 방문 수요가 있으나 특정 시간대 환승·예약 실패가 반복되는 지역의 정책 대안을 비교하는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 지자체 정책 담당, 교통 운영자, 접근성 검토자, 주민 의견 수렴 담당 |
| 입력 | 비식별 이동 수요·시간대·목적·대기·실패·노선·운영제약·정책 기준 |
| 행동·전환 과제 | 미충족 이동을 정의 → 기존 노선·예약조건과 대사 → DRT/노선조정/안내개선 대안 비교 → 운영자·주민 검토 → 제한 시행과 실패 관측. |
| 산출물 | 대안별 해결 대상·제약·비용 항목, 시행 협의안과 실패·미충족 추적표 |
| 예외·인계 | 요청 건수만으로 수요를 확정하지 않음. 전화번호만으로 본인 확인·자격 판단하지 않으며, 취약계층 원자료 공개를 제외. |
| 완료 판단 | 정책 담당과 운영자가 시행 또는 보류 근거·담당·관측 방법을 수락. 개별 배차 완료는 운영시스템의 별도 결과. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 예약·실패·노선 집계의 품질 개선 | 허용된 비식별 정책 분석 연결 | 실시간 운영연계는 운영자 권한·안전 검증 후 |
| 지식 아카이브 | 기존 서비스 조건·지역·시간·접근성 사전 정비 | 필수이동 미충족·대안 제약 지식 | 정책 효과 추론은 비교지역·외부요인 평가 후 |
| 업무서비스 | 기존 공식 서비스 안내·실패 분류 개선 | 대안 협의·시행·관측 업무 | 배차 지원은 별도 운영실증과 예산 검토 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 수요·정책 소관·기존 DRT와 자료권리 확인; 미충족 정의 합의.
- **2027**: 보류 후보로 대안 타당성만 검토. S01 공개안내와 DRT 구축을 묶어 착수하지 않음.
- **2028**: 협력 지역·운영자가 확보된 한 사례에서 정책 대안과 실패지표 제한 검증.
- **2029**: 다른 지역은 노선·인구·운영 조건 차이를 다시 확인한 후 확대 검토.
- **2030**: 실제 필수 이동 개선·공급 부담·접근성을 평가해 운영 정착 또는 철수 결정.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 선정 업무의 허용 입출력·권한·기록 연결 | 예외·중복 실행·권한 회수·실패 복구의 검증 | 공식 원천·기존 시스템과 승인된 API 또는 제한된 도구 연결 |
| 지식 아카이브 | 지역·시간대·필수 목적·서비스 조건·접근성·대기·실패 사유 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 이동 필요 확인 → 현행 서비스 대조 → 정책 대안 검토 → 운영자 협의 → 시행·실패 관측 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 지자체·운영자 자료 및 정책·배차 책임, 접근성·실패 기준과 현행 TS-DRT 범위를 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 소관·수요·자료·예산 경로가 확인될 때에만 사전 타당성 검토. 연도 도래만으로 구축 착수하지 않음.
- **2028:** 타당성·비교시험을 통과한 하위 범위만 제한 검증. 미충족이면 이월 또는 중단.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

2027 카카오톡 공개안내와 DRT 구축을 함께 앞당기지 않음. 전국 예산 배분·개인 제재·LLM 배차 최적화 제외.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
