# 공공 마이데이터 기반 증빙·신청 지원

## 문제와 제공 결과

**문제 가설:** 신청인이 이미 보유기관에 있는 증빙을 반복 제출한다는 가설. 기존 공동이용·비대면 검증으로 해결된 업무는 신규 기회에서 제외.

**제공 결과:** 한 업무에서 필요한 본인정보만 동의받아 수신하고, 증빙 충족·추가 제출·철회 상태를 담당자와 신청인이 확인하는 지원.

분류는 조건부 확장 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 공식 공공 마이데이터 목록에 TS의 건설기계 관련 본인정보 3종이 보유기관 정보로 등재. 서비스 소개는 한전 전기요금 복지할인에 필요한 항목을 여러 증빙에서 선별하는 묶음정보 방식을 설명함. TS 자동차검사 공식 FAQ는 보험가입 여부를 전산 확인하고 전산 장애 시 증명서 확인 경로를 안내하므로, 이미 연계된 확인업무의 최초 구축을 제안하지 않음.

관련 공식 근거: [공공 마이데이터 한전 복지할인 묶음정보 설명](https://www.mydata.go.kr/pc/intro/serviceIntro.do), [TS 자동차검사 보험가입 확인 FAQ](https://main.kotsa.or.kr/portal/bbs/faq_list.do?cateCode=C01&menuCode=04010100).

**현장 검증 필요:** 목록 등재만으로 TS가 제안 업무의 수신기관 승인·묶음정보·운영 연계를 확보했다고 볼 수 없음. K-패스·튜닝 등의 실제 반복 제출과 기존 검증으로 대체되지 않은 부분을 확인.

### TS 검토 시나리오와 전환 과제

검사 관련 감면 증빙이 필요한 이용자가 제공 요구에 동의했지만 일부 항목만 돌아오는 경우를 다루는 TS 검토 시나리오. 해당 감면 업무와 수신권은 착수 전 확인 대상.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 신청인, 증빙 검토 담당, 개인정보 책임자, 연계 운영자 |
| 입력 | 선정 업무의 필요한 최소 항목, 본인확인 결과, 제공요구·동의 상태, 수신 시점, 누락·철회 정보 |
| 행동·전환 과제 | 증빙 요구를 항목으로 정의 → 기존 공동이용과 비교 → 이용자가 범위를 확인 → 승인된 경로로 수신 → 담당자가 충족/누락을 검토 → 공식 신청에 인계. |
| 산출물 | 증빙 충족표·누락 안내·제공이력·철회 처리와 공식 신청 인계 결과 |
| 예외·인계 | 동의 거부·수신 실패·정보 상충은 종이 또는 기존 제출 경로로 전환. 미수신 항목을 ‘자격 없음’으로 판단하지 않으며 철회 후 처리 가능범위는 규정으로 판단. |
| 완료 판단 | 기관의 공식 신청 또는 보완 경로가 확인되고 목적별 보유·만료·철회 상태를 추적할 수 있는 상태. 데이터 수신과 자격 확정은 별개. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 공동이용·증빙 검증의 누락·장애 대응 보강 | 승인된 수신·동의·철회 연결만 신규 구현 | 복합 신청은 기관별 목적·보존·철회 경계를 검증한 뒤 |
| 지식 아카이브 | 기존 증빙 서식에서 필수 항목·대체조건 정비 | 항목별 출처·시점·목적·증빙 동등성 원장 | 다기관 증빙 관계는 최신성·불일치 처리 합의 후 |
| 업무서비스 | 현재 증빙 제출의 안내·보완 부담 개선 | 한 업무의 동의→수신→충족 확인→인계 | 연속 신청은 오판·철회·정보주체 권리 시험 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 제출 부담이 남은 한 업무를 선정하고 수신권·묶음정보·법적 근거·기존 공동이용을 대조.
- **2027**: 승인 요건이 확보된 경우에만 합성/허용 표본으로 동의·누락·거부·철회 시험; 미확보면 기획에 한정.
- **2028**: 한 업무의 실제 제출 횟수·보완·실패와 권리 처리 결과를 비교해 제한 적용.
- **2029**: 기관별 책임·목적·반환 항목이 다른 복합 신청은 단계별 동의·보관·이의처리를 새로 검증.
- **2030**: 실제 증빙 대체효과와 보관·철회 부담을 평가하고 필요 없는 항목·연계를 제거.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 승인 업무의 동의·수신·철회 상태 연결 | 항목 최소화·만료·재전송·실패 복구 | 승인된 본인정보 묶음·현행 신청 시스템 |
| 지식 아카이브 | 업무별 필요 항목·이용 목적·보유 기간·동의 범위·증빙 대체 조건 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 본인 확인 → 항목별 동의 → 승인된 수신 → 누락 확인 → 공식 신청 인계 → 철회·만료 처리 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 활용기관 승인, 묶음정보, 수신권·연계 시험, 개인정보 책임과 실제 제출 부담을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 원칙적으로 수요·권리·정답·기존 중복의 후보검증을 수행. 다만 승인된 업무·수신권·동의·묶음정보·연계시험이 확보되고 대표업무로 선정되면 최소 범위 실증 가능.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

TS 전체 미연계·최초 참여로 표현하지 않음. 제공기관 등재는 수신·가동의 증거가 아님. K-패스·튜닝의 기존 검증방식과 구분.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
