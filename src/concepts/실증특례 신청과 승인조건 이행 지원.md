# 실증특례 신청과 승인조건 이행 지원

## 문제와 제공 결과

**문제 가설:** 신청 보완, 승인조건, 개시·보고·변경·종료의 책임과 기한이 끊겨 미이행을 놓칠 수 있다는 가설.

**제공 결과:** 신청 요건·서류 대조와 승인 후 조건별 기간·증빙·책임을 별도 관리해 공식 검토자에게 인계.

분류는 조건부 확장 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 기존 실증 컨셉 K049~K061과 RI 재설계는 승인조건·보고기한·적용기간·보완·종료의 관리로 구체화됨.

**현장 검증 필요:** 실제 승인문에서 조건이 어떻게 추출·확정되고 변경 승인 후 기한·증빙·사업자 통보가 갱신되는지 확인.

### TS 검토 시나리오와 전환 과제

실증 운영범위가 변경되었지만 이전 승인조건의 보고기한과 안전계획이 그대로 남아 있는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 신청 사업자, 신청·사후관리 담당, 승인기관, 안전 검토자 |
| 입력 | 공고·신청자료·승인문·변경 승인일·조건·기한·안전계획·이행 증빙 |
| 행동·전환 과제 | 신청 요건과 승인조건을 분리 → 담당자가 조건·기간 확정 → 변경 전후 적용기간 분할 → 조건별 증빙 대사 → 보완·연장·종료 검토를 공식 경로에 인계. |
| 산출물 | 판본별 조건대장, 이행·보완 목록, 변경 영향과 종료·연장 검토자료 |
| 예외·인계 | 승인문 해석이 모호하면 조건을 만들어내지 않고 승인기관 확인 대기. 조건 변경과 사업자 계획 변경을 구분. |
| 완료 판단 | 적용기간별 조건의 이행·미이행·확인불가가 근거와 함께 정리되고 권한자가 후속 검토를 수락. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 신청·사후관리의 사건·변경 연결 | 조건·기간별 이행상태 기능 | 기관 간 협의는 승인 원천·회신 책임 확보 후 |
| 지식 아카이브 | 기존 승인문·안전계획의 조건·기한 정비 | 조건판본·기간·증빙 관계 | 변경 영향 추천은 누락·과잉요구 검증 후 |
| 업무서비스 | 기존 신청 보완·보고 안내 개선 | 조건 확인·이행 검토·종료 인계 | 연속 실증지원은 특례 승인과 실행 책임 분리 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 한 신청유형의 승인·변경·보고 사례와 공식 관할 확인.
- **2027**: 과거 조건·기간·증빙의 정답을 사람이 확정해 후보 검증.
- **2028**: 한 실증의 변경·보완·종료 흐름을 제한 지원하고 기한·조건 누락 측정.
- **2029**: 다기관 조건은 상충·회신 지연·책임을 합의한 범위만 연결.
- **2030**: 조건 이행의 추적성과 관리부담을 평가해 유효 유형만 유지·확산.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 선정 업무의 허용 입출력·권한·기록 연결 | 예외·중복 실행·권한 회수·실패 복구의 검증 | 공식 원천·기존 시스템과 승인된 API 또는 제한된 도구 연결 |
| 지식 아카이브 | 공고·관할·조건판본·안전계획·보고기한·변경 이력 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 신청 준비 → 요건 검토 → 공식 신청 → 승인조건 등록 → 이행·보완 → 종료·연장 검토 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 공고별 관할과 승인권자, 조건 원문·변경일·이행 책임과 공식 증거를 확보. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반·대표실증을 우선하고 이 업무는 수요·권리·정답·기존 중복의 후보검증까지만 수행 가능.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

자동 특례 승인·조건 변경·연장·사업화 보장 제외. 실증 수행 기술개발과 신청·조건관리 비용을 구분.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
