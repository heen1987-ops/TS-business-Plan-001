# 민원 답변과 업무문서 근거 검토

## 문제와 제공 결과

**문제 가설:** 질문별 요구와 답변의 충족 여부를 문장 단위로 확인하지 못해 누락·상충·근거 없는 표현이 남는다는 가설.

**제공 결과:** 민원 요구 목록, 대응 답변·근거, 누락·불일치 후보와 담당자 확정 결과를 한 검토 묶음으로 제공.

분류는 조건부 확장 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 기존 기획은 민원 요구별 충족·누락 검토와 문서 근거 대사를 별도 검토 결과로 제안함. 현재 TS의 누락률·재작업 실적은 확인되지 않음.

**현장 검증 필요:** 민원 원문에서 요청이 몇 개인지, 현행 답변 검토가 어느 요구·시점을 놓치는지 비식별 사례와 담당자 정답으로 확인.

### TS 검토 시나리오와 전환 과제

한 민원에 검사 기한·수수료·이의신청 세 질문이 있는데 답변은 기한만 설명한 경우의 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 민원 담당자, 답변 검토자, 기준 소관자 |
| 입력 | 질문 원문·작성 답변·적용일·기준판본·답변 필수 요소·발신 권한 |
| 행동·전환 과제 | 요구를 분리해 담당자 확인 → 요구별 답변 문장·출처 연결 → 누락·상충 후보를 제시 → 검토자가 수정·확정 → 공식 발신 경로로 인계. |
| 산출물 | 요구-답변-근거 대응표와 보완 의견, 확정 답변·검토 이력 |
| 예외·인계 | 개인 사건 판단·분쟁·기준 상충은 답을 단정하지 않고 전문 검토에 인계. 검토 보류와 답변 완료를 구분. |
| 완료 판단 | 모든 요구가 충족 또는 미답변 사유·인계처로 설명되고 발신 권한자가 최종본을 확인한 상태. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 기존 민원 시스템의 사건·판본 연결 보강 | 미지원 요구별 대사 기능 | 여러 채널의 동일 사건 연결은 본인·보관·중복 정책 확보 후 |
| 지식 아카이브 | 기존 FAQ의 적용조건·예외 정비 | 요구 유형·필수 응답요소·정답 사례 | 개정 영향 답변 재검토는 중요 누락 시험 통과 후 |
| 업무서비스 | 기존 답변 검토 단계의 누락 확인 개선 | 담당자 수정·검토자 확정의 비교 화면 | 자동 초안 확대는 민원 유형별 오답 영향 검증 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 비식별 민원 표본의 요구 수·누락·검토시간을 사람이 판정.
- **2027**: 기존 과업 중복 대조 후 요구별 검토를 동일 표본에서 현행 방식과 비교.
- **2028**: 검증된 유형을 늘리되 기준 개정·복합질문·미답변 사례 회귀시험.
- **2029**: 타기관 질문은 공식 소관·인계 확인을 확보한 유형만 연결.
- **2030**: 재문의·정정·검토부담을 재평가하고 효과 없는 자동 검토 항목을 축소.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 선정 업무의 허용 입출력·권한·기록 연결 | 예외·중복 실행·권한 회수·실패 복구의 검증 | 공식 원천·기존 시스템과 승인된 API 또는 제한된 도구 연결 |
| 지식 아카이브 | 요구 유형·답변 필수 요소·기준판본·검토 의견과 예외 사례 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 요구 분해 → 답변·근거 대사 → 누락 후보 → 검토자 수정·확정 → 공식 발신 경로 인계 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 기존 민원·문서검토 과업과의 차이, 비식별 사건 표본, 현업 정답·발신 책임을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반·대표실증을 우선하고 이 업무는 수요·권리·정답·기존 중복의 후보검증까지만 수행 가능.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

기존 문서검토 기능을 새 플랫폼으로 다시 계상하지 않음. 민원 결론·공식 발신은 권한자가 확정. 개인 민원 원문 공개 금지.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
