# 신규 모델 추천과 검증·배포 운영

## 문제와 제공 결과

**문제 가설:** 새 모델이 자주 공개되어도 업무 정확도·라이선스·폐쇄망·지연·비용 조건에 맞는지 비교하기 어렵다는 가설.

**제공 결과:** 모델 후보와 버전·라이선스를 등록하고 동일 조건 시험, 제한 적용, 승격·회수 판단을 이어가는 모델 검토 지원.

분류는 대표 실증 후보. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 모델 카드에는 용도·한계·학습/평가 정보 등을 기록할 수 있음. 공개된 카드·순위만으로 TS 업무 적합성을 보증하지는 않음.

**현장 검증 필요:** 현행 모델의 오류·지연·총비용·면허·폐쇄망 실행 가능성과 새 후보의 호환성은 같은 업무 조건으로 측정 필요.

### TS 검토 시나리오와 전환 과제

한국어 표와 개정 규정 해석이 많은 업무에서 새 경량 모델이 빨라 보이지만 중요 누락이 늘어나는 경우를 비교하는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 모델 운영자, 업무 평가자, 보안·권리 담당, 배포 승인자 |
| 입력 | 버전·면허·가용 장비·동결 업무셋·동일 토큰/부하 조건·현행 모델 결과 |
| 행동·전환 과제 | 조건 미충족 후보 제외 → 같은 셋·부하·출력 기준 시험 → 중요 오류·지연·비용 비교 → 제한 적용 → 배포 승인 또는 보류 → 회수 시험. |
| 산출물 | 후보 적합성표, 재현 가능한 비교 결과, 채택/보류 사유, 제한 적용·회수 계획 |
| 예외·인계 | 면허·버전 불명, 비공개 자료 반출 필요, 중요 오류 악화는 승격 중단. 장애 시 기존 모델로 복귀하고 결과 상태를 대사. |
| 완료 판단 | 업무·보안·운영 책임자가 검증 결과와 롤백을 수락하고 버전이 고정된 상태. 추천 목록 생성만으로 도입 완료 아님. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 현행 모델 호출·배포·비용·회수 계측 개선 | 후보 등록과 비교시험 환경 | 다중 모델 라우팅은 업무별 오분류·전환 실패 검증 후 |
| 지식 아카이브 | 기존 모델 카드·면허·버전 근거 정비 | 업무·장비별 적합성 원장 | 적합성 자동 갱신은 변경 감지와 재현 시험 확보 후 |
| 업무서비스 | 기존 모델 변경 승인 절차 보강 | 후보 검토→시험→제한 적용→승격·회수 업무 | 지속 교체 운영은 품질·비용 편익이 반복 확인될 때 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 현행 모델·장비·비용·면허 기준선과 업무별 중요 오류 정의.
- **2027**: 최소 S05로 한 업무의 현행/후보를 같은 조건에서 비교하고 배포·회수 시험.
- **2028**: 검증된 모델만 제한 적용하고 운영 데이터의 성능 편차·회귀 여부 감시.
- **2029**: 업무별 모델 선택은 라우팅 오판·전환 실패의 영향과 운영책임을 확인 후 적용.
- **2030**: 미사용 모델 정리, 면허·호환·유지비 재점검과 정기 채택/보류 의사결정 정착.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 후보·시험·제한 배포·회수 상태 관리 | 재현 시험·버전 비교·비용·장애 복구 | 모델 허브 정보·승인된 내부 실행환경 |
| 지식 아카이브 | 모델 카드·라이선스·버전·사용 제한·장비 호환·업무별 시험 결과 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 후보 발견 → 자격 조건 확인 → 같은 데이터·부하 시험 → 제한 적용 → 운영 승인 → 회수·재평가 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 현행 모델 기준선, 반출 금지 자료, 재현 가능한 시험셋·장비·측정 방식과 배포 책임을 확인. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 공통 기반 인수 후 대표업무 1~2개 선정 시 최소 범위만 실증. 현행 방식과 같은 조건으로 비교.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

공개 순위나 추천 문구만으로 모델 교체 금지. 내부 대화·원문을 외부 모델 허브에 업로드하지 않음. 새 모델 운영비와 기존 유지관리 중복 제거.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
