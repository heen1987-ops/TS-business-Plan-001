# AX 현황진단·ISP와 대표업무 비교실증

## 문제와 제공 결과

**문제 가설:** 실제 병목·기존 계약·자료·수요가 확인되지 않은 채 구축 범위를 정하면 중복 투자나 측정 불가능한 실증이 될 수 있다는 가설.

**제공 결과:** 현행 사건 관찰, 업무량·재작업 기준선, 기존 기능·계약 대조, 대안 비교와 진입 조건을 포함한 실행·예산 기획.

분류는 공통 기반·진단. TS의 발주·예산·수요 확정 또는 구현 완료를 뜻하지 않으며, 효과 수치는 현행 기준선과 비교한 뒤 제시.

## 사례 기반 AS-IS → TO-BE 상세

### 현재 확인한 내용과 남은 확인

**확인된 범위:** 기존 분기 기획은 현장 실측·대표업무 비교시험을 선행 게이트로 제시. 제안된 수량·일정·인력은 현장 실적과 구분해야 함.

**현장 검증 필요:** 병목이 정보 검색인지 규정 모호성인지 조직 승인 지연인지, 이미 계약된 개선인지 실제 사건을 따라 확인.

### TS 검토 시나리오와 전환 과제

담당자가 ‘문서 찾기가 오래 걸린다’고 말하지만 관찰 결과 대부분이 승인 대기인 업무를 진단하는 TS 검토 시나리오.

아래 업무 사례는 설계·검증용 예시이며 TS에서 실제 발생했거나 구현·실증한 사건을 뜻하지 않음. 타기관 사례는 위에서 확인한 공개 범위에만 적용.

| TO-BE 요소 | 수행 내용과 수락 조건 |
|---|---|
| 주체 | 현업 수행·승인자, 분석 PM, 정보화·예산 담당, 검수자 |
| 입력 | 업무 사건표본·단계시간·대기·재작업·기존 기능/계약·자료권리·운영비 |
| 행동·전환 과제 | 실제 사건 관찰 → 원인별 시간 분해 → 서식·권한·규칙 개선과 AI 대안 비교 → 작은 대표실증 → 효과·비용·검수조건을 ISP/RFP로 연결. |
| 산출물 | AS-IS 증거, 대안 비교, 범위·물량·산정식, 역할·산출·진입/중단 조건 |
| 예외·인계 | 자료가 없으면 추정값을 실측으로 쓰지 않음. 병목이 조직·제도에 있으면 플랫폼 추가를 우선 처방하지 않음. |
| 완료 판단 | 현업과 구매·검수 담당이 문제·범위·기존 중복·비교기준과 후속 투자 판단자료를 수락. |

### 세 영역의 고도화·신규 구축·조건부 차세대사업

‘고도화’는 확인된 기존 경로의 개선, ‘신규 구축’은 현재 부재·추가 필요성을 확인한 기능, ‘차세대사업’은 앞 단계 성과와 추가 권한·자원이 확보된 후속·파생 경로를 뜻함. 동일 기능을 세 유형의 사업비로 반복 합산하지 않음.

| 영역 | 고도화 | 신규 구축 | 조건부 차세대사업 |
|---|---|---|---|
| 인프라·플랫폼 | 현행 계측·로그·연계 현황 진단 보강 | 필요시 제한 비교시험 환경 | 차세대 아키텍처는 현행 한계·수요 증거 확보 후 |
| 지식 아카이브 | 기존 업무·자료·계약 목록 정비 | 문제-원인-근거-대안 추적 원장 | 기관 간 재사용은 권리·조건 차이 검토 후 |
| 업무서비스 | 현재 절차·서식·승인 대안 개선 | 현장 진단→대안→실증→RFP 업무 | 본사업은 실증·예산·조달 판단 통과 후 |

### 업무별 2026~2030 단계와 검증 기준

- **2026**: 실제 사건·기존 계약·구매 조건을 확인해 현행 기준선과 진단 범위 확정.
- **2027**: 대표업무 1~2개에서 현행·단순 개선·AI 방식을 같은 조건으로 비교.
- **2028**: 검증된 결과를 요구사항·검수·운영 인수에 반영하고 과장 편익 재산정.
- **2029**: 타업무·기관 적용은 원인·권한·자료 차이를 새로 진단.
- **2030**: 계획 편익과 실현 성과·유지비를 대조해 다음 투자 또는 종료 근거로 활용.

각 단계의 수량·허용 오류·소요시간 목표는 기준선 조사 후 업무·검수 책임자가 합의. 기한 도래만으로 다음 단계에 진입하지 않으며, 중요 예외의 미해결·자료권리 미확보·기존 기능 대비 편익 미확인은 보완·축소·중단 판단 사유.

## 세 영역의 신규·고도화·연계

| 영역 | 신규 개발·구축 | 고도화 | 연계 강화 |
|---|---|---|---|
| 인프라·플랫폼 | 선정 업무의 허용 입출력·권한·기록 연결 | 예외·중복 실행·권한 회수·실패 복구의 검증 | 공식 원천·기존 시스템과 승인된 API 또는 제한된 도구 연결 |
| 지식 아카이브 | 현행 절차·계약·수락 기준·업무량·비용 가정·기준선·구매 조건 | 정본·시점·소관·권리·변경·회수 상태와 오류 사례 보강 | 해당 원천·공식 기준·검토 결과를 출처와 함께 연결 |
| 업무서비스 | 범위 확정 → 현장 실측 → 기존 기능 대조 → 대안 비교 → 대표업무 실증 → ISP/RFP·검수조건 연결 | 담당 수락·보완·사람 확정·실패 인계·완료 증거 보강 | 기존 공식 처리·검토·보고 경로로 인계하고 실제 결과 확인 |

공통 기반을 업무마다 새로 구축하지 않으며, 기존 8.3 업무지식의 절차·규칙·예외 자산을 서비스에 연결. 개별 기관의 원문·정답·개인정보와 재사용 가능한 공통 자산의 권리를 구분.

## 2026~2030 진입 조건

- **2026 준비:** 현업 참여·자료권리·조사 범위와 산정 방법을 합의하고, AI 없이 해결되는 대안도 비교. 같은 기간·대상에서 현행 처리·오류·재작업의 기준선을 확보.
- **2027:** 기존 이행·권리·현업 정답을 확인한 공통 추가분과 대표업무 1~2개만 검증.
- **2028:** 현업 검증을 통과한 범위만 확산하고 기준·화면·권한 변경 시 재검증.
- **2029:** 고유업무·기관 간 연계는 각각의 소관·협약·입출력 계약과 예외 인계를 확인한 뒤 추가.
- **2030:** 사용 성과·유지 부담·권리·비용을 다시 비교해 운영 정착·재사용·축소를 결정. 전사 전면 자동화를 약속하지 않음.

2027 ON27-BASE의 M1~M9 최대 9개월은 기존 사이트의 상대 일정 제안이며 이 컨셉의 확정 착수일·납기를 뜻하지 않음.

## 책임·검증·예외

진단을 별도 계약과 구축의 사전 공수로 두 번 계상하지 않음. 관심 표명을 발주 약속으로 보지 않음.

업무 소관자가 정답·승인·이의처리·인수를 맡고, 정보화·데이터 담당은 권한·원천·운영을 확인. 공급자는 추가분 설계·연계·시험·복구·운영 인계의 책임과 범위를 명시. 구매·예산·계약 권한은 실제 기관 절차로 확인.

수요·자료권리·검수 책임이 없거나 기존 기능으로 충분하면 보류·축소. 중요 오류·권한 위반·복구 불가가 확인되면 해당 적용을 중단하고 수동 경로로 인계. 비용은 추가 분석·정비·개발·시험·운영의 인정 공수와 직접비로 산정하며 공통비 1회, 기존 의무·R&D·운영비의 중복 계상은 제외.
