사전기획·설계안 v1.0 · 2026-09-22 · 공고 미매핑 · 운영 시스템이 아닌 검토자료

  • 사업목적 → 업무성과 → 기능·비기능 요구 → 검수 증거 → 공수 항목 순으로 역설계했음.
  • 다음 문구는 공고·발주기관 확정 전 초안임. CCK의 내부 제안 설계는 NOA 기반으로 설명하되, 발주 RFP는 필요한 상호운용성·성능·결과를 규정함.

Given / When / Then 검수 사례

  • Given: 원문·판본·대상키가 일치하고 권한이 있는 사건. When: 이동 목적·제약 구조화 수행. Then: 이용건수와 별도로 목적·미충족 이유·미이용자를 기록.

  • Given: 계획 v1 승인. When: 수요 부족보다 승하차 보조 부족이 주원인이라는 근거가 나오면 배차 확대 중심안에서 보조·접근성 대안으로 변경. Then: 영향받는 후속 실행에서 기존 승인 토큰의 재사용을 차단하고 재검토를 요청하고 변경한 과업·근거를 명시. 새 판본 승인 전 실행 0건.

  • Given: 같은 execution_id의 응답 유실. When: 담당자가 다시 실행 시도. Then: 쓰기 재요청을 차단하고 결과 조회 경로로 전환. 대사되지 않은 성공 표시 0건.

  • Given: 일부 자료 또는 전문 판단이 없음. When: 완료 요청. Then: 미확인·후속 책임을 노출하고 공식 판단/국민 편익 완료로 잘못 종결하지 않음.

  • 비용 소유 열은 주 구현·검증 작업을 표시함.

  • 화면 구성(W03)과 해당 처 전문검수(W06)는 보조 작업이며 원장 supporting_wbs에 연결했음.

  • 공통 권한·실행 통제는 CORE-W05에서 한 번 구현하고 처별로 같은 엔진을 재개발하지 않음.

  • ‘0건’은 고정된 필수 안전 시험세트에서의 허용 오류 기준(제안)이다.

  • 실제 모든 환경에서 오류가 없다는 보장이나 실적이 아님. 40사건은 공수 추정을 위한 시험자료 구성 가정이며 통계적 효과 입증에 충분한 표본으로 간주하지 않음.

RFP 분류·산출물

분류 작성·납품할 범위 검수 증거
SFR 기능 필수 이동의 미충족을 줄이는 정책 실행의 8개 요구 사건 입력·계획변경·승인·공식 결과 비교 기록
SIR 연계 PS-IF-01/02 및 공통 도구계약 스키마·오류·중복·권한·판본 계약시험
DAR 데이터 원자료 계보·판본·접근범위·정정 마이그레이션 대사·접근 거부 시험
SER 보안 권한·프롬프트주입·민감정보·실행분리 금지 도구·타부서 자료 유출 차단시험
PER 성능 기존 서버/모델/동시사용 조건 명시 후 목표 확정 대표 사건 지연 p50/p95·큐·메모리 측정
TER/QUR 품질 공통 필수 안전세트 + 처별 전문가 정답·반례 독립 검수결과·결함조치·회귀 기록
PMR/PSR 관리·지원 일정·형상·교육·장애·인수·지원범위 운영자 시나리오·복구·인수 확인
  • 정형 수치와 현업 성과는 사전 기준선을 확보한 뒤 목표값·기간·책임자를 확정함.
  • 성능/효과 목표가 미정인 상태로 발주용 완성 RFP라고 표시하지 않음.
  • 인력 MM은 별도 내부 수행계획으로 관리하며 FP/SLA RFP의 필수 인원 조건으로 옮기지 않음.
  • 관련 근거의 열람판과 적용 한계는 공통 요구 참조.

공식 기능점수 산정으로 전환할 입력

  • 측정 경계: NOA 추가 기능과 기존 업무시스템의 경계, 기존 기능 변경/신규 구분, 사용자 인지 기능 확인.
  • 식별 후보: 사건/근거 접수(EI 후보), 상태·근거 조회(EQ 후보), 계획·대사결과 제공(EO 후보), 사건·계획 이력(ILF 후보), 기존 기준·공식 결과 참조(EIF 후보).
  • 이 분류는 후보이며 확정 FP가 아님. 실제 DET/FTR/RET·초등프로세스 독립성·중복 여부를 확인해야 함. 화면 수·문서 수를 기능점수로 바꾸지 않음.
  • 공통 CORE 기능은 공통 경계에서 한 번 산정함. FP 대가와 MM 참고치에 포함된 분석·설계·PM·시험을 다시 더하지 않음.
