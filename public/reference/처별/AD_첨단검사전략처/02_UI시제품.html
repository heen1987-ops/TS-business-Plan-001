제안 화면 · 가상 사건 · 읽기 전용

복합 진단불능의 검증과 현장 해결

통신 성공 응답은 있으나 필요한 진단항목 결과가 없는 가상 사건

사건·근거

  • vehicle_config / ecu_ref / software_version
  • protocol_version / session_id / 원천 응답
  • 지원조건 / 검사환경 / 미확인 사유
  • 전문 검증결과 / 적용판본 / 현장 재현

확인계획·업무 진행

  • 차량·프로그램·규격·세션의 적용조건 확인
  • 통신 성공·미응답·정상·고장 판단의 근거 분리
  • 승인된 자료조회·오프라인 대사 후 전문확인 인계
  • 검증된 기술의 현장 재현과 잔여 한계 확인

결과·남은 사항

  • 대상 판본·조건에서 확인한 진단범위와 한계가 전문 검증 및 현장 재현에 연결
  • 무응답을 정상 또는 고장으로 확정하지 않고 지원범위와 미확인 상태를 표시
  • 최종 판단·원천 결과·조회시점 표시

사용자 흐름

  1. 허용된 사건과 대상·판본을 확인함.
  2. NOA가 필요한 확인질문·자료·선행조건을 구성하고 담당자가 중요한 전문쟁점을 검토함.
  3. 승인된 조회·분석의 반환 결과와 미확인 사유를 확인함.
  4. 지원 판본 불일치가 확인되면 고장 추정을 중단하고 적용조건·전문 검증계획을 변경함.
  5. 대상 판본·조건에서 확인한 진단범위와 한계가 전문 검증 및 현장 재현에 연결함.

상태와 예외

상태 보여줄 내용 후속 처리
진행·로딩 실제 수행 중인 과업과 마지막 확인시점 완료로 오인하지 않도록 대기 사유 제공
자료 없음·부분 성공 결손 항목·조회 실패 원천·영향 범위 미확인 표시 후 보완/담당자 인계
권한 없음 허용된 사건명과 접근 거부 사유 자료 본문·요약·로그 노출 차단
시간초과·오프라인 실행 시도와 결과 미확인 분리 조회·대사 경로로 복구; 쓰기 자동 반복 금지
보완·판단 대기 무응답을 정상 또는 고장으로 확정하지 않고 지원범위와 미확인 상태를 표시 원문·미결 과업·책임자·기한 유지
완료 대상 판본·조건에서 확인한 진단범위와 한계가 전문 검증 및 현장 재현에 연결 정정·새 사실은 이력 보존 후 재검토

사용자·권한·표시 원칙

  • 전문검토 의견과 국민에게 제공할 행동 안내는 권한별로 구분함.

  • 실제 운영에서 등록·발송·공식 변경은 별도 권한·승인 경로를 적용함.

  • 이 제안 화면은 읽기 전용이므로 승인·실행 버튼을 만들지 않았음.

  • 화면 순서는 사건 → 근거 → 계획 → 결과이며 키보드 순서도 같음.

  • 색상만으로 상태를 구분하지 않음.

  • 작은 화면에서는 세 열을 세로로 배치하며 표는 개별 가로 스크롤을 제공함.

  • 공식 원문은 기존 시스템에서 확인하고 개인정보 원값은 필요한 역할에만 표시함.

화면 수용기준

  • 항목별 원문·판본·결손·공식 상태를 식별할 수 있고, 동일성 오류나 부분 완료가 전체 완료로 표시되지 않아야 함.
  • 화면과 데이터 필드는 차량–ECU–프로그램–진단 세션 단위로 함께 검수함.
  • 접근성 목표는 WCAG 2.2 AA이며 인증·전수 실사용 평가는 미수행임.
