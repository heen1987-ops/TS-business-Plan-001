사전기획·설계안 v1.0 · 2026-09-22 · 공고 미매핑 · 운영 시스템이 아닌 검토자료

ERP의 첫 적용: 전표 초안 등록

  • 비용 증빙 확인 → 규칙 검산 → 전표 초안 → 회계 권한자 확인 → 유효 승인·권한 재확인 → ERP DRAFT 등록 → 같은 execution_id의 record_id/필드/합계/판본 재조회 → 일치 여부 대사.

  • 재정회계·예산 관련 실무자가 협업해야 하며 실제 담당부서·전결은 아직 확인하지 않았음.

  • 실행요청에는 work_id, execution_id, idempotency_key, target_system/action, target_record, fields/values/units, evidence_bundle, approval_ref, actor_scope, expected_version, preconditions, expected_result를 포함함.

  • 합계·단위·계정 허용 여부는 검증된 규칙으로 검사함.

  • 지급·계좌 변경·마감·취소를 자동 실행하지 않음.

개인 작업공간에서 조직업무로의 연결

  • 개인 문서·메모·대화는 개인 권한으로 보관 → 사용자가 제출 대상과 판본 선택 → 제출받을 조직·목적·범위 확인 → 선택본만 조직 사건에 연결 → 공식 지식 편입은 별도 검수.
  • 제출하지 않은 자료는 검색·요약·로그·학습 경로로 조직에 노출하지 않음.

RFP 역설계 순서

  1. 국민·기관 결과와 현재 문제를 확인함.
  2. 대표 업무·완료조건·권한·자료경계를 정함.
  3. 재사용·추가·제외 범위와 SFR/SIR/DAR/SER/PER/TER/QUR를 연결함.
  4. 각 요구에 화면·논리 API·산출물·검수 사례·비용 소유를 부여함.
  5. FP/투입공수/견적의 적용 근거를 선정하고 동일 작업의 이중계상을 제거함.
  6. 목표값·라이선스·외부연계·법령 적용판이 확정되면 발주용 문구로 전환함.
  • RFP는 특정 제품명 강제보다 기구축 플랫폼과의 연동·업무 결과·보안·성능을 중심으로 작성함.
  • 공급사 내부의 NOA 구현계획과 발주기관의 경쟁 규격은 목적이 다름.

비용·인력의 사용 범위

  • 역할·MM·월별 FTE는 내부 사전 수행계획임.

  • 확인한 관리감독지침 2023년 시행판 제11조제3항은 FP/SLA 방식 RFP의 투입인력 수·인적사항·기간 등 요구를 제한함.

  • 이번 열람판을 2026년 현행판이라고 확정하지 않음.

  • 실제 발주 시 현행 조문·사업유형을 다시 확인함.

  • 모든 규모에서 문제정의·요구·설계·개발·시험·인수의 기본 흐름을 유지함.

  • 예산이 작다는 이유로 필수 과정을 생략하지 않음.

  • 감리·영향평가·심의 등은 규모뿐 아니라 기관·사업유형·적용 규정에 따라 따로 판정함.

승인·완료 상태의 해석

  • 근거가 바뀌었을 때 차단하는 것은 영향받는 후속 실행에서 기존 승인 토큰을 재사용하는 행위다.
  • 공식 협약·검사판정·종결의 원기록을 AI가 취소하거나 효력을 변경하지 않음.
  • 공식 효력·정정은 권한자가 판단함.
  • 여러 부서가 같은 사건의 해결에 기여해도 해당 국민 편익·재방문 감소를 각각 중복 합산하지 않음.
