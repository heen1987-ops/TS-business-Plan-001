제품 재사용 검증과 공수·대가 전환

제품 재사용 가능성은 요구사항별로 판단하고, 공통 25 M/M을 일괄 신규 개발비 또는 일괄 절감 대상으로 처리하지 않음. 실제 검증 결과에 따라 재사용·설정·연계·차이 개발·시험·인수를 다시 견적함.

이 문서는 검증 설계와 재견적 기준임. 제품 실행시험 0건 · 승인된 절감 M/M 없음 · 확정 가격 없음. 기존 산정값은 설계 가정으로 유지함.

1. 요구사항 → 제품 → 검수 → WBS

기존 요구 기능 재사용 후보 검수 시나리오 WBS
CORE-SFR-001 목표·완료조건·과업 상태 PR-02 RV-01 CORE-W04
CORE-SFR-002 근거 계보·권한·판본 PR-02, PR-07 RV-02 CORE-W03

  • 제품 ID는 재사용 근거 페이지의 PR-01~07에 대응함.
  • 요구사항 13개는 기존 공통/선택 ERP 원장의 ID를 유지했으며 신규 요구로 중복 집계하지 않았음.

2. 제품 검증 시나리오 — 아직 실행하지 않음

  • 가짜 사건·가짜 개인자료와 승인된 테스트 도구를 사용함.
  • 실제 TS 등록/발송/결제/지급을 수행하는 시험이 아님.
  • 각 항목은 재현용 시작 상태, 조작, 기대 결과, 증빙, 책임 역할을 지정했음.

RV-01 · 목표 완료조건

  • 요구 / WBS: CORE-SFR-001 / CORE-W04
  • Given: 검토서만 생성된 사건 / 필수 후속조치 1개 미이행
  • When: 에이전트가 완료 처리를 요청
  • Then: 보고서는 생성됨으로 기록하되 사건은 미완료; 누락 조치와 담당자 표시
  • 남길 증거: DB 상태·계획 로그·화면·누락 조건
  • 검토 역할: 업무분석가+현업
  • 현재 상태: 미실행 — 제품 build·실제 결과·판정은 확보 후 기록

3. 제품 승인 기준과 판정 경로

  1. 같은 버전 확인: 소스 commit/설치 build·사용권·의존성·설정·모델·TS 서버 사양을 하나의 evidence manifest로 연결.
  2. 동작 검증: 공통 13개와 적용 처 시나리오를 실행. 법정 판단은 현업 권한자가 맡고 자동실행은 사전 허용 도구·행위에 한정.
  3. 차이 명세: 통과는 재사용, 부분 충족은 설정/확장, 실패는 수정/대체, 증거 없음은 미확인으로 구분. 미확인=신규 개발 확정도, 재사용 확정도 아님.
  4. 운영 변화 검증: 현행 SI 대조 경로와 같은 사건 조건에서 비교. 계획 수정·예외 대응·조치 해소·후속 편익을 확인하고 생성 문서 수만으로 AX 효과를 평가하지 않음.
  5. 재견적: 구현 재사용분과 TS 추가 작업을 인력·산출물·소유권으로 연결. 실제 시험 전 자동 공수 감액 금지.
  • 승인/권한 우회, 중복 쓰기, 근거 유출은 제시된 시험셋에서 0건을 수용기준으로 제안함.
  • 이 기준은 모든 상황의 무결함 보증이 아님.
  • 처리시간·정확도 목표는 TS 서버/모델·데이터·동시성 실측 후 합의하며 임의 숫자를 넣지 않음.

6. 처별 적용 순서와 구매/개발 경계

  1. 모빌리티연구처의 대표 사건으로 로컬 모델·근거 판본·승인·unknown 대사까지 연결된 수직 흐름을 먼저 검증함. 엔진 데모와 공식 업무처리 적합성을 구분함.
  2. 교통안전처처럼 후속조치의 실제 해소가 중요한 다른 유형으로 공통성이 유지되는지 확인함. 결과를 보고 공통/처별 경계를 조정함.
  3. 다른 처는 도구·지식·예외·평가셋 증분으로 이관함. 공통 회귀검증은 묶되 해당 처의 법정업무·원자료·현업 검수는 생략하지 않음.
  4. ERP 초안 등록은 선택 과업, DRT 전국 운영/예산배분은 별도 사업 경계임. 현 단계 8개 대표 서비스 비용과 섞지 않음.
  • 이는 설계상 권고 순서이며 예산·계약·현업 참여가 확정된 수행 일정은 아님.
  • 소규모 사업도 요구·설계·개발·검증·인수 절차를 유지하고 기능/데이터/연계 범위를 조정함.
