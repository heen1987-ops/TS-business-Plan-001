K009. 적용기준 버전대장

09 / 92 · 원문 작업 W02.04 · 독립 컨셉 상세안

아홉 번째 컨셉의 결과물은 **「기준 버전·유효기간 대장」**임. TS 자료관리 책임자와 현업 담당자가 2027년 AX 적용을 준비하면서, 기준의 현행본·과거본·변경문서를 실제 적용기간과 연결하고, 수집시점과 효력시점의 혼동을 줄이는 항목임.

  • 아래 등록항목·대조방법·사례는 원문 K009를 구체화한 설계 제안임.
  • 실제 TS 기준의 최신본이나 법령·승인문서의 효력을 확인한 결과는 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 가장 최근에 받은 문서와 적용해야 할 기준은 다름

K008이 원문을 변환하면서 내용이 보존됐는지 확인했다면, K009는 그 원문의 어느 버전이 어떤 대상·기간에 적용되는지에 관한 근거를 정리함.

  • 예를 들어 7월에 수집한 개정 기준의 적용시작일이 6월일 수 있고, 이미 확보한 새 기준의 적용시작일이 아직 도래하지 않았을 수도 있음.

  • 이는 가능성을 설명하는 예시이며, 실제 적용시점은 해당 원문으로 확인해야 함.

  • 파일 정렬 순서가 기준의 효력을 결정하지는 않음.

  • 따라서 다음 세 정보를 구분함.

구분 기록할 내용 혼동하지 않을 사항
자료 확보·등록 언제 어떤 문서·버전을 수집했는가? 수집일을 시행일로 사용하지 않음
기준의 효력·적용범위 어떤 대상·항목·기간에 적용된다는 근거가 있는가? 최신 등록본을 모든 사건의 적용본으로 확정하지 않음
실제 업무의 참조 이력 기존 검토기록에서 어느 기준·버전을 사용했는가? 기준대장이 바뀌었다고 과거 참조기록을 덮어쓰지 않음
  • K009의 중심은 두 번째 항목임.
  • 첫 번째 정보와 연결하고, 개별 업무에서 참조할 수 있도록 근거를 남깁니다.

핵심 질문은 다음과 같습니다.

“이 기준은 어느 발행원문의 어떤 버전이며, 어느 대상·항목에 언제부터 언제까지 적용된다는 근거가 있는가?”

대장에 기준을 등록하는 것과 개별 사건에 적용할 기준을 최종 확정하는 것은 별도임. K009를 자동 법령해석이나 과거 사건 재판정 기능으로 확대하지 않음.

2. 무엇을 구분할 것인가: 발행·승인·시행·수집 시점

  • 원문의 수행내용은 **“시행/승인 시점과 수집시점을 구분하고 적용기간이 겹치는 항목을 확인”**하는 것임.
  • 이를 다음 날짜 항목으로 구체화했음.
시점 구체적으로 기록할 내용 피해야 할 처리
① 발행·개정 문서일 원문에 표시된 작성·발행·개정일과 날짜의 종류 날짜를 발견했다는 이유로 시행일에 입력
② 승인 시점 승인문서의 승인일·대상·범위 승인일과 적용시작일이 항상 같다고 간주
③ 시행·적용시작 적용이 시작된다고 명시된 날짜·시각·발생조건 수집일이나 등록일로 빈 값을 보충
④ 적용종료 종료일 또는 종료조건과 그 근거 새 문서가 들어왔다는 이유로 구버전 종료일 확정
⑤ 수집·등록 시점 실제 원문 확보일과 내부 등록일 확보가 늦었다고 효력시점도 늦춰 기록
⑥ 확인 시점 누가 언제 어떤 근거로 적용기간을 확인했는가? 마지막 확인일 이후의 변경까지 확인한 것으로 표시
  • 이 여섯 항목은 상세 등록을 위한 제안임.
  • 모든 원문에 같은 종류의 날짜가 있다고 가정하지 않으며, 확인되지 않은 값은 그대로 미확인으로 남깁니다.

적용종료가 비어 있으면 의미부터 구분

다음 세 상태는 다르게 기록함.

명시된 종료일 없음: 확인한 원문에 종료일이 적혀 있지 않은 상태.

종료조건 존재: 특정 변경·사건·조건에 따라 종료된다는 문구가 있는 상태.

종료시점 미확인: 필요한 원문이나 관계를 확인하지 못한 상태.

  • 모두 날짜 칸은 비어 보일 수 있지만, 의미와 후속 작업은 다릅니다.

  • 공란을 무기한 적용이나 임의의 먼 미래 날짜로 바꾸지 않음.

  • 명시된 종료일이 없다는 경우에도 어떤 원문을 어느 시점에 확인했는지 남깁니다.

  • 미래에도 계속 적용된다는 보증으로 사용하지 않음.

경계일과 적용조건은 원문 표현을 보존

원문에 ‘6월 30일까지’, ‘7월 1일부터’, ‘승인된 대상부터’, ‘기존 대상 제외’라고 적혀 있다면 그 표현과 위치를 기록함.

  • 날짜의 포함·제외, 기준시각, 대상 구분이 불명확하면 확인사항으로 남깁니다.
  • 원문에 없는 경과규정이나 예외를 작성자가 추가해 기간을 맞추지 않음.

3. 기준 버전·유효기간 대장에 무엇을 넣을 것인가

  • 원문의 입력자료는 기준 현행본·과거본·승인변경문서임.
  • 최신 파일만 받는 방식이 아니라, 필요한 적용기간을 설명할 수 있는 원문과 변경관계를 대조함.

상세 등록 단위는 다음과 같이 제안함.

기준 ID × 원문 버전 × 대상·항목 범위 × 적용구간

  • 한 문서의 모든 항목이 같은 대상·시점에 적용된다고 확인되면 같은 범위로 기록할 수 있음.
  • 반대로 항목이나 대상에 따라 적용기간이 다르면 근거에 따라 행을 나눕니다.

확인·쟁점 확인자·역할·확인일·미확인·상충 사유·요청자료 무엇을 확인했고 무엇이 남았는가?

원천 버전과 대장용 임시표시는 분리

  • 발행원문에 버전 번호가 없으면 연결을 위한 임시 등록표시를 둘 수 있음.
  • 다만 공식 문서번호·원천 버전과 대장용 임시표시를 별도로 기록함.

임시로 v1, v2를 붙였다는 이유만으로 공식 개정 순서를 확인한 것으로 처리하지 않음.

변경문서와 본문을 함께 연결

변경문서에 새로운 적용일이 적혀 있지만 본문 파일은 종전 날짜를 표시하는 경우, 두 자료를 연결하고 관계를 확인함.

  • 어느 문서의 어느 항목이 변경내용과 효력을 설명하는지 남기는 것임.

  • 하나의 파일만 선택해 나머지를 삭제하거나, 여러 문서를 합성한 내용을 공식 발행본으로 취급하지 않음.

  • 부분 변경이라면 실제 영향을 받는 항목을 구분함.

  • 확인되지 않은 다른 항목의 적용기간까지 일괄 변경하지 않음.

등록 완료와 기간 확인 완료를 분리

대장에 값을 입력한 상태와 원문 근거를 확인한 상태를 구분하도록 제안함.

  • 예를 들어 **‘기간 근거 확인’, ‘일부 미확인’, ‘상충 확인 중’**으로 기록할 수 있음.
  • 이는 상세안의 상태 예시이며 실제 TS 상태코드가 아닙니다.

‘현행본’으로 표시할 때에도 어떤 대상·항목에 대해 어느 기준일 현재 확인했는지 함께 남깁니다.

  • 기준·문서·날짜·확인 상태는 모두 가정이며 실제 TS 규정이나 법령이 아닙니다.

4-1. 사례의 전제

  • 가상 검사기준 A의 **‘확인항목 1’**을 대상으로 함.
  • 이 항목에서 적용기준을 구분하는 날짜는 점검 수행일이라고 별도 근거로 확인됐다고 가정함.

가상 승인변경문서 D02에는 다음 내용이 명시되어 있다고 가정함.

같은 대상의 확인항목 1은 2027년 6월 30일까지 v1, 7월 1일부터 v2를 적용함.

  • 이 사례 범위에는 별도 예외가 없음을 확인했다고 가정함.
  • 실제 업무에서도 항상 점검일이나 접수일로 적용본을 나눈다는 뜻은 아닙니다.

나중에 효력을 확인한 사실과 과거에 무엇을 알고 사용했는지는 구분해야 함.

  • 과거 검토기록이 v1을 사용했다면 그 참조 이력은 보존함.
  • 이후 확인된 v2와의 차이는 별도 기록하고 필요한 확인사항을 인계함. K009에서 과거 결론을 자동으로 수정하거나 무효화하지 않음.

가장 최근 파일이 ‘변경안’인 경우

가상 v3 파일을 7월 9일에 받았더라도 승인·효력 정보가 확인되지 않은 변경안이라면, 최신 파일이라는 이유로 현행 적용본으로 등록하지 않음.

원문의 제한은 **“변경 효력이 불명확하면 임의 최신본 적용 금지”**임.

5. 기간이 겹치거나 비어 있을 때의 처리

  • 원문은 적용기간이 겹치는 항목을 확인하도록 함.
  • 겹침이 있다는 이유만으로 한 버전을 삭제하거나 기준의 우선순위를 자동 판정하라는 뜻으로 확대하지 않음.
상황 대장에 남길 내용 추가 확인·제한
같은 항목·대상에 두 기간이 겹침 두 기준·버전·기간·적용범위와 근거 위치 별도 조건·예외·변경관계 확인. 근거 없이 최신본 선택 금지
날짜는 같지만 적용대상이 다름 대상별 적용범위와 구분 근거 정상적인 병존인지 확인. 날짜 중복만으로 오류 확정 금지
구버전 종료와 신버전 시작 사이에 공백 빈 구간과 미확인 문서·조건 앞뒤 기간을 임의 연장해 공백을 채우지 않음

일부 항목만 변경됨 변경항목·유지항목과 각각의 근거 문서 전체를 동일 시점에 대체 처리하지 않음
본문과 변경문서 내용이 상충 상충 문구·문서 버전·확인 요청 AI나 작성자가 우선순위·소급범위를 임의 결정하지 않음
과거본·변경문서가 미확보 필요한 버전·대상기간·자료 소관 과거 근거를 현행본으로 대신 채우지 않음
날짜·적용문구가 판독되지 않음 불명 영역·원문 위치·품질진단 참조 추정 날짜 없이 원자료 확인 또는 보류

날짜 중복만으로 충돌을 확정하지 않음

예를 들어 변경문서에서 ‘신규 대상’과 ‘기존 대상’을 구분한다면, 같은 날짜에 서로 다른 기준이 적용되는 구조일 수 있음.

  • 반대로 같은 대상에 서로 다른 조건이 겹치는데 구분 근거가 없다면 확인이 필요함.
  • 대상·항목·기간을 함께 대조해야 하는 이유임.

이 설명은 가상 구조이며, 실제 TS 기준에 특정 경과규정이 존재한다거나 그 의미를 확정한 것은 아닙니다.

과거본 보존과 무제한 이용은 다름

  • 과거 기준은 발행원문 위치와 적용기간의 관계를 남깁니다.

  • 그렇다고 모든 과거 자료를 무기한 보관하거나 모든 사용자에게 열람시키는 것은 아닙니다.

  • K009는 버전과 기간의 관계를 정리함.

  • 실제 보관·열람 범위는 해당 자료의 이용조건과 별도로 연결해 확인함.

6. 수행 순서와 K009의 독립 범위

수행은 대상·원문 확인 → 날짜 구분 → 버전·변경 연결 → 기간 대조 → 확인·인계 순서로 제안함.

순서 구체적인 수행내용 남길 결과
1. 대상·원문 확인 허용된 현행본·과거본·승인변경문서와 필요한 항목·기간 식별 대상 기준·원문 목록
2. 날짜 종류 분리 발행·승인·시행·종료 문구와 실제 수집·등록일 구분 날짜–원문 위치 대응
3. 버전·변경 연결 이전·이후 버전, 변경대상·항목·예외 연결 버전·변경관계표
4. 기간 대조 동일 대상·항목의 겹침·공백·미확인 범위 확인 기간 대조결과와 추가 확인목록
5. 확인·인계 확인자·근거·기준일과 남은 조건 기록 기준 버전·유효기간 대장과 제한사항
  • AI를 활용한다면 허용된 원문에서 날짜·변경문구·관계의 후보를 제시하는 수준으로 검토할 수 있음.
  • 확정된 날짜의 겹침은 명시적인 비교로 처리하고, 불명확한 변경 효력이나 예외는 해당 확인 주체의 판단사항으로 남깁니다.

AI 사용 자체는 K009의 필수 완료조건이 아닙니다. 기존 목록과 원문 대조로 충분하다면 별도 모델이나 검색시스템을 추가하지 않아도 됩니다.

이번 컨셉에서 끝낼 일

기준 ID·버전·발행원문, 시행·승인·수집시점, 적용시작·종료, 변경관계, 기간 겹침·공백·미확인 사유와 근거를 정리함.

별도로 남길 일

개별 사건의 적용본 자동 선정, 기준변경 영향 자동분석, 과거 검토 재실행·결론 수정, 신규 법령 수집 플랫폼, 법률 해석·기준 효력의 독자 판정, 원장 쓰기, 다른 컨셉과의 통합은 포함하지 않음.

K007의 식별정보와 K008의 판독결과는 필요한 범위에서 참조하되, 이전 상세안이 작성됐다는 이유로 실제 확인까지 완료된 것으로 승계하지 않음.

  • 원문의 완료기준은 **“기준 ID·버전·적용시작/종료·발행원문을 추적”**하는 것임.

8. 바로 사용할 보고서 문안

AX 적용 대상 기준의 현행본·과거본·승인변경문서를 기준 ID·버전·발행원문과 연결하고, 시행·승인 시점과 수집시점 및 적용시작·종료를 구분한 기준 버전·유효기간 대장 작성 필요. 항목·대상별 적용범위와 변경관계를 확인하여 기간의 겹침·공백·미확인 사항을 근거와 함께 기록. 변경 효력이 불명확한 경우 임의 최신본 적용을 금지하고 소관 주체의 확인사항으로 관리하며, 대장 등록·기간 확인과 개별 사건의 적용 판단·과거 결과 변경을 별도 범위로 구분 추진.

제공한 MD에는 대상·등록범위 확인서, 기준 버전·유효기간 개별 카드와 목록, 변경·발행원문 관계표, 기간 겹침·공백 대조표, 미확인·정정·재확인 기록, 결과·활용한계 확인서를 포함했음.

K009의 최종 결과는 ‘최신 기준을 보유하고 있다’는 목록이 아니라, 어떤 기준의 어느 버전이 언제부터 언제까지 적용된다는 근거와 아직 확인하지 못한 부분을 발행원문까지 연결해 설명하는 대장임.
