K008. 원문 변환 품질 진단

08 / 92 · 원문 작업 W02.03 · 독립 컨셉 상세안

  • 여덟 번째 컨셉의 결과물은 **「필드별 변환 품질·실패 진단표」**임. TS 자료관리 책임자와 수행 데이터 담당자가 2027년 AX 적용을 준비하면서, 문서를 변환한 뒤에도 본문·표·쪽·위치가 보존되는지 확인하고, 읽지 못한 부분과 활용 한계를 기록하는 항목임.

  • 원문도 읽히지 않은 값을 추정으로 채우지 않는 것을 목적으로 제시함.

  • 아래 대조항목·상태·사례는 원문 K008을 구체화한 설계 제안임.

  • 실제 TS 표본을 변환하거나 품질을 측정한 결과는 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 파일 변환 완료와 내용 보존은 다름

K007이 어느 사건의 어떤 문서·버전인지를 연결했다면, K008은 그 문서를 변환하면서 내용과 근거 위치가 달라지지 않았는지 확인함.

  • 가령 원문에 ‘점검 미실시’라고 적혀 있는데 변환 결과가 ‘점검 실시’라면, 문장은 자연스럽게 읽히지만 의미는 반대임.
  • 파일이 열리고 문장이 생성됐다는 사실만으로 정상 변환이라고 처리해서는 안 됩니다.

따라서 다음 세 가지 판단을 구분함.

변환 실행: 파일을 처리해 출력물이 생성됐는가?

원문 대조: 출력된 값·문장·표의 관계·근거 위치가 원문과 맞는가?

업무 판단: 그 자료로 실제 이행이나 적합 여부를 판단할 수 있는가?

K008은 두 번째 판단을 중심으로 하는 진단임. 문서에 적힌 사실의 진실성이나 안전기준 충족 여부까지 확정하는 단계가 아닙니다.

핵심 질문은 다음과 같습니다.

“이 값과 문장은 원문의 어디에서 읽혔으며, 대상·기간·단위·표의 행과 열·예외문구까지 같은 관계로 보존됐는가?”

  • 반대로 원문 자체에 잘못된 날짜나 상충 내용이 적혀 있다면, 변환 결과를 상식에 맞게 조용히 고치지 않음.
  • 원문을 그대로 읽었는지와 원문의 내용이 타당한지는 별도 기록으로 남깁니다.

2. 무엇을 대조할 것인가: 본문·표·쪽·위치와 필수값

  • 원문의 입력은 PDF·HWP·표·스캔 등 허용 표본이며, 수행내용은 본문·표·쪽·좌표의 보존 여부를 대조하고 판독불가 영역을 따로 남기는 것임.
  • 다음은 이를 실제 확인 질문으로 구체화한 안임.
대조대상 구체적으로 확인할 내용 기록해야 할 문제의 예시
① 본문 제목·문장·항목 순서, 부정 표현, 조건·단서·각주 연결 ‘미실시’가 ‘실시’로 변환, 예외문구 누락, 다른 문단 혼입
② 표 행·열 제목, 병합된 제목의 적용범위, 항목–값–단위 관계 계획값을 실적값으로 연결, 다른 대상의 행 값 혼입
③ 필수값 선정 업무에 필요한 식별정보·일자·수치·단위 소수점·단위 누락, 날짜 오인식, 원문에 없는 값 생성
④ 쪽 원문 파일의 실제 쪽, 인쇄 쪽번호, 변환 결과와의 대응 앞표지 포함 여부 혼동, 쪽 누락, 다른 쪽을 근거로 연결
⑤ 위치 해당 원문 버전의 문단·표·셀·영역좌표와 출력 위치의 관계 문서는 맞지만 다른 표로 연결, 좌표 누락, 잘못된 기준면 적용

보존한다는 것이 같은 모양으로 복제한다는 뜻은 아님

본문을 구조화된 텍스트로 바꾸거나 표를 항목별 값으로 정리하더라도, 어떤 제목 아래의 문장인지, 어느 행·열의 값인지, 원문의 어디에서 확인할 수 있는지를 보존하도록 진단함.

  • 원문에 없는 ‘모든 글꼴·여백·페이지 배치를 동일하게 재현’하는 요구를 추가하지 않음.

  • 반대로 출력물의 모양이 깔끔하다는 이유로 내용 대조를 생략하지도 않음.

  • 출력물의 쪽 구성이 달라지는 방식을 사용한다면 원문 쪽과 출력 위치의 대응을 남깁니다.

  • 쪽 수가 같다는 사실만으로 내용이 보존됐다고 판단하지 않음.

필수 필드는 업무별로 확인

  • 문서번호·대상기간·검사일·실적값 등은 필수 필드의 후보 예시임.
  • 모든 TS 문서에 동일하게 적용되는 확정 필드가 아닙니다.

필요한 경우 필드를 다음과 같이 정의함.

대상 + 기간 + 항목 + 값 + 단위 + 적용조건

예를 들어 ‘28’이라는 숫자만 맞게 읽는 것으로 끝내지 않고, 어느 기간의 어떤 대상에 대한 실적 28명인지까지 대조하는 방식임.

쪽과 좌표의 기준도 기록

원문 파일의 실제 7쪽과 문서 하단에 인쇄된 ‘5쪽’이 다르다면 각각 기록함. HWP 등을 특정 화면이나 대조본으로 확인할 때도 원문 버전·대조본·쪽 기준을 남기는 안임.

  • 좌표는 어느 쪽·이미지를 기준으로 한 위치인지 함께 기록함.
  • 실제 좌표를 확보하지 못했으면 임의로 숫자를 만들지 않고, 위치정보 부족으로 남깁니다.

3. 진단표는 ‘필드 × 변환 실행’ 단위로 작성

진단 단위는 다음 조합으로 제안함.

문서 ID·원문 버전 × 변환 실행·결과 버전 × 필수 필드·원문 영역

  • 같은 원문을 다시 변환한 경우와 원문 자체가 개정된 경우를 구분하기 위한 구조임.
  • 변환 결과를 정정했다고 원문 버전까지 바꾸지는 않음.
기록묶음 구체적인 등록항목 확인하려는 사항
대상·범위 사건·문서 ID, 원문 버전, 허용 표본, 확인할 쪽·필드 무엇을 진단했는가?
실행·결과 변환 실행 ID, 처리방식·설정·시각, 변환본 위치·버전 어느 처리 결과에서 문제가 발생했는가?
원문 관찰 실제 읽히는 표기, 빈칸·마스킹·판독불가 여부 원자료의 상태는 무엇인가?
원문 위치 실제 파일쪽, 인쇄 쪽번호, 문단·표·행·열·좌표 같은 근거를 다시 찾아볼 수 있는가?
변환 판독결과 처음 반환된 값·문장·단위·연결 위치 도구가 실제로 무엇을 출력했는가?
대조·실패 일치·불일치·누락·판독불가·위치문제, 관찰 증상 무엇이 보존됐고 무엇이 달라졌는가?
보완·확인 재처리·원자료 요청·수동 확인, 정정 근거, 확인자·일자 문제를 어떻게 확인·보완했는가?

최초 출력과 담당자 정정값은 분리

가상 원문이 98.5%인데 최초 출력이 985%라면, 다음을 각각 기록함.

최초 출력: 985%

원문에서 확인한 값: 98.5%

정정 근거: 해당 문서·버전·쪽·표의 위치와 확인자.

  • 정정값을 최초 출력에 덮어써서 도구가 처음부터 정확하게 읽은 것처럼 보고하지 않도록 설계함.
  • 날짜·단위를 표준형으로 정리하는 경우에도 원문 표기와 정리된 값을 구분함.

실패 증상과 원인 가설도 분리

확인한 사실이 ‘세 번째 행의 실적값 누락’이라면 우선 그 증상을 기록함.

  • 원인이 확인되지 않았다면 **‘표 병합 처리 영향 가능성, 원인 미확인’**처럼 적습니다.
  • 원인을 모르더라도 문제 위치와 영향받는 필드는 남길 수 있지만, 추측한 원인을 확정하지는 않음.

표의 값이 모두 존재해도 정상 변환은 아닐 수 있음

가상 원문에 다음 표가 있다고 가정함.

항목 계획 실적
교육 인원 30명 28명

변환 결과에 ‘교육 인원 30명 28명’이 모두 들어 있어도, 어느 값이 계획이고 실적인지 구분되지 않으면 실적값을 확인했다고 처리하지 않음.

올바르게 대조할 단위는 다음과 같습니다.

교육 인원 → 실적 → 28명 → 해당 원문 표·행·열 위치

  • 원문 각주에 ‘실적은 추가 교육 제외’라는 단서가 있다면, 그 단서와 적용범위도 확인대상에 포함했는지 기록함.
  • 문서에 없는 설명을 추가하라는 뜻은 아닙니다.

일부 문제가 남아 있을 때의 결과 문안

다음 표현은 범위가 불명확함.

“문서 변환 완료, 날짜 및 수치 확인 완료.”

실제 확인 결과에 따라 다음처럼 작성하는 편이 적절함.

“선정 필드의 원문 대조 결과, 일자·수치·표 관계의 불일치와 판독불가 영역을 구분 기록. 해당 필드의 재처리 또는 원자료 확인이 필요하며, 미확인 결과는 정상 입력으로 확정하지 않음.”

  • 이 문안은 작성 예시임.
  • 이번에 실제 진단을 수행했다는 의미가 아닙니다.

5. 판독불가·빈칸·변환누락을 구분해 처리

  • 원문은 읽을 수 없는 값을 AI가 채워 넣지 않도록 제한함.
  • 이를 지키기 위해 실패 상태를 다음과 같이 구분하는 안임.
  • 상태명 자체는 상세설계 제안임.
대조상태 구분 기준 후속 처리안
대조 일치 확인한 값·문장·표 관계·위치가 원문에 부합 확인범위 기록. 업무 적합성까지 승인하지 않음
변환 불일치 원문은 읽히지만 출력값·문장·표 관계가 다름 해당 결과의 재처리·수동 확인과 사용 제한사항 검토
변환 누락 원문에 확인 가능한 내용이 있으나 출력에 없음 누락내용·원문 위치 기록 후 재확인
원문 판독불가 원문 자체에서 값을 확정할 수 없음 불명 영역과 원자료 재확인 요청 기록
위치 연결불가 출력값의 근거를 원문의 쪽·영역에서 재확인할 수 없음 위치정보 보완 전 추적확인 완료로 처리하지 않음
미검토 선정 대상이지만 원문 대조를 아직 수행하지 않음 미검토 범위·담당·확인계획 기록
  • 한 필드에서 값 불일치와 위치 오류가 함께 발생하면 각각 표시함.
  • 하나의 상태를 선택하느라 다른 문제를 감추지 않음.

원문 빈칸과 변환 누락은 다름

원문이 빈칸이면 ‘원문 빈칸 확인’, 원문에 값이 있는데 변환 결과에서 빠졌다면 **‘변환 누락’**임.

  • 빈칸이 그대로 보존됐는지와 업무상 필요한 값이 확보됐는지는 서로 다른 판단임.

  • 빈칸을 0, 정상, 해당없음, 이행완료로 바꾸지 않음.

  • 마스킹된 부분은 ‘마스킹 확인’, 필요한 쪽이 제공되지 않았다면 **‘원문 미제공’**으로 기록함.

  • 마스킹이나 열람제한을 우회해 값을 복원하는 행위는 포함하지 않음.

일부만 읽히면 그 범위까지만 기록

  • 날짜가 가상으로 2027.04.[판독불가]까지 확인된다면, 아는 부분과 불명 영역을 구분함.

  • 주변 문맥이나 제출 순서를 근거로 나머지 날짜를 채우지 않음.

  • 다른 자료에서 날짜를 확인할 수 있어도, 그것은 다른 자료에서 확인한 근거임.

  • 해당 원문이 정상적으로 변환된 결과로 바꾸어 기록하지 않음.

재처리와 수동 확인 후에도 이력을 남김

  • 다시 변환했으면 새로운 실행 결과와 기존 결과를 연결함.

  • 담당자가 원문에서 값을 확인했다면 수동 확인 근거를 남깁니다.

  • 재처리를 요청한 상태, 재처리가 끝난 상태, 새 결과를 원문과 대조한 상태는 구분함.

  • 재처리 버튼을 눌렀다는 이유로 오류 해소까지 완료한 것으로 기록하지 않음.

6. 수행 순서와 K008의 독립 범위

수행은 허용 표본·버전 고정 → 필수 필드·위치 기준 정의 → 변환 결과 확보 → 원문 대조 → 실패·보완 기록 → 확인·인계 순서로 제안함.

순서 구체적인 수행내용 남길 결과
1. 표본·조건 확인 허용된 문서·원문 버전·형식·쪽·필드를 특정 대상·범위표와 이용조건 참조
2. 대조기준 정의 필수 필드, 표 관계, 쪽·좌표 기준과 보류방법 확인 필드·위치 대조기준
3. 결과 확보 확인할 변환 실행과 출력물·설정·버전 기록 보정 전 결과와 실행정보
4. 원문 대조 본문·표·값·쪽·좌표를 원문과 비교 필드별 판독결과·위치·문제
5. 실패·보완 기록 원자료 한계와 변환 실패를 구분하고 확인 요청 실패사유·영향·후속 확인사항
6. 확인·인계 확인범위·잔여 문제·보완결과를 담당자가 확인 진단표와 자료 활용 한계
  • 기존에 허용된 변환 결과가 있다면 먼저 그 결과를 대조함.
  • 특정 인식 엔진을 새로 도입하거나 모든 문서를 같은 방식으로 재처리하는 것을 자동으로 전제하지 않음.

이번 컨셉에서 끝낼 일

필수 필드와 원문 위치의 대조, 본문·표 구조의 보존 확인, 판독불가·불일치·누락 기록, 보정 전후·재처리 결과 구분, 활용 한계와 후속 확인사항을 정리함.

별도 작업으로 남길 일

신규 문서변환 플랫폼·모델 구축, 전체 자료 일괄 이관, 원문 내용의 사실검증·안전 판정, 권한 부여, 모델 학습, 다른 컨셉과의 통합은 포함하지 않음.

  • 변환 도구가 원문을 제대로 읽었는지와 AI 답변이 정확한지, 실제 업무시간이 줄었는지는 다른 검증임.
  • 다른 사업의 답변 정확도 목표를 K008의 변환 합격기준으로 가져오지 않음.

7. 완료기준·역할·기간

  • 원문의 완료기준은 **“필수 필드별 판독결과·원문 위치·실패사유가 진단표에 존재”**하는 것임.
  • 모든 필드가 정상 변환돼야만 진단을 완료할 수 있다는 기준으로 바꾸지 않음.

  • 미검토 필드가 남아 있으면 그 범위를 표시함.

  • 실패 필드를 표본에서 빼고 정상 자료만 확인한 것처럼 보고하지 않음.

8. 바로 사용할 보고서 문안

AX 적용 대상의 허용 표본을 기준으로 문서 변환 전후의 본문·표·쪽·좌표와 필수 필드의 판독결과를 대조하고, 원문 위치·실패사유를 연결한 품질 진단표 작성 필요. 값뿐 아니라 행·열·단위·부정·예외문구의 관계를 확인하고, 원문 판독불가·빈칸·변환 누락·위치 연결불가를 구분하여 미확인 값을 AI가 임의로 채우지 않도록 관리. 보정 전 출력과 담당자 확인·재처리 결과를 분리하며, 진단기록 완료와 자료 품질 충족·업무 판단을 구분하여 활용 한계와 후속 확인사항 명시.

제공한 MD에는 대상·표본 확인서, 필수 필드 대조기준표, 필드별 진단 카드, 본문·표·쪽·위치 대조표, 실패·정정·재처리 이력표, 결과·활용한계 확인서를 포함했음.

K008의 최종 결과는 ‘변환 성공’이라고 표시된 파일 목록이 아니라, 필수값을 원문 어디에서 확인했고 어떤 부분은 읽지 못했으며 무엇을 보완해야 하는지를 설명하는 진단표임.
