K003. 기존 기능·계약 중복 진단

03 / 92 · 원문 작업 W01.03 · 독립 컨셉 상세안

세 번째 컨셉의 결과물은 **「기존 기능–신규 필요사항 대응표」**임. TS 현업·정보화·사업기획 담당자가 2027년 AX 과제를 검토할 때, 이미 충족된 기능을 다시 구축하지 않고 실제로 추가해야 할 작업만 구분하는 것이 목적임.

  • 아래 비교항목·판정방법·사례는 원문 K003을 구체화한 설계 제안임.
  • 실제 TS 계약·인수·운영자료를 대조해 중복 여부를 확정한 결과는 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 새 업무라고 모든 기능이 새로운 것은 아님

K003에서는 새로운 업무에 필요한 결과를 기존 기능으로 어디까지 처리할 수 있는지 확인함.

  • 예를 들어 철도 안전심사 지원을 새로 기획하더라도, 문서 검색·사용자 인증·자료 저장까지 모두 새로 만들어야 하는지는 별도 문제임.
  • 반대로 기존 플랫폼에 ‘승인 기능’이 있다는 이유만으로 실행증거 확인, 승인 대상 버전 연결, 자료 변경 후 재확인까지 모두 가능하다고 볼 수도 없습니다.

따라서 다음 세 가지를 구분함.

기능의 존재: 비슷한 기능이 명세나 시스템에 있는가?

업무요구 충족: 그 기능이 이번 업무의 입력·처리·결과·예외조건을 실제로 충족하는가?

적용·계약 조건: 해당 업무에 사용할 수 있으며, 필요한 추가 작업이 기존 계약의 어느 범위와 관계되는가?

핵심 질문은 다음과 같습니다.

“기존 기능으로 충족되는 부분은 무엇이고, 부족한 부분은 무엇이며, 그 판단을 어느 문서와 확인 결과로 설명할 수 있는가?”

‘기능이 있다’와 ‘이번 업무에 그대로 쓸 수 있다’를 같은 말로 취급하지 않는 것이 K003의 출발점임.

2. 무엇과 무엇을 비교할 것인가

  • 원문은 현행 기능별로 그대로 사용·설정변경·추가구현·확인불가를 구분하고 신규 과업에 대응하도록 제시함.
  • 이를 위해 비교 단위를 사업명이나 시스템명보다 작게 설정함.

비교 단위는 ‘신규 필요사항 한 건 × 대응하는 기존 기능 × 적용조건 × 확인 근거’임.

  • 예를 들어 ‘철도 AI’와 ‘기존 공통플랫폼’을 통째로 비교하지 않고, 심사자료 검색, 보완요청 양식 변경, 종결조건 확인, 승인 후 자료변경 감지처럼 구체적인 처리로 나누어 대조함.
  • 이는 K003 안의 비교행을 나누는 것이며, 새로운 컨셉을 추가하는 것은 아닙니다.
비교항목 구체적으로 확인할 내용 같은 기능으로 보기 전에 확인할 차이
업무목적·사용자 누가 어떤 업무결과를 얻으려는가? 일반 문서검색과 검사관의 증빙 검토는 목적이 다를 수 있음
입력자료 파일형식·대상·기간·식별자·버전 같은 PDF라도 필요한 표·항목·원문 위치가 다를 수 있음
처리내용 검색·대조·검토·승인·인계와 예외처리 검색 결과 제공과 기준 충족 여부의 검토 지원은 다름
출력·완료조건 초안·확정본·원장 반영·조치 종결 보고서 생성과 업무 완료는 다름
권한·운영조건 대상 자료·사용자·이용기간·자원·지원범위 기능이 동작해도 신규 업무 적용조건은 미확인일 수 있음
계약·인수 근거 관련 문서·항목·버전·인수범위·잔여사항 제안된 기능과 실제 인수한 기능을 구분해야 함

하나의 필요사항 중 일부만 충족된다면, 충족분과 부족분을 분리함. 일부가 부족하다는 이유로 전체를 신규 개발로 돌리거나, 일부가 있다는 이유로 전체를 재사용으로 처리하지 않음.

3. 네 가지 분류와 판단방법

  • 분류명은 원문의 그대로 사용·설정변경·추가구현·확인불가를 유지함.
  • 아래 판단조건은 이를 적용하기 위한 상세 제안임.
분류 기능 차이 관점의 판단조건 대응표에 남길 내용
① 그대로 사용·재사용 확인된 기존 기능이 해당 입력·처리·출력 요구를 기능 추가 없이 충족 재사용할 기능·버전·범위와 적용 전 확인조건
② 설정변경 기존에 제공되는 설정·양식·매핑 기능을 변경하면 요구 충족 가능 바꿀 설정, 변경 전후 차이, 확인할 결과
③ 추가구현 기존 기능과 명세를 대조한 결과 필요한 처리·연결·통제가 미충족 기존 충족분, 미충족분, 추가 작업의 최소 범위
④ 확인불가 자료 미확보·버전 불일치·상충 설명·작동 확인 부족으로 판단 불가 미확인 사항, 필요한 자료, 확인 담당과 재확인 조건

기능 분류와 계약 판단은 분리

추가구현이 필요하다는 사실이 곧 신규 예산을 편성해야 한다는 뜻은 아닙니다.

  • 현재 기능에는 부족하지만 기존 계약에서 이미 다루기로 한 범위일 수 있음.
  • 이 경우 기능 차이는 기록하되, 기존 이행범위와의 관계를 확인하기 전에 신규 비용으로 넘기지 않도록 설계함.

반대로 기능은 충족되더라도 새로운 업무의 이용권·지원기간·자원 할당이 미확인이라면 **‘기능 충족 / 적용조건 미확인’**으로 남깁니다.

이를 위해 대응표에는 다음 세 정보를 별도로 기록함.

관리 축 기록할 상태 예시 의미
기능 차이 그대로 사용·설정변경·추가구현·확인불가 필요한 기능과 현재 기능의 차이
계약범위 확인 포함 확인·미포함 확인·해석 보류·문서 미확보 해당 작업과 기존 계약의 관계
적용 가능성 적용조건 확인·조건부·미확인 실제 해당 업무·기간에 사용할 수 있는지

설정변경도 무조건 무상·즉시 적용은 아닙니다. 설정, 자료 등록, 적용검증, 교육 등에 어떤 작업이 필요한지 구분하되, 실제 금액과 수행 주체는 별도로 확인함.

4. 어떤 자료를 대조해야 하는가

  • 원문의 핵심 입력자료는 기능명세·인수자료·운영계약임.
  • 제안서와 발표자료는 비교할 후보를 찾는 데 활용하되, 실제 인수·운영 여부를 대신하는 근거로 사용하지 않음.
자료 확인할 내용 그 자료만으로 확정하지 않을 내용
기능명세·설계자료 지원 입력·처리·출력·예외·버전 실제 구현·배포·인수 완료
인수자료·시험결과 인수한 기능과 버전, 시험조건, 결과, 잔여사항 다른 업무·사용자·처리량에서도 동일하게 사용 가능
운영계약·관련 범위자료 수행대상·기간·지원·변경·운영 책임에 관한 내용 모든 추가 작업이 기존 계약에 포함되거나 제외된다는 일괄 판단
제안서·발표자료 제안 기능, 재사용 구조, 비교할 문구 위치 계약 반영·납품·실제 작동·사용권 확정
허용된 운영 시연·기록 확인 시점과 환경에서 동작한 범위 전체 기관·전체 조건·차년도 이용 가능성
자산·라이선스·이용조건 자료 이용 주체·업무범위·기간·제약 보유했다는 이유만으로 모든 업무에서 사용·수정 가능

  • 문서에는 최소한 자료명·버전·작성일·쪽·절·요구사항 ID·확인 문구·확인자·확인일을 연결하는 안임.

  • ‘계약서 참조’ 한 줄로 끝내지 않고, 어떤 부분을 대조했는지 남깁니다.

  • 문서끼리 내용이 다르면 각 문구와 버전을 병기함.

  • 본 컨셉에서 유리한 문서 하나를 선택하거나 계약문서의 효력을 임의로 판단하지 않음.

제공자료에서 바로 식별할 수 있는 대조 후보

  • 정성제안서 PDF 44쪽의 ‘사업 범위 3중 구조’ 도식에는 데이터 파이프라인, API Gateway·MCP 연계, AI 아키텍처 표준의 재사용·계승이 제시되어 있음. K003에서는 이를 신규 업무에 적용하기 전에 대조할 기존 기반 후보로 등록할 수 있음.

  • 다만 해당 문서만으로 현재 인수된 모듈·버전이나 2027년 가용성을 확정할 수는 없습니다.

  • 발표자료 PDF 11쪽의 ‘기능 구현 총괄’ 표에는 공통플랫폼 고도화, 자동차검사 Q&A, 상시감사지원, 보도자료 초안, 민원분석, 전세버스 AI와 내부·외부 데이터 파이프라인 등이 제시되어 있음.

  • 이는 이미 제안된 기능과 신규 필요사항의 중복 후보를 찾는 자료이며, 전체가 계약에 반영되거나 인수·운영 중이라는 증거는 아닙니다.

따라서 이번 자료 확인의 결과는 **‘재사용 확정’이 아니라 ‘대조 후보 식별’**임.

기존에 부족한 부분이라는 가정

승인 당시의 자료 버전 연결, 현재 버전과의 비교, 변경 발생 시 재확인 표시가 없습니다.

추가 작업범위안

  • 위 세 부분만 추가 대상으로 정의함.
  • 문서저장소·사용자 관리·승인화면 전체를 새로 구축하는 범위로 확대하지 않음.

계약 확인사항

해당 작업이 기존 계약의 이행대상인지, 변경 협의가 필요한지, 별도 신규 범위인지 소관 담당에게 확인함. K003에서 비용부담이나 계약처리 방식을 확정하지 않음.

판정 한계

  • 일부 화면이나 시연에서 기능을 찾지 못했다는 이유만으로 전체 시스템에 기능이 없다고 단정하지 않음.
  • 가정과 달리 증거가 불충분하다면 ‘추가구현’이 아니라 ‘확인불가’로 기록해야 함.

6. 실제 수행 순서와 이번 컨셉의 범위

수행은 필요사항 분해 → 기존 기능 연결 → 기능·인수 대조 → 계약·운영 대조 → 분류·근거 기록 → 담당자 확인 순서로 진행하는 안임.

순서 수행내용 남길 결과
1. 필요사항 분해 입력·처리·출력·완료조건을 비교 가능한 행으로 작성 신규 필요사항 목록
2. 기존 기능 연결 대응하는 기능·버전·자료 위치를 찾음 기존 기능 후보와 근거
3. 기능·인수 대조 명세·인수·시험·허용된 시연의 일치와 차이 확인 충족·미충족·미확인 부분
4. 계약·운영 대조 기존 범위·기간·이용조건·운영 책임과의 관계 확인 계약·적용조건과 보류 사유
5. 분류·확인 네 가지 분류와 최소 추가 작업, 확인 담당 기록 대응표와 추가 확인목록

K003에서 끝낼 일

기존 기능과 신규 필요사항의 대응, 네 가지 분류, 근거 위치, 추가 작업의 최소 범위, 확인불가 사항까지 정리함.

반면 실제 기능 개발, 시스템 설정 변경, 전체 접근통제 설계, 계약 변경, 예산·단가 확정, 다른 컨셉과의 통합은 포함하지 않음.

  • 특히 이번 컨셉을 새로운 자산관리시스템이나 자동 계약심사 AI 구축사업으로 바꾸지 않음.
  • 목적은 진단표를 만드는 것이지, 진단표를 만들기 위한 시스템을 하나 더 만드는 것이 아닙니다.

7. 완료기준·역할·기간

  • 원문의 완료기준은 **“각 신규 기능에 기존 미충족 부분과 대조 문서 위치가 존재”**하는 것임.
  • 동시에 자료 미확보를 기존 기능 부재로 해석하지 않는다는 제한을 유지해야 함.

상세 확인에서는 다음을 점검하도록 제안함.

확인항목 완료를 확인할 질문 부족할 때의 처리
비교단위 명확성 어떤 입력·처리·결과를 기존 기능과 비교했는가? 필요사항 재작성
대응 근거 어느 기능·버전·문서 위치와 대조했는가? 자료·버전 추가 확인
차이의 구체성 기존 충족분과 실제 부족분이 구분되는가? 추가 범위 확정 보류
증거 상태 구분 제안·계약·인수·운영을 섞지 않았는가? 상태와 근거 재분류
계약·적용조건 기존 범위와의 관계, 해당 업무에서의 이용조건이 확인되는가? 조건부·확인 중 유지
확인불가 관리 무엇을 누구에게 추가 확인해야 하는가? 자료요청·재확인 조건 기록
  • 그대로 사용할 수 있는 행은 미충족란에 **‘확인 범위 내 미충족 없음’**으로 기록할 수 있음.
  • 추가구현 행은 구체적인 부족분을 적어야 하며, 확인불가 행은 미확인 부분과 필요한 자료를 남깁니다.

대응표 초안 작성과 진단 확인 완료도 분리함. 보류행이 남아 있다면 해당 범위를 명시하고, 전체 사업의 비중복성을 확인했다고 보고하지 않음.

  • 수행 역할은 원문대로 수행 기획·PM, 결과 확인·승인은 TS 과제별 사업책임자, 협의·검토는 현업·정보화·예산임.

  • 실제 담당 배정은 별도 확인사항이며, 계약·이용조건의 판단이 필요한 부분은 소관 담당의 확인을 요청하는 안임.

  • 기간은 원문의 2~5근무일 가정을 유지함.

  • 이는 대상·자료·협의에 따라 조정하는 사전 진단 작업기간이지, 기관 전체 계약 조사나 사용권·변경 승인까지 모두 완료한다는 일정은 아닙니다.

8. 바로 사용할 보고서 문안

신규 AX 필요사항을 기존 기능명세·인수자료·운영계약과 대조하여 그대로 사용·설정변경·추가구현·확인불가로 구분하고, 추가구현 항목에는 기존 충족분·미충족분 및 근거 문서 위치를 명시할 필요. 기능의 존재·실제 인수·운영 가능성·계약범위를 분리하여 검토하고, 자료 미확보를 기존 기능 부재로 해석하지 않도록 통제. 재사용 항목의 실제 적용조건과 설정·검증 작업은 별도로 식별하며, 계약관계 또는 사용조건이 미확인인 항목은 신규 범위·비용 확정 전 추가 확인 추진.

제공한 MD에는 신규 필요사항 카드, 기능·근거 대조표, 계약·적용조건 확인표, 근거자료 대장, 확인불가·상충 쟁점표, 개별 대응결과 확인서를 포함했음.

K003의 최종 결과는 새로 만들 기능의 긴 목록이 아니라, 무엇은 그대로 쓰고 무엇만 더 필요하며 무엇은 아직 판단할 수 없는지를 근거와 함께 설명하는 대응표임.
