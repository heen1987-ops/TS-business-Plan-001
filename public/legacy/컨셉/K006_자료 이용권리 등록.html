K006. 자료 이용권리 등록

06 / 92 · 원문 작업 W02.01 · 독립 컨셉 상세안

  • 여섯 번째 컨셉의 결과물은 **「자료별 이용권리 대장」**임. TS 자료관리 책임자와 수행 데이터 담당자가 2027년 AX 적용을 준비하면서, 자료를 확보했는지와 그 자료를 어떤 목적으로 어디까지 사용할 수 있는지를 분리하여 기록하는 항목임.

  • 원문은 자료별 소유자·허용목적·사용행위·이용기한을 등록하도록 정의함.

  • 아래 등록항목·상태·사례는 원문 K006을 구체화한 설계 제안임.

  • 실제 TS 자료의 이용 승인이나 법적 이용 가능성을 확인한 결과가 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 파일을 받았다고 모든 활용이 허용되는 것은 아님

K005가 과제의 착수조건을 검토했다면, K006은 개별 자료의 이용조건을 등록함.

  • 예를 들어 심사자료를 전달받고 담당자의 열람이 허용되었다고 가정하겠습니다.
  • 여기서 확인된 것은 해당 자료의 제공과 열람 범위임.
  • 그 자료를 AI에 입력하거나, 별도 서버에 저장하거나, 학습자료로 만들거나, 다른 기관과 공유하는 조건까지 확인한 것으로 처리하지 않음.

따라서 대장에는 다음과 같은 상태가 함께 존재할 수 있음.

자료 수령 완료 / 지정 담당자 열람 허용 확인 / AI 분석 미확인 / 학습 불허 확인

  • ‘자료 사용 가능’이라는 한 칸으로 줄이면 이 차이가 사라집니다.
  • 관리하기는 편해지겠지만, 정작 무엇을 허용받았는지는 알 수 없게 됩니다.

K006의 핵심 질문은 다음과 같습니다.

“누가, 어떤 자료를, 어느 업무목적으로, 어떤 행위와 환경에서, 언제까지 사용할 수 있으며, 그 확인 근거는 무엇인가?”

이용권리 대장은 확인 결과를 기록하는 문서임. 대장에 행을 만들었다는 사실이 자료 이용권 부여, 시스템 접근권한 설정, 적법성 검토 완료를 의미하지는 않음.

등록 단위

다음 조합을 하나의 조건 기록으로 구체화하는 안임.

자료 ID·버전 × 사용목적 × 이용 주체 × 사용환경 × 사용행위 × 이용기간

  • 같은 파일이라도 심사 검토용 이용과 모델 학습용 이용, 내부 담당자 이용과 외부 수행사 이용은 각각 조건을 확인함.
  • 이는 대장 안의 기록 단위를 나누는 것이며, 새로운 컨셉이나 사업을 추가하는 것은 아닙니다.

2. 열람·분석·저장·학습·공유를 각각 확인

  • 원문은 자료 소유자와 열람·분석·저장·학습·공유 허용범위, 이용기한을 자료별로 등록하도록 제시함.
  • 이 다섯 구분을 그대로 유지했음.
사용행위 구체적으로 등록할 내용 허용 근거를 대신하지 못하는 설명
① 열람 누가 어떤 원문·변환본을 어느 화면·환경에서 볼 수 있는가? “파일을 받았다”, “접속할 수 있다”
② 분석 항목 추출, 비교·요약, 검색 기반 답변 등 어떤 처리를 수행할 수 있는가? “사람이 볼 수 있으니 AI에도 넣어도 된다”
③ 저장 원문·변환본·검색용 자료·결과·로그를 어디에 얼마 동안 보관할 수 있는가? “분석이 허용됐으니 결과는 계속 보관한다”
④ 학습 모델 개선용 데이터 구성, 학습·재학습 등 어떤 행위가 허용되는가? “검색에 쓸 수 있으니 학습에도 쓸 수 있다”
⑤ 공유 누구에게 원문·발췌·요약·결과 중 무엇을 어떤 방법으로 전달할 수 있는가? “내부 공유가 되니 다른 과제나 외부에도 전달한다”
  • 이 다섯 항목은 등록을 위한 실무적 구분임.
  • 실제 처리 한 번에 분석·저장·공유가 함께 포함될 수 있으므로, 수행할 내용을 구체적으로 풀어 적습니다.

‘학습에 사용하지 않음’만 확인해서는 부족

검색 기반 답변에 활용할 계획이라면 다음 행위를 사용계획에 각각 적도록 제안함.

원문 반입 → 변환·추출 → 검색용 자료 저장 → 모델 입력 → 결과 보관·공유

  • 이 과정에서 무엇이 허용됐는지 확인해야 함.

  • 학습에 사용하지 않는다는 설명만으로 분석·저장·외부 전송까지 허용된 것으로 등록하지 않음.

  • 평가자료 활용, 질문·답변 예시 생성, 오류분석 로그 활용도 실제 요청 목적에 포함되는지 명시함.

  • 원문의 ‘분석’이나 ‘학습’이라는 말에 모든 후속 이용이 포함된 것으로 가정하지 않는 방식임.

외부 전송은 처리경로까지 확인

  • 외부 전송 여부는 별도 확인정보로 남깁니다.

  • 분석을 수행하는 환경, 자료를 받는 시스템·운영 주체, 저장 위치, 결과를 보는 대상을 함께 기록함.

  • 원문에서도 열람 허용을 외부 전송·학습 허용으로 확대하지 않도록 제한함.

  • 따라서 내부에서 열람한 내용을 외부 모델에 전달하는 계획은 별도로 확인해야 할 행위로 남깁니다.

  • 반대로 ‘내부 환경’이라는 이유만으로 모든 이용을 허용 처리하지도 않음.

  • 자료·목적·이용 주체·행위·기간이 확인된 범위를 기록하는 것이 기준임.

3. 자료별 이용권리 대장에 무엇을 넣을 것인가

  • 원문의 입력자료는 원천자료 목록·제공조건임.
  • 상세 등록에서는 그 조건이 적힌 원문과 확인 결과를 연결함.
등록항목 반드시 남길 내용 미확인일 때의 처리

근거·확인 이력 제공조건 문서·버전·위치, 확인자·역할·확인일, 미확인 사유 추가 확인사항과 소관 주체 기록

소유자·제공자·확인자를 같은 사람으로 채우지 않음

  • 원문의 ‘자료 소유자’ 명칭은 유지함.

  • 다만 자료를 보관하는 부서, 파일을 보내 준 사람, 이용조건을 확인할 주체가 같은지는 별도로 기록함.

  • 파일을 전달한 담당자가 있다는 이유로 모든 이용행위를 허용할 권한까지 확인됐다고 처리하지 않음.

  • 복수 기관의 내용이나 첨부자료가 포함되어 있다면 어느 파일·쪽·항목에 어떤 제공조건이 적용되는지도 구분함.

법적 권리 귀속이 불명확한 경우에는 이 대장에서 독자적으로 판정하지 않고, 해당 쟁점과 확인 주체를 남깁니다.

확인 상태는 네 가지로 구분하는 안

아래 상태명은 상세설계를 위한 제안이며, 원문에 정해진 공식 코드가 아닙니다.

‘조건부 허용 확인’과 ‘조건 충족’은 다릅니다. 예를 들어 지정 항목을 제거한 사본만 분석할 수 있다면, 그 조건이 확인되어도 실제 제거·확인이 끝나기 전에는 분석 준비가 완료됐다고 표시하지 않음.

  • 또한 ‘이번 이용계획에 미포함’과 ‘불허 확인’도 구분함.
  • 학습할 계획이 없다는 사실이 학습 불허를 확인했다는 뜻은 아닙니다.
  • 이후 계획에 추가할 때는 해당 조건을 다시 확인함.

4. 작성 예시: 가상 철도 심사자료 A

  • 다음은 등록방법을 설명하기 위한 가상 사례임.
  • 기관·자료·조건·날짜·확인 상태는 모두 가정이며, 실제 TS 자료의 승인 결과가 아닙니다.

4-1. 처음 확인된 조건이 내부 열람뿐인 경우

가상 제공조건 문서에 ‘지정된 검토자의 내부 열람 허용’만 기재되어 있고, AI 분석·별도 저장·학습·공유에 관한 내용은 없다고 가정함.

이때 등록 결과는 다음과 같습니다.

자료 확보: 수령 확인.
열람: 지정 검토자와 해당 내부 환경에서 허용 확인.
AI 분석·별도 저장·학습·공유·외부 전송: 미확인.

  • 언급되지 않은 행위를 곧바로 실제 불허가 확정된 것으로 기록하지는 않음.
  • 그러나 확인되지 않은 행위를 허용으로 취급하지도 않음.

4-2. 추가 확인 후에는 행위별로 다르게 등록

후속 제공조건에서 다음 내용이 권한 있는 주체에 의해 확인됐다고 가정함.

이 경우 분석의 최초 상태는 다음과 같이 기록함.

조건부 허용 확인 / 지정 필드 제거·확인 미완료 / 분석 착수 전 조건 이행 확인 필요

  • 지정 필드 제거는 그 처리 자체가 허용된 환경·담당자에 의해 수행되도록 정해졌다는 가정임.

  • 전처리를 위해 원문을 임의로 다른 도구에 먼저 전송하는 경로를 만들지 않음.

  • 조건을 충족한 뒤에도 허용은 v1·해당 사건 목적·지정 환경·지정 사용자·해당 기간에 한정됩니다.

  • 다음 버전의 자료, 다른 실증사업, 다음 연도의 재학습까지 자동으로 확대하지 않음.

등록 완료와 실제 종료처리도 분리

이용기간과 종료 시 처리조건을 대장에 적었다고 자료가 실제로 삭제·반환된 것은 아닙니다.

  • K006에서는 무엇을 언제 어떻게 처리해야 하는지와 인계 대상을 기록함.
  • 실제 차단·반환·삭제가 수행됐는지는 해당 실행 근거로 별도로 확인하도록 남깁니다.

5. 자주 발생할 수 있는 예외와 처리방식

아래는 실제 TS에서 발생한 문제 목록이 아니라, 등록 누락을 막기 위해 검토할 예외사례 제안임.

이용권리를 확인하기 위한 작업 자체도 허용된 범위에서 시작해야 함. 원천자료 목록과 제공조건을 먼저 확인하고, 권한이 불명확한 민감 원문을 외부 AI에 올려서 이용조건을 분석하는 방식은 이번 상세안에 포함하지 않음.

  • 대장에는 필요한 조건과 원문 위치를 연결함.
  • 대장을 만들기 위해 자료 본문 전체를 추가 복제하거나 별도 공간에 모으는 것을 전제하지 않음.

6. 수행 순서와 K006에서 끝낼 범위

수행은 목록 확보 → 이용계획 대조 → 조건 등록 → 미확인 해소 요청 → 결과 확인·인계 순서로 제안함.

  • 먼저 허용된 원천자료 목록에서 자료·버전·범위를 식별함.

  • 그다음 실제로 하려는 목적·행위·환경·기간을 제공조건과 대조하고, 확인된 내용과 미확인 부분을 자료별로 등록함.

  • 확인되지 않은 부분에는 질문, 확인 주체, 필요한 근거, 재확인 시점을 남깁니다.

  • 마지막으로 해당 자료를 사용하는 담당자에게 허용범위와 제한사항을 인계함.

K006에서 작성할 것

  • 자료별 허용목적, 다섯 사용행위의 조건, 이용기간, 확인 근거, 미확인 사유와 확인 주체를 기록함.
  • 조건이 바뀌었을 때 무엇을 다시 확인해야 하는지도 남깁니다.

별도 작업으로 남길 것

사건·문서 식별자 연결 기능, 역할별 접근정책 구현, 파생정보 접근통제, 자료 만료·파기 실행, 계약 변경, 실제 권리 부여, 법적 적합성 판정, 모델 학습 수행은 K006에 포함하지 않음.

  • 따라서 이번 컨셉을 새로운 권한관리 플랫폼이나 자동 법률심사 AI 구축사업으로 확대하지 않음.
  • 필요한 것은 우선 자료별 이용조건을 설명할 수 있는 대장임.

8. 바로 사용할 보고서 문안

AX 적용 대상 자료별로 소유자·제공 주체·허용목적·열람·분석·저장·학습·공유 범위와 이용기한을 근거 기반으로 등록할 필요. 자료 확보와 이용 허용을 구분하고, 사용목적·이용 주체·처리환경·행위·기간이 달라지는 경우 해당 조건의 적용 여부를 별도 확인. 열람 허용을 외부 전송·모델 학습으로 확대하지 않으며, 미확인·상충 조건은 사유·확인 주체·필요 증거와 함께 관리. 이용권리 대장 작성, 실제 이용조건 충족, 시스템 권한 적용 및 종료 시 자료 처리는 별도 상태로 기록하여 확인 범위를 넘는 활용 방지 추진.

제공한 MD에는 자료별 이용권리 카드, 행위별 허용범위 확인표, 미확인·상충·조건충족 기록서, 제공조건 근거대장, 변경·만료 및 결과 확인 기록서를 포함했음.

K006의 최종 결과는 ‘자료를 받았다’는 목록이 아니라, 각 자료를 누가 어떤 목적으로 어디까지 사용할 수 있고 무엇은 아직 확인되지 않았는지를 근거와 함께 설명하는 대장임.
