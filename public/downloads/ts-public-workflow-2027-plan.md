# 2027년 공공기관 NOA 기반 업무흐름 고도화 사업기획·RFP 초안

v0.2 · 작성·선택 원문 재대조 2026-10-12 · 공고 미매핑 기획 초안

## 1. 사업 방향과 판단

- 권고 사업명: 기구축 AI 공통플랫폼 기반 공공업무 흐름 고도화 및 업무별 AX 서비스 확장
- 내부 기술 매핑: NOA 기반 공공기관 업무흐름 실행·관리 고도화
- 목적: 법정·수탁업무의 처리 연속성·서비스 품질·책임성 강화
- 목표: 업무별 접수·자료 확인·수행·검토·승인·처리결과·인계의 연결과 국민의 재문의·재제출·지연 부담 개선
- 수단: 기구축 AI 플랫폼·NOA + 공통 업무흐름 관리의 부족분 보강 + 업무별 규칙·서식·지식·연계·검증
- 구조: 공통 기반 1개와 업무별 적용 절차. AI PMS는 사업관리 적용 사례이며 전체 업무흐름 플랫폼과 동일 개념 아님
- 판단: 기획 구조 조건부 타당. 기존 계약과의 차이·현업 수요·설치본·사용권·기관 승인·예산 미확정으로 별도 발주 적정성 확정 보류

현재 문제는 부서·자료·시스템 사이에서 업무가 끊기고 후속조치가 누락되는지를 확인할 개선 가설. 실제 반복 발생률·처리시간·기존 시스템 미지원 범위·현업 수요는 미확인. 인터뷰·동의·기관 확약을 확보한 사실 없음.

Assumptions: 로컬 LLM·기존 서버 활용, 신규 인프라 구매 0원 전제. 실제 자원 여유·지원료·라이선스·저장·백업·운영비는 별도 확인. 비전·의료정보 자동 연계·자격/처분/송금 자동 결정은 초기 범위 제외.

## 2. 구축 단계와 업무흐름 고도화 단계

| 구분 | 구축·기존 고도화 기반 | 2027년 업무흐름 고도화 후보 |
|---|---|---|
| 중심 가치 | 허용 자료와 AI 서비스를 이용할 기반 | 업무 건별 처리와 후속조치의 연결 |
| 대상 | 모델·지식·권한·대화·API/MCP·직무별 AI 기능 | 역할·상태·기한·필수자료·검토·승인·인계·예외·완료조건 |
| 산출물 | 플랫폼과 서비스 기능·연계·시험 | 업무별 수행 절차·승인된 시스템 연계·실제 결과 확인·운영 개선 |
| 검수 | 기존 계약의 기능·성능·연계·납품 기준 | 업무별 결과·누락·재작업·안전·검토부담의 실측과 추가 기능 시험 |
| 비용 경계 | 기존 계약으로 납품하는 동일 기능 | 기존 기능 재사용 후 추가 설정·변경·연계·검증의 증분 |

기존 2026년 공고 자체가 이미 플랫폼 고도화 사업. 구축/고도화는 사업가치의 단계 구분이며 실제 “1차/2차” 계약 차수와 동일하게 확정하지 않음. 별도 RFP 작성은 가능성 검토이며 새 사업 발주·예산 확보 사실 아님.

## 4. 기존 RFP와 추가 범위의 대조

근거: TS 공통플랫폼 RFP 2026.6, SFR-001/003/004/005/006~009·SIR-001/002. 공식 HWP에 해시 대응하는 보관 추출 본문의 선택 재대조. 실제 최종 계약·변경·검수·설치는 미확인.

| 기존 발주 요구 | 재사용·계약 대조 | 추가 설계 후보 |
|---|---|---|
| SFR-001 온나라·EP포털·통합경영 파이프라인 | 기존 수집·지식 구성·자료 권한·연계 계약 대조 | 업무 건별 문서·판본·결과 연결; 동일 파이프라인 재구축 제외 |
| SFR-003 직무별 특화 기능 3건 | 자동차검사 Q&A·상시감사 지원·보도자료 초안의 최종 범위 대조 | 답변·초안 이후 업무별 검토·승인·결과·후속조치의 부족분 |
| SFR-004·005 통합권한·AI서비스·대화형 업무지원 | 기존 권한·대화·운영·편의 기능 및 사용권 확인 | 업무 상태·담당·기한·승인 판본·변경 후 재검토·인계 |
| SIR-001·002 MCP 허브·OpenAPI의 AI Tool 변환 | 기존 API Gateway·MCP·도구 변환 기능 활용 | 업무별 허용 도구·필드·권한·실행 승인·중복 방지·결과 대사 |
| SFR-006~009 민원·신문고·전세버스 공시 | 동일 서비스 납품분 재편입 제외 | 현행 범위 밖의 후속 업무만 계약 차이·공수로 입증 |

“업무흐름”이라는 명칭이 원문 검색에서 발견되지 않는 것을 해당 기능의 부재로 해석하지 않음. 최종 계약·설치본 확인 후 기존/설정/변경/신규/제외의 대응표 확정 필요.

## 5. 기술적 HOW와 End-to-End 실행

| 단계 | 입력·처리 | 산출물·주체·예외 |
|---|---|---|
| 1 접수·업무 식별 | 허용 요청→업무 건 ID·유형·담당 후보·적용 기준 판본 | 담당자의 관할·유형 확인; 불명확하면 확인 요청 |
| 2 근거·조건 확인 | 기존 ACL·검색과 NOA 문서 이해 지원→필수자료·근거·누락 후보 대조 | 원문 위치·판본·보완안; 자료 부족의 자동 합격 전환 제외 |
| 3 수행안 제시 | NOA 작업 지원 + 확정 업무 규칙→허용 단계·담당·기한·확인 질문 | 단계별 수행안; AI 임의 법령·권한·처분 생성 제외 |
| 4 수행·실질적 검토 | 규칙 엔진의 상태·필수값 검증 + NOA 초안·비정형 자료 지원 | 검토자의 근거 접근·수정·반려·인계; AI 추천의 최종 결정 대체 금지 |
| 5 승인·연계 | 승인 판본·입력 고정→기존 MCP/API 또는 승인된 파일 내보내기 | 실행 직전 권한 재확인; 중요 입력 변경 시 재승인 |
| 6 결과·예외 확인 | 공식 처리 ID·응답·실패·중복·부분 성공 대조 | 실제 결과 확인; 지연 시 원거래 조회 후 재시도·수동 대체 |
| 7 인계·개선 | 처리시간·재보완·이관·후속조치·검토부담 기록 | 업무별 개선안; 절차 변경 승인·회귀시험 후 적용 |

- 기존 AI 플랫폼: 인증·권한·LLM·RAG·데이터·API/MCP·운영 기반의 계약·설치 확인 후 재사용
- NOA: 공식 제품 소개의 문서 이해·근거 연결·업무 수행 지원·정책/승인 설명을 적용 방향으로 활용. TS 설치본·API·사용권·성능·통제 동작은 미검증
- 추가 개발: 업무 정의·상태·역할·기한·승인 판본·인계·예외·결과 대사 등 실제 부족분만 보강
- aRDa: 기존 설계의 근거·판본 연결 적용 후보. 제품 원본·API·사용권 확인 전 확인된 기능이나 완료된 연계로 표기 금지
- 결정적 계산·상태 전이·권한 강제는 확정 규칙/일반 코드로 처리. 비정형 요청 이해·자료 관계·보완안·문서 초안에 AI 적용 가치 검증

시범 2~3개 업무는 선정 규모 제안이며 기관 승인·확정 범위 아님. 공통 기반과 업무별 절차를 분리해 처별 솔루션의 중복 방지.
