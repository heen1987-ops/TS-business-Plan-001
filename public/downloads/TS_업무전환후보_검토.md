# TS 업무 전환 후보 검토

조사일: 2026-09-23 · 현업 검증 전 기획 가설

선행사례에서 바뀐 처리단위를 TS 업무에 연결. 기존 계약의 추가 납품범위·부서 책임·기대효과는 미확정.

## 1. 이번 검토에서 수정·보완한 점

- 리즈시: 2025년 제한적 베타 이후 2026년 5월 확대 파일럿·기관 발표 성과 추가. 전체 운영 완료 또는 TS 성과 입증으로 확대하지 않음.
- SAFE-i24: 2025년 3월은 인증 발표. 공식 발표상 법적 근거 마련은 2023년 6월. 공포·시행일은 법령 연혁 추가 대조 대상.
- FDA: HALO 데이터 통합과 Elsa 연계 착수를 구분. 종단간 업무효과 완료 주장 제외.
- 온북: PDF 33쪽 경력 기재 직접 확인. 현재 TS 운영 및 스마트폰 녹음 승인 근거로 사용하지 않음.
- 3개 우선 후보는 추가 작업 검증 단위. 기존 13개 처 대표서비스·22개 기획·DRT와 별개 신규사업 건수로 합산하지 않음.

## 2. 선행사례와 TS 적용 판단

### E01. 영국 DVSA · MOT Risk Rating

- 상태: 운영 기록 / 2025.02.10 공개기록
- 전환: 마지막 방문 이후 경과시간 중심의 방문 우선순위 → 검사 패턴과 다른 정보를 함께 검토한 방문대상 선정
- 확인 사실: 알고리즘의 방문 우선순위 신호를 담당자가 종합 검토. 징계 결정에는 방문 등으로 확보한 별도 증거 사용.
- 한계: 이상 패턴과 위반 사실의 구분. 차량·검사 유형과 업무량 차이, 오경보 검토 필요. 이 기록만으로 사고 감소 효과 확정 불가.
- 발굴 질문: 방문대상 선정과 과거 지적·증빙 준비에 어떤 반복 작업이 남는가?
- TS 적용 가설: 추가 탐색 · 현장 확인 대상의 사전 점검자료 묶음
- CCK 조건: 검증된 정형 위험분석을 입력으로 사용하고, 로컬 LLM은 확인질문·이력·근거 묶음 구성. 위험점수의 LLM 임의 생성 제외.
- 근거: [DVSA · MOT Risk Rating](https://www.gov.uk/algorithmic-transparency-records/dvsa-mot-risk-rating) · 2025-02-10 · §2.3–2.4, §3.1–3.4, §4.1.2

### E02. 영국 리즈시 · Xylo Core

- 상태: 확대 파일럿 / 2025.11 → 2026.05 후속 확인
- 전환: 체크리스트 대조·이력 검색·통신문 복사와 재작성 → 안건별 확인목록·누락 후보·관련 근거를 담당자가 검토
- 확인 사실: 2025년 ATRS는 제한적 베타·PoC. 2026년 5월 LGA는 참여자 8명에서 20명으로의 파일럿 확대와 인터뷰·사용기록 기반 성과를 보고.
- 한계: 전체 부서 운영 완료와 구분. 지표별 표본·기간·산식·대조군이 본문에 명시되지 않은 효과 수치를 TS 목표로 이전하지 않음. 기존 시스템 연계 제약 잔존.
- 발굴 질문: 첫 추출 이후 보완요청과 재제출 대조가 실제 병목인가?
- TS 적용 가설: C02 · 요청사항별 재제출·미해결 항목 연결
- CCK 조건: 담당자 검토와 근거 제시 패턴 참고. 외부 클라우드·LLM API·GIS·이미지 활용 구조의 그대로 도입 제외. TS 텍스트 문서·기존 서버 조건으로 별도 검증.
- 근거: [Leeds · Xylo Core ATRS](https://www.gov.uk/algorithmic-transparency-records/leeds-city-council-xylo-core) · 2025-11-27 · §2.1–2.3, §3.1–3.3, §4.1
- 근거: [LGA · Leeds 파일럿 후속 사례](https://www.local.gov.uk/case-studies/leeds-city-council-and-xylo-transforming-planning-ai) · 2026-05-08 · The collaborative process / Integration / Successes and results / What's next

### E03. 영국 재무부 · Correspondence Triage

- 상태: 운영 기록 / 2024.12.17 공개기록
- 전환: 직원이 서신의 처리팀·주제·후속조치 등을 수동 분류 → 분류·요약·후속확인 후보를 기존 서신관리시스템으로 전달
- 확인 사실: SVM·GPT-4·RAG를 결합한 처리. 직원이 분류를 수정하고 최종 답변 작성·확정. 시간절감 설명은 기대효과로 기재.
- 한계: 단일 LLM·자동 최종답변 사례로 해석하지 않음. 팀 자동 배정의 오류·이관 정정 비용까지 검증 필요.
- 발굴 질문: 이전 회신의 미해결 내용과 다음 담당자의 확인자료가 함께 인계되는가?
- TS 적용 가설: C01 · 재문의 묶음에서 안내 개선까지의 확장
- CCK 조건: 로컬 LLM의 의미 대조와 기존 분류·접수시스템 연계. 반복 민원인 위험등급 생성 제외.
- 근거: [HMT · Correspondence Triage](https://www.gov.uk/algorithmic-transparency-records/hmt-correspondence-triage-automation-tool) · 2024-12-17 · §2.1–2.4, §3.4, §4.1.1–4.1.2

### E04. 미국 FDA · Elsa 4.0 + HALO

- 상태: 통합 착수 발표 / 2026.05.06 기관 발표
- 전환: 직원이 대화마다 관련 문서를 찾아 수동 업로드 → 신청·제출 데이터 기반의 질의·업무흐름 구성 지향
- 확인 사실: 40개 초과 신청·제출 데이터원·시스템·포털의 HALO 통합과 Elsa 연계 착수를 발표.
- 한계: 데이터 기반 통합과 종단간 업무효과 입증은 별개. FDA 발표만으로 TS 권한·연계·로컬 모델 성능 확보를 추정하지 않음.
- 발굴 질문: 검토 전에 최신 자료를 찾아 모으는 준비작업이 얼마나 남는가?
- TS 적용 가설: 공통 기반 · 안건별 권한·판본을 반영한 근거자료 묶음
- CCK 조건: aRDa 문서·판본과 허용된 업무시스템 조회의 결합 제안. FDA 클라우드 구성을 TS 적용 아키텍처로 복제하지 않음.
- 근거: [FDA · Elsa 4.0·HALO 발표](https://www.fda.gov/news-events/press-announcements/fda-expands-ai-capabilities-and-completes-data-platform-consolidation) · 2026-05-06 · 데이터원 통합·HALO와 Elsa 연계 착수 설명

### E05. 대한민국 식약처 · SAFE-i24

- 상태: 조건부 자동수리 운영 / 2025.03 발표·운영 공지
- 전환: 반복 수입신고의 요건을 검사관이 확인·처리 → 정해진 적합 조건은 자동처리, 제외 대상은 검사관 처리
- 확인 사실: 반복 수입·서류검사 대상의 모든 전자심사 항목 적합 시 자동수리. 2025년 4월 4일부터 반복 신고오류에 따른 일정 기간 자동수리 제외를 공지.
- 한계: 2025년 3월은 인증 발표. 발표가 설명하는 법적 근거 마련은 2023년 6월이며 정확한 공포·시행일은 별도 법령 연혁 대조 대상. 생성형 AI 단독 또는 TS 자동처분 권한의 근거가 아님.
- 발굴 질문: 고정 규칙의 준비단계와 해석·예외 검토를 구분할 수 있는가?
- TS 적용 가설: 추가 탐색 · 자료 완결성·일치 검사와 예외 검토 재배치
- CCK 조건: 필수값·일치·계산은 규칙, 비정형 설명의 맥락 대조는 로컬 LLM. TS 최종 처분 자동화는 이번 후보 범위에 미포함.
- 근거: [법제처·식약처 발표 공식 전재본](https://m.korea.kr/briefing/pressReleaseView.do?gubun=pressRelease&newsId=156681124&pageIndex=233&repCode=) · 2025-03-27 · 자동처분 법적 근거·단계 적용·인증 설명; 직접 열람은 독립 검토자 확인
- 근거: [식약처 · 자동 신고수리 예외 운영](https://impfood.mfds.go.kr/CFBAA01F02/getCntntsDetail?cntntsMngId=00001&cntntsSn=599878&limit=10&page=1&searchCondition=&searchInpText=) · 2025-03-20 · 반복 신고오류 대상·시행일·검사관 처리 전환

## 3. 우선 검증 후보

### C01. 반복되는 혼선을 안내자료 개선으로 연결

- 국민·기업 편익: 국민이 같은 문제로 다시 문의하는 부담 완화
- 사용자: 민원·상담 실무자, 해당 업무의 FAQ·매뉴얼 관리부서
- 부서 매핑 조건: 업무별 협의 접점 제안. 실제 민원 총괄·콘텐츠 소유자·승인권은 확인 필요.
- 착수 사건: 종결된 문의의 재접수 또는 동일 조건에서 서로 다른 안내의 발견
- 문제 가설: 제안서상 분석·답변 기능의 실제 구현·사용 여부와, 안내자료 수정 대상·담당 부서 결정까지 연결되는지 확인 필요.
- 현행 흐름 가설: 상담이력 확인 → 답변 작성 → 건별 종결
- 전환 흐름 제안: 미해결 질문 식별 → 원인 가설 비교 → 안내 수정·검증 → 같은 원인의 재문의 추적
- 입력 자료: 접수·회신 이력, FAQ·매뉴얼 판본, 실제 수정·배포 기록, 서비스 운영상태. 연결키와 열람권한 필요.
- 재사용 검토: 기존 녹취·민원원인·상담이력 분석, 매뉴얼 검색·답변지원, 권한·로그 기능의 재사용 검토.
- 추가 작업 후보: 분석 결과→수정 대상·담당 업무→반영판본→재문의 변화의 연결. 기존 납품 기능 포함 여부는 계약·기술협상·RTM 대조 필요.
- CCK 구현 제안: NOA의 조사·개선 과업 계획/실행/검증 확장, aRDa 문서 판본·근거 조회, 로컬 LLM 의미 대조. 실제 배포본 재사용 가능 범위 미검증.
- 비AI 비교안: 민원 분류 규칙 + 문서 개정대장 + 담당자 검토만으로 가능한 안과 비교.
- 검증 지표: 동일 원인 재문의율, 잘못 제안한 수정 비율, 반영까지의 기간, 담당자 검토부담.
- 대상·분모: 관측기간·업무유형이 같은 종결 문의 중 동일 원인 재문의 건수 / 대상 종결 건수. 동일 원인 라벨은 담당자 검토.
- 반증 질문: 문의 감소가 계절성·서비스 수요 감소 때문인지, 원인이 시스템 지연인데 매뉴얼을 바꾼 것은 아닌지 확인.
- 권한·책임: 개인 민원인의 위험도·성향 점수 금지. 자동 대외 답변·게시 없이 권한자 확정. 원문 접근권한을 넘는 이력 결합 제외.
- 산정 상태: 미산정 · 공통 연계·판본 조회 1회분과 C01 전용 분류·평가·배포 확인 공수 분리.

**제안 서비스 흐름**

1. 기존 시스템 / 문의 묶음 구성: 가명 사건ID·접수시점·업무유형으로 관련 이력 조회. 동일인·동일 문제라는 추정은 검증 대상으로 표시.
2. NOA · 로컬 LLM / 원인·수정 후보 도출: 기존 회신·FAQ·매뉴얼을 대조해 미해결 질문과 설명 불일치 후보 제시. 처리지연·예약상태 등 대안 원인 병행 검토.
3. 업무 담당자 / 수정 범위 확정: 근거를 확인해 자료 수정·운영 개선·추가조사로 분기. 실제 문서 변경은 정당한 권한과 검토 기록에 연결.
4. 기존 지식관리 / 반영·효과 확인: 확정 판본과 배포 위치를 재조회. 관측기간·업무유형별 동일 원인 재문의의 변화를 검토하고 미해소 시 다시 조사.

**납품물 후보**

- 재문의–안내근거 연결표
- 원인별 수정·운영개선 제안서
- 반영판본 및 효과 확인 기록

### C02. 바뀐 자료와 아직 남은 보완사항의 동시 확인

- 국민·기업 편익: 사업자의 불필요한 보완 왕복과 처리 지연 완화
- 사용자: 공시·검정·신청 자료 검토자, 보완자료 제출 사업자
- 부서 매핑 조건: 전세버스 공시의 기존 수행분 포함 여부 우선 대조. 앱미터·실증·검정 분야는 별도 자료·담당 권한 확인 후 적용.
- 착수 사건: 공식 보완요청에 대한 새 자료 접수
- 문제 가설: 재제출 때 모든 자료를 다시 읽거나, 요청사항과 수정본의 연결을 수작업으로 재구성하는지 확인 필요.
- 현행 흐름 가설: 최초 제출 검토 → 보완요청 → 재제출 자료 전체 재검토
- 전환 흐름 제안: 요구사항ID별 보완 연결 → 변경·영향범위 확인 → 미해결 검토 → 종료 근거 확정
- 입력 자료: 동일 사건의 최초 제출·공식 보완요청·재제출·최종 검토기록, 적용 기준 판본, 요청ID·제출차수.
- 재사용 검토: 기존 제출자료 추출·항목 판별·기준 버전·담당자 반영 및 현행 접수시스템 활용.
- 추가 작업 후보: 보완요청 항목–변경근거–해결판정–후속조치의 차수별 추적. 단순 재추출·버전 관리의 이름 변경과 구분.
- CCK 구현 제안: NOA 재검토 계획·미해결 작업 관리, aRDa 판본·문단 참조, 로컬 LLM 요청-증빙 의미 대조, 규칙 기반 완결성 검사.
- 비AI 비교안: 제출목록 강제화 + 파일차이 비교 + 보완 체크리스트와 비교.
- 검증 지표: 사건당 보완 왕복 횟수, 재검토 소요시간, 해결로 잘못 표시한 항목 비율, 변경영향 누락.
- 대상·분모: 동일 사건유형·난이도의 보완 차수 또는 요구 항목 단위. 종료·미종료 사건 모두 포함해 선택편향 점검.
- 반증 질문: 요청문 자체가 모호했는지, 법정 추가자료 때문에 재보완이 필요한지, 검토범위 축소가 누락을 키웠는지 확인.
- 권한·책임: AI의 합격·승인·증빙 진위 확정 제외. 서류 보완과 재시험 구분. 원 공식 승인·검토 이력 보존.
- 산정 상태: 미산정 · 공통 문서 연계 재사용, 요청ID 모델·차이 대조·검토화면·업무별 평가 증분 산정.

**제안 서비스 흐름**

1. 기존 접수시스템 / 요청·판본 연결: 사건ID·보완요청ID·제출차수와 원문 해시 연결. 잘못 연결된 제출물은 담당자 확인 전 사용 보류.
2. 규칙 + 로컬 LLM / 변경·해결 후보 대조: 필수 증빙 존재와 필드 일치는 규칙으로 확인. 비정형 설명이 요청 취지에 대응하는지는 근거 문단과 함께 후보 제시.
3. 전문 검토자 / 검토 범위 결정: 변경이 다른 요건에 영향을 주면 관련 부분까지 확대. 미변경 자료의 안전성을 자동 인정하지 않고 전문 검토자가 범위 확정.
4. NOA · 업무도구 / 다음 조치·완료 확인: 추가 보완·재시험·검토 종료 경로를 계획에 반영. 승인된 통보와 시스템 기록을 대조하며 미해결 요구가 남으면 종료 보류.

**납품물 후보**

- 차수별 요구–증빙 추적표
- 변경·미해결·추가 영향 검토안
- 보완 종료 및 후속처리 확인 기록

### C03. 바뀐 기준이 닿는 문서·진행 업무의 누락 방지

- 국민·기업 편익: 오래된 안내·양식에 따른 국민과 기업의 재작업 완화
- 사용자: 업무기준 소관부서, FAQ·서식 담당자, 진행 사건 검토자
- 부서 매핑 조건: 예시 협의부서. 법무·규정 소관과 각 업무의 적용 판단권은 별도 확인.
- 착수 사건: 확정된 규정·업무기준의 새 판본 수신
- 문제 가설: 신구 기준 자체는 관리되더라도 연관 FAQ·서식·진행 사건에 대한 반영 누락이 남는지 확인 필요.
- 현행 흐름 가설: 개정 알림 수신 → 담당자별 관련 문서 수색·수정
- 전환 흐름 제안: 적용시점 해석 → 영향관계 추적 → 변경 과업 조정 → 반영 검증·미해결 재계획
- 입력 자료: 개정 전후 원문, 시행·경과조치, 문서 참조관계, 게시·서식 버전, 진행 사건 기준일과 담당 조직.
- 재사용 검토: 기존 법령검색·개정알림·기준 버전 관리·문서검색·권한·로그의 활용.
- 추가 작업 후보: 개정 내용→영향 문서·사건→부서별 변경결정→실제 반영 결과의 연결. 기존 단순 알림·버전관리와 증분 구분.
- CCK 구현 제안: aRDa 기준·문서 관계와 판본, NOA 영향조사·부서 과업 조정·반영검증, 로컬 LLM 의미 관계 후보. 온톨로지 구축 범위는 자료 확인 후 결정.
- 비AI 비교안: 명시 조문 인용 검색 + 신구대비표 + 소관별 변경대장과 비교.
- 검증 지표: 전문가가 확인한 영향대상 재현율, 오탐 검토시간, 잘못된 소급 적용 후보, 반영 누락·지연.
- 대상·분모: 과거 개정 한 건에 대한 전문가 확정 영향대상 집합. AI·담당자 간 불일치는 미확정 목록으로 유지.
- 반증 질문: 문서가 기준을 인용만 할 뿐 변경할 필요가 없는지, 경과조치 때문에 기존 사건 적용이 유지되는지 확인.
- 권한·책임: 시행일·적용시점·경과조치 구분. AI의 법적 효력 확정·일괄 소급·공식 승인 자동취소 제외.
- 산정 상태: 미산정 · 영향관계·적용시점 모델 및 업무별 검증 증분. 기존 법령검색 엔진 중복 계상 제외.

**제안 서비스 흐름**

1. 기준 소관자 + 규칙 / 적용 범위 확인: 개정문·신구조문·시행일·경과조치와 사건 기준일을 확인. 해석 미확정 조건은 영향 판정 보류.
2. NOA · 로컬 LLM / 영향대상 후보 탐색: 명시 조문참조와 의미 연관성을 결합해 매뉴얼·FAQ·서식·진행 사건 후보 제시. 검색 누락 가능성을 함께 기록.
3. 소관 업무부서 / 변경·유지 결정: 후보별 적용 여부·담당자·완료조건 확정. 과거 사건 일괄 소급 또는 기존 공식 승인 취소를 자동 수행하지 않음.
4. 기존 문서·업무도구 / 반영 결과 재확인: 확정 변경판본과 게시·접수 서식을 대조. 누락·모순이 남으면 추가 확인과 후속 과업으로 재계획.

**납품물 후보**

- 개정–문서–사건 영향 후보 지도
- 소관별 변경·유지 결정표
- 게시·업무 반영 검증 및 잔여과업

## 4. 공통 아키텍처·검증

- 원 자료 → 기존 민원·접수·기준 시스템 / 읽기권한·사건ID 유지
- 근거 구성 → aRDa 문서·판본 + 허용된 조회도구 / 원문 위치·적용시점
- 과업 수행 → NOA 계획 → 로컬 LLM 의미 대조 + 규칙 검증 → 결과 확인 → 재계획
- 업무 적용 → 담당자 검토·확정 → 승인된 도구 실행 → 원 시스템 결과 재조회
- 편익 확인 → 완료조건·오류·재작업 관측 → 개선 후보·다음 과업

구현 제안이며 현재 제품의 해당 기능·연계 완료 주장과 구분. Agentic OS는 기존 계약에 미포함이라는 사용자 확인을 반영. 기능 자체와 업무별 증분의 재사용·납품 경계는 별도 합의.

- 1. 실제 사건 확보: 최근 처리한 사건의 처음–보완–종결 전체 자료와 단계별 시간을 권한 범위에서 확보. 자료 미확보 시 추정치를 성과로 사용하지 않음.
- 2. 비교안 구성: 현행 업무 / 체크리스트·검색·규칙 개선 / CCK AX+SI를 같은 대상과 완료조건으로 비교.
- 3. 이력 재현: 담당자 정답을 검토한 과거 사건으로 읽기 전용 비교. 쉬운 성공 건만 선택하지 않고 미완료·예외·반려를 포함.
- 4. 업무 적용 검증: 실제 작성·발송·게시·승인은 정해진 책임자가 수행. 권한 없는 자료 접근과 근거 없는 상태 확정 여부 별도 확인.
- 5. 도입 판단: 검토부담·누락·보완왕복·국민 불편을 함께 평가. 기준선과 허용한계는 사전 합의; 순효과가 없으면 비AI 개선 또는 후보 유보.

단계 규모와 무관하게 요구분석·보안·연계·시험·인수 절차 유지. 공통 기능 1회 + 업무별 추가 공수 + 확인된 사용료·운영비로 구성. 신규 인프라 0원, 감원 인원 환산 없음. 현업 범위 미확정으로 금액 미산정.
