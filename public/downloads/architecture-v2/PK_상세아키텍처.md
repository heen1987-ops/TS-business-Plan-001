# PK 주차안전처 상세 아키텍처

공고 미매핑·논리 상세 설계 / 실제 배포 구조·제품기능 검증과 구분

- 목적: 장치별 중요 미흡을 실제 보수·필요한 공식 확인으로 해소하고 확인 없는 종결과 반복 미흡을 줄인다.
- 기존 기반: 기계식주차장 검사·점검·보수·공식 결과 원천
- 식별단위: 장치–미흡–보수–공식 확인
- 공통키: case_id + 대상키 + source_version + plan_version
- 공식 판단: 해당 업무의 현업 담당·전문가 및 원시스템의 공식 권한자. 내부 전결·대결·위탁범위 확인 후 확정.
- 제외·전문가 책임: 장치 가동·운행 제어, AI 이용재개 승인, 보수·현장검사 대체

## 데이터·완료조건

- 필드: facility_id / device_id / finding_id / 설계·부품 판본 / 적용기준 / 보수 실행증거 / 필요한 재확인 / 공식 결과 / 실제 이용상태 / 후속관측
- 원장 관계: 공식 결과는 원시스템 ID·판본·조회시각으로 참조; 로컬 검토상태와 구분
- 완료: 해당 미흡의 조치증거·필요한 공식 확인·책임자 판단이 연결되고 잔여조건을 인계
- 예외: 일부 미흡 해소·부품 주문·정상 입력만으로 전체 안전확보나 이용재개를 확정하지 않음
- 허용 인계: 담당자가 확인한 전문검토·후속과업 인계

## 기존 요구 추적

기존 요구사항을 상세 모듈로 추적하는 설계 매핑. 기존 요구ID·문구·검수·산정값은 변경하지 않음.

| 기존 ID | 요구 | 상세 모듈 | 기존 시험 | 수용 기준 |
|---|---|---|---|---|
| PK-DAR-001 | 사건·대상·판본 | PK-M01 | PK-ADD-T01 | 타 대상·타 판본 자료를 섞은 사건에서 오연결을 표시하고 미확인 상태를 유지 |
| PK-SFR-002 | 근거에 따른 검증계획 | C05 | PK-ADD-T02 | 필수 확인·선행조건·담당·완료증거가 계획에 포함되고 불필요한 도구실행을 막음 |
| PK-SFR-003 | 승인된 조회·검증 수행 | C06 | PK-ADD-T03 | 정상·권한거부·자료부족·응답미확인을 구분하며 허용범위 밖 명령이 발생하지 않음 |
| PK-SFR-004 | 새 근거에 따른 재계획 | C05 | PK-ADD-T04 | 변경 전후 계획·근거·해당 승인 영향이 연결되고 무관한 결과는 자동 변경하지 않음 |
| PK-SFR-005 | 공식 결과와 완료조건 | PK-M04 | PK-ADD-T05 | 일부 미흡 해소·부품 주문·정상 입력만으로 전체 안전확보나 이용재개를 확정하지 않음 |
| PK-SER-006 | 자료·실행 권한 | C01 | PK-ADD-T06 | 타 사건 자료·문서 내 우회 지시·회수된 권한으로 조회 또는 실행하지 못함 |

## 공통 설계 참조

[공통 모듈·연계 계약·데이터·배치·복구](00_공통아키텍처.md)

논리 설계의 각 연결은 AV2-I01~I12 참조. 원시스템 API 미확보 시 승인된 파일 및 담당자 수동 인계. 실제 연계 미검증.

공통 모듈은 도입 단위에서 1회 산정, 업무별 규칙·연계·검증은 증분 산정. 기존 계약 납품·제품 사용권·추가 개발 대조 전 금액·MM 추가 없음. 기존 원장의 산정값 유지.
