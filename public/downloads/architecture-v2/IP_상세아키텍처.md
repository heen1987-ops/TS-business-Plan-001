# IP 검사기획처 상세 아키텍처

공고 미매핑·논리 상세 설계 / 실제 배포 구조·제품기능 검증과 구분

- 목적: 확인된 안전미흡을 적정 조치·정정과 공식 재확인까지 연결하고 예방 가능한 재방문을 줄인다.
- 기존 기반: 검사결과·예약·공식 재검사/정정 원천
- 식별단위: 차량–검사건–부적합 항목
- 공통키: case_id + 대상키 + source_version + plan_version
- 공식 판단: 해당 업무의 현업 담당·전문가 및 원시스템의 공식 권한자. 내부 전결·대결·위탁범위 확인 후 확정.
- 제외·전문가 책임: 정비 원인진단, 검사 판정·면제·기한 연장, 위험한 자가정비·운행 허용

## 데이터·완료조건

- 필드: vehicle_ref / case_id / item_id / 기준판본 / 적용일 / 검사 회차 / 공식 판정 / 조치 상태 / 조치증거 / 재검사·정정 결과 ID / 조회시점
- 원장 관계: 공식 결과는 원시스템 ID·판본·조회시각으로 참조; 로컬 검토상태와 구분
- 완료: 원래 항목별 공식 해소·정정 결과를 조회·대사하고 남은 항목·미추적을 구분
- 예외: 견적서만 있거나 공식 결과가 없으면 조치·전체 사건을 완료로 표시하지 않음
- 허용 인계: 담당자가 확인한 전문검토·후속과업 인계

| IP-SFR-002 | 근거에 따른 검증계획 | C05 | IP-ADD-T02 | 필수 확인·선행조건·담당·완료증거가 계획에 포함되고 불필요한 도구실행을 막음 |

## 공통 설계 참조

[공통 모듈·연계 계약·데이터·배치·복구](00_공통아키텍처.md)

논리 설계의 각 연결은 AV2-I01~I12 참조. 원시스템 API 미확보 시 승인된 파일 및 담당자 수동 인계. 실제 연계 미검증.

공통 모듈은 도입 단위에서 1회 산정, 업무별 규칙·연계·검증은 증분 산정. 기존 계약 납품·제품 사용권·추가 개발 대조 전 금액·MM 추가 없음. 기존 원장의 산정값 유지.
