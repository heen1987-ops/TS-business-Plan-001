# RI 규제혁신처 상세 아키텍처

공고 미매핑·논리 상세 설계 / 실제 배포 구조·제품기능 검증과 구분

- 목적: 허가조건 변화와 현장의 불일치를 조기에 확인하여 안전한 실증 준비·이행을 돕는다.
- 기존 기반: 샌드박스 신청·승인·사후관리 기록
- 식별단위: 특례 조건·시점·공간·운영 변경
- 공통키: case_id + 대상키 + source_version + plan_version
- 공식 판단: 해당 업무의 현업 담당·전문가 및 원시스템의 공식 권한자. 내부 전결·대결·위탁범위 확인 후 확정.
- 제외·전문가 책임: 특례 자동 승인·연장, 공식 허가조건 변경, 사업화 성공 보장

## 데이터·완료조건

- 필드: 실증 사건키 / 공식 조건 원문 / 유효기간·구역 / 책임자·증거 / 변경요청 버전 / 공식 회신·이행 상태
- 원장 관계: 공식 결과는 원시스템 ID·판본·조회시각으로 참조; 로컬 검토상태와 구분
- 완료: 공식 회신과 현장 이행 증거가 대상 조건·판본에 맞게 연결됨
- 예외: 기업의 변경계획만으로 허가조건이 바뀐 것으로 처리하지 않음
- 허용 인계: 조건별 확인·보완 과업의 승인된 인계

## 기존 요구 추적

기존 요구사항을 상세 모듈로 추적하는 설계 매핑. 기존 요구ID·문구·검수·산정값은 변경하지 않음.

| 기존 ID | 요구 | 상세 모듈 | 기존 시험 | 수용 기준 |
|---|---|---|---|---|
| RI-SFR-001 | 조건 원문 연결 | RI-M01 | RI-T-001 | 조건별 대상·시점·구역·책임·증거를 원문 위치와 연결 |
| RI-SFR-002 | 변경영향 분석 | RI-M02 | RI-T-002 | 운영 변경이 영향을 주는 조건과 영향 없음의 근거를 구분 |
| RI-SFR-003 | 공식 경로 계획 | RI-M04 | RI-T-003 | 변경검토 필요사항과 기업 준비·기관 확인과업을 분리 |
| RI-SFR-004 | 조건 변경 재계획 | RI-M02 | RI-T-004 | 운영구역 변경 후 영향받는 후속 실행의 기존 승인 토큰 재사용을 차단하고 재검토를 요청하고 재확인 과업 생성 |
| RI-SFR-005 | 영향 과업 보류 | C06 | RI-T-005 | 공식 확인 전 영향받는 실행만 보류하고 무관한 확인업무는 구분 |
| RI-SFR-006 | 회신·현장 대사 | C10 | RI-T-006 | 공식 회신과 현장 이행은 별도 증거로 확인 |

## 공통 설계 참조

[공통 모듈·연계 계약·데이터·배치·복구](00_공통아키텍처.md)

논리 설계의 각 연결은 AV2-I01~I12 참조. 원시스템 API 미확보 시 승인된 파일 및 담당자 수동 인계. 실제 연계 미검증.

공통 모듈은 도입 단위에서 1회 산정, 업무별 규칙·연계·검증은 증분 산정. 기존 계약 납품·제품 사용권·추가 개발 대조 전 금액·MM 추가 없음. 기존 원장의 산정값 유지.
