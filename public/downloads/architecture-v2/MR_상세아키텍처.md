# MR 모빌리티연구처 상세 아키텍처

공고 미매핑·논리 상세 설계 / 실제 배포 구조·제품기능 검증과 구분

- 목적: 필수 검정의 신뢰성을 유지하면서 변경된 제품에 맞는 입증을 준비하고 반복 보완을 줄인다.
- 기존 기반: TIMS 앱미터 검정
- 식별단위: 제품·설정·시험회차
- 공통키: case_id + 대상키 + source_version + plan_version
- 공식 판단: 해당 업무의 현업 담당·전문가 및 원시스템의 공식 권한자. 내부 전결·대결·위탁범위 확인 후 확정.
- 제외·전문가 책임: AI 적합·부적합 확정, 확인서 발급 권한 대체, 필수 주행시험 생략

## 데이터·완료조건

- 필드: product_id·버전 / configuration_hash / test_round_id / 기준판본·적용일 / 증빙 문서 위치 / 공식 검정결과
- 원장 관계: 공식 결과는 원시스템 ID·판본·조회시각으로 참조; 로컬 검토상태와 구분
- 완료: 공식 검정 결과·보완경로가 정확한 제품·설정·회차와 대사되고 잔여 과제가 인계됨
- 예외: 주행 검정 부적합은 해당 공식 주행 절차로, 증빙 미충족은 신청·자료 보완 경로로 구분
- 허용 인계: 검정 검토요청 묶음의 등록·담당자 인계

논리 설계의 각 연결은 AV2-I01~I12 참조. 원시스템 API 미확보 시 승인된 파일 및 담당자 수동 인계. 실제 연계 미검증.
