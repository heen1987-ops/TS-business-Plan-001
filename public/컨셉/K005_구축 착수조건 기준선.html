K005. 구축 착수조건 기준선

05 / 92 · 원문 작업 W01.05 · 독립 컨셉 상세안

다섯 번째 컨셉의 결과물은 **「착수조건·미해결사항 검토안」**임. TS 현업·사업기획 담당자가 2027년 AX 과제를 검토할 때, 대상·자료권한·재원·책임이 어디까지 확인됐는지를 근거로 구축 진행·범위 축소·보류를 판단하도록 정리하는 항목임.

아래 확인항목·판단방법·사례는 원문 K005를 구체화한 설계 제안임. TS의 실제 착수 승인이나 예산 확보를 확인한 결과가 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 계획을 만들었다는 것과 시작할 수 있다는 것은 다름

K004까지는 업무를 어떻게 처리할지 설계했다면, K005에서는 그 설계를 실제로 추진할 조건이 있는지 확인함.

  • 대상업무를 정하고 기능을 설계했더라도, 실제 자료를 사용할 수 있는지, 해당 범위의 재원이 확인됐는지, 결과를 검토하고 책임질 담당자가 정해졌는지는 별개임.
  • 제안서가 완성됐다고 자료와 예산까지 생기는 것은 아닙니다.

따라서 K005의 질문은 다음과 같습니다.

“지금 제시한 범위를 시작할 근거가 있는가? 부족하다면 어느 범위를 줄이거나, 무엇이 해결될 때까지 보류해야 하는가?”

  • 여기서 기준선은 특정 시점에 어떤 범위·자료·재원·책임을 어떤 근거로 검토했는지 기록한 판단 기준임.
  • 불확실한 전제를 확정 사실로 바꾸는 것이 아닙니다.

세 가지 상태를 반드시 구분

구분 실제로 의미하는 것 의미하지 않는 것
검토안 작성·상신 확인된 조건과 미해결사항을 정리하고 진행·축소·보류 의견을 제시 구축 승인·재원 확보
실제 의사결정 권한 있는 결정자가 특정 범위의 진행 여부와 조건을 결정 검토자가 작성한 권고안 자체
실제 착수 승인·허용된 범위의 작업이 실제로 시작됐다는 근거가 존재 승인문서가 있다는 이유만으로 작업 시작까지 추정

K005의 결과가 ‘보류 검토안’이어도 정상적인 산출물임. 부족한 조건을 발견하고 해소 담당과 재검토 방법을 남기는 것이 이 컨셉의 목적이기 때문임.

  • 반대로 검토안을 작성했다는 이유로 관리대장에 ‘착수 완료’나 ‘예산 확보’를 표시하면 안 됩니다.
  • 원문도 실제 승인 전 착수·재원 확보로 표시하지 않도록 제한함.

2. 무엇을 확인할 것인가: 대상·자료권한·재원·책임

  • 원문의 입력자료는 대상·자료권한·재원·책임 확인자료임.
  • 네 항목을 단순한 체크 표시가 아니라 이번에 시작하려는 범위와 대응하는 근거로 확인하도록 구체화했음.
확인 축 구체적으로 확인할 내용 필요한 근거의 예시 확인 완료로 취급하지 않을 설명
① 대상 어느 업무유형의 어떤 처리·자료·결과물을 대상으로 하는가? 무엇을 제외하는가? 대상업무·사건 경계, 포함·제외 범위, 역할배분, 기존 기능 대응 결과 “철도 업무 전반”, “AI 고도화 추진”
② 자료권한 어떤 자료를 누가 어떤 목적·환경·기간에 열람·분석·저장할 수 있는가? 자료목록, 이용조건 확인기록, 제공 주체·방법·시점, 제한사항 “자료는 보유 중”, “나중에 제공 예정”
③ 재원 현재 요청 범위에 필요한 비용과 확인된 재원 단계·목적·기간이 대응하는가? 범위별 소요 근거, 요구·승인·배정 등 확인된 문서와 조건 “예산을 요청했다”, “다른 사업에 예산이 있다”
④ 책임 누가 업무결과를 확인하고, 남은 조건을 해소하며, 진행 여부를 결정하는가? 역할 확인기록, 소관 담당 의견, 검토·결정 주체, 필요한 운영 인계 책임 “연락할 담당자는 있다”, “수행사가 알아서 한다”

대상: 이름이 아니라 시작할 범위를 특정

‘철도 안전심사 AI’라는 명칭만으로는 착수조건을 판단하기 어렵습니다.

  • 예를 들어 과거 완료사례의 오프라인 검토지원, 실제 진행 중인 사건의 검토지원, 검토결과의 업무 원장 반영은 사용하는 자료와 실행 범위가 다릅니다.
  • 이번 결정이 어디까지를 대상으로 하는지 적어야 함.

앞선 K001~K004의 결과를 참조하되, 초안이 존재한다는 사실을 현업 확인 완료로 바꾸지 않음. K005에서 해당 컨셉들을 다시 작성하거나 통합하는 것도 아닙니다.

자료권한: 보유·열람·분석·저장을 분리

  • 양식 열람이 허용됐다고 실제 사건자료의 AI 분석까지 허용된 것은 아닙니다.

  • 실제 자료를 제공받았더라도 예정한 환경에 저장하거나 모델 학습에 사용할 수 있는지는 별도로 확인함.

  • K005에서는 이번 착수에 필요한 자료·사용행위·처리환경·기간의 확인 결과를 기록함.

  • 전사 자료권리 등록대장이나 접근통제 시스템을 새로 만드는 단계로 확대하지 않음.

재원: 금액보다 해당 범위와의 관계를 확인

  • 소요 산정액·요구액·승인액·배정액·집행액을 구분하는 기록방식을 제안함.

  • 금액이 적혀 있다는 사실보다, 어느 단계의 문서가 어떤 작업을 뒷받침하는지가 중요함.

  • 기획비가 확인됐다고 구축비까지 확보한 것으로 쓰지 않고, 전체 프로그램 예산이 있다고 특정 신규 기능에 사용할 수 있다고 추정하지 않음.

  • 실제 적용할 예산·계약 절차는 소관 담당의 확인사항으로 남깁니다.

책임: 협의 창구와 결정권자를 구분

자료를 전달하는 담당자, 현업 결과를 검토하는 담당자, 미해결 조건을 해소하는 담당자, 구축 진행을 결정하는 담당자는 다를 수 있음.

  • 같은 사람이 여러 역할을 맡더라도 어떤 역할로 무엇을 확인했는지 기록함.
  • 연락처를 확보했다는 이유만으로 업무·승인·운영 책임이 모두 정해진 것으로 보지 않음.

3. 확인 상태와 미해결사항은 어떻게 기록하는가

  • 원문에는 점수제나 세부 상태코드가 정해져 있지 않음.
  • 다음은 확인 결과를 구분하기 위한 기록방식 제안임.
상태 기록 기준 이후 처리
확인 충족 해당 범위·행위·시점의 조건을 근거와 함께 확인 근거·확인자·확인일·유효범위 기록
확인 미충족 필요한 조건이 충족되지 않았음을 확인 영향받는 작업과 보완·축소·보류 조건 기록
미확인 자료 미확보·검토 대기·해석 상충으로 판단 근거 부족 추가자료·확인 주체·재검토 시점 기록
적용 제외 현재 검토 범위에는 필요하지 않은 조건임을 근거와 함께 확인 제외 이유와 범위 변경 시 재검토 조건 기록

미확인과 미충족은 다릅니다. 승인 여부를 확인하지 못한 상태를 승인 거절로 쓰지 않고, 반대로 승인자료가 없다는 이유로 별문제가 없다고 처리하지도 않음.

  • 일부만 확인됐다면 행을 나누는 편이 명확함.
  • 예를 들어 ‘자료권한 일부 충족’ 한 줄 대신 다음처럼 구분함.

양식 열람: 확인 충족.
실제 사건자료 분석·저장: 미확인.

조건 한 건에 남길 정보

조건 ID → 적용 대상·범위·시점 → 필요한 확인사항 → 현재 상태 → 근거자료 → 확인자 → 영향받는 작업 → 해소 담당·방법 → 완료증거 → 재검토 시점

‘자료 확보 필요’로 끝내지 않고, 어떤 자료를 어떤 방식으로 사용할 수 있어야 하며, 누가 무엇을 확인해야 문제가 해소되는지 적습니다.

예를 들어 다음 문장은 부족함.

“자료 제공 예정이므로 착수 가능.”

다음처럼 바꾸는 것이 적절함.

“실제 심사자료의 분석·저장 허용범위는 미확인. 자료 소관 담당이 대상·목적·환경·기간을 확인한 근거를 제공한 뒤, 해당 자료를 사용하는 작업의 착수 여부를 재검토.”

해소 목표일과 실제 해소 여부도 분리함. 예정일이 지났다는 이유로 조건이 충족되거나 승인이 발생한 것으로 처리하지 않음.

4. 진행·축소·보류는 어떻게 구분하는가

  • 원문의 세 가지 방향인 진행·축소·보류를 유지함.
  • 별도의 점수나 ‘조건부 진행’ 등급을 추가하지 않고, 각 방향의 적용범위·제한·남은 조건을 구체적으로 적는 방식임.
검토 방향 적용할 상황 상신안에 반드시 남길 내용
진행 제시한 범위에 필요한 대상·자료권한·재원·책임의 확인 근거가 있음 진행 대상, 포함·제외 범위, 근거, 결정자, 남은 후속 관리사항
축소 원안 전체는 어렵지만 분리 가능한 일부 범위의 조건을 확인할 수 있음 남길 범위, 제외 범위, 산출물·비용·일정·검증 변경, 축소 범위의 착수조건
보류 핵심 조건이 미해결이거나 독립적으로 수행할 범위의 근거가 부족함 보류 대상, 이유, 해소 담당·방법, 필요한 증거, 재상신 조건·시점

진행: 지금 필요한 조건을 미래 약속으로 대체하지 않음

현재 요청한 작업의 필수조건과 이후 단계의 관리조건을 구분함.

  • 지금 실제 자료를 분석하려는데 이용조건이 미확인이라면, “나중에 확인한다”는 문구로 충족 처리하지 않음.
  • 반면 아직 대상이 아닌 차년도 확장조건은 후속 확인사항으로 남길 수 있음.

확인한 범위에 한해 진행을 검토하는 것이지, 관련된 모든 업무와 미래 단계까지 허용하는 것이 아닙니다.

축소: 규모만 줄이는 것이 아니라 결과물도 다시 정의

  • 자료 이용권한이 없는 상태에서 표본 수만 줄인다고 권한 문제가 해결되지는 않음.

  • 축소된 범위 자체에 필요한 조건을 다시 확인해야 함.

  • 또한 실서비스 적용을 제외하고 오프라인 검토만 수행한다면, 결과물도 한정된 검토지원 결과와 제약 보고로 바뀝니다.

  • 원안의 실사용 성과까지 달성한 것으로 보고하지 않음.

보류: 중단 사유와 다시 검토할 조건을 함께 기록

‘보류’는 과제가 없거나 영구 종료됐다는 뜻이 아닙니다.

  • 무엇이 해결되면 어느 범위를 다시 검토할 수 있는지 남겨야 함.
  • 별도로 허용된 기획 협의는 이어갈 수 있더라도, 그 활동을 구축 착수로 표시하지 않음.

확인된 항목이 많다는 이유로 미해결 필수조건을 상쇄하지 않는 것도 중요함. K005에는 ‘몇 개 중 몇 개 충족이면 진행’이라는 원문 기준이 없습니다.

5. 작성 예시: 가상 철도 심사자료 검토지원

  • 다음은 판단방식을 설명하기 위한 가상 사례임.
  • 실제 TS의 자료권한·예산·담당자 상태를 확인한 결과가 아닙니다.

가상 원안

검사유형 A의 실제 심사자료를 활용하여 사전검토와 시정조치 확인을 지원하고, 결과를 기존 업무 원장에 반영하는 범위로 가정함.

확인 축 확인된 것으로 가정한 내용 남아 있는 조건
대상 검사유형 A와 사전검토·조치확인 범위를 업무부서가 검토 원장 반영의 구체적 허용범위 추가 확인
자료권한 비식별 양식의 열람 허용 실제 심사자료의 AI 분석·저장·처리환경 허용 미확인
재원 해당 범위의 예산요구 자료 존재 승인·배정·집행 가능범위의 확인자료 미확보
책임 협의 창구 확인 결과 확인·원장 반영·운영 인계·진행 결정권 확인 필요

이 상태에서 작성할 검토안

검토 방향: 원안 구축 착수 보류.

실제 심사자료의 이용조건, 해당 범위의 재원, 결과 확인 및 진행 결정권이 확인되지 않아 원안 구축을 진행할 근거가 부족함. 자료·재원·책임별 해소 담당과 필요한 확인자료를 지정하고, 근거 확보 후 해당 범위의 진행 여부 재검토 필요.

  • 양식 열람과 기획 협의가 별도로 허용되어 있다면, 그 범위에서 처리절차와 산출물 정의를 보완할 수 있음.
  • 그러나 이를 ‘축소 구축 착수’나 ‘실자료 검증 완료’로 기록하지 않음.

미해결사항 기록 예시

미해결 조건 해소 담당 역할안 필요한 완료증거
실제 자료 분석·저장 허용 자료 소관·이용조건 확인 역할 대상·목적·환경·기간을 특정한 이용조건 확인 근거
해당 범위의 재원 예산·사업총괄 소관 역할 확인된 예산 단계·대상 범위·제약을 보여주는 문서
결과 확인·진행 결정권 업무·사업 책임 확인 역할 해당 역할과 권한 범위·담당 확인
원장 반영범위 업무·정보화 소관 역할 읽기·쓰기 범위와 적용조건 확인 또는 제외 결정
  • 실제 담당자는 확인 후 기입함.
  • 이 표에 역할을 적었다고 해소 담당 지정이나 승인이 완료된 것은 아닙니다.

이후 ‘축소안’을 검토할 수 있는 상황

가상으로, 과거 완료사례 일부를 승인된 내부 환경에서 오프라인 검토할 이용조건·재원·검토 역할은 확인됐지만, 실서비스와 원장 반영 조건은 미확인이라고 가정함.

이때는 다음과 같이 축소안을 작성할 수 있음.

남길 범위: 허용된 과거 완료사례의 사전검토 지원과 전문가 비교 검토.

제외할 범위: 실시간 업무 처리, 원장 쓰기, 대외 발신, 확대 적용.

변경할 결과물: 원안 전체 운영체계가 아니라 한정 범위의 검토지원 결과·오류·제약 보고.

재확인할 사항: 축소된 범위의 비용·일정·검증조건·역할.

  • 이 역시 축소 상신안임.
  • 실제 결정이 있기 전에는 착수 확정으로 표시하지 않음.

6. 수행 순서와 K005의 범위

수행은 검토범위 고정 → 근거 대조 → 미해결 영향 구분 → 해소계획 작성 → 진행·축소·보류 상신 → 실제 결정 기록 순서로 제안함.

순서 수행내용 남길 결과
1. 검토범위 고정 이번 판단의 대상·행위·기간·버전 확인 기준일과 범위 식별정보
2. 근거 대조 대상·자료권한·재원·책임 자료 확인 조건별 상태·근거·미확인 사항
3. 영향·해소 정리 미해결 조건이 영향을 주는 작업과 해소방법 확인 영향범위·담당·필요 증거·재검토 시점
4. 결정안 작성·상신 진행·축소·보류를 근거와 함께 제시 G0 검토자료와 상신안
5. 실제 결정·변경 기록 실제 결정이 있으면 범위·조건·근거를 기록 결정기록 또는 미결정 상태
  • 원문에서 사용하는 G0 표기는 유지함.
  • 다만 이를 TS가 현재 운영하는 공식 승인절차로 확인한 것은 아닙니다.

이번 컨셉에서 끝낼 일

조건별 근거와 확인 상태, 미해결 영향, 해소 담당·방법, 재검토 조건, 진행·축소·보류 상신안까지 작성함.

반면 실제 예산 배정, 자료 이용권 부여, 계약·발주, 시스템 구축, 성능검수, 실서비스 적용 승인, 92개 컨셉의 통합은 K005의 범위에 포함하지 않음.

다른 컨셉의 결과를 참조하되, 그 결과의 완료 상태를 자동으로 승계하지도 않음.

조건이 바뀌면 기준선도 다시 확인

대상업무, 자료의 이용목적·환경·기간, 재원 범위, 확인·결정 책임이 바뀌면 기존 검토결과가 새 범위에도 적용되는지 재확인하도록 제안함.

  • 예를 들어 오프라인 검토를 승인받은 뒤 실제 사건 처리와 원장 반영을 추가한다면, 기존 결정의 범위를 그대로 확대해서 사용하지 않음.
  • 변경 전후와 영향받는 조건을 기록함.

7. 완료기준·역할·기간

  • 원문의 완료기준은 **“G0 검토자료에 과제별 결정자·근거·남은 조건이 기록”**되는 것임.
  • 실제 구축 승인을 받아야만 K005 문서를 작성할 수 있다는 뜻으로 바꾸지 않음.

결정자나 핵심 근거가 미확인인데 서식만 작성했다면 ‘검토안 초안’임. 반대로 필요한 기록을 갖춘 보류 검토안은 K005의 유효한 결과가 될 수 있음.

  • 수행 역할은 원문대로 수행 기획·PM, 결과 확인·승인은 TS 과제별 사업책임자, 협의·검토는 현업·정보화·예산으로 유지함.

  • 실제 담당 배정이나 권한 위임은 별도 확인사항임.

  • 기간은 원문의 2~5근무일 가정임.

  • 이는 자료를 대조해 검토안과 미해결 조건을 작성하는 기획 작업기간이지, 예산 승인·자료 제공·계약·실제 구축 착수까지 완료한다는 일정은 아닙니다.

8. 바로 사용할 보고서 문안

AX 구축 검토 대상별로 업무 범위·자료 이용권한·재원·책임의 확인 상태를 대조하고, 진행·축소·보류 판단에 필요한 근거와 미해결 조건을 기록할 필요. 미해결 조건은 영향을 받는 작업, 해소 담당·방법·완료증거 및 재검토 시점과 연결하여 관리. 검토안 작성·상신·실제 결정·실제 착수를 구분하고, 실제 승인 전 착수 또는 재원 확보로 표시하지 않도록 통제. 축소안은 남길 범위의 독립 수행 가능성과 자료·재원·책임 조건을 재확인하고, 제외된 기능·검증·효과를 원안의 완료성과로 해석하지 않도록 명시.

제공한 MD에는 검토범위·기준선 표지, 착수조건 확인표, 미해결사항·해소계획 대장, 진행·축소·보류 상신안, 실제 결정·허용범위 기록서, 변경 재검토 기록서를 포함했음.

K005의 최종 결과는 ‘착수하겠다’는 선언이 아니라, 어떤 범위는 진행을 검토할 수 있고 어떤 범위는 무엇이 해결될 때까지 멈춰야 하는지를 결정자와 근거까지 연결해 설명하는 검토안임.
