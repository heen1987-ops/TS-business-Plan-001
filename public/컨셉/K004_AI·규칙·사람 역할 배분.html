K004. AI·규칙·사람 역할 배분

04 / 92 · 원문 작업 W01.04 · 독립 컨셉 상세안

  • 네 번째 컨셉의 결과물은 **「처리주체·수동대체 경계표」**임. TS 현업·정보화·사업기획 담당자가 2027년 AX 적용을 검토할 때, 어느 단계는 AI가 보조하고, 어느 단계는 규칙으로 처리하며, 무엇을 담당자가 판단해야 하는지를 정하는 항목임.

  • 처리방식의 선택 근거와 AI를 사용하지 못할 때의 대체 경계까지 명확히 하는 것이 목적임.

  • 아래 배분기준·사례·수동대체 방식은 원문 K004를 구체화한 설계 제안임.

  • 실제 TS 업무분장이나 자동처리 허용범위를 확정한 결과는 아니며, 다른 컨셉과의 묶음은 지정하지 않음.

1. 컨셉의 핵심: 업무 전체가 아니라 ‘처리행위별’로 역할을 나눔

K004는 업무마다 ‘AI 담당’ 또는 ‘사람 담당’이라는 이름표를 붙이는 작업이 아닙니다. 한 업무 안에서도 자료를 읽는 일, 값을 비교하는 일, 예외를 해석하는 일, 결과를 확정하는 일은 서로 다르기 때문임.

예를 들어 ‘제출기한 검토’라는 하나의 단계에도 다음 행위가 포함될 수 있음.

서술형 문서에서 기한 표현 찾기 → 기준일·예외 해석 → 확정된 날짜 비교 → 지연 여부에 따른 조치 판단

이 전체를 AI에 맡기거나 전부 단순 계산으로 취급하지 않고, 행위별로 나누어 다음과 같이 설계함.

AI는 조건 후보와 원문 위치를 제시하고, 담당자는 필요한 해석과 입력을 확정하며, 규칙은 확정된 값을 비교하고, 담당자는 그 결과의 업무상 의미와 후속조치를 판단하도록 배분.

  • 이미 확정된 기한과 접수시각이 구조화되어 있다면, 그 비교 단계에는 AI가 필요하지 않을 수 있음.
  • 단순 날짜 비교까지 AI로 처리해야 AX가 되는 것은 아닙니다.

원문도 기한·필수항목은 규칙, 서술형 대조는 AI 보조, 판단·현장확인은 담당자에게 배분하도록 제시함.

처리방식과 책임·실행권한은 별도

경계표에는 다음 세 가지를 구분해 기록하는 안임.

구분 정해야 할 내용 혼동하지 않을 사항
처리방식 AI 보조·명시적 규칙·담당자 판단의 범위와 순서 AI가 초안을 만들었다고 업무 책임까지 맡는 것은 아님
결과 확인·확정 역할 누가 어떤 원문·기준·질문을 확인하고 결과를 확정하는가 ‘사람 확인’이라는 문구만으로 실제 확인사항이 정의되지는 않음
실행·반영 범위 내부 후보 제시, 저장, 원장 변경, 대외 발신, 종결 중 어디까지 허용되는가 자료 열람 권한과 발신·수정·종결 권한은 동일하게 취급하지 않음

‘AI가 처리하고 사람이 최종 확인’만으로는 부족함. 사람이 무엇을 보고, 어떤 질문에 답하고, 어디까지 확정하는지를 명시해야 실제 업무에 사용할 경계표가 됩니다.

2. AI·규칙·담당자에게 무엇을 배분할 것인가

다음은 원문의 세 가지 처리방식을 적용하기 위한 상세 기준안임.

처리방식 맡길 범위안 적용 전 확인조건 결과의 지위·제한
AI 보조 서술형 조건 추출, 관련 근거 탐색, 문서 간 차이 후보, 검토·요청 초안 자료 이용 가능 여부, 대상·기준, 원문으로 확인할 수 있는 출력 후보·초안으로 제공. 근거 없는 값 보충이나 최종 적합·위반·종결 확정은 제외
명시적 규칙 확정 기한 비교, 필수 입력·첨부 존재, 단위·기간·버전·대상 일치 검사 입력의 확정 여부, 규칙 버전, 예외·적용범위 정의된 비교결과로 제공. 자료 존재만으로 실질 이행까지 인정하지 않음
담당자 판단 기준·예외 해석, 자료의 업무상 적합성, 실제 현장 확인, 조치 필요와 최종 확정 판단할 역할·권한, 원문·기준·미확인 정보 판단 근거와 결과를 기록. 확인할 수 없는 사항은 임의 확정하지 않음

규칙 처리도 ‘입력이 확정된 경우’로 한정

확정된 제출기한과 접수시각을 비교하는 일과, 문장에서 제출기한을 해석하는 일은 구분해야 함.

  • 예외 문구가 있거나 기준일이 불명확한데 AI가 추출한 날짜를 그대로 규칙에 넣으면, 계산은 맞아도 적용한 조건은 잘못된 상태가 될 수 있음.
  • 따라서 해당 단계에는 후보 입력 → 필요한 담당자 확인 → 확정 입력의 구분을 둡니다.

반대로 이미 승인된 구조화 입력을 받는 단계라면, 동일한 값을 AI로 다시 해석하는 절차를 넣을 이유가 있는지 검토함.

사람이 판단한다고 자료 준비까지 모두 수작업일 필요는 없음

현장 확인이나 최종 판단을 담당자에게 남기더라도, 관련 자료 찾기·차이 정리·미확인 질문 작성은 AI 보조 대상으로 검토할 수 있음.

따라서 ‘사람 판단 단계’에는 다음 두 내용을 함께 적습니다.

담당자에게 미리 제공할 자료: 적용기준, 관련 원문, 비교결과, 미확인 사항.

담당자가 직접 결정할 질문: 해당 증빙을 인정할 수 있는지, 예외가 적용되는지, 추가자료·현장 확인이 필요한지, 어떤 조치를 할지.

이렇게 해야 담당자에게 단순히 승인 버튼만 남기는 설계와 구분됩니다.

3. 어떤 입력을 받아 무엇을 작성하는가

  • 원문의 입력자료는 병목표·비중복표임.
  • 즉, 앞서 확인할 업무 부담과 기존 기능의 충족 여부를 바탕으로 처리방식을 정하도록 되어 있음.
입력자료 K004에서 사용할 내용 아직 확인되지 않았다면
병목표 탐색·대조·판단·보완 중 실제 부담이 큰 구간과 실측·추정 상태 AI 효과를 확정하지 않고 지원 후보로 기록
비중복표 기존 기능의 충족분, 설정변경·추가구현·확인불가 기존 기능 부재나 신규 개발 필요를 임의 확정하지 않음
업무사건 경계 정보 대상업무·시작·종료·포함·제외·인계 지점 역할배분의 적용범위를 잠정으로 표시
적용 기준·조건 기한·필수항목·예외·유효기간·버전 미해석 조건을 실행규칙으로 취급하지 않음
현행 절차·역할 정보 담당자 판단, 발신·종결, 기존 화면·양식과 대체 경로 실제 권한·수동대체 가능성을 추가 확인
  • 첫 두 항목은 원문 입력이며, 나머지는 상세 배분을 위해 확인할 보조자료 제안임.
  • K001~K003 문서 초안이 있다는 사실을 실제 업무·자료·재사용 범위의 확인 완료로 취급하지 않음.

경계표 한 행의 작성 단위

각 행은 다음 정보를 담도록 구성했음.

업무단계 → 필수 입력 → AI 보조 범위 → 규칙 처리 범위 → 담당자 판단 → 선택 근거 → 결과 인계조건 → 실패·보류 조건 → AI 미사용 대안

예를 들어 ‘문서 검토는 AI’가 아니라, 다음처럼 작성함.

운영보고서와 제출 증빙의 서술형 차이는 AI가 원문 근거와 함께 후보로 제시하고, 확정된 대상·기간은 규칙으로 대조하며, 담당자가 해당 증빙의 적합성과 보완 필요를 판단. AI 처리 불가 시 동일한 자료·기준을 이용한 현행 대조 절차로 전환. 원자료 부족 시에는 판단보류와 자료요청으로 처리.

AI를 사용하지 않는 대안까지 설명할 수 있어야 한다는 원문의 검토 질문을 배분표 안에 넣은 것임.

4. 작성 예시: 실증사업 운영보고서 검토

  • 다음은 역할과 대체 경계를 설명하기 위한 가상 업무임.
  • 실제 TS 승인조건·처리절차·담당 권한을 확인한 결과는 아닙니다.

입력은 승인조건 원문, 확정된 기한·필수자료 목록, 운영보고서, 접수기록, 운영 증빙으로 가정함.

업무단계 AI 보조 규칙 처리 담당자 판단·확인 AI 미사용 시 대체
① 조건 파악 의무·대상·기간·필요자료 후보와 원문 위치 제시 필수 필드·원문 연결 누락 표시 조건 누락·추가 생성·해석 확인 담당자가 원문을 읽어 조건표 작성
② 적용조건 확정 복수 해석·추가 확인 질문 정리 확정표시·적용기간·버전 검사 기한·예외·필수자료 확정 현행 기준·양식으로 확정 기록
③ 기한·첨부 점검 확정된 구조화 입력이면 사용하지 않음 기한·첨부 존재 여부 비교 예외·자료 유효성 확인이 필요한 항목 처리 기존 화면·확인된 계산표 또는 수기 점검
④ 운영내용 대조 보고서와 증빙의 설명·대상·기간 차이 후보 제시 확인된 날짜·식별자·기간 비교 후보의 정합성·중요도·보완 필요 확인 담당자가 같은 원문을 대조
⑤ 실제 이행 확인 필요한 자료·질문·근거 위치 정리 필요한 확인기록의 존재 검사 자료로 확인할 수 있는 범위와 실제 현장 사실 판단 현행 확인 절차 유지
⑥ 보완요청 작성 조건·부족사항·필요자료를 연결한 초안 확정 기한·필수항목·인계조건 점검 요청 내용·대상·발신 또는 인계 승인 기존 양식과 승인·인계 경로 사용
⑦ 검토 확정·종결 근거·미해결 사항 정리 필수 증거·확인·승인 기록 검사 보완·판단보류·종결 중 허용된 결론 확정 같은 완료조건을 적용한 현행 절차
  • 표의 일곱 단계는 설명용 분해임.
  • 새로운 컨셉 수나 개발기능 수, 실제 자동화 실적을 뜻하지 않음.

한 행을 구체화하면: ‘안전요원 배치 설명과 증빙 대조’

가상 승인조건에서 안전요원 배치 확인자료가 필요하다고 담당자가 확정한 상황을 가정함.

항목 작성 예시
입력 확정 조건·버전, 운영보고서의 배치 설명, 배치 증빙, 대상기간
AI 수행 관련 문단과 증빙 위치를 찾고 대상·기간·설명 차이 후보 제시
규칙 수행 확인된 대상 식별자·날짜·필수값의 일치·부족 검사
담당자 확인질문 같은 대상·기간의 자료인가? 자료만으로 무엇을 확인할 수 있는가? 추가자료나 현장 확인이 필요한가?
AI 출력의 지위 검토후보. 실제 미배치·위반·이행 완료를 확정한 결과가 아님
수동대체 조건 AI 처리 실패, 근거 위치 미확보, 원문과 후보의 불일치
수동대체 방식 담당자가 허용된 원문과 확정 기준으로 같은 비교항목을 확인
보류 조건 원자료 부족, 접근·판단 권한 미확인, 필요한 현장 확인 미완료
금지할 처리 파일이 없다는 이유로 미배치 확정, 파일 제목이 있다는 이유로 이행 완료 인정, 자동 발신·종결

이 사례에서 첨부파일 존재 확인은 규칙, 서술형 자료의 관련성·차이 제시는 AI 보조, 실제 이행을 인정할 수 있는지는 담당자 판단으로 나뉩니다.

  • 수동대체로 넘겼다고 부족한 사실이 생기는 것은 아닙니다.
  • 원자료가 없으면 담당자도 임의로 값을 채우지 않고 자료요청·판단보류로 처리하도록 설계함.

5. 수동대체: ‘오류 시 사람 확인’보다 구체적으로 정의

  • 수동대체는 모든 업무를 처음부터 손으로 다시 하라는 뜻이 아닙니다.
  • 허용된 기존 화면·규칙·양식은 유지하고, AI가 지원하던 구간만 담당자가 이어받는 방식을 우선 검토함.

이를 위해 전환 사유·중단 범위·받는 역할·인계자료·재개조건을 함께 정함.

상황 정지·제한할 처리 인계할 정보 대체·재개 방식
AI가 결과를 생성하지 못함 후보·초안 생성. 완료로 표시하지 않음 사건·단계, 입력자료 위치, 실패 범위 허용된 원문으로 해당 비교·작성 수행
근거 미확보·원문과 결론 불일치 해당 결론의 확정·후속 반영 의견, 원문 위치 또는 근거 미확보, 불일치 내용 담당자 원문 대조·추가자료 요청
입력 누락·판독불가 해당 입력을 전제로 한 계산·판정 누락 필드·문서·영향받는 단계 원자료 확인·재제출 요청, 필요 시 보류
기준·예외·시점 불명확 불명확한 규칙 적용과 후속 결론 서로 다른 해석·문구·버전·기간 해석 담당자 확인 후 필요한 단계부터 재개
접근·실행권한 미확인 해당 접근·수정·발신·종결 제한 대상과 권한 확인 요청 정당한 권한·절차 확인. 수동대체를 이유로 우회하지 않음
수동 완료 후 지연된 AI 결과 도착 기존 결과 덮어쓰기·중복 인계 기존 확정결과, 지연결과, 자료 버전 담당자가 참고·재검토 필요를 판단

두 가지 경계를 특히 남겨야 함

  • 첫째, AI 실패와 자료 부족을 구분함. AI만 중단됐고 원문·기준·기존 규칙이 사용 가능하다면 해당 구간을 수동으로 이어갈 수 있음.

  • 그러나 자료 자체가 없거나 담당자도 열람할 수 없다면, 그 상태는 수동 수행으로 해결되는 문제가 아닙니다.

  • 둘째, 모델의 점수와 업무상 승인권한을 구분함. 원문에는 자동승인용 신뢰도 임계값이 제시되어 있지 않음.

  • 따라서 임의의 점수 기준을 추가해 최종 판단·발신·종결을 자동 허용하지 않음.

  • K004에서는 이 경계를 정의함.

  • 실제 장애복구, 권한통제, 중복처리 방지 기능을 구축·시험하는 작업까지 포함하지 않음.

6. 수행 순서와 이번 컨셉의 범위

수행은 입력 확인 → 단계 분해 → 역할 배분 → 대체·보류 정의 → 사례 대입 → 현업 확인 순서로 진행하는 안임.

순서 수행내용 남길 결과
1. 입력 확인 병목표·비중복표·업무경계의 확인 상태 점검 확정 입력과 잠정 입력
2. 단계 분해 입력·행위·출력·확인조건으로 배분 단위 작성 대상 단계 목록
3. 역할 배분 AI·규칙·담당자 역할과 선택 근거 정의 처리주체 배분 초안
4. 대체·보류 정의 실패·자료부족·기준충돌 시 인계방법 작성 수동대체·보류 경계
5. 사례 대입·확인 허용된 사례 또는 가상 사례로 역할 공백·불필요한 AI 적용 확인 수정사항과 경계표 결정안
  • 규칙만으로 충분한 단계를 발견하면 AI 구현범위를 줄이는 것이 정상적인 결과임.
  • 원문도 이를 처리 제한으로 명시함.

이번 컨셉에서 끝낼 것은 단계별 역할, 선택 근거, 결과 인계조건, AI 미사용 대안, 보류·재개조건임.

모델·검색엔진 선정, 승인시스템 개발, 전체 권한정책 구현, 장애복구 시험, 예산·절감률 확정, 다른 컨셉과의 통합은 별도 작업으로 남깁니다.

7. 완료기준·역할·기간

  • 원문의 완료기준은 각 단계의 처리 주체와 수동 대체 방식이 결정안에 존재하는 것임.
  • 경계표를 작성하는 단계와 실제 시스템을 구현·운영하는 단계를 구분해야 함.

상세 검토에서는 다음을 확인하도록 제안함.

  • 수행 역할은 원문대로 수행 기획·PM, 결과 확인·승인은 TS 과제별 사업책임자, 협의·검토는 현업·정보화·예산으로 유지함.

  • 이는 역할안이며 실제 인명·부서 배정이나 권한 위임을 의미하지 않음.

  • 기간은 원문의 2~5근무일 가정임.

  • 자료·협의 조건에 따라 조정하는 기획 작업기간이며, 모델 개발·실사용 검증·운영승인까지 완료한다는 일정은 아닙니다.

8. 바로 사용할 보고서 문안

AX 적용 대상업무의 단계별 입력·처리·출력과 확인조건을 기준으로 AI 보조·명시적 규칙·담당자 판단의 역할을 구분할 필요. 확정된 기한·필수항목은 규칙 처리, 서술형 대조는 근거 기반 AI 보조, 기준 해석·예외·현장 확인 및 최종 판단은 담당자 수행으로 배분 추진. 단계별 선택 근거와 AI 미사용 대안을 명시하고, 실패·자료부족·기준충돌 발생 시 수동대체 또는 판단보류의 조건·담당·인계자료를 함께 정의. 기존 기능과 규칙만으로 충분한 업무는 AI 구현범위 축소·제외를 검토하고, 역할·자료·권한이 미확인인 구간은 실제 적용 전 추가 확인 추진.

제공한 MD에는 단계·입력 정의서, 처리주체 배분표, 담당자 확인·실행 경계표, 수동대체·보류 정의서, 사례별 경계 확인표, 쟁점·결정 기록서를 포함했음.

K004의 최종 결과는 ‘AI가 하고 사람이 확인한다’는 문구가 아니라, 단계마다 무엇을 AI·규칙·담당자에게 맡기고 처리할 수 없을 때 어디까지 멈추고 어떻게 이어갈지를 설명하는 경계표임.
