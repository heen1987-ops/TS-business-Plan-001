참조 대화의 전개는 [한국교통안전공단 조사 — 대화 구조화](../04_기관리서치/TS_대화구조화/한국교통안전공단_대화구조화_2026-09-09.md)에 정리했습니다. 예약 대안·자연어 요청에서 편의와 안전을 함께 보는 방향으로 확장된 과정, AI가 제안한 3개 조사안과 4개 비교 주제를 확인할 수 있습니다. 기존 컨셉의 확정 상태와 사업 후보 집계를 변경한 것은 아닙니다.

현재 논의는 [국민체감 AX 컨셉 목록](국민체감_AX_컨셉목록.md)에서 이어갑니다. **AI가 먼저 용건을 파악해 상담사에게 전달·연결하는 컨셉은 보관**하고 다음 문제를 발굴합니다. 이전 민원 완결 문서의 자동 예약·실행까지 현재 1차 범위로 확정한 것은 아닙니다.

최신 추가 발굴: [말로 시작해서 신청·예약까지 끝내는 TS 민원 AX](고령자_민원완결_AX_구상.md). 고령자의 사이트 탐색·반복 입력·중도 포기를 줄이는 업무 완료 경험을 검토합니다. 기존 5건과 별도의 발굴 초안이며 기존 민원 과업과의 비중복·실행 연계는 미확정입니다.

**최신 방향 v0.2:** 국민이 겪는 불편·위험을 TS의 실제 업무·법령 범위에서 AI로 줄이는 솔루션을 중심으로 재검토했습니다. 첫 화면은 한 문장 WHY·국민 효과·작은 적용·파급력이며, 이전의 구현 구성·사례는 상세 자료로 접었습니다. [선정기준](../00_기획지침/국민체감형_AX_선정기준.md)과 [후보별 판단](국민체감_재검토.json)을 함께 관리합니다.

기존 5건에 대한 기획 판단은 구체화 검토 2건(002·005), 수행 근거 선확인 1건(004), 문제 재발굴 1건(006), AI 필요성 재검토 1건(007)입니다. 기존 원장의 `신규 범위 검토대상`을 최종 추천으로 읽지 않습니다. 법적 수행 가능성·비중복·국민 효과는 미확정입니다.

**국민 문제 → 업무 전환 → AI·정보화 → 실제 조치 → 국민 성과**를 연결한 기획 초안입니다. 현재 추진사업을 제외하는 사용자 지침에 따라 검토대상 5건만 본 구상에 포함합니다. 사업 선정·계약상 비중복·기관 참여·예산·일정은 확정하지 않았습니다.

## 범위·가정

- 대상 독자: TS 신규 사업기획 담당자와 내부 검토자. 용도: 후보 간 사업 경계 비교와 다음 자료 확보 결정.
- 기준일: 2026-09-09. 사업 원장 버전은 생성 시 입력 기록에 남깁니다.
- 사실: 기존 원장에 기록된 후보 분류·조사 범위·사례 근거를 재사용했습니다. 이번 작업은 새 외부 조사나 법령 현행성 재검증이 아닙니다.
- 가설: 현행 업무의 단절, 개선 효과와 도입 필요성은 추가 현장 검증 대상입니다. 흐름도는 제안 설계입니다.
- 시간축: 날짜·기간을 임의 지정하지 않고 단계별 진입 조건을 사용합니다. 예산·정량 목표는 기준선 조사 후 산정합니다.
- 제외: 추진 중인 공통 AI 플랫폼·민원/콜센터/신문고 AI·전세버스 공시 AI 확장, 독립 R&D, 일반 내부 문서 챗봇.
- 유보·제외 3건은 판정 이력으로만 표시합니다. AI 추가 가치가 없으면 해당 AX 기획을 보류합니다.

## 설계 판단과 수용기준

작업 유형은 사업기획 시각화·문서화, 규모 M, 위험도 Medium입니다. Stage-Gate와 근거 추적을 적용합니다. 구현 전 범위·근거·미확정 표기·기존 문서 연결을 검토했습니다. 운영 시스템 구현과 배포는 이번 범위에 없으므로 제품 API·ERD·배포 계획은 생성하지 않습니다.

단일 대형 플랫폼으로 통합하는 안은 후보별 권한·운영 책임이 확인되지 않아 채택하지 않았습니다. 5개 독립 사업을 동일한 검토 체계로 비교하고, 이미 있는 기능은 재사용 여부를 확인하는 구조를 선택했습니다. 제안의 경계가 명확해지는 대신 개별 연계·검증 작업은 남습니다.

수용기준은 ① 본 구상에 현재 검토대상 5건만 포함 ② AX 2건·디지털전환+AI+정보화 3건 구별 ③ 각 후보의 WHY·전환 흐름·AI/SI·비AI 비교·최소 실증·성과·권한·비중복 확인 표시 ④ 국내외 사례의 단계·AI 증거·한계 보존 ⑤ 근거 링크 연결 ⑥ 화면·키보드·좁은 화면 확인입니다.

## 원장·갱신·보관

분류의 기준은 [05 사업포트폴리오](../05_통합사업기획/사업포트폴리오.json), 문제·실증·사례의 기준은 [06 후보분석 원장](../06_심층리서치/01_후보별/후보분석_원장.json)입니다. 이 폴더는 이를 시각화한 파생 산출물입니다. 분류를 여기서 별도로 변경하지 않습니다.

1. 범위 변경은 `05` 원장과 `06`의 기준 원장부터 일치시킵니다.
2. 구체화한 사업 설계는 `기획_보완.json`에 기록합니다. 이는 사실 자료가 아닌 제안 설계입니다.
   국민체감형 후보 판단과 WHY·작은 적용·성과·확산 가설은 `국민체감_재검토.json`에 기록합니다. `기획_보완.json`의 이전 구현 가설은 필요성을 다시 확인한 범위만 사용합니다.
3. `생성_사업구상.py`를 실행하면 문서·도식·보기·입력 기록을 갱신합니다. 기존 생성 파일의 수동 변경을 발견하면 중단합니다.
4. `검증_사업구상.cjs`로 브라우저 검증을 수행합니다. 결과·화면을 확인한 후 `검증_결과.md`에 한계까지 기록합니다.
5. 버전 기록은 입력·출력 SHA-256을 남깁니다. 생성 파일이 바뀌면 이전 생성본과 입력 기록을 `99_버전보관` 아래 자동 보존합니다. 동일 입력·출력 재실행은 중복 보관하지 않습니다. 원천 자료는 원래 위치를 유지합니다.

롤백은 보관된 해당 버전 생성본·입력 기록의 복원입니다. 원장을 임의로 되돌리지 않으며, 과거 도식에는 과거 버전임을 명시해야 합니다. 정기 리서치로 원장이 갱신되면 이 폴더 재생성·검증도 필요합니다.
