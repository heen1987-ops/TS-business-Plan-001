# TS 사업기획 재구조화 v1.0

2026-09-21 · 공고 미매핑 기획 초안 · 사업 승인/계약 범위/예산 확정 아님

## 1. 결론과 범위

국민의 불편과 교통안전 문제를 먼저 정의하고, 각 업무에 필요한 공개자료와 추가자료를 붙인다. 데이터 파일마다 새 사업을 만들지 않는다. 기존 업무·기존 AI를 기반으로 CCK AI의 추가 적용분을 구체화한다.

이번 범위는 CSV 25개·ZIP 2개 전부의 구조 점검, 홈페이지 의견 44행 분류, 기존 대화 TS-01~04 컨셉 보존, TS-16 사례와 정책기획 AI 연결, 나머지 자료의 연결 후보·보류 사유 정리다. 추가 발견 MP4 3개는 존재만 반영했다. 파일 목록·점검 결과가 TS의 실제 구매 수요나 현재 운영 문제를 입증하지는 않는다.

가정: 내부 검토용이며 CCK 주관·NOA/로컬 LLM·기존 서버·신규 인프라 투자 0원을 적용한다. 서버 여력은 미검증이다. 비전·신규 센서·장비·제어·독립 R&D는 제외한다. PoC는 AX+SI 적용 과업 일부로 둔다.

## 2. 번호와 구조

- TS-01~04: 참조 대화 「CCK TS 사업 조사」의 업무 묶음과 의미를 유지한다.
- TS-16: 이전 대화의 개인 자동차 이용·검사 사례 묶음으로만 연결한다. 이번 공개자료로 세부 번호를 재발급하지 않는다.
- 정책기획 AI: 각 업무의 문제정의·대안 검토를 돕는 공통 기능이다. 이전 로컬 기획의 TS-P23과 통합 대조할 대상이다. 이번 시도에서 해당 원문 경로를 찾지 못했으므로 동일 범위·현행 버전을 확정하지 않았다.
- 기기검사·철도/자격·궤도·위험물·항공: 자료 연결용 업무명이다. 기존 TS-05 이후 및 TS-P01~P23 대조 전 새 사업번호를 부여하지 않는다.
- TS-XX-YY는 실제 세부 과업에만 사용한다. 법령·부처·데이터는 설명 항목이며 독립 사업으로 세지 않는다.

구조: 국민 문제 → 업무 컨셉 → 근거자료 → 원인 가설과 반대 설명 → TS 역할·협력기관 → 현행/비AI 대안 → CCK AI 추가분 → 검증 → 추진 판단.

## 5. 정책 문제정의·사업기획 AI의 위치

한 문장 WHY: 담당자가 흩어진 국민 의견과 현황을 근거·한계와 함께 비교하여, TS가 실제로 해결할 문제와 필요한 사업을 선택하도록 돕는다.

대상 사용자는 정책·사업기획 담당자와 업무전문가다. 최종 수혜는 안전·접근성·서비스 품질이 개선될 국민이다. 내부 보고서 생성량이나 감축 인원을 최종 성과로 삼지 않는다.

### 입력과 판단 흐름

1. 출처 접수: 뉴스·정책보고서·법령·공개통계·적법하게 확보한 민원·현장 의견을 출처/발행일/관측기간/권리/기관과 함께 등록한다.
2. 신호 분류: 사실 관측, 국민 주장, 공급기관 설명, 원인 가설, 개선 제안을 구분한다. 재인용 뉴스와 동일 사건을 별도 근거로 중복 집계하지 않는다.
3. 현황 검증: 승인된 SQL/규칙으로 산출한다. 모집단·기간·분모·결측·표본성·범위 밖 집단을 표시한다. LLM에 전체 수치 계산을 맡기지 않는다.
4. 원인 검토: 여러 원인 가설과 대안 설명을 나란히 제시하고, 확인/반박에 필요한 자료를 요청한다. 상관관계를 원인으로 확정하지 않는다.
5. 책임 매핑: 문제별로 법정 업무·위탁/지정·실제 수행조직·정책 결정자·현장 실행자·데이터 소유자를 분리한다.
6. 기존 대응 대조: 기존 정책·시스템·CCK 계약 산출물과 비교해 미충족 기능을 식별한다. 동일 납품분은 재사용한다.
7. 대안 비교: 현행 유지, 업무절차 개선, 규칙 기반 SI, AX+SI의 국민 효과·오류·운영 부담·비용을 비교한다.
8. 사업카드 작성: WHY, 수혜자, 근거, 반대근거, 추가 기능, 확보자료, 법적 책임, 검증계획, 공통 재사용/업무 증분을 작성한다.
9. 사람 검토: 업무전문가가 문제와 권한, 기획 담당자가 기존 사업과 재정경로를 검토한다. 미확인 필수 항목은 보류 사유로 출력한다.

### 예시: 예약 불편에서 사업으로

관측: 2019년 의견 29행은 결제·전화 연결 실패를 주장한다. 34행은 운전적성정밀검사 장소 사전 안내와 접근성을 문제 삼는다.

가설 A는 안내·화면 순서 문제, B는 거래/인증 장애, C는 공급 부족이다. A는 조건형 안내 및 화면 개선, B는 시스템 복구, C는 시설·일정 정책 검토가 우선이다. AI는 A의 복잡한 질의 해석과 검증된 절차 설명에 추가 가치를 낼 수 있다. 현재 로그·사용자 재현 없이 AI 도입 필요성을 확정하지 않는다.

산출물: 문제정의 카드, 근거대장, 반증/확인질문, 업무·기관 관계표, 기존사업 차이표, 대안 비교표, 검증계획, 승인된 양식에 맞춘 사업기획 초안. 자동 예산확정·정책결정·발주 실행은 포함하지 않는다.
