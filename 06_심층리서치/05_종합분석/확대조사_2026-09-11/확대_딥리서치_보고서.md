# 국민의 업무 완료와 안전조치 이행을 위한 공공 AX 확대 연구

## 1. 핵심 판단

신규 사업은 **신청·보완을 끝내는 서비스, 안전조치와 증빙을 대조하는 서비스, 위험신고의 정보 품질을 높이는 서비스**라는 세 가지 업무군으로 구성하는 것이 타당하다. 법령·기준 변경 반영은 이 업무군에 공통으로 필요한 관리 기능으로 둔다. 이는 기존 TS X01~X05와 한국도로교통공단 N01~N07을 재분류한 분석이며, 세 건의 신규 사업이 선정되었다는 의미는 아니다.

가장 먼저 검증할 대상은 신청·보완 완료다. 이용자는 어려운 규정을 해석하기보다 “내 상황에서 무엇을 준비하고, 무엇이 부족하며, 어디까지 처리됐는가”를 알고 싶어 한다. 다만 기존 민원 AI·예약 서비스에 포함된 기능이면 신규 사업에서 제외해야 한다. 독립성이 성립하는 구체적 업무와 반복 보완 원인이 확인될 때만 별도 정보화사업으로 발전시킬 수 있다.

안전조치 증빙 대조는 더 넓은 안전 효과를 기대할 수 있는 두 번째 축이다. 점검 결과에 적힌 조치 요구와 제출된 설명·증빙 사이의 누락과 불일치를 담당자가 빠르게 확인하도록 한다. AI는 실제 시설의 안전 상태를 확인할 수 없으므로 현장 검사와 최종 적합 판정은 기존 책임체계에 남는다. 서류상 완료와 실제 위험 해소의 차이를 줄이는 것이 이 사업의 핵심 검증 질문이다.

위험신고 분석은 탐색 단계에 둔다. 표현이 다른 신고를 연결하고 조사에 필요한 사실을 보완하는 가치는 있으나, 신고 증가를 위험 증가로 해석하거나 AI가 결함을 확정해서는 안 된다. 미국의 항공 안전보고와 자동차 결함조사 체계는 전문가 분석과 자료의 맥락을 강조하는 비교 기준이다. 이 사례들은 AI 도입 효과 자체를 입증하지 않는다.[^12][^13]

## 2. 범위와 판단 기준

연구 기준일은 2026년 9월 11일이다. 기존 프로젝트의 원장·기획 기준과 공식 공개자료를 대조했으며, 법령은 열람한 조문과 표시 시행일 범위로만 판단한다. 기관의 전체 법령, 위탁 고시, 조직, 계약과 운영 현황을 전수 확인한 결과는 아니다. 현장 불편의 규모와 원인은 별도 실측이 필요한 가설이다.

기술적 전제는 CCK 주사업자 검토, NOA 및 로컬 LLM 활용, 기존 장비 재사용이다. 신규 인프라 투자 0은 기획 제약이며, 현재 장비로 목표 서비스를 처리할 수 있다는 검증 결과가 아니다. 입력은 텍스트와 구조화 데이터, 또는 기존 시스템이 적법하게 제공하는 검증된 텍스트 산출물로 제한한다. 새 OCR·영상 인식·STT·센서·제어 장비 구축을 기본 범위에 넣지 않는다.

기존 공통플랫폼·민원·전세버스 공시 AI의 후속 확장을 신규 사업으로 재포장하지 않는다. 유보된 튜닝·드론 후보도 이 연구만으로 검토대상으로 복귀시키지 않는다. 독립 R&D 대신 필요한 연구와 PoC를 AX 전환·AI 결합 정보화사업의 세부 과업으로 둔다. TS의 기존 미승인 예산 상한은 다른 기관의 예산 근거로 사용할 수 없다.

| 판단 질문 | 통과 근거 | 통과하지 못할 때 |
|---|---|---|
| 국민이 왜 필요한지 바로 이해하는가 | 재방문·반복 보완·미조치 위험 등 구체적 불편과 완료 상태 | 단순 검색·요약 기능으로 분류 |
| 해당 기관이 수행할 권한이 있는가 | 업무 근거 조문, 개별 위탁, 담당 조직의 연결 | 법적 경계 확인 대기 |
| 기존 사업과 독립적인가 | 계약 과업·개발 예정 기능과 대조한 차이 | 기존 사업 개선 항목으로 환원 |
| AI가 추가로 필요한가 | 규칙·서식 개선만으로 해결되지 않는 문맥 해석 문제 | SI·업무 개선 우선 |
| 기존 자원으로 운영 가능한가 | 실제 모델·입력 길이·동시 요청에 대한 측정 | 범위·빈도 축소 후 재검토 |
| 다른 기관에도 확장 가능한가 | 공통 처리 구조와 기관별 규칙의 분리 | 해당 기관 전용 과제로 유지 |

## 3. 기관과 법정업무의 확장 관계

TS와 한국도로교통공단은 서로 다른 기관이며 검사 대상과 권한이 다르다. 한국도로교통공단법 제6조는 운전면허시험·적성검사와 교통사고 분석 등 사업을 규정한다. TS의 자동차검사·자동차 결함 관련 업무를 이 조문으로 정당화할 수 없다. 공단 이름이 유사하다는 이유로 두 기관의 데이터나 처리권한을 합칠 수 없다.[^1]

한국산업안전보건공단은 안전보건 진단·기술지원, 위험기계 인증·검사 등과 관련한 확장 검토 대상이다. 공단법의 포괄적 사업 조항을 확인했지만, 특정 신청을 접수하거나 행정처분을 수행할 권한은 개별 법령과 위탁관계를 더 확인해야 한다. 안전점검 후 개선 요구와 증빙을 연결하는 처리 구조는 비교할 수 있다. 기관 간 원자료 공유는 별도의 권한 문제다.[^2]

한국승강기안전공단은 설립 근거인 승강기 안전관리법 제55조까지 본문을 확인했다. 구체적인 사업 조항과 검사·대행 조건은 추가 검증 대상으로 남긴다. 한국전기안전공사는 관계법령 진입점에서 직접 본문 확보가 충분하지 않았으므로 업무 조문을 확정하지 않는다. 두 기관은 확장 가능성 검토 대상이며 현재 사업화 가능성이 검증된 기관 목록이 아니다.[^3][^4]

| 기관 / 기존 관계원장 ID | 기관 분류의 근거 상태 | 이번 확인 범위 | 연결할 업무 가설 | 남은 확인 |
|---|---|---|---|---|
| TS / A_C0019 | 기존 2026-09-09 원장의 위탁집행형 준정부기관 분류 참조 | 리콜 제도 설명, 기존 TS 업무자료 | 신청·후속조치·위험신고 | 대상 업무별 최신 조문·위탁·담당 조직 |
| 한국도로교통공단 / A_C0064 | 같은 기존 분류 참조 | 공단법 제6조, AI 플랫폼 공개계획 | N02 사전점검·N03 조치·N04 기준 변경 | 기존 플랫폼의 실제 구현 범위 |
| 한국산업안전보건공단 / A_C0209 | 같은 기존 분류 참조 | 공단법 제6조 | 인증 신청 보완·안전개선 증빙 | 산업안전보건법 하위 규정·수탁 범위 |
| 한국승강기안전공단 / A_C0224 | 같은 기존 분류 참조 | 설립 조항 제55조 | 검사 관련 준비·개선 이행 | 사업 조항·검사 위탁·운영 시스템 |

분류 열은 새로 검증한 지정 결과가 아니다. 기존 기관 원장의 기준일·출처를 유지하며, 명칭만으로 기관 유형을 추정하지 않는다. 이 표의 연결은 분석 가설이고 법적 위탁관계 원장의 확정 간선으로 승격하지 않는다. 신규 기관이 추가되더라도 “기관 → 근거 법령 → 개별 업무 → 수행 조직 → 데이터 → 문제 → 솔루션”의 순서를 유지한다.

## 4. 국내외 사례가 실제로 보여 주는 것

### 4.1 국내: 기존 서비스와의 중복을 먼저 제거

행정안전부·NIA의 2026년 사례집 게시문은 6개 분야 16개 사례를 소개한다. 산재조사 분류, 근로감독관 지원, TS AI 운전자격확인, 법제처 생성형 AI 법령검색이 포함돼 있다. 이번 확인은 게시문과 목차 범위이며 첨부 PDF의 개별 성능·구축비·운영조건까지 검증하지 않았다. 따라서 실제 업무 완료율 향상이나 CCK 구현 가능성의 증거로 사용하지 않는다.[^14]

적용 판단은 명확하다. 운전자격확인이나 법령검색을 새 이름으로 제안하기 전에 기존 서비스의 범위와 차이를 확인해야 한다. 법령 변경 기능의 차별점도 검색 자체가 아니라 “변경된 조항이 어떤 신청 서식과 체크 항목에 영향을 주는가”를 관리하는 데서 찾아야 한다. 이러한 차이조차 기존 구축 범위에 포함돼 있다면 독립 신규 과제로 인정하기 어렵다.

한국도로교통공단에는 2026년 교통 AI 플랫폼 서비스 구축사업 공개계획이 있다. 공개계획의 존재는 확인했지만 현재 계약 진행, 검수 완료 기능과 가용 장비를 확인한 것은 아니다. N01~N07은 모두 이 플랫폼과 기능 수준에서 중복 검토해야 한다. 공개계획에 있다는 이유만으로 이미 운영 중이라고 하거나, 반대로 아직 구현되지 않았다고 가정해서도 안 된다.[^6]

### 4.2 해외: 검색 성능과 처리 완료를 구별

영국 GDS는 2026년 3월 GOV.UK Chat의 공개 시범 결과와 접근 확대 방향을 발표했다. 공식 안내를 근거로 답변하더라도 오류와 답변 불가 상황이 있으며, 개인 정보에 접근하는 상담 인계도 당시 지원되지 않는다고 설명했다. 이는 안내 품질과 실제 개인 업무 완료를 구별해야 한다는 근거다. 발표에 사용된 클라우드·모델의 결과를 국내 로컬 LLM의 성능으로 이전할 수 없다.[^8]

Consult의 투명성 기록은 대량 의견의 주제 분석에서 사람의 판단이 계속 필요함을 보여 준다. 기록된 표본에서 감독자 판단과의 일치율은 AI 62%, 비교 인력 70~73%였고 평가 방식의 한계도 명시돼 있다. 비용·시간 비교 역시 특정 평가 조건의 결과다. 이를 한국어 신고 분석의 목표 성능이나 전체 업무 비용 절감률로 사용하지 않는다.[^7]

싱가포르의 신청 처리 참조 구성은 화면, 규칙 엔진, 업무흐름, AI 문서 확인을 분리한다. 설계 패턴으로는 적합하지만 명명된 기관의 독립 성과평가 자료는 아니다. 특히 스캔·문서 인식 기능은 현재 로컬 텍스트 처리 범위에 그대로 포함할 수 없다. 적용할 부분은 이미 텍스트화된 신청 내용과 기준을 대조하고, 결과를 기존 처리 흐름으로 반환하는 방식이다.[^10]

MAESTRO는 정부 상용 클라우드 기반의 공통 AI 제공 기능을 소개한다. 프랑스 Albert API도 공통 AI 서비스 기능을 제공하는 제품 문서다. 두 사례는 기능 재사용과 운영 통제 구조의 참고자료지만, 신규 장비 투자 없이 같은 규모로 운영할 수 있다는 증거는 아니다. 공통 기술 기반을 새로 구축하는 사업을 이번 국민 서비스 과제의 중심으로 삼지 않는다.[^9][^11]

### 4.3 안전보고: AI 도입 사례가 아닌 비교 기준도 필요

NASA ASRS는 전문가가 안전보고를 읽고 식별정보를 제거하며 분석하는 절차를 설명한다. NHTSA도 여러 자료를 활용해 잠재적 제작결함을 조사하는 체계를 제공한다. 이러한 자료를 비교할 때는 보고의 신뢰도, 표본 편향, 전문가의 역할을 함께 고려해야 한다. 공개된 처리 체계의 존재를 AI 분석의 인과효과로 바꿔 해석하지 않는다.[^12][^13]

| 비교 대상 | 증거의 성격 | 적용할 요소 | 가져오면 안 되는 결론 |
|---|---|---|---|
| 국내 AI 정부 사례집 | 공식 편찬·목차 확인 | 중복 탐지와 후속 실사 대상 | 사례별 성과가 독립 검증됨 |
| GOV.UK Chat | 운영팀의 시범 연구 발표 | 출처 확인·답변 불가·사용자 평가 | 상담·신청이 자동 완료됨 |
| Consult | 알고리즘 투명성·평가 기록 | 분류 보조·사람의 주제 수정 | 표본 비용 절감률의 국내 적용 |
| 싱가포르 신청 처리 구성 | 공식 참조 설계 | 규칙·AI·업무흐름 분리 | 실명 현장 효과 검증 |
| MAESTRO·Albert API | 공식 제품·서비스 문서 | 공통 기능의 재사용 구조 | 기존 TS 장비의 충분한 용량 |
| ASRS·NHTSA | 공식 안전 업무 설명 | 보고 보완·전문가 검토 | AI가 결함이나 사고율을 확정 |

## 5. 사업군 A: 신청·보완 완료 AX

**WHY: 필요한 것을 한 번에 준비하고, 무엇이 부족한지 몰라 다시 방문하는 일을 줄인다.** 대상은 반복 보완이 발생하는 특정 신청 업무다. 기존 X01·X05, N01·N02를 연결하되 예약·민원 공통기능의 중복 부분은 제외한다. 사용자 의견에서 제기된 고령자의 탐색 불편은 출발점이며, 전체 이용자의 불편 비율로 일반화하지 않는다.

현행 문제는 상황별 준비 내용이 여러 안내문과 서식에 나뉘어 있다는 가설이다. 먼저 반려·보완 사유를 확인해 안내 문제인지, 심사 기준 불명확성인지, 공급 부족인지 구분한다. 예약이 만석으로 보이는 현상은 실제 공급, 슬롯 정책, 갱신 지연의 문제일 수 있다. 이 경우 AI보다 예약 재고·상태 동기화 개선이 우선이며, AI는 실제 예약 자리를 만들어 내지 못한다.

전환 흐름은 상황 입력 → 대상 업무 확인 → 필수 항목 규칙 점검 → 설명 내용과 기준의 의미 대조 → 부족한 항목 안내 → 기존 접수 채널로 전달 → 결과·보완 상태 확인이다. 법정 자격, 금액, 날짜와 필수 여부는 승인된 규칙으로 계산한다. AI는 자유로운 표현을 신청 항목에 연결하고 부족한 설명을 이해하기 쉽게 작성한다. 제출·확정은 권한 있는 시스템과 사용자의 확인을 통해서만 처리한다.

SI 기준안은 조건별 체크리스트와 입력 검증을 개선하는 것이다. AI 대안이 이 기준안보다 최초 적정 제출률을 높이지 못하면 생성형 기능을 축소한다. 기존 시스템의 상태 조회·접수 인터페이스가 없으면 첫 실증은 제출 전 보완 지원으로 제한한다. 시스템 연결 없는 시제품을 업무 완료 서비스라고 부르지 않는다.

필요 데이터는 현행 서식, 적용일이 확인된 안내문, 정형화된 보완 사유와 승인된 익명 표본이다. 측정값은 최초 적정 제출률, 반복 보완 횟수, 이용자 과업 완료시간, 잘못된 필수 요건 안내와 답변 보류 비율이다. 목표 수치는 기준선을 측정한 후 담당 부서와 정한다. 고령 이용자에게는 짧은 문장·단계별 확인·사람에게 이어지는 대안을 제공하며 새로운 음성 장치 도입을 전제로 하지 않는다.

## 6. 사업군 B: 안전조치·증빙 대조 AX

**WHY: 지적된 위험이 어떤 근거로 해결됐는지 끝까지 확인한다.** TS X04와 N03, 기존 TS-BIZ-005·006의 적용 가능 부분을 연결한다. 공단의 지적·권고·검사 결과가 같은 법적 효력을 갖는다고 가정하지 않는다. 대상 업무에서 기관의 실제 추적 책임이 확인되는 부분만 사업 범위로 삼는다.

핵심 가설은 조치 요구와 제출 결과를 사람이 문서 사이에서 대조하는 과정에 누락이 발생한다는 것이다. 행정 지연이나 조치 비용 부담이 원인이라면 AI 대조만으로 개선되지 않는다. 먼저 종료된 건과 미완료 건을 비교해 누락 유형과 책임 구간을 찾는다. 실증은 안전 판정에 영향을 주지 않는 병행 검토 방식으로 시작한다.

전환 흐름은 지적사항별 식별자 부여 → 요구 조치·기한·근거 연결 → 제출된 텍스트 설명 대조 → 누락·상충 후보 제시 → 담당자 확인 → 기존 시스템의 처리 상태 반영이다. 사진·도면이나 실제 설비의 상태는 새로 인식하지 않는다. 텍스트가 충분하지 않은 증빙은 확인 불가로 표시하고 담당자에게 보낸다. AI가 작성한 완료 요약은 승인 기록을 대체하지 않는다.

비AI 기준안은 필수 증빙 목록, 상태 관리와 기한 알림이다. AI의 추가 가치는 문구가 서로 달라도 요구한 조치와 제출 설명의 관계를 찾는 데 있다. 성능은 단순 요약 만족도보다 중요 미충족 사항의 탐지, 잘못된 누락 경고, 담당자의 대조시간과 추가 확인 부담으로 판단한다. 실제 안전 개선 효과는 더 긴 기간의 별도 평가 대상으로 남긴다.

다른 기관으로 확장할 때 재사용할 대상은 문서 전체나 법적 판정이 아니다. 요구사항·제출 근거·확인자·상태·적용 기준 버전의 관계 구조를 재사용한다. 승강기·산업안전·전기안전의 구체적 권한과 데이터 접근이 확인되지 않은 상태에서는 확장 계약이나 시장 규모를 계산하지 않는다. 초기에는 TS의 한 업무만으로 구조와 비용을 검증한다.

## 7. 사업군 C: 위험신고 품질·조사 인계 AX

**WHY: 위험을 알리는 시민의 설명이 필요한 사실을 갖춰 조사 담당자에게 전달되게 한다.** 기존 X03을 중심으로, X02의 후속 안내와 연결 가능성을 살핀다. 제작결함 조사와 리콜 제도 설명은 TS 적용의 업무 맥락을 제공하지만 AI 도입 필요성을 직접 입증하지 않는다. 조사 착수·결함 확정·리콜 결정은 기존 절차에 둔다.[^5]

입력 누락 보완, 표현이 다른 유사 신고의 탐색, 기존 보고와의 연결 후보 제시가 초기 범위다. 사람의 불완전한 설명을 확정 사실로 바꾸거나, 서로 다른 사건을 동일 사건으로 합치지 않는다. 확인되지 않은 차량 정보·발생 조건은 질문하거나 미확인 값으로 남긴다. 동일 신고의 재접수와 서로 다른 반복 발생을 구별할 수 있어야 한다.

현재는 A·B보다 데이터와 평가의 불확실성이 크다. 익명화된 신고 표본, 전문가가 확인한 분류, 중복 기준과 조사 단계 정보가 필요하다. 규칙 기반 입력 보완·검색을 먼저 비교하고, LLM의 추가 분류가 조사 누락이나 오인 연결을 늘리지 않는지 확인한다. 사회적으로 주목받는 사건의 신고량 편향도 분석에서 표시한다.

평가는 필수 정보 충족률, 잘못된 사건 병합, 중요한 신고의 누락, 담당자의 수정량으로 한다. 신고 건수 자체의 감소를 목표로 삼지 않는다. 신고 접근성이 좋아지면 접수량이 늘 수 있기 때문이다. 이 사업은 자료와 평가 기준이 확보되기 전까지 탐색 상태를 유지한다.

## 8. 공통 기능과 CCK 수행 범위

법령·기준 변경 반영은 A·B·C에서 사용하는 근거의 품질을 유지하는 공통 기능이다. 게시일·시행일·개정 이력·취득 시점을 분리하고, 변경된 문장이 영향을 주는 서식과 규칙을 후보로 연결한다. AI가 개정 법령을 해석해 운영 규칙을 자동 배포하지 않는다. 담당자가 적용 대상과 경과조치를 확인한 뒤 변경을 승인한다.

CCK의 NOA·로컬 LLM은 검색·대조·분류와 기존 업무시스템 연결을 수행하는 구현 후보로 검토한다. 제품 소개나 내부 기술 목록만으로 과업 전체의 수행 능력을 검증했다고 판단하지 않는다. 모델·라이선스·권한 분리·로그·연계 방식의 실제 제공 범위는 시연과 계약 명세로 확인해야 한다. 특정 제품 이름이 기능 수용기준을 대신해서는 안 된다.

| 처리 | 기본 수단 | AI 사용 경계 |
|---|---|---|
| 필수 항목·날짜·기한 확인 | 승인된 규칙·DB | 추정값으로 빈칸 채우기 금지 |
| 자유로운 설명의 업무 항목 연결 | 로컬 LLM + 근거 검색 | 후보 제시, 불확실하면 확인 요청 |
| 설명·증빙의 의미 대조 | 검색·문장 대조 | 실제 안전 상태 판정 불가 |
| 접수·예약·처리상태 변경 | 기존 시스템 API·권한 | 동작 성공 응답 없이 완료 표시 금지 |
| 기준 변경 적용 | 버전 비교 + 담당자 승인 | 자동 법률 해석·배포 금지 |
| 성과·운영 관리 | 기존 로그·통계 집계 | 감축 인원으로 효율 환산 금지 |

장비 투자를 하지 않으려면 실제 입력 길이, 동시 요청, 배치 처리량과 추론 지연을 측정해야 한다. 긴 자료 전체를 매번 모델에 전달하기보다 필요한 근거를 검색하고 확정 규칙을 먼저 적용한다. 가용 자원이 부족하면 처리 대상·빈도·문서 길이를 줄이거나 오프라인 배치로 제한한다. 이를 국민에게 즉시 응답하는 서비스와 혼동하지 않도록 운영 수준을 명시한다.

## 9. 사업화·실증과 공공 가치

권고하는 첫 단계는 신규 구축 발주가 아니라 한 업무의 근거·중복·데이터 확인이다. 다음 단계에서 비AI 개선안과 AI 보조안을 같은 표본으로 비교한다. 오류 사례와 담당자 수정 부담까지 포함해 추가 가치가 확인된 부분만 AX+SI 과업으로 확정한다. 성능을 확인하기 전에 여러 기관을 묶은 대규모 기반 사업을 제안하지 않는다.

| 단계 | 확인할 내용 | 다음 단계로 넘어가는 조건 | 멈추거나 축소할 조건 |
|---|---|---|---|
| 업무 선정 | 민원·보완·조치 이력, 기존 계약 | 독립 문제와 담당 부서 확인 | 기존 과업과 동일 |
| 근거·데이터 | 조문·위탁·서식·표본 접근 | 권한 있는 데이터와 기준 확보 | 권한 또는 최신 기준 불명확 |
| 비교 실증 | 규칙 개선안 대비 AI 대안 | 추가 효과와 오류 수준을 수용 | 규칙만으로 해결되거나 오류 증가 |
| 연결 실증 | 기존 상태·접수 API | 실제 성공·실패·중복 처리 검증 | 시제품과 업무 상태 불일치 |
| 운영 검토 | 부하·유지관리·사용자 지원 | 기존 자원 내 서비스 수준 합의 | 신규 자원 없이는 목표 불가능 |
| 확장 검토 | 두 번째 기관의 규칙·권한 차이 | 공통 구조의 재사용 효과 확인 | 사실상 별도 시스템 전면 재구축 |

기획의 공공 가치는 편익, 안전, 권익과 책임성으로 나눠 평가한다. 편익은 방문·보완 부담, 안전은 미충족 조치의 확인, 권익은 잘못된 안내를 바로잡을 수 있는 경로로 구체화한다. 내부 시간 절감은 전문 판단과 서비스 품질에 재투입하는 관점으로 검토한다. 인원 감축을 효과 지표로 환산하지 않는다.

2026년 공공부문 AI 도입 가이드의 공개 사실을 확인했으며 개별 사업의 적용 경로를 정할 때 최신 지침을 추가 대조해야 한다. 개인정보보호위원회도 공공 AX 프라이버시 안내서를 게시하고 있다. 이번 연구는 게시문 확인 범위이므로 해당 지침의 모든 요구를 검토한 준수 판정이 아니다. 로컬 처리라는 이유만으로 개인정보 처리 근거와 보존·접근 통제가 면제되는 것으로 보지 않는다.[^15][^16]

예산·사전협의는 기관 유형, 사업 내용, 재원과 규모가 정해진 뒤 해당 규정을 확인한다. 모든 신규 사업에 동일한 기재부 사전 심의가 필요하다고 단정하지 않는다. SW 사업과 AI 운영·유지관리 비용을 나누고, 기존 자원 사용에도 운영 인력·소프트웨어·보안 유지 비용이 발생할 수 있음을 반영한다. 이 연구에는 승인 예산·확정 매출·추정 시장 규모를 제시하지 않는다.

우선 조사 순서는 기존 사업 명세 대조, A·B의 실제 반복 문제 확인, 법정업무와 개별 위탁 검증, 익명 표본과 기존 장비 검증이다. 국내 사례집의 개별 사례 본문과 운영기관 자료도 이어서 확인해야 한다. 특히 승강기·전기안전은 구체적 업무 근거가 미완료이므로 확장 확정 대상으로 사용하지 않는다. 새로운 기관 이름을 추가하는 것보다 한 업무의 권한·문제·효과를 끝까지 연결하는 것이 다음 조사의 완료 기준이다.
