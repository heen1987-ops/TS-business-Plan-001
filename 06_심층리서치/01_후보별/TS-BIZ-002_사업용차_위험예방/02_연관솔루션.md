# TS-BIZ-002 · 연관솔루션과 대안 설계

## 현행 → 개선 가설

| 전환 항목 | 범위 |
| --- | --- |
| AS-IS | 분석 결과와 교육·안전조치 이행이 분리돼 있는지 확인 |
| TO-BE | 위험 신호→담당 검토→안전조치 배정→이행·결과 확인 |
| 디지털전환 | 차량·운행·조치 ID, 노선·운행량과 조치 결과 정합성 |
| AI 핵심 기능 | 상황별 이상·위험 신호 탐지와 검토용 설명 |
| 정보화 구축·연계 | 운행기록 품질·권한 관리, 위험 신호 전달, 담당자 검토·교육 연계, 조치 이력·성과 모니터링 |
| 운영·책임 | 운전자·현업을 단순 점수로 서열화하거나 인력 감축 지표로 전용하지 않는다. 안전교육·예외 검토·이의제기 책임 유지 |
| 추진사업과 제외 경계 | 기존 eTAS 분석·전세버스 등급 산정·공시 보고서 생성 |

운행기록 품질·권한 관리, 위험 신호 전달, 담당자 검토·교육 연계, 조치 이력·성과 모니터링

| 대안 | 구현 범위 | 선택 조건 |
| --- | --- | --- |
| A. 비AI 비교 기준 | 기존 위험운전 규칙·통계 점검·안전교육 | AI 추가 가치가 없으면 이번 신규 후보를 유보·제외 |
| B. AX·디지털전환+AI+정보화 | 상황별 이상·위험 신호 탐지와 검토용 설명 | 현재 추진사업과의 비중복 대조 및 데이터 적법성·품질과 현장 조치 주체를 먼저 확보 |
| C. 필요한 기술 검증·PoC | 운행 조건 변화에도 위험 신호를 안정적으로 찾고, 설명 가능한 개입이 기존 규칙보다 예방 활동의 효과를 높이는가? | 전환사업의 세부 과업으로 검토·독립 R&D 기획 제외 |

비용·기간은 모두 미산정이다. 비교에는 콘텐츠 정비, 데이터 연계·정답 작성, 전문가 검토, 모델 이용료, 모니터링·정정, 장애 대체 절차까지 포함한다. AI 사용량이나 모델 정확도 한 가지로 대안을 선택하지 않는다.

## 데이터·업무 흐름 — 제안

공식 원천·업무 규칙 등록 → 출처·시점·접근권한 확인 → 기존 검색·규칙 기준안 → 허용된 AI 보조 → 담당자 판단 또는 국민의 공식 절차 진행 → 오류·정정·조치 결과 기록.

- 필요한 입력: 허가된 DTG·차량·노선·시간·교육·조치·사고 또는 준사고 기록, 품질·누락·동의와 법적 근거
- 책임 경계: 사후 검토·교육 연계와 제한적 실증. 운전 중 새 경보와 운전자 제재·서열화는 별도 안전·권한 검증 전 제외.
- 공개 전 조건: 비중복 근거, 업무·데이터 전환, AI 추가 가치, 시스템 구축·연계, 운영·국민 성과를 모두 확인. 데이터 사용권·현재 시스템 가동과 개입 주체를 먼저 확인하고 안전 신호를 정확도만으로 평가하지 않는다.

업무 규칙과 원자료의 버전을 답변·검토 결과에 연결한다. 원문 부족, 규칙 충돌, 접근권한 부족은 각각 이유를 표시하고 공식 담당 채널로 넘긴다. 생성한 문장이 원자료에 없는 사실·허가·검사 결과를 만들지 않도록 검토한다.

## 기존 사업과 중복 판단

전세버스 공시 산출물과 구분한 운행위험→교육·안전조치→이행 확인 업무를 검토한다. 최종 계약·승인 범위의 대조는 미완료다.

기존 계약 원문, 승인된 요구사항, 실제 구축 화면·데이터 연계·운영 기능을 대조하기 전에는 재사용 가능 자산이나 신규 과업으로 확정하지 않는다. 계약 이행·신규 사업·수행사 내부 도구는 각기 다른 범위로 기록한다.
