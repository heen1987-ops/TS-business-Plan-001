3줄 요약
① 같은 시스템 맞다 — 내가 영상으로 관찰한 tsai.kotsa.or.kr과 아카이브의 "원사업"이 AI서비스 6종·데이터스튜디오·AI스튜디오·대시보드 구성까지 정확히 일치해, 동일 시스템임이 확인됐다(v1 문서에서 추정이었던 부분 해소).
② CCK가 실제로 더 가진 것은 "이미 완성된 기능"보다 "설계 원칙과 격리 구조"다 — 결정성(계획/실행 분리)·추적성(좌표 매칭)·통제성(규칙 내장) 축은 소스 경로까지 문서화된 반면, 성능·재현율 실측치는 대부분 없다.
③ 가장 큰 취약점은 HITL이다 — 공공 규제 도메인에서 사실상 필수로 여겨지는 기능인데, CCK 엔진 코드에 관련 구현이 전무하고(grep 0건), TS 제안서에서도 "신규개발"로 명시돼 있다.

엔진 기술 차별성 4축

도메인(회계·TS 무관)을 뺀 CCK 엔진 자체의 논증 — 08_ENGINE_PLATFORM 정본 축약

축 1 · 결정성 (Determinism)

비결정적 LLM 위에 결정적 실행 계층(Planner/Executor/DataFlowManager 분리)을 얹어 "동일 입력 → 동일 결과"를 계층 수준에서 확보하려는 설계
가장 강한 근거13-Layer 컨텍스트 방어 체계가 파일·라인 단위로 소스 문서화된 코퍼스 내 유일한 사례. No-Aggregation 원칙(배치 결과를 합치지 않고 직접 참조)
정량 실측없음 — 15,000토큰/5의존성 등은 전부 설계 파라미터. 재현율·환각률 실측치 0건
최대 약점"LangGraph 기반" 서술 8개 문서 vs "자체 엔진" 서술 1개 파일이 공존 — 자립성 주장은 위험, 결정성 주장까지만 안전
안전 표현: "오픈소스 에이전트 프레임워크를 실행 기반으로 활용하되, 컨텍스트 통제·데이터 정합성 계층은 자체 개발" — 이 표현만 세 가지 해석 어느 쪽이든 참이다.

축 2 · 추적성 (Traceability)

생성형 OCR이 잃는 "좌표"와 검출 기반 OCR이 잃는 "구조 관계"를 크로스모달 매칭으로 결합, 모든 출력 텍스트에 원본 좌표를 부여
가장 강한 근거전체 매칭 91.0% / 중복단어 85.3% / 0.25초·장(GPU) — 동일 조건 Gemini 53.0%·ChatGPT 34.6% 대비 우위. 미학습 VLM 4종 교체 제로샷 실증(92.0~93.8%, 최대 1.7%p 차이)
측정조건CCK 자체 비공개 벤치마크, 672장·5카테고리·영어 중심, 제3자 검증 없음. 한국어 전용 금지(게이트 위반=반려 대상)
최대 약점Evidence Trail(근거 추적 산출물화)은 TRL 2~3 — 미개발. KPI 5종 전부 목표치

축 3 · 통제성 (Controllability)

도메인 규칙을 매번 프롬프트로 지시하는 대신 에이전트 system_prompt에 사전 내장, Core/Plugin(YAML) 분리로 코드 변경 없이 도메인 확장
가장 강한 근거Core/Plugin 분리가 2025.09부터 가동 중 — "규칙 누락 경로 자체를 제거"하는 구조적 설계. Mochi E/S/X(엔진고정·스킬교체) 정부 제출본 공식 기재
정량 실측규칙 준수율 실측치 없음. 노코드 GUI(비개발자 자율 확장)는 미보유 — 개발자가 YAML을 직접 작성하는 전제
최대 약점HITL — InterruptService·Resume Token grep 전 코퍼스 0건. Keeper 기능표 7항목에 HITL 없음. "중단·재개 지원 엔진"은 근거 전무

축 4 · 운용성 (Operability)

연구 프로토타입과 프로덕션을 가르는 것은 모델 성능이 아니라 인프라 — 자체 LLM 게이트웨이(Nexus)·실행 런타임(Keeper)·멀티테넌트 허브(Mothership) 보유
가장 강한 근거Keeper의 SELECT ... FOR UPDATE SKIP LOCKED 원자적 클레임, Graceful Shutdown — "연구 코드가 아니라 운영 시스템에만 있는 기능". 멀티 프로바이더로 벤더 종속성 제거
정량 실측TPM 임계값·처리량·가용률·SLA 전부 UNKNOWN — Nexus·Keeper 운영지표 없음
최대 약점폐쇄망 실무 성능 미확보 — 현재 SaaS는 Claude·GPT·Gemini 상용 API 사용. 폐쇄망용 공개 LLM 파인튜닝은 "연구 진행 중"(자인). TS의 망분리 대응 체계는 존재하나 별건(제안 단계)
