# TS 업무별 AX 공통 수행 설계

22개 업무를 각각 검토하되 같은 검색·권한·연계·승인 기능을 22번 구축하지 않는 구조다. 데이터 주권을 공통 운영조건으로 두고 국민서비스 처리와 안전업무의 결과를 개선한다. CCK의 주관 수행은 제품 사용권·실행·인력·연계·납품·운영을 확인한 뒤 확정한다.

## 1. 아키텍처와 기술 재사용

기관 인증·업무 권한 → 허용된 전자문서/정형 결과 → 규칙·버전 검증 → 로컬 검색·LLM → 근거가 있는 초안 → 사용자·담당자 확인 → 허용된 공식 API 또는 기존 화면 인계 → 결과·감사 이력의 순서로 구성한다. 이 구조는 설계 제안이며 구현 완료를 뜻하지 않는다.

| 계층 | 재사용 후보와 신규 작업 | 확인 증거 |
|---|---|---|
| NOA 실행 환경 | 기존 TS의 사용권·모델·문서처리·감사 기능 재사용 후보 | 설치 버전·사용 계약·폐쇄망 실행 로그 |
| 문서/지식 | 텍스트 원본·규칙·출처·버전 관리, 업무별 정비 필요 | 실제 문서 형식·추출 누락·권한·개정 시험 |
| 업무 모듈 | 증빙 대조·준비 지원·사례화 등 필요한 차이만 구성/개발 | 기존 기능 대조표·구체 요구사항·시연 |
| SI 연계 | 공식 상태·조회·인계·승인·복구 | API 계약·인증·응답 스키마·중복/타임아웃 시험 |
| 운영 | 변경·보안·평가·장애·교육·복귀 | 운영 책임자·주기·예산·인수 문서 |

공급사 공개 자료와 내부 기술 대장은 근거 종류가 다르다. NOA 소개의 폐쇄망·감사·문서 업무 설명은 제품 기능 주장으로 분류한다. 카탈로그의 TA 명칭·자사 TRL·다른 도메인 시험은 TS 설치물의 성능 보증이 아니다. 계획 단계 기술·자동 재실행·SQL 실행·스캔 인식을 필수 완성 기능으로 가정하지 않는다.[^33][^44][^45][^46]

## 2. 공통화할 다섯 기능 묶음

| 기능 묶음 | 관련 기획 | 비용 중복 방지 |
|---|---|---|
| 증빙 대조 | P01·03·04·05·11·12, P17 연계 | 공통 대조·근거 UI 1회, 업무별 기준·필드·평가만 추가 |
| 국민서비스 처리 | P02·07·09·10·15·18·19·20 | 본인확인·동의·상태·인계 패턴 재사용, 업무별 API와 규칙 별도 |
| 보호된 안전사례 | P06·08 | 사례 초안 엔진 구조 재사용, 원본·권한·분류·전파 절차 분리 |
| 기준 변경·준비 | P13·14 | 변경 영향 구조 재사용, 제작자 준비와 시험기관 문서 분리 |
| 교육·결과 설명 | P16·21, P22 과정 모듈 | 교재·결과 근거 연결 1회, 과정별 승인 콘텐츠팩 추가 |

기능 묶음은 재사용 설계이며 예산 확보나 다섯 개 사업 선정이 아니다. 업무와 데이터가 같지 않은데 엔진이 같다는 이유로 모든 문서를 통합하지 않는다. P17은 P01의 COSAS 연결, P22는 P21의 이륜차 과정으로 통합하는 검토안이다.

## 3. 비중복 확인의 실제 순서

1. 최종 계약·승인 RFP·추가합의·현재 납품 기능을 확보한다.
2. SFR-003의 자동차검사·자격시험·안전단속 실제 시나리오를 구체적으로 대조한다.
3. SFR-001~005의 데이터·지식·대화형 지원과 신규 업무 모듈의 차이를 산출물로 적는다.
4. SFR-006~007 민원 범위와 새 신청·완료 확인 흐름을 비교한다. 민원이라는 명칭만으로 일괄 배제하지 않는다.
5. SFR-008~009 전세버스 공시 과업은 신규로 재포장하지 않는다.
6. 운영사 기능과 비교해 이미 구현된 기능이면 유지·고도화 또는 제외로 처리한다.[^43][^31]

## 4. 데이터·보안·실행 통제

원본·임베딩·검색·재정렬·문서 변환·로그·백업·라이선스 호출·외부 모델 대체경로까지 데이터 흐름을 확인한다. 기관 내부 LLM 설치만으로 데이터 주권이 완성되는 것은 아니다. 권한 없는 문서가 검색 결과·요약·추론에 들어가지 않게 하고, 원본 회수·개정을 인덱스와 캐시에 반영한다.

예약·신청은 입력 준비, 사용자의 확인·동의, 정형 API 검증, 접수 상태 확인을 분리한다. API에 멱등성 기능이 없다면 애플리케이션의 요청ID·상태조회·재시도 잠금으로 중복을 통제하되 실제 계약 시험으로 확인한다. 성공 여부를 알 수 없는 타임아웃을 성공으로 표시하지 않는다. 안전·법적 판정과 보호자료 공개는 담당자가 책임진다.

## 5. 기존 서버·예산·일정

1차 7억·2차 추가 5억 원은 VAT 포함으로 해석한 전체 프로그램 목표 상한이다. 22개 독립 사업이나 22개 전체 구축 견적이 아니다. GPU·서버·저장·백업·망 장비의 신규 구매·증설·임차, 클라우드 자원비, 기존 장비 유지보수·자원 증분은 이번 신규 사업비에서 제외한다. 기존 환경 배포 설정·SW 연계·복원 시험 공수는 구분한다.[^38][^48]

원가는 공통 기능 1회분 + 선정 업무별 증분 + 연계·검증·전환 + 확인된 증분 사용료로 계산한다. 운영·변경 비용도 따로 기록한다. 공식 단가·견적·가용인력·문서량·API 계약이 없으므로 이 단계에서 항목별 금액과 이익률을 확정하지 않는다. 범위를 정한 뒤 역할별 공수와 검증된 단가, 산정방식과 부가세를 대조한다.

기존 서버에서는 모델 버전·정밀도·문맥 길이·동시성·평균/최대 문서 길이·지식량·피크 사용시간을 기록하고 부하·응답·근거 품질을 함께 시험한다. 여력이 부족하면 대기열·배치·업무량·모델 설정·범위를 줄이고 재검증한다. 외부 클라우드 대체나 신규 장비 구매를 숨겨 넣지 않는다.

단일 업무의 예시 일정은 조건 확인 2~4주, 제한 시범 6~10주, 검증·인수 2~4주다. 실제 기간은 인력·문서·승인·API 협조에 달려 있으며 22건 동시 구축 계획이 아니다. 1차에는 근거가 확보된 소수 업무를 선택하고, 2차는 재사용 효과·추가 수요·서버 여력 확인 후 확대한다.

## 6. 먼저 확인할 업무와 결정 순서

- **P13 자기인증:** TS가 제작자의 절차·서류 어려움을 공식 설명했다. 실제 보완 사례를 확보해 기존 영상·서식 안내와 비교하는 수요 검증을 먼저 시작할 근거가 있다.[^40]
- **P04 철도 안전증빙 또는 P11 주차장 보완:** 기존 후보와 연결되므로 한 업무의 실제 자료·검토자·계약 경계를 확보한 후 선택한다. 수요 검증·데이터 확보 전 순위 확정은 하지 않는다.
- **P06·P08 자율보고:** 핵심 업무 연결은 확인되지만 보호자료 이용 목적·권한·전문 검토 확보가 선행한다.
- **P10 예약:** 최신 화면에서 불편을 재현하고 UI·API 개선으로 얻는 효과를 먼저 확인한다.
- **P17·P22:** 독립사업으로 새 엔진과 예산을 잡지 않고 각각 P01·P21의 부속 과업으로만 검토한다.

## 7. 실제 시험·심의와 전달 준비

사업화 판정은 문서의 완성도와 다르다. 실제 수요, 최종 계약 비중복, NOA 설치물, 사용권, 자료·API, 가용인력, 견적, 수용기준을 갖춰야 구축 착수가 가능하다. 법령·보안·개인정보·정보화·조달 관련 절차는 사업 유형·금액·재원·시점별 적용성을 확인한다. 특정 심의를 모든 안에 일률적으로 단정하지 않는다.

이번 단계의 시험계획은 실제 제품 시험 결과가 아니다. 문서 QA에서는 22개 ID의 대응, 출처·필수 항목, 금액·제외 조건, 중복 합산 방지, 링크·검색·필터·화면을 확인한다. 독립 평가위원·실제 사용자의 승인과 NOA 시험은 미수행 상태로 남긴다.
