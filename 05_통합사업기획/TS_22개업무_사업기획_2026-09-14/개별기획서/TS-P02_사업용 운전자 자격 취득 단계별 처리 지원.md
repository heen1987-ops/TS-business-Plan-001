# TS-P02 사업용 운전자 자격 취득 단계별 처리 지원

**버스·택시·화물 자격 취득을 준비하는 국민과 자격 상담 담당자**이 겪는 문제를 사업용 운전자 자격 취득 단계별 처리 지원로 줄이는 AX+SI 기획 초안이다. 자격시험 직무특화·민원 과업에 같은 범위가 있는지 먼저 확인.

| 구분 | 내용 |
|---|---|
| 업무 연결 | TS-L02 · 도로 교통안전 관리 · 사업용 운전자 검사·자격 |
| 검토 상태 | 중복 선확인. 핵심 업무의 공식 안내 확인; 수요·현행 법령 전체·최종 계약·제품 성능 미검증 |
| 대상 독자·발주 검토 | CCK 사업·기술·수행 책임자, TS 해당 업무부서. 실제 발주부서·재원 미확정 |
| 기술·자원 전제 | NOA·로컬 LLM, 기존 서버, 신규 인프라 구매·임차·클라우드 비용 0원 |
| 판정의 범위 | 별도 신규 사업 등록·사업 선정·CCK 주관 수행 확정 아님 |
| 기준일 | 업무 재확인 2026-09-14. 개별 출처의 최초 조사일·재열람 여부는 각주 참조 |

## 1. 실제 업무와 기획 대상

**확인된 업무:** 운전적성정밀검사, 화물 등 사업용 자격의 시험·교육·발급. [^12][^3][^7]

**수행 근거와 경계:** TS 공식 자격 취득절차 확인. 각 자격의 법정 요건·최종 결정 권한은 별도 확인. 업무의 존재와 새 AI 과업의 발주 필요성은 별도 판단이다. 페이지의 법령 인용은 조사 출발점이며 현행 법령·위탁·사무분장을 모두 대조한 법률 검토 결과가 아니다.

**공식 업무 중 이번 초기 범위:** 초기는 화물 자격 1개 경로, 상태 조회 1개, 신청 시스템 인계 1개. 나머지 세부 업무는 이번 최소 구축 범위에 넣지 않고 동일 묶음의 후속 검토로 둔다.

## 2. 국민·현업 문제와 WHY

- 문제의 근거 수준: 검사·시험·교육·발급을 따로 확인하면서 다음 단계나 준비자료를 놓치는 가설.
- 설명용 상황: 검사를 마친 신청자가 자격시험 응시 전에 무엇을 더 해야 하는지 다시 묻는 상황. 실제 관찰·면담 결과로 일반화하지 않는다.
- 국민 가치: 잘못된 안내·보완 누락·처리 실패를 줄이고 근거를 확인할 수 있게 한다. 안전 업무에서는 검토의 질을 높이는 경로를 검증하며 사고 감소를 직접 보장하지 않는다.
- 공공 개입 이유: 법정 절차·공공 안전서비스에서 이용자의 정보 격차와 업무 실패를 줄일 필요가 있다.
- 왜 AI인가: 자격별 단계형 안내와 링크·입력값 유지만으로 해결되지 않는 자유 서술의 조건 해석·근거 연결이 있는지 비교한다. 같은 효과가 나면 AI 개발 범위를 줄이거나 제외한다.
- 수요 확인: 현재 특화직무 시나리오와 단계별 API·본인확인 조건.

## 3. 현재 흐름과 변경할 행동

현재 업무는 공식 안내에서 확인했지만 실제 화면 조작·처리시간·오류 발생률은 현장 확인 전이다. 아래 변경 흐름은 제안이다.

1. 이용자의 목표 자격과 현재 진행단계를 확인.
2. 공식 규칙으로 충족·미확인 조건을 구분.
3. 필요한 입력과 준비자료를 확인하고 다음 화면에 인계.
4. 접수번호·원천 처리상태로 완료 여부를 확인.

최종 산출물은 **개인별 다음 단계 목록과 처리상태 확인 화면**이다. LLM의 자연스러운 답변이나 문서 생성 자체를 업무 완료로 표시하지 않는다.

## 4. 서비스 범위와 요구사항

| 요구사항 ID | 수행할 기능 | 수용기준 초안 |
|---|---|---|
| TS-P02-F1 | 이용자의 목표 자격과 현재 진행단계를 확인 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P02-F2 | 공식 규칙으로 충족·미확인 조건을 구분 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P02-F3 | 필요한 입력과 준비자료를 확인하고 다음 화면에 인계 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |
| TS-P02-F4 | 접수번호·원천 처리상태로 완료 여부를 확인 | 입력·근거·사용자 또는 담당자 확인·결과 상태가 추적되고 미확인 값은 미확인으로 유지 |

- 핵심 입력: 자격 종류·검사/시험/교육 상태·적용 규칙·동의한 최소 신청정보.
- 결과: 개인별 다음 단계 목록과 처리상태 확인 화면.
- 초기 물량: 2개 문서 유형, 1개 규칙·지침 묶음, 1개 조회 인터페이스, 1개 처리·인계 인터페이스를 상한 가정으로 견적 확인한다. 실제 API 개수나 제공 사실이 아니다.
- 제외: 비전·OCR·STT·TTS·센서·차량제어·검사설비, 자동 법적·안전 판정, 기관 간 원본 데이터의 포괄 통합.
- 입력 제한: 텍스트 전자문서·승인된 정형 결과만 사용한다. 스캔·사진 필수자료는 기존 공식 제출경로에서 사람이 확인하며 전체 제출절차를 AI가 완결했다고 표시하지 않는다.

## 5. 데이터·NOA·SI 및 책임

| 계층 | 역할·범위 | 확보 상태 |
|---|---|---|
| 데이터 | 자격 종류·검사/시험/교육 상태·적용 규칙·동의한 최소 신청정보 | 담당부서 허용·표본·품질·용도 확인 전 |
| NOA·로컬 LLM | 입력 서술의 구조화·검색·근거 설명·개인별 다음 단계 목록과 처리상태 확인 화면 초안 | 공급사 설명과 내부 대장 참고; TS 버전·실행·사용권 검증 전 |
| 업무 규칙·SI | 자격별 상태머신, 본인확인, 허용된 상태 조회·신청 인계 | 인터페이스·권한·변경 협조 미확정 |
| 사람 | 사실 정정, 보완·적격·안전·공개·발송의 최종 확인 | 자격 업무부서·국가자격시험 운영부서와 실제 분장 협의 필요 |
| CCK 주관 범위 | 요구사항·NOA 구성·업무 모듈·연계·검수·운영 인수 총괄 | 담당 인력·가용률·납품계약 확인 전 |

NOA 공개 소개는 폐쇄망·업무 연결·감사·사람 검토를 설명한다. 특정 기능이 현재 TS 설치물에서 동작한다는 증거와는 다르다. 내부 대장의 기재와 현재 정정도 원 코드·사용권·실행 시험을 대신하지 않으므로, NL2SQL·승인 중단/재개·자동 재실행을 기본 보유 기능으로 확정하지 않는다.[^33][^44][^45][^46]

기존 운영사에는 자격별 상태머신, 본인확인, 허용된 상태 조회·신청 인계의 계약·인터페이스 협조를 요청하는 역할안을 둔다. 협력사 확보나 기관 협조가 완료됐다는 뜻은 아니다. 쓰기 연계가 허용되지 않으면 준비·조회·공식 화면 인계까지만 납품하고 신청 완료 기능과 비용을 축소한다.

## 6. 대안·중복과 현재 판정

| 대안 | 범위·효과 가설 | 비용·기간 영향 | 판단 |
|---|---|---|---|
| 현행 유지·운영 개선 | 자격별 단계형 안내와 링크·입력값 유지 | 신규 구축 최소; 반복 문제 잔존 여부 확인 | 유효한 비교 기준 |
| SI·규칙 개선 | 입력·식별자·상태·원문 검색 정비 | 연계·데이터 정비 필요, LLM 운영 부담 없음 | 같은 목표를 달성하면 우선 적용 |
| NOA+SI | 개인별 다음 단계 목록과 처리상태 확인 화면와 검토 흐름 | 문서 정비·AI 평가·연계·운영 비용 추가 | 중복 선확인 |

**중복 대조:** SFR-003 자격시험, SFR-005~007; 일반 운전면허 시험 업무를 포함하지 않음. 비교 단위는 업무·대상자·입력 데이터·기능·산출물·성과다. SFR-001~009 정리자료는 기존 플랫폼·자동차검사/자격시험/안전단속 특화·민원·전세버스 공시 기능을 명시한다. 계약 원문·승인된 직무 시나리오와 같은 범위이면 신규로 제안하지 않는다.[^43][^31]

**현재 판단:** 중복 선확인 — 자격시험 직무특화·민원 과업에 같은 범위가 있는지 먼저 확인. 비중복·제품·수요 검증 전에는 확정 후보나 발주 가능 사업으로 승격하지 않는다.

## 7. 화면·예외·사용자 경험

| 화면 ID | 목표·주요 행동 | 권한·표시 |
|---|---|---|
| TS-P02-UI1 | 입력·자료·현재 상태 확인 | 본인 또는 담당 권한, 필수 입력·자료 미확보 표시 |
| TS-P02-UI2 | 개인별 다음 단계 목록과 처리상태 확인 화면 검토 | 원문·버전·확인/미확인·상충을 함께 표시 |
| TS-P02-UI3 | 수정·확인·인계 결과 확인 | 사용자·담당자 승인 기록, 원천 접수·판정과 AI 초안을 구분 |

- 업무 예외: 검사 유효상태를 조회하지 못하면 응시 가능으로 단정하지 않고 공식 확인 단계로 인계.
- 로딩: 문서·시스템 조회 중임을 표시하고 중복 실행을 막는다.
- 빈 상태: 자료·결과가 없다는 사실과 다음 확인 항목을 표시한다.
- 권한 없음: 자료 제목·요약도 노출하지 않고 허용된 문의 경로를 제시한다.
- 일부 성공·타임아웃: 완료된 단계와 실패 단계를 나누고 마지막 확인시점·재시도 가능 여부를 표시한다.
- 접근성 목표: WCAG 2.2 AA를 목표로 키보드·초점·레이블·확대·스크린리더를 설계 단계에서 검증한다. 이번 기획 문서 검사는 제품 접근성 인증이 아니다.
- 개인정보·운영: 로그는 최소 식별자·상태 중심, 원문 접근은 별도 권한, 원본 변경·삭제를 검색 인덱스·캐시까지 반영한다. 보존기간은 업무 규정으로 확정한다.

## 8. 성공지표와 시험 설계

핵심 지표는 **잘못된 다음 단계 안내·조건 재입력·신청 완료 실패**다. 기준값은 미측정이며 임의의 달성률을 쓰지 않는다. 같은 업무 사례에서 현행/비AI와 NOA+SI를 비교하고 입력·모델·규칙·동시성·문서 버전을 기록한다. 표본과 목표 개선폭은 실제 자료와 피해 수준을 보고 실증 전에 정한다.

| 시험 | Given / When / Then 요약 | 합격 기준 초안 | 상태 |
|---|---|---|---|
| TS-P02-T1 정상 | 승인된 자료가 있을 때 해당 입력을 처리하면 개인별 다음 단계 목록과 처리상태 확인 화면와 원문 근거가 연결됨 | 필수 근거와 상태 연결 누락 없음 | 미수행 |
| TS-P02-T2 업무 예외 | 검사 유효상태를 조회하지 못하면 응시 가능으로 단정하지 않고 공식 확인 단계로 인계 | 해당 예외에서 완료·적합·공개를 임의 확정하지 않음 | 미수행 |
| TS-P02-T3 권한·개정 | 권한 회수 또는 원문 개정 후 조회하면 제한·개정 상태가 반영됨 | 사전 정의한 시험 사례에서 무권한 노출 0건 | 미수행 |
| TS-P02-T4 인계·복구 | 승인·접수 실패 또는 중복 요청 시 결과를 확인하고 재처리 | 무승인 상태변경·허위 완료 표시·중복 처리 0건 | 미수행 |
| TS-P02-T5 가치 비교 | 동일 입력을 자격별 단계형 안내와 링크·입력값 유지과 비교 | 중대한 품질 저하 없이 사전 합의한 국민·현업 지표 개선 | 미수행 |

시험집의 실패 0건은 실제 운영 위험 0의 보증이 아니다. 안전·개인정보 결함은 빈도와 피해를 함께 검토하며 미해결 중대 결함이 남으면 확대하지 않는다. 개선시간을 감축 인원으로 환산하지 않는다. 현업 의견은 아직 수집하지 않았고, 검토 품질·교육·국민 지원에 확보 시간을 활용하는 방안을 협의한다.

## 9. 비용·일정·납품 범위

견적 산정의 초기 입력은 초기는 화물 자격 1개 경로, 상태 조회 1개, 신청 시스템 인계 1개다. 이는 물량을 제한한 제안 가정이며 확보된 서버 성능·인력·공수의 실측값이 아니다.

| 원가 항목 | 산정 입력 | 현재 금액 |
|---|---|---|
| 업무·데이터 정비 | 2 문서 유형 × 유형별 표본 확인·필드·버전 정비 공수 | 견적 필요 |
| 규칙·지식 구성 | 1 규칙/지침 묶음 × 적용일·원문 위치·예외 정비 공수 | 견적 필요 |
| 기능·화면 | 4개 요구기능과 3개 화면의 개발·접근성 검토 공수 | 견적 필요 |
| 시스템 연계 | 조회 1개 + 처리/인계 1개 × 인증·계약·오류 복구 공수 | 제공 여부·견적 필요 |
| NOA 사용·구성 | 기존 계약 사용권 확인 후 추가 모듈·사용료 여부 대조 | 기존분 재청구 금지, 증분만 견적 |
| 검증·보안·전환·교육 | 시험자료·평가·배포 설정·복원 시험·운영 인수 | 견적 필요 |
| 신규 인프라 | GPU·서버·저장·백업·망 장비 구매/임차·클라우드 | **0원** |
| 지속 운영 | 기준·지식 변경, API 변경 대응, 모델 품질 점검, 문의·장애 처리 | 책임·주기·연간 공수 확인 후 산정 |

계산식은 역할별 공수×검증된 단가 + 승인된 증분 SW/용역비이며 계약조건에 맞는 제경비·부가세 등을 별도로 확인한다. 시장 단가·라이선스 견적·실측 공수 없이 금액을 확정하지 않는다. 프로그램의 1차 7억·2차 추가 5억 원은 VAT 포함으로 해석한 목표 상한이며, 이 22건 각각의 예산이나 전부 구축 가능한 예산이 아니다.[^38][^48]

| 단계 | 기간 가정 | 책임·산출물 | 다음 단계 조건 |
|---|---|---|---|
| 범위·근거 확인 | 2~4주 | CCK+업무부서: 중복표·자료·업무규칙·서버 확인 | 계약·자료·사용권·수요 조건 충족 |
| 제한된 시범 구축 | 6~10주 | CCK: 화면·문서/규칙팩·허용된 연계·로그 | 기능·보안 시험 준비 |
| 현업 검증·인수 | 2~4주 | CCK+TS: 비교시험·오류정정·교육·운영문서 | 사전 수용기준·현업 인수 승인 |

기간은 인력·연계 협조가 확보된 한 업무의 예시 일정이며 계약 납기가 아니다. 자료·권한·API가 지연되면 무조건 병행 개발하지 않고 초기 범위와 일정을 재조정한다. 납품은 요구사항·데이터/규칙·화면·소프트웨어 구성·연계 명세·시험 결과·운영/복구 문서·교육을 포함한다.

## 10. 추진 조건·운영·확장

- 다음 증거: 현재 특화직무 시나리오와 단계별 API·본인확인 조건.
- 운영 책임: 자격 업무부서·국가자격시험 운영부서가 업무·규칙·승인을, CCK가 계약 범위의 소프트웨어 품질·변경·장애 대응을 담당하는 역할안이다. 실명·협력 계약·가용인력은 미확정이다.
- 축소/중단 조건: 비중복 미입증, 허용 자료 부재, 비AI와 차별적 성과 없음, 기존 서버 품질 미달, 중대 결함 발생.
- 복귀: AI 제안 기능을 끄고 기존 업무 화면·규칙·공식 처리 경로를 유지한다. 원본을 수정하지 않으며 배포 구성·규칙 버전을 되돌린다.
- 확장: 공공 자격 신청의 단계 안내·완료 확인 재사용; 자격요건은 별도. 기관 간 개인정보·업무자료 통합 권한을 확보했다는 뜻은 아니다.
- 발주 전 절차: 사업 유형·재원·금액·시점에 따라 정보화·보안·개인정보·계약 관련 검토의 적용 여부를 TS 담당자와 확정한다. 모든 과제에 같은 심의를 요구한다고 단정하지 않는다.
- 자체 기획 판정: **중복 선확인**. 실제 실행 승인·외부 평가위원 판정은 미실시.
