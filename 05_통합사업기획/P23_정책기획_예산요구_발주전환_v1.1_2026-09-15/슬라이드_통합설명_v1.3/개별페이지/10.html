전체 아키텍처

개념상 흐름: 담당자 요청 → NOA 서비스·접근제어 → 검색 컨텍스트 구성 → 로컬 LLM 응답 → 규칙 검사·사업원장 저장 → 사람 검토 → 문서 초안. 생성 결과를 화면과 원장으로 되돌리는 응답 경로가 필요하다.

외부 자료 수집망과 내부 추론망의 실제 망 구성·반입 승인 방식은 TS 환경에 따라 정한다. 이 그림은 인터넷 수집을 내부 서버에서 자유롭게 허용한다는 뜻이 아니다.

공식 제출 이후 확인된 심의·발주·실행 결과를 담당자가 등록하면 원장의 새 버전과 후속 평가에 연결한다. 외부 시스템 자동 제출 API는 초기 범위 밖이다.

기존 서버 성능·사용권·NOA API·SSO·문서 라이브러리·백업 운영은 미검증이다. 근거 접근 권한과 생성 문서의 공개 권한을 별도로 확인한다.
