## 가정과 사용 범위

기존 서버 활용과 신규 인프라 투자 0원을 전제로 한 기획안이다. 실제 기관의 데이터·서식·NOA·서버 성능 확인과 제품 구현·인수시험은 별도다. 이미지 모델로 생성한 두 그림은 설명용이며 제품에 비전 기능을 추가한 것이 아니다. 비용은 기존 v1.1의 조건별 추정을 승계했다.

## 01. TS 정책·사업 기획지원 플랫폼

근거를 검토하고 사업과 예산을 설계하는 공동 작업대

![기존 로컬 환경에서 자료를 검토하는 부서 공동 작업대의 생성형 컨셉 이미지](assets/표지_협업컨셉.png)

이 자료는 한국교통안전공단(TS)의 여러 부서가 정책 의제를 검토하고 사업·예산·발주 초안을 함께 만드는 P23 추가 후보의 설명자료다. TS의 공식 23번째 업무분류나 확정 도입사업을 뜻하지 않는다.

표지와 3장의 그림은 이미지 생성 모델로 만든 설명용 컨셉이다. 실제 TS 시설·직원·운영 시스템의 사진이 아니다. 제품의 입력 범위는 허용된 텍스트와 구조화 데이터이며 비전·OCR·영상처리 기능을 제안하지 않는다.

CCK의 주관 수행을 전제로 하는 기획안이다. 실제 NOA 인터페이스와 이용권, 기존 서버 여력 확인 후 범위와 비용을 확정한다.



## 02. 자료가 많을수록 판단의 연결이 중요해진다

부서마다 근거를 다시 찾고 문서를 다시 쓰는 부담이 있다는 업무 가설

자료량과 재작성 시간이 실제로 어느 정도인지는 확인 전이다. 착수 인터뷰와 대표 의제의 현행 처리과정 관찰로 빈도·소요시간·누락 사례를 측정한다.

보고서 생성량이나 처리시간 절감을 교통사고 감소의 직접 증거로 사용하지 않는다. 국민 불편·위험의 개선은 선택한 정책사업에서 별도 성과지표와 비교 기준으로 확인한다.



## 03. 전체 서비스 컨셉

허용 자료와 담당자의 판단을 연결해 목적별 문서 초안을 만든다.

![왼쪽 자료, 중앙의 내부 분석 작업대, 오른쪽 정책·예산·발주 초안을 연결한 생성형 컨셉 이미지](assets/전체_서비스컨셉.png)

입력: 공개·이용 권한을 확인한 뉴스, 정책보고서, 공개 국민제안과 내부 민원·현황자료. 원문과 수집일, 접근정책, 출처를 함께 기록한다.

처리: 로컬 LLM의 근거 검색·요약·초안 후보, 일반 프로그램의 계산·필드 검사·버전 관리, 담당자의 검토 결정을 결합한다.

출력: 문제정의, 대안 비교, 사업설명·예산요구, 발주기관 RFP·공고 인계 초안. 실제 공식 제출과 공고는 담당자의 별도 절차다.



## 04. 부서가 함께 쓰는 서비스 모델

하나의 사업원장을 중심으로 근거 작업대와 사업·예산 작업대를 연결한다.

부서 명칭은 기능별 역할을 설명한 것이다. 실제 TS 조직명과 전결 권한은 착수 때 확인한다.

최소 관리 단위는 원문 파일뿐 아니라 근거, 사업원장, 검토 결정이다. 문서들은 같은 원장 버전을 다른 목적의 양식으로 보는 출력물이다.

원장 핵심 필드: 의제 ID, 대상자·문제, 근거 링크와 상태, 원인 가설, 반대 근거, TS 소관, 대안, 선택 사유, 사업범위, 성과지표, 비용·재원, 검토자·결정·시각, 문서 프로필·버전.



## 05. 서비스 흐름과 부서별 인계

각 단계는 다음 담당자가 판단할 수 있는 산출물을 남긴다.

| 단계 | 자료·문제 | 대안·사업 | 예산·보완 | 발주·평가 |
| --- | --- | --- | --- | --- |
| 담당자 행동 | 자료 등록 / 문제 검토 | 대안 비교 / 사업 범위 선택 | 요구액 검토 / 심의 결과 등록 | RFP 검토·인계 / 실행 결과 등록 |
| AI·규칙 | 근거 묶음 / 가설·조사 공백 | 소관·중복 후보 / 범위·KPI 초안 | 산식·단위 검사 / 문서·보완 초안 | 요구·검수 연결 / 성과 대비 분석 |
| 산출물 | 근거 묶음 / 문제 카드 | 선택 사유 / 사업 버전 | 예산요구안 / 보완 이력 | 발주 초안 묶음 / 후속 평가 |
| 다음 단계 조건 | 근거 검토 완료 | 대안·범위 검토 | 확정 범위 확인* | 계약·공개 검토 |

기본 흐름: 자료 등록 → 근거 검토 → 문제정의 → TS 소관과 현행사업 확인 → 대안 비교 → 사업범위·성과 설계 → 예산요구와 보완 → 발주 초안 → 담당자 인계 → 실행·성과 환류.

자료 부족 시 추가 조사로, 소관 외이면 협업·이관 검토로, 감액 시 범위·일정 재설계로 돌아간다. 계약·예산 단계의 제품 상태를 기관의 공식 승인과 동일시하지 않는다.

## 06. 문제정의 예시: 자동차검사 예약 탐색 불편

사용자의 경험을 출발점으로 확인된 사실과 추가 조사 항목을 나눈다.

문제 카드 P-001의 예시다. 실제 예약 데이터 갱신 장애나 시스템 전체의 공통 결함으로 단정하지 않는다.

확인된 출발점은 제공된 대화의 사용자 경험이다. 원인 후보는 상태 표시·화면 흐름, 조회 연계, 실제 공급 부족으로 나누고 각각 필요한 증거를 지정한다.

실제 공개 국민제안의 존재와 처리 결과는 기존 조사자료를 다시 확인해야 한다. 이 슬라이드의 가상 사례에는 민원 건수나 효과 수치를 부여하지 않았다.

대상자, 경험한 상황, 불이익, 현상, 가설, 반대 근거, 조사 공백, 검토자를 문제 카드의 필수 필드로 설계한다.



## 07. 정책 수단과 솔루션 도입 대안

문제의 원인과 현행 기능을 확인한 뒤 적합한 개선 수단을 선택한다.

| 대안 | 해결하려는 부분 | 필요한 전제 | 판단 |
| --- | --- | --- | --- |
| 운영·안내 개선 | 이용 절차·대안 안내 | 문의·안내 오류 근거 | 작은 변경으로 개선 가능? |
| 기구축 기능 활용 | 이미 있는 기능의 이용 | 기능·계약·운영 확인 | 현재 범위와 중복되는가? |
| 화면·조회 SI 개선 | 가능 상태 비교와 동선 | 슬롯 데이터와 연계 권한 | 사례의 직접 개선 후보 |

P23 플랫폼과 P23로 기획하는 자동차검사 예약 개선사업을 구분한다. 예약 탐색 불편 자체는 UI·조회 연계 SI가 직접 해결 후보일 수 있다. LLM 도입을 사전 결론으로 두지 않는다.

이미 구축된 사업에도 AI를 적용할 수 있다. 다만 동일 계약의 같은 납품 결과를 다시 산정하지 않고 재사용 기능과 추가 수행분을 구분한다.

TS 소관·개입 가능성·법정 요구·사업 중복·재사용성을 먼저 확인한다. AI의 유사사업 검색은 공식 중복검토나 정부 협의 절차를 대체하지 않는다.



## 08. 사용자 화면과 작업 방식

의제 하나를 열면 근거, 선택한 대안, 예산, 문서를 같은 맥락에서 확인한다.

사용자 유스케이스: 업무담당자가 의제를 등록하고 접근 가능한 근거를 검토한다. 기획담당자는 가설·반대 근거·대안 비교를 수정한다. 예산담당자는 확정되지 않은 필드를 확인하고 산식·재원을 검토한다. 계약담당자는 RFP의 요구사항과 공개 가능 범위를 확인한다.

화면별 공통 상태: 대기, 처리 중, 빈 결과, 부분 성공, 입력 오류, 권한 부족, 연결 실패·시간 초과, 재시도, 검토 요청, 재검토 필요. 오류가 나도 입력 조건과 저장된 사업 버전을 유지한다.

근거 부족은 빈칸을 추측으로 채우는 대신 담당자·기한이 있는 조사 과제로 남긴다. 키보드 접근·명확한 포커스·상태 문구·모바일 상세 목록을 설계 요구에 포함한다.

[7단계 사용자 화면 시연](../시각설계_v1.2/06_사용자화면_시연.html)

## 09. AI, 규칙 프로그램, 담당자의 역할

서술과 계산, 공식 판단을 분리해 검토 가능한 결과를 만든다.

LLM의 유창한 문장이나 자동 점수는 원인의 확정이나 정책의 객관성을 보장하지 않는다. 반대 근거와 누락 정보를 함께 보여준다.

금액 계산은 구조화된 단가·수량·기간·세율·가정으로 재현한다. AI가 작성한 수치를 승인 없이 확정값으로 저장하지 않는다.

외부 자료의 명령문을 실행 지시로 취급하지 않고, 자료에서 나온 내용과 사용자의 업무 지시를 구분한다. 실행 가능한 도구는 승인된 읽기·내부 초안 기능으로 제한하는 설계다.



## 10. 전체 아키텍처

기존 기관 서버 안에서 NOA와 추가 SI를 연결하는 제안 구조

개념상 흐름: 담당자 요청 → NOA 서비스·접근제어 → 검색 컨텍스트 구성 → 로컬 LLM 응답 → 규칙 검사·사업원장 저장 → 사람 검토 → 문서 초안. 생성 결과를 화면과 원장으로 되돌리는 응답 경로가 필요하다.

외부 자료 수집망과 내부 추론망의 실제 망 구성·반입 승인 방식은 TS 환경에 따라 정한다. 이 그림은 인터넷 수집을 내부 서버에서 자유롭게 허용한다는 뜻이 아니다.

공식 제출 이후 확인된 심의·발주·실행 결과를 담당자가 등록하면 원장의 새 버전과 후속 평가에 연결한다. 외부 시스템 자동 제출 API는 초기 범위 밖이다.

기존 서버 성능·사용권·NOA API·SSO·문서 라이브러리·백업 운영은 미검증이다. 근거 접근 권한과 생성 문서의 공개 권한을 별도로 확인한다.

[아키텍처 구성요소 상세](../시각설계_v1.2/02_전체_아키텍처.html)

## 11. 데이터 흐름과 근거 추적

원문에서 출발해 각 판단과 문서가 어떤 버전을 사용했는지 기록한다.

연결키 예시: source_id, evidence_id, issue_id, project_id, project_version, budget_version, template_id, template_version, document_version, review_id. ID 예시는 설계안이다.

데이터 처리: 승인된 자료 반입 → 텍스트·표 구조화 → 출처 메타데이터와 접근정책 등록 → 근거 단위 연결 → 가설·문제 검토 → 사업·비용 원장 → 양식별 초안. 스캔·음성·영상 인식은 제안 범위에 포함하지 않는다.

검색은 권한 필터를 적용하고, 요약·생성문서도 사용한 보호 근거에 맞는 접근 수준을 유지한다. 내부 열람 권한이 외부 공개 권한을 의미하지 않는다.

원문 정정·철회가 발생하면 파생 주장과 영향을 받은 문서를 재검토 대상으로 표시한다. 이전 버전은 승인된 보존정책에 따라 유지하며 삭제·보존기간은 TS가 정한다.

[데이터 흐름 상세](../시각설계_v1.2/03_데이터_흐름도.html)

## 12. 판단 로직과 예외 처리

자료가 부족하거나 조건이 바뀌면 다음에 해야 할 검토를 표시한다.

| 판단 질문 | 진행할 조건 | 조건을 충족하지 못하면 |
| --- | --- | --- |
| 문제의 근거가 있는가? | 출처·대상·현상을 확인 | 추가 조사 과제와 미확정 초안 |
| TS가 개입할 수 있는가? | 소관·역할·협업 범위 확인 | 타기관 협업·이관 검토 |
| 추가 수행이 필요한가? | 대안·계약 중복 검토 후 추가분 확인 | 운영 개선·기존 기능 활용·추가 조사 |
| 재원·범위가 확인됐는가? | 실제 심의 결과와 범위 일치 | 감액 시 일정·기능·검수 재설계 |
| 외부 인계할 수 있는가? | 양식·권리·공개·계약 검토 | 보완 사유와 책임자 표시 |

AI 추천 상태와 기관 공식 상태는 별도 필드다. 문제 검토 완료·내부 초안 완료가 예산 승인·공고 게시를 의미하지 않는다.

## 15. 사업범위를 RFP의 검수 조건으로 연결

발주기관이 필요한 결과를 확인할 수 있도록 요구사항을 구체화한다.

RFP는 발주기관이 요구하는 과업·성과·검수·계약 조건의 초안이다. 수행사가 제출할 제안서와 구분한다. P23의 기획지원 요구사항과 P23가 출력할 개별사업의 요구사항 ID도 서로 분리한다.

수량·처리시간·접근성·보안·오류 처리 등 수용기준은 확보한 기준선과 실제 연계 계약에 맞추어 정한다. 근거 없는 지연시간·효과 수치를 제시하지 않는다.

CCK 주관 수행을 검토한다는 사실로 특정 업체만 충족하는 입찰규격을 자동 작성하지 않는다. 실제 계약방식·평가기준·공고조건·법규 적용은 계약담당자가 검토한다.

공고 전환은 내부 승인본에서 공개 가능 필드를 추출하고 필요한 첨부·미확정 필드를 인계하는 기능이다. 나라장터 자동 공고 게시나 대외 전송 기능은 초기 범위에 포함하지 않는다.

## 16. 변경이 생기면 관련 문서를 다시 검토한다

원문 정정·예산 감액·범위 변경의 영향을 추적하고 이전 판단을 보존한다.

원장 변경이 모든 문서를 무조건 덮어쓰게 하지 않는다. 영향받은 필드·근거·문서·검토자를 식별하고 재검토 필요 상태와 변경 비교를 표시한다.

실행 후에는 실제 비용·범위·성과 측정 결과를 해당 사업원장에 연결하고 차기 의제의 근거로 사용한다. 공식 실행 결과의 등록은 권한과 출처 증빙을 남긴다.

## 20. 초기 도입 범위와 확장 조건

작은 의제에서 자료·판단·문서의 연결을 확인하고 다른 TS 업무로 확장한다.

1차 시범에서 근거·사업원장·검토·변경·양식의 공통 기능을 검증한다. 다른 22개 업무 또는 타기관 확장은 신규 데이터 연계·소관 규칙·양식·권한을 추가 설정하고 추가 공수만 산정하는 방식이다.

핵심 가치 가설은 문제정의의 근거 누락 감소와 실행 가능한 사업 선택 지원이다. 도입 또는 예산 확보 자체를 성과로 삼지 않고, 시범 평가 결과에 따라 확대·보완·보류를 결정한다.
