자료를 보는 단위

원문 파일 하나를 요약하는 데서 끝내지 않고, 하나의 주장에 어떤 근거가 있고 어떤 근거가 반대하는지를 검토한다. 같은 뉴스를 여러 매체가 전재한 경우 자료 수와 독립 근거 수를 구분한다.

입력 쓸 수 있는 내용 확인할 점
정책보고서·연구자료 정책목표·분석조건·과거 대안·평가 결과 발간 시점, 분석 대상, 현재 적용 가능성

TS 사업계획·계약·성과 소관·기구축 범위·계약 산출물·개선 성과 최신 계약·변경계약·검수 결과·자료별 부서 권한

자동 수집은 허용된 API·제공 파일·등록 출처에 한정하는 설계다. 현재 신문고 내부 민원 접근권한, 뉴스 원문 이용권, 통계 연계 API는 확인되지 않았다. 초기에는 담당자 승인 자료의 일괄 반입으로 시작한다.

담당자 판단 채택·보완·유보·종결 사유, 검토자·버전·날짜

정책 원인과 해결수단을 서둘러 연결하지 않는다

예를 들어 ‘자동차검사 예약 탐색이 번거롭다’는 경험이 있으면, 화면 이동 횟수·마감 표시·실제 가용 슬롯·예약 로그를 나누어 확인한다. 불편의 원인이 화면 구성이라면 UI·조회 연계 개선이 우선일 수 있고, 슬롯 자체의 부족이라면 운영 대안도 비교해야 한다. 로컬 LLM은 이 판단을 위한 자료 정리와 문서화를 돕는다.

위 사례는 사용자 경험을 활용한 검토 예시이며, 현재 TS의 전체 민원 빈도나 실제 예약 장애를 입증한 조사 결과는 아니다.

부서 협업

기획 담당자는 공통 문제 틀을 관리하고 업무 담당자는 현장 사실을 확인한다. 예산 담당자는 비용·재원, 정보화 담당자는 재사용·연계, 계약 담당자는 발주 가능성을 검토한다. 부서 의견이 다르면 어느 의견을 채택했는지 사유를 남기고, 미해결 이견을 삭제하거나 자동 합의로 바꾸지 않는다.

부서별 원문 권한을 검색·답변·내보내기까지 적용한다. 다른 부서의 존재만으로 비공개 자료를 공동 지식에 자동 편입하지 않는다. 공개 가능한 공통 사실과 접근이 제한된 원문을 별도 관리한다.

우선순위 제안

안전·국민 불편·공공 책무·시급성·개입 가능성·근거 충분성·비용·실행 의존성을 비교한다. 가중치는 부서가 합의해 버전으로 보존한다. 기사량·민원량·감정 강도만으로 예산 순위를 결정하지 않는다. 점수는 검토 보조이며 정책 승인 결과가 아니다.
