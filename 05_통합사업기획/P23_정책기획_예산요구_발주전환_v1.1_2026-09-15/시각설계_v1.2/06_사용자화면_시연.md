# 사용자 화면 시연

실제 제품·데이터가 아닌 설명용 가상 화면이다.

## 01 자료함

목적: 어떤 자료를 함께 볼 것인가

입력: 가상 의제: 자동차검사 예약 탐색의 불편

- SRC-01 / 이용자가 날짜·검사소를 반복 확인한다는 의견 / 사용자 경험을 바탕으로 만든 설명 예시
- SRC-02 / 실제 예약 조회·이동 로그 / 미확보 · 담당자 제공 필요
- SRC-03 / 현행 기능·계약 범위 자료 / 미확보 · 중복 판단 전 확인 필요

출력·다음 단계: 3개 항목은 설명용 등록 예시입니다. 실제 조사 자료·연결 결과가 아닙니다.

## 02 문제 카드

목적: 현상·원인 가설·반대 근거를 나누어 본다

입력: 자료함의 근거 카드와 검토 질문

- 현상 / 가용 일정을 찾는 과정이 번거롭다는 이용 경험 / 검사소·날짜 이동의 불편
- 원인 가설 / 화면 구성·상태 표시 또는 가용 슬롯 부족 / 실제 원인 미확인
- 추가조사 / 화면 이동·조회 상태·슬롯 현황 확인 / 근거 확보 전 원인 확정 보류

출력·다음 단계: ISS-01 문제 초안 → 업무 담당자의 확인·보완

## 03 대안 비교

목적: 어떤 방법이 문제를 줄일 수 있는가

입력: 검토된 문제 + TS 소관 + 기존 수행 범위

- 대안 A / 화면·조회 동선 개선 / 실제 조회 인터페이스 확인 필요
- 대안 B / 일정 안내·운영 방식 개선 / 슬롯 부족 여부 확인 필요
- 대안 C / 근거를 더 확보한 후 판단 / 현재 자료 부족 시 선택 가능

출력·다음 단계: 자동으로 AI 도입을 선택하지 않습니다. 담당자가 선택 사유를 남깁니다.

## 04 사업 작업대

목적: 선택한 대안을 수행범위로 구체화한다

입력: 선택 대안과 실제 제공 가능한 자산

- 포함 검토 / 차량·날짜·지역 조건 유지 및 가용상태 표시 / 범위 확정 전 API 확인
- 요구사항 연결 / 문제 → 기능 → 데이터 → 검수 / 가상 REQ-01 · 실제 RFP 아님
- 전제 / 기존 시스템·자료 제공·운영환경 확인 / 미확인 항목을 원장에 보존

출력·다음 단계: PRJ-01 공통 원장 초안. 개별 사업 구현비는 P23 플랫폼 개발비와 별도입니다.

## 05 예산 작업대

목적: 범위와 산출 근거가 맞는지 확인한다

입력: 범위·수량·단가·연차·VAT·근거

- 요구액 가정 / 100백만원 → 감액 예시 70백만원 / 설명용 금액 · 실제 승인액 미확인
- 미확정 비용 / 연차별 운영비·이용권·기타 경비 / 미확인을 0원으로 계산하지 않음
- 감액 대응 / 필수 유지·축소·단계 분리 대안 / 범위·일정·검수 다시 확인

출력·다음 단계: F02·F03 예산자료 초안 + F06 보완표

## 06 문서 작업대

목적: 같은 사업정보로 제출 목적에 맞는 초안을 만든다

입력: 검토 원장 버전 + 실제 수신기관 양식

- 공통 필드 / 사업목적·대상·범위·요구액·기간 / F01·F02·F04에서 같은 버전 참조
- 양식 필드 / 제출연도·부처·비목·실제 의견조회 / 근거가 없으면 미확인
- 출력 결과 / 정책 검토·예산 설명·RFP 초안 / 고정 HWPX 실제 변환은 실증 전

출력·다음 단계: 작성된 초안과 근거를 담당자가 함께 확인합니다.

## 07 검토·인계

목적: 미해결 사항과 문서 변경을 확인하고 인계한다

입력: 실제 승인 증빙·양식·계약조건·검토 의견

- 예산 결과 / 실제 회신·승인액 확인 필요 / 미확인 상태를 승인 완료로 바꾸지 않음
- 변경 영향 / 문제·범위·예산·RFP의 재검토 목록 / 과거 검토본은 보존
- 공식 처리 / 권한 있는 담당자의 기존 시스템에서 별도 수행 / 이 시연에는 제출·공고 버튼 없음

출력·다음 단계: F04·F05·F06 검토 파일 인계 준비. 화면 클릭은 실제 결재가 아닙니다.
