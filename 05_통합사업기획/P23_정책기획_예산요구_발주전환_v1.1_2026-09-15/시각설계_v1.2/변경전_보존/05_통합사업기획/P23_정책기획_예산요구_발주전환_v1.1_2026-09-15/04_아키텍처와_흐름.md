# 로컬 LLM 기반 구성과 검토 흐름

기존 서버 위에 논리 모듈을 연결하는 제안 설계


## 전체 아키텍처

![전체 논리 아키텍처](자산/architecture.svg)

표시한 모듈은 새 장비 수량을 의미하지 않는다. 외부 자료는 승인된 반입 경로를 통해 로컬 저장소에 넣고 내부 문서·질문·임베딩·모델 입력을 외부 LLM으로 전송하지 않는 구성이다. 인터넷 수집이 허용되지 않는 환경에서는 제공 파일 반입 방식으로 작동한다.

| 역할 | 재사용 후보 | 추가 구현·검증 |
| --- | --- | --- |
| 문서 의미 파악·근거 검색 | NOA, TA01 Argus, TA20 RAG 관련 자산 | 근거 카드·문제 틀·부서별 권한 필터·평가셋 |
| 실행·도구 연결 | TA02 Keeper·TA03 Nexus 관련 자산 | 허용 도구·실패 처리·단계별 결과 저장; 사람 검토의 중단·재개 기능은 신규 구현 가정 |
| 양식 출력 | TA18 docsmith 및 python-hwpx 활용 후보 | 서식 등록·확정 매핑·HWPX 어댑터·렌더 검수 |
| 숫자·규칙 | 기존 산정 산식과 통상적인 SW 개발 | 연차·단위·누락값·증감·범위 일치 검사; LLM 산술에 의존하지 않음 |
| 변경·검토·공개본 | 현행 권한·결재체계의 확인 가능한 부분 | 사업 버전·승인 증빙·변경 영향·공개본 분리 |
| 미구축 기술 | TA23 NL2SQL+EvidenceTrail은 계획 상태 | 즉시 사용 가능한 기본 기능으로 산정하지 않음 |

## 사용자 흐름

![담당자 검토와 인계 흐름](자산/user.svg)

상태는 자료검토 → 문제확인 → 대안검토 → 사업안검토 → 예산요구준비 → 심의결과확인 → 발주검토 → 인계준비로 진행한다. 각 상태에서 보완·유보·종결이 가능하다. 화면의 클릭만으로 공식 예산 승인·전자결재·나라장터 공고 상태를 생성하지 않는다.

## 운영 규칙

- 변경 전 검토본은 보존하고 새 버전에 영향 문서·검토 사유를 붙인다. 원문 철회·권한 회수 시 검색 인덱스·캐시·생성물 참조 사용을 중지한다.
- 자료 문장 안의 명령은 지시로 실행하지 않는다. 문서 입력은 근거 데이터이며 자동 도구 권한을 부여하지 않는다.
- 생성 작업은 큐로 관리하고 실패·부분 완료·재시도 여부를 표시한다. 저장된 초안을 유지하며 공식 처리 성공으로 오인시키지 않는다.
- 외부 제출은 검토 파일 인계까지다. 실제 예산 시스템·전자결재·나라장터 연계는 API·권한·계약 범위 확인 후 별도 변경 판단한다.
- 서버 실측 전 응답시간·동시 사용 인원을 보장하지 않는다. 시범 자료로 메모리·저장공간·처리량을 측정하고 범위를 확정한다.
