# TS 국민 편의와 안전 AX 서비스 정의서

버전 0.1 · 2026-09-10 · 발주 전 검토안

국민이 교통안전 업무의 결과를 이해하고 필요한 예약·보고·신청·후속 조치를 마칠 수 있도록, 로컬 LLM의 언어 처리와 공식 업무 시스템의 상태를 연결한다. CCK가 전체 설계·통합·품질·운영 인수를 책임지는 구상이다.

## 서비스 포트폴리오

| ID | 서비스 | 최초 적용과 단계 |
| --- | --- | --- |
| X01 | 조건을 알아듣는 예약·신청 실행 | 2단계 자동차검사 예약 |
| X02 | 검사·리콜 결과에서 후속 행동까지 | 1단계 자동차검사 결과 |
| X03 | 위험·결함 보고를 정확하게 전달 | 2단계 자동차 결함 보고 |
| X04 | 안전 지적사항의 조치·증빙 연결 | 1단계 기계식주차장 조치증빙 |
| X05 | 복잡한 신청의 준비·보완 지원 | 2단계 자격 또는 튜닝 중 1종 |

5개는 독립 발주가 확정된 사업 수가 아니다. 1단계에서 X02·X04와 필요한 공통 적응을 검증하고, 2단계는 수요·권한·API·비중복 확인 후 착수한다. 사업군의 전체 확장 가능성과 이번 비용의 제한된 최초 적용 범위를 구분한다.

## 가정과 성공 기준

성공은 실제 후속 행동의 이해·전환, 정보 누락 감소, 불필요한 재입력 감소로 검토한다. 사고 감소·감원 수치·로컬 모델의 무오류를 약속하지 않는다. 공수·기간·품질 목표는 검토안이며 현장 표본과 CCK 데모로 조정한다.

전자 텍스트와 공식 구조화 데이터만 처리한다. 비전, 신규 OCR, 원시 센서, 차량 제어, 정비 진단, 물리적 안전 판정, 일반 민원 챗봇과 전세버스 공시 AI 후속 고도화는 이번 구축 범위에서 제외한다.

## X01 조건을 알아듣는 예약·신청 실행

검사 이용자가 가능한 날짜·장소를 반복해서 뒤지지 않고 자신의 일정에 맞는 선택지를 찾고 예약하도록 돕는다.

| 정의 항목 | 내용 |
| --- | --- |
| 직접 사용자 | 자동차검사 예약 이용자 |
| 국민 가치 | 유효 후보를 찾는 시간·왕복·재입력, 필수조건 보존, 실제 예약 완료율, 마감 슬롯 제시·허위 완료·중복 요청 오류. 평가안이며 목표값·효과 실측은 미확정. |
| 입력과 근거 | 차량·검사종류·공식 검사기간, 이용자가 확인한 날짜/시간/이동 범위, 공식 검사소·슬롯 데이터와 조회시각. |
| 처리와 출력 | 로컬 LLM이 필수조건과 선호조건을 구조화 → 사용자 확인 → 허용 목록의 조회 API → 규칙으로 부적합 슬롯 제거 → LLM이 대안의 차이를 설명 → 동의·재조회 후 예약 요청 → 공식 확정 결과 표시. |
| 최초 구축 범위 | 자동차검사 한 예약 시스템, 공식 다중 조회·확정·상태·취소 어댑터. |
| 실패와 책임 경계 | 조회 실패는 빈자리 없음과 구별. 확정 요청의 타임아웃은 결과 미확인으로 두고 상태를 확인한 뒤 재시도. LLM이 기한·자격·빈자리·완료를 생성하지 않는다. |

### CCK 수행과 외부 의존

CCK: 조건 해석·대안 설명·전체 연계와 품질. 협력사: 예약 화면·인증·기존 예약 서버 어댑터 등 확보된 범위. TS/운영사: 공식 가용정보·권한·예약 처리 책임.

공식 다중 검사소/날짜 조회, 차량 적합성·기간 확인, 인증·예약/취소 인터페이스. 공개 웹 화면의 존재만으로 API 제공·접근권한을 가정할 수 없다.

### 비AI 비교와 착수 조건

달력·필터·마감 표시 개선을 기준안으로 삼는다. 복합 조건 해석과 대안 수정에서 추가 가치가 없으면 단순 UX 개선으로 분류한다.

기존 민원·공통플랫폼과 최종 계약 기능을 대조한다. 설명·답변 생성만이면 신규성이 약하다. 예약 UI 개선을 AI 사업으로 부풀리지 않는다.

추적: SFR-101, SFR-102, SFR-103, SFR-104 / W07

## X02 검사·리콜 결과에서 후속 행동까지

차량 소유자가 공식 검사·리콜 결과에서 자신이 해야 할 조치와 다음 접점을 이해하고 빠뜨리지 않도록 돕는다.

| 정의 항목 | 내용 |
| --- | --- |
| 직접 사용자 | 차량 소유자와 결과 안내 담당자 |
| 국민 가치 | 필수사항 이해·보존, 근거 없는 설명, 조치 누락·재문의, 실제 조치 단계 전환. 예약·사용자 체크와 공식 수리 완료는 서로 다른 지표다. |
| 입력과 근거 | 공식 결과 텍스트/구조화 항목, 결과 코드, 차량/캠페인 식별자, 기준 버전, 공식 설명·후속 절차, 허용된 조치상태. |
| 처리와 출력 | 결과 항목과 근거 문단 연결 → 규칙으로 필수/권고/추가확인 구별 → LLM이 쉬운 설명과 확인 질문 생성 → 사용자에게 행동 목록 제시 → 공식 채널 연결 → 완료 근거의 출처별 상태 표시. |
| 최초 구축 범위 | 자동차검사 결과 유형 10종 이하, 코드 100개 이하. 리콜은 승인된 표본 설명만. |
| 실패와 책임 경계 | 해당 결과·버전 근거가 없으면 미확인 표시와 전문가 연결. 자동차·배터리 고장을 진단하거나 운행 안전을 보증하지 않는다. |

### CCK 수행과 외부 의존

CCK: 결과 구조화·근거 설명·후속 단계·전체 QA. 협력사: 결과 연계·화면. TS 전문가: 결과·기준 해석 검수. 제작사·정비업체: 수리·부품·예약 및 실제 완료 근거.

공식 결과와 현행 설명자료, 전문가 검토, 이용 허가. 리콜 통지 확인만으로 제작사 정비 일정·완료 데이터를 확보했다고 보지 않는다.

### 비AI 비교와 착수 조건

결과코드별 표준 안내·체크리스트와 비교. 여러 항목·개인 상황을 함께 이해하고 질문을 보완하는 이점이 있는지 확인한다.

단순 검사 민원 답변·리콜 대상 검색과 중복을 배제한다. 공식 결과에 연결된 행동과 이행 장애를 다루는 미포함 범위가 있어야 한다.

추적: SFR-201, SFR-202, SFR-203, SFR-204 / W04

## X03 위험·결함 보고를 정확하게 전달

국민·종사자가 경험한 위험을 빠뜨리거나 과장하지 않고 해당 보고 절차에 전달하도록 돕는다.

| 정의 항목 | 내용 |
| --- | --- |
| 직접 사용자 | 자동차 결함 보고 작성자와 접수 담당자 |
| 국민 가치 | 작성 완료·중단, 필수정보 누락, 재질의, 원문에 없는 사실 추가·의미 변경, 신원 노출 오류. 보고량 증가를 사고 감소로 해석하지 않는다. |
| 입력과 근거 | 보고자가 입력한 텍스트, 제도별 서식·가이드, 확인한 날짜·장소·상황·근거. 사진·영상 판독은 포함하지 않는다. |
| 처리와 출력 | 서술을 원문 구간과 연결해 항목화 → 관찰/추정/미상 표시 → 서식상 빠진 정보에 중립적 질문 → 작성자에게 원문·변경 대조 → 확정한 초안만 서식 출력 또는 공식 접수 연계. |
| 최초 구축 범위 | 자동차 결함 한 신고 유형부터. 항공·철도 보호체계 도입비 제외. |
| 실패와 책임 경계 | 모르는 정보를 채워 쓰지 않는다. 긴급·의무보고 가능성은 승인된 안내와 공식 채널을 제시하고 자율보고만으로 의무를 이행했다고 표시하지 않는다. |

### CCK 수행과 외부 의존

CCK: 텍스트 구조화·확인·작성자 검토·품질과 통합. 제도 운영기관: 보고대상·보호·공식 접수·전문 분석. 협력사: 보안·신원 분리·접수 연계.

보고제도별 자료사용·보존·접근권한, 의무보고와 자율보고 경계, 전문 검토, 접수 규격. 익명화·법적 보호 효과는 LLM으로 보장하지 않는다.

### 비AI 비교와 착수 조건

개선된 입력 서식·작성 예시·필수항목 검증과 비교. 자유 서술의 사실 보존과 누락 확인에서 AI 추가 가치가 있는지 확인한다.

기존 민원 요약·답변과 제도별 사실 보존·작성자 확인·접수 흐름을 대조한다. 자동차 결함신고를 별도 신규 사업 수로 중복 집계하지 않는다.

추적: SFR-301, SFR-302, SFR-303, SFR-304 / W08

## X04 안전 지적사항의 조치·증빙 연결

시설 이용자가 같은 위험에 반복 노출되지 않도록 지적사항과 실제 조치 근거의 누락·불일치를 담당자가 발견하게 돕는다.

| 정의 항목 | 내용 |
| --- | --- |
| 직접 사용자 | 시설 관리자·보수업체·권한 있는 검토자 |
| 국민 가치 | 미대응 지적사항·잘못 연결된 증거, 보완 재요청, 담당자 수정률, 공식 조치 확인까지의 지연. 감원 수치로 환산하지 않으며 사고 예방 효과는 별도 검증. |
| 입력과 근거 | 검사·점검보고서의 지적사항, 공식 기준, 보수·조치기록과 전자 증빙, 시설/항목 ID, 담당자 확인 상태. 원시 센서와 현장 이미지 판독은 제외. |
| 처리와 출력 | 지적사항을 항목 ID로 분해 → 조치기록의 대응 근거 검색 → 항목별 수행 내용·대상·날짜·증빙의 차이 검토 → 미확인·불일치·추가확인 목록 → 담당자 검토 → 공식 이행상태 반영. |
| 최초 구축 범위 | 기계식주차장 한 업무, 지적 유형 20종 이하. 전자 텍스트 증빙 2,000건 이하. |
| 실패와 책임 경계 | ‘증빙 있음’과 ‘조치 내용 일치’, ‘공식 조치 확인’, ‘현장 안전 판정’을 각각 분리. 대상 시설이 다르거나 기록이 충돌하면 판정 보류와 확인 요청. |

### CCK 수행과 외부 의존

CCK: 대조 워크플로·근거 조회·누락 검토·통합 품질. 시설/보수업체: 실제 조치와 증빙. TS·권한자: 공식 검토와 판정. 협력사: 전자기록 연계·검토 UI.

사용 허가된 지적사항-조치 쌍, 동일 시설/항목 식별자, 전문가 정답 검토, 기존 관리시스템의 기능 범위. 증빙이 스캔뿐이면 텍스트 확보가 선행 조건.

### 비AI 비교와 착수 조건

항목별 체크리스트·첨부 필수화·기한 알림과 비교. 서로 다르게 쓰인 보수기록의 의미 대응과 근거 불일치 검토에서 AI 추가 가치를 검증한다.

기존 검사·직무특화 SFR-003, 현 관리시스템, 공공PMS 병목관리 조사와 중복 대조. 일정·진척 대시보드만이면 해당 사업군의 보조 기능으로 통합한다. COSAS의 기존 진행관리 기능도 새 기능으로 주장하지 않는다.

추적: SFR-401, SFR-402, SFR-403, SFR-404 / W05

## X05 복잡한 신청의 준비·보완 지원

신청자가 자기 상황에 필요한 절차와 자료를 빠뜨려 반복 방문하거나 보완 요청을 받는 부담을 줄이도록 돕는다.

| 정의 항목 | 내용 |
| --- | --- |
| 직접 사용자 | 선정된 신청 유형의 신청인·보완 검토자 |
| 국민 가치 | 첫 신청의 자료 완비, 불필요한 보완·반복 방문, 잘못된 자격 안내, 필수자료 누락·임의 사실 생성, 이의·정정 처리. 공식 승인율을 AI 정확도와 동일시하지 않는다. |
| 입력과 근거 | 사용자가 확인한 이력, 권한 있는 공식 자격·검사상태, 승인된 절차표, 텍스트 신청서·자료 목록·보완 통지. 민감 이력의 불필요한 수집은 피한다. |
| 처리와 출력 | 일상어 설명을 요건 항목에 대응 → 모르는 사실 확인 → 규칙으로 선행 단계·필수 자료 대조 → LLM이 부족한 내용과 이유 설명 → 신청자가 수정·동의 → 서식 출력 또는 공식 접수 연결. |
| 최초 구축 범위 | 자격 또는 튜닝 중 한 신청 유형, 문서 양식 5종 이하. 양쪽 동시 도입 아님. |
| 실패와 책임 경계 | 예외·기준 충돌·이력 미조회는 확정 안내를 멈추고 담당 확인. 신청서 출력과 접수, 접수와 승인을 구분한다. |

### CCK 수행과 외부 의존

CCK: 요건 연결·설명·보완 검토·워크플로 통합. TS 업무전문가: 적용 기준과 예외 검수. 협력사: 신청 화면·이력/접수 어댑터.

정확한 요건표·유효한 서식·예외 처리자, 기존 민원·직무특화 과업과의 비중복, 전자 원본. 튜닝 문서가 도면·사진 판독 중심이면 해당 적용은 축소한다.

### 비AI 비교와 착수 조건

절차 안내표·조건형 폼·필수값 검증과 비교. 비정형 설명의 요건 연결·보완 사유 이해에서 이점이 없으면 별도 AX 후보로 유지하지 않는다.

민원 SFR-006~007 및 직무특화 SFR-003과의 중복 위험이 크다. 상담을 넘어 실제 신청의 준비·보완 문제와 미포함 산출물이 확인된 유형만 남긴다. X01의 슬롯 탐색과 같은 기능은 공동 사용.

추적: SFR-501, SFR-502, SFR-503, SFR-504 / W09

Argus·Keeper·Nexus 및 문서 구조화 자산은 자료 기재 수준에서 재사용을 검토한다. 로컬 호환, 승인 후 재개, 거래 중복 방지, 사용권은 선행 검증 대상이다. 기존 모듈 적응 실패 시 전면 재구축으로 자동 확대하지 않고 범위·일정·금액을 재산정한다.

M01 기준 변경 영향과 M02 이용 실패 기반 개선은 각 서비스의 품질·운영 요구로 포함한다. 별도 신규 플랫폼이나 추가 사업군으로 계산하지 않는다.
