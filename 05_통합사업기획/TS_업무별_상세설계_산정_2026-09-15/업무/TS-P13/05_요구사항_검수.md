# TS-P13 요구사항·검수

자동차 제작자 자기인증 준비·변경 반영 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P13-HF01 | 유형별 준비자료 / 제작자 유형·차종·절차로 요구자료를 선택한다. | 유형을 모르거나 복수 경로면 추가 질문하며 가장 단순한 경로로 자동 배정하지 않는다. / TS-P13-HT01 |
| TS-P13-HF02 | 서식·증빙 대조 / 서식 필수 필드와 제출 증빙을 원문 위치로 연결한다. | 서식이 존재한다는 이유로 빈 필드·미첨부 증빙을 준비 완료로 표시하지 않는다. / TS-P13-HT02 |
| TS-P13-HF03 | 개정 적용 확인 / 개정 조항·적용일·차종 범위를 분리해 영향 후보를 제시한다. | 시행 전 개정을 현행 의무로 단정하지 않고 적용 조건을 담당자가 확인하게 한다. / TS-P13-HT03 |
| TS-P13-HF04 | 보완·준비 상태 / 담당자가 영향 후보와 보완을 검토하고 확정한 버전을 기록한다. | 서식 변경 뒤 이전 준비 완료 상태가 자동 유지되지 않는다. / TS-P13-HT04 |
| TS-P13-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P13-HT05 |
| TS-P13-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P13-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 제작자 유형 1개·절차 1개, 전자문서 3종·기준집 1개, 승인된 개정 사례 1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
