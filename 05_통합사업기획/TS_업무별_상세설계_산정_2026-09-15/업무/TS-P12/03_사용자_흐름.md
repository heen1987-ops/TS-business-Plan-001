# TS-P12 사용자 흐름

자동차 결함·수리 이력의 사건 정리 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

![사용자 흐름](user.svg)

## 사용자 목표·사전조건

결함을 신고하는 차량 소유자·소비자 지원 및 조사 담당자가 자동차 증상·수리·재발 진술을 원문과 연결해 소비자와 조사 담당자가 확인하는 사건 정리 지원를 이용한다.

신고·조사 담당자가 사실 묶음의 필수 항목과 소비자 확인 절차, 기존 리콜 AI 상담 범위를 확인한다.

## 기본·대안·예외 흐름

소유자 입력 → 전자기록 연결 → 사건 정리 → 상충 질문 → 본인 확인 → 담당자 인계. 결함·보상·리콜 판단은 별도 공식 절차다.


| 단계 | 사용자 행동 | 시스템·공식 확인 |
| --- | --- | --- |
| 진입 | 자동차 소유자·조사자가 목적 선택 | 권한·자료 범위 확인 |
| 입력 | 증상·수리·재발 진술 | 구조화·누락·적용일 확인 질문 |
| 검토 | 사건표·상충 질문 | 발생·수리·재발의 시점과 원문 근거를 연결한다. |
| 수정·대안 | 같은 차량·사실 확인? | 진술과 증빙의 날짜·주행거리가 다르면 차이를 설명해 소유자에게 묻는다. |
| 최종 확인 | 공식 조사·검토 인계 | 확인된 사실 묶음만 인계하고 법적·기술적 결론은 생성하지 않는다. |
| 예외 | 날짜 상충 → 소유자 확인 | 입력·검토 맥락 보존, 기존 경로 제공 |


## 화면 정의


| 화면 ID | 목적·주요 정보 | 이동·권한 |
| --- | --- | --- |
| TS-P12-UI01 | 조건·자료 입력 / 증상·수리·재발 진술 | 역할 확인 후 UI02 |
| TS-P12-UI02 | 결과·근거·불확실성 비교 / 사건표·상충 질문 | 같은 맥락에서 수정 → UI01 또는 UI03 |
| TS-P12-UI03 | 검토·공식 상태 / 공식 조사·검토 인계 | 권한자 확인 후 완료·보완·유보 |
| TS-P12-UI04 | 오류·재조회·기존 처리 경로 | 조건 보존 / 허용된 단계 복귀 |


## 화면 상태·복구


| 상태 | 동작 |
| --- | --- |
| 기본·로딩 | 입력조건·범위·진행 상태 표시. 중복 버튼 비활성 |
| 빈 결과 | 조건 일치 없음과 확인한 조회 범위 표시. 필수조건 임의 변경 금지 |
| 부분 성공 | 확인·미확인 항목을 분리 |
| 입력 오류 | 해당 필드에 수정 이유 표시, 다른 입력 보존 |
| 권한 거부 | 원문 노출 없이 접근 불가·확인 경로 안내 |
| 시스템 오류·오프라인 | 기존 경로·재시도 안내. 조회 실패를 마감·불합격으로 바꾸지 않음 |
| 타임아웃 | 이전 접수·결과 유무를 재조회한 뒤 재시도 |
| 성공·비활성 | 공식 확정과 초안 완료 구분. 승인 전 확정 불가 |


## 화면 배치·접근성

입력 조건 / 결과와 근거 / 확인·보완·유보의 정보 순서로 구성한다. 이는 설계용 화면 구성안이며 현행 시스템 화면의 재현이 아니다.

키보드 이동·명시적 레이블·포커스·색 외 상태 문구를 제공한다. 390/768/1440px와 확대·스크린리더에서 핵심 과업을 검증한다. WCAG 2.2 AA는 목표이며 실제 서비스 합격 판정은 미실행이다.
## 도식의 연결


| 연결 | 전달 내용 |
| --- | --- |
| 01 진입·목표 설정 → 02 조건·권한 확인 | 목표·자료 |
| 02 조건·권한 확인 → 03 원천 확인 | 허용 범위 조회 |
| 03 원천 확인 → 04 초안·후보 표시 | 상태·자료 |
| 04 초안·후보 표시 → 05 검토·선택 | 후보·이유 |
| 05 검토·선택 → 보완·재조회 | 아니요 / 오류 |
| 보완·재조회 → 01 진입·목표 설정 | 입력 보존·수정 |
| 05 검토·선택 → 06 확정 요청 | 예 / 확인 |
| 06 확정 요청 → 07 공식 결과 확인 | 선택·승인 |
| 07 공식 결과 확인 → 08 종료·후속 경로 | 확인된 결과 |
| 보완·재조회 → 근거 부족·권한 없음 | 재확인 불가 |
