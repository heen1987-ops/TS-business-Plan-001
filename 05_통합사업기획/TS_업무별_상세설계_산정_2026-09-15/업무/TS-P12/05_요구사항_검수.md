# TS-P12 요구사항·검수

자동차 결함·수리 이력의 사건 정리 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P12-HF01 | 사건 범위 고정 / 차량과 사건 식별키를 고정하고 비슷한 증상을 가진 타 차량 기록을 분리한다. | 문장이 같아도 차량키가 다르면 하나의 수리 이력으로 합치지 않는다. / TS-P12-HT01 |
| TS-P12-HF02 | 시간순 정리 / 발생·수리·재발의 시점과 원문 근거를 연결한다. | 정확한 날짜가 없는 진술은 임의 날짜를 만들지 않고 부분 순서로 둔다. / TS-P12-HT02 |
| TS-P12-HF03 | 상충 질문 / 진술과 증빙의 날짜·주행거리가 다르면 차이를 설명해 소유자에게 묻는다. | 더 상세한 문서라는 이유만으로 진술을 삭제하거나 사실을 확정하지 않는다. / TS-P12-HT03 |
| TS-P12-HF04 | 판단과 사실 분리 / 확인된 사실 묶음만 인계하고 법적·기술적 결론은 생성하지 않는다. | 반복 수리 기록만으로 결함 인정·보상 확정·리콜 대상이라고 표시하지 않는다. / TS-P12-HT04 |
| TS-P12-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P12-HT05 |
| TS-P12-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P12-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 소비자 제출자료 준비 흐름 1개, 수리내역·신고서 2종, 조회 0–1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
