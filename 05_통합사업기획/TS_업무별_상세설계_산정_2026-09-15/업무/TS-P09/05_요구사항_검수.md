# TS-P09 요구사항·검수

드론 기체 변경·말소 신고 준비 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P09-HF01 | 의무 종류 구분 / 기체 신고·조종자격·비행 승인 질문을 분리한다. | 기체 소유권 이전 완료가 비행 승인 완료로 표시되지 않는다. / TS-P09-HT01 |
| TS-P09-HF02 | 제원 미확인 처리 / 중량·용도 등 필요한 제원을 공식 또는 이용자 확인 정보로 받는다. | 제원이 비어 있으면 신고 면제로 단정하지 않는다. / TS-P09-HT02 |
| TS-P09-HF03 | 준비자료 점검 / 필수 문서 항목과 기체·사건 정보의 일치를 확인한다. | 다른 기체 증빙이나 텍스트 없는 사진을 검토 완료로 표시하지 않는다. / TS-P09-HT03 |
| TS-P09-HF04 | 공식 접수 인계 / 신청자가 확인한 입력만 인계하고 접수 응답을 구분한다. | 접수 시스템 오류에 완료 안내를 하지 않으며 입력을 보존한다. / TS-P09-HT04 |
| TS-P09-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P09-HT05 |
| TS-P09-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P09-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 소유권 이전 또는 말소 중 1개 경로, 문서 2종, 공식 접수 경로 인계
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
