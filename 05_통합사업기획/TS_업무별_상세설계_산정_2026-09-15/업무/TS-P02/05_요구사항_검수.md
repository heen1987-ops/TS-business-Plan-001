# TS-P02 요구사항·검수

사업용 운전자 자격 취득 단계별 처리 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P02-HF01 | 경로 범위 고정 / 자유 질문을 화물 자격의 단계로 정리하고 일반 운전면허와 구분한다. | 일반 면허 질문에 화물 응시 절차를 대신 제시하지 않고 담당 기관의 공식 확인 경로를 안내한다. / TS-P02-HT01 |
| TS-P02-HF02 | 미조회 요건 보류 / 검사 유효 여부와 시험·교육 상태를 공식 응답으로만 표시한다. | null·오류·기간 만료를 충족으로 변환하지 않는다. / TS-P02-HT02 |
| TS-P02-HF03 | 다음 행동 설명 / 요건 규칙이 정한 다음 단계를 쉬운 문장으로 설명하고 사용자가 입력을 확인한다. | 근거 규칙 버전과 다음 단계 사유가 있으며 AI가 추가 자격요건을 만들지 않는다. / TS-P02-HT03 |
| TS-P02-HF04 | 인계·접수 구분 / 인계와 접수를 다른 상태로 기록한다. | 링크 열림만으로 신청 완료를 표시하지 않으며 공식 접수 응답이 없으면 미확인 상태를 유지한다. / TS-P02-HT04 |
| TS-P02-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P02-HT05 |
| TS-P02-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P02-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 초기는 화물 자격 1개 경로, 상태 조회 1개, 신청 시스템 인계 1개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
