# TS-P04 사용자 흐름

철도 안전관리체계 요건·증빙·보완 연결

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

![사용자 흐름](user.svg)

## 사용자 목표·사전조건

철도운영기관 안전관리 담당자·TS 검사관·철도 이용 국민가 철도 안전관리체계의 요건별 제출·보완·현장 확인 근거를 연결하는 검사관 검토 화면를 이용한다.

검사 요건군, 적용 기준, 서류·현장 구분, 비식별 보완 사례를 검사관이 확인한다.

## 기본·대안·예외 흐름

요건 고정 → 제출자료 연결 → 보완 이력 대조 → 서류 검토 → 현장 결과 연결 → 검사관 결정. 문서상 충족 후보와 법정 검사결과는 분리한다.


| 단계 | 사용자 행동 | 시스템·공식 확인 |
| --- | --- | --- |
| 진입 | 운영기관·철도 검사관가 목적 선택 | 권한·자료 범위 확인 |
| 입력 | 요건·절차서·이행 증빙 | 구조화·누락·적용일 확인 질문 |
| 검토 | 요건별 증빙·보완 질문 | 절차서에 규정되어 있다는 사실과 실제 이행 증빙을 구분한다. |
| 수정·대안 | 서류·현장 확인이 충분? | 이전 지적별로 변경된 문서·증빙을 찾는다. |
| 최종 확인 | 검사관의 검사 판단 | 현장 확인이 필요한 요건은 서류 검토와 별도 상태로 관리한다. |
| 예외 | 절차서만 존재 → 이행 증빙 보완 | 입력·검토 맥락 보존, 기존 경로 제공 |


## 화면 정의


| 화면 ID | 목적·주요 정보 | 이동·권한 |
| --- | --- | --- |
| TS-P04-UI01 | 조건·자료 입력 / 요건·절차서·이행 증빙 | 역할 확인 후 UI02 |
| TS-P04-UI02 | 결과·근거·불확실성 비교 / 요건별 증빙·보완 질문 | 같은 맥락에서 수정 → UI01 또는 UI03 |
| TS-P04-UI03 | 검토·공식 상태 / 검사관의 검사 판단 | 권한자 확인 후 완료·보완·유보 |
| TS-P04-UI04 | 오류·재조회·기존 처리 경로 | 조건 보존 / 허용된 단계 복귀 |


## 화면 상태·복구


| 상태 | 동작 |
| --- | --- |
| 기본·로딩 | 입력조건·범위·진행 상태 표시. 중복 버튼 비활성 |
| 빈 결과 | 조건 일치 없음과 확인한 조회 범위 표시. 필수조건 임의 변경 금지 |
| 부분 성공 | 확인·미확인 항목을 분리 |
| 입력 오류 | 해당 필드에 수정 이유 표시, 다른 입력 보존 |
| 권한 거부 | 원문 노출 없이 접근 불가·확인 경로 안내 |
| 시스템 오류·오프라인 | 기존 경로·재시도 안내. 조회 실패를 마감·불합격으로 바꾸지 않음 |
| 타임아웃 | 이전 접수·결과 유무를 재조회한 뒤 재시도 |
| 성공·비활성 | 공식 확정과 초안 완료 구분. 승인 전 확정 불가 |


## 화면 배치·접근성

입력 조건 / 결과와 근거 / 확인·보완·유보의 정보 순서로 구성한다. 이는 설계용 화면 구성안이며 현행 시스템 화면의 재현이 아니다.

키보드 이동·명시적 레이블·포커스·색 외 상태 문구를 제공한다. 390/768/1440px와 확대·스크린리더에서 핵심 과업을 검증한다. WCAG 2.2 AA는 목표이며 실제 서비스 합격 판정은 미실행이다.
## 도식의 연결


| 연결 | 전달 내용 |
| --- | --- |
| 01 진입·목표 설정 → 02 조건·권한 확인 | 목표·자료 |
| 02 조건·권한 확인 → 03 원천 확인 | 허용 범위 조회 |
| 03 원천 확인 → 04 초안·후보 표시 | 상태·자료 |
| 04 초안·후보 표시 → 05 검토·선택 | 후보·이유 |
| 05 검토·선택 → 보완·재조회 | 아니요 / 오류 |
| 보완·재조회 → 01 진입·목표 설정 | 입력 보존·수정 |
| 05 검토·선택 → 06 확정 요청 | 예 / 확인 |
| 06 확정 요청 → 07 공식 결과 확인 | 선택·승인 |
| 07 공식 결과 확인 → 08 종료·후속 경로 | 확인된 결과 |
| 보완·재조회 → 근거 부족·권한 없음 | 재확인 불가 |
