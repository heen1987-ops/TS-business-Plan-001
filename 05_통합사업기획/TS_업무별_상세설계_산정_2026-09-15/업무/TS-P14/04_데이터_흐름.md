# TS-P14 데이터 흐름

미래차 안전기준 변경의 시험·안내 문서 영향 검토

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

![데이터 흐름](data.svg)

## 자료의 입력·결과

안전기준 개정문·적용일·시험계획서·문서 서식·공개 안내 → 기준 변경 영향표와 문서 반영 확인 목록. 실제 DB명·API·보존기간은 자료 소유자와 확정한다.


| 논리 저장소 | 내용 | 권한·수명주기 |
| --- | --- | --- |
| D1 승인 근거 | 개정·영향·문서 버전 / 원문 위치·버전·적용일 | 권한 계승 / 변경·삭제 시 색인 갱신 |
| D2 검토 결과 | 영향 후보·반영 이력 / 초안·수정·근거 | 업무 대상키·역할별 접근 / 승인본 분리 |
| D3 결정·처리 이력 | 문서 승인·발행 확인 / 검토자·이유·참조 | 공식 상태는 원 시스템 기준 |
| D4 최소 감사 | 권한·자료 버전·행동·성공/실패 | 원문 전체 중복 저장 금지 / 보존기간 협의 |


## 데이터 정의·검증


| 논리 필드 | 의미·검증 |
| --- | --- |
| standard_id / jurisdiction | 기준 식별자와 국내·해외 관할 |
| old_version / new_version | 비교할 원문 버전과 개정 조항 |
| effective_at / transition | 시행일·경과 규정의 확인 상태 |
| document_id / owner | 시험계획·서식·안내문 및 책임부서 |
| impact_ref / reason | 영향 후보의 원문 위치·사유 |
| approved_revision / published_at | 승인된 변경본과 실제 발행 확인 |


## 품질·예외·변경 처리


| 조건 | 처리 |
| --- | --- |
| 대상·기간·단위 불일치 | 키워드 일치만으로 필수 개정이라고 단정하지 않고 영향 사유를 검토 가능하게 한다. |
| 문서 변경·근거 철회 | 재색인·캐시 만료·생성물 근거 상태를 함께 갱신. 최신 확정 표시 중지 |
| 권한 변경·삭제 | 원문·색인·캐시·결과 참조에 전파. 보존 의무·삭제 권한 담당자 확인 |
| 자료 내 명령 | 입력은 분석 대상이며 시스템 권한·도구 설정을 덮어쓰지 못함 |
| 자료 없음·모호함 | 초안 저장만으로 반영 완료를 표시하지 않는다. |


## 데이터 주권의 구현 조건

- 기관이 원문·색인·임베딩·질문·생성물·감사의 저장 위치와 접근을 통제
- 외부 공개자료 반입 권한과 내부 모델 처리 경계 분리
- 운영자·원격 유지보수·백업·반출·정정·삭제 경로까지 검증
- 납품 시 지식·규칙·구성·근거·검토 이력을 이관할 형식 명시


## 도식의 연결


| 연결 | 전달 내용 |
| --- | --- |
| E1 승인된 원천 → P1 반입·구조 검증 | 허용 자료 |
| P1 반입·구조 검증 → D1 근거 자료 | 검증·분리 결과 |
| D1 근거 자료 → P2 근거·규칙 검색 | 원문·메타정보 |
| P2 근거·규칙 검색 → P3 로컬 LLM 구성 | 근거·규칙 |
| P3 로컬 LLM 구성 → P4 검토·수정 | 초안·불확실성 |
| P4 검토·수정 → D2 검토 결과 | 검토된 결과 |
| D2 검토 결과 → D3 결정·처리 이력 | 승인·선택 |
| D3 결정·처리 이력 → D4 최소 감사기록 | 참조·행동 |
| P2 근거·규칙 검색 → D4 최소 감사기록 | 검색·권한 기록 |
