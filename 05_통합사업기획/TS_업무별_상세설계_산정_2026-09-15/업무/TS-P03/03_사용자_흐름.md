# TS-P03 사용자 흐름

위험물질 운송계획·점검 인계 문서 일치 확인

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

![사용자 흐름](user.svg)

## 사용자 목표·사전조건

위험물 운수업체·TS 및 관할 지자체 점검 담당자와 운송 경로 주변 국민가 위험물 운송계획·점검·인계 기록의 상충과 수신 누락을 한 건으로 검토하는 문서 지원를 이용한다.

TS-BIZ-007 계약 범위, 비식별 문서 묶음, 계획 버전 및 수신기관 권한을 확인한다.

## 기본·대안·예외 흐름

계획 버전 선택 → 점검 연결 → 문서 대조 → 인계 초안 검토 → 기존 경로 발송 → 수신 확인 대기/확인. 문서 도착은 현장 상황 확정이 아니다.


| 단계 | 사용자 행동 | 시스템·공식 확인 |
| --- | --- | --- |
| 진입 | 운송업체·점검 담당자가 목적 선택 | 권한·자료 범위 확인 |
| 입력 | 계획·차량·물질·수신 기록 | 구조화·누락·적용일 확인 질문 |
| 검토 | 문서 상충·수신 누락 | 명칭 유사도와 공식 식별값 대조를 분리한다. |
| 수정·대안 | 계획·점검·인계가 일치? | 조치 내용·수신기관·회신 책임을 초안에서 점검한다. |
| 최종 확인 | 담당자 인계·수신 확인 | 발송과 수신 확인을 원천 상태로 구분한다. |
| 예외 | 차량 불일치·수신 없음 → 인계 보완 | 입력·검토 맥락 보존, 기존 경로 제공 |


## 화면 정의


| 화면 ID | 목적·주요 정보 | 이동·권한 |
| --- | --- | --- |
| TS-P03-UI01 | 조건·자료 입력 / 계획·차량·물질·수신 기록 | 역할 확인 후 UI02 |
| TS-P03-UI02 | 결과·근거·불확실성 비교 / 문서 상충·수신 누락 | 같은 맥락에서 수정 → UI01 또는 UI03 |
| TS-P03-UI03 | 검토·공식 상태 / 담당자 인계·수신 확인 | 권한자 확인 후 완료·보완·유보 |
| TS-P03-UI04 | 오류·재조회·기존 처리 경로 | 조건 보존 / 허용된 단계 복귀 |


## 화면 상태·복구


| 상태 | 동작 |
| --- | --- |
| 기본·로딩 | 입력조건·범위·진행 상태 표시. 중복 버튼 비활성 |
| 빈 결과 | 조건 일치 없음과 확인한 조회 범위 표시. 필수조건 임의 변경 금지 |
| 부분 성공 | 확인·미확인 항목을 분리 |
| 입력 오류 | 해당 필드에 수정 이유 표시, 다른 입력 보존 |
| 권한 거부 | 원문 노출 없이 접근 불가·확인 경로 안내 |
| 시스템 오류·오프라인 | 기존 경로·재시도 안내. 조회 실패를 마감·불합격으로 바꾸지 않음 |
| 타임아웃 | 이전 접수·결과 유무를 재조회한 뒤 재시도 |
| 성공·비활성 | 공식 확정과 초안 완료 구분. 승인 전 확정 불가 |


## 화면 배치·접근성

입력 조건 / 결과와 근거 / 확인·보완·유보의 정보 순서로 구성한다. 이는 설계용 화면 구성안이며 현행 시스템 화면의 재현이 아니다.

키보드 이동·명시적 레이블·포커스·색 외 상태 문구를 제공한다. 390/768/1440px와 확대·스크린리더에서 핵심 과업을 검증한다. WCAG 2.2 AA는 목표이며 실제 서비스 합격 판정은 미실행이다.
## 도식의 연결


| 연결 | 전달 내용 |
| --- | --- |
| 01 진입·목표 설정 → 02 조건·권한 확인 | 목표·자료 |
| 02 조건·권한 확인 → 03 원천 확인 | 허용 범위 조회 |
| 03 원천 확인 → 04 초안·후보 표시 | 상태·자료 |
| 04 초안·후보 표시 → 05 검토·선택 | 후보·이유 |
| 05 검토·선택 → 보완·재조회 | 아니요 / 오류 |
| 보완·재조회 → 01 진입·목표 설정 | 입력 보존·수정 |
| 05 검토·선택 → 06 확정 요청 | 예 / 확인 |
| 06 확정 요청 → 07 공식 결과 확인 | 선택·승인 |
| 07 공식 결과 확인 → 08 종료·후속 경로 | 확인된 결과 |
| 보완·재조회 → 근거 부족·권한 없음 | 재확인 불가 |
