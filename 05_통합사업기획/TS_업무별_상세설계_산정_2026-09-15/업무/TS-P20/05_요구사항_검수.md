# TS-P20 요구사항·검수

데이터 개방센터 이용·분석 준비 지원

> **기획 검토안**: CCK 주관 AX+SI / NOA·로컬 LLM / 기존 서버 / 신규 인프라 0원. 실제 API·물량·견적·효과는 확인 전.

## 기능·비기능 요구사항


| ID | 요구·행동 | 수용기준·시험 |
| --- | --- | --- |
| TS-P20-HF01 | 카탈로그 범위 검색 / 공개 승인된 목록만 검색하고 존재·제공 범위를 근거로 표시한다. | 카탈로그에 없는 데이터셋이나 실시간·세부 항목을 만들어 제시하지 않는다. / TS-P20-HT01 |
| TS-P20-HF02 | 정의·단위 설명 / 비슷한 이름의 필드를 정의·단위·집계 수준으로 구분한다. | 명칭 유사성만으로 결합 가능성을 보장하지 않는다. / TS-P20-HT02 |
| TS-P20-HF03 | 신청 준비 점검 / 목적·필요 항목·이용 조건의 누락을 질문한다. | 과도한 원시 개인정보 요청을 신청 목적에 필수라고 생성하지 않는다. / TS-P20-HT03 |
| TS-P20-HF04 | 이용·반출 경계 / 공식 안내와 신청 준비만 제공하고 승인 상태를 생성하지 않는다. | 미승인 원시 데이터·결과물을 내보내거나 임의 SQL을 실행하지 않는다. / TS-P20-HT04 |
| TS-P20-HN01 | 접근권한·로컬 처리 / 원문·인덱스·로그·호출의 권한과 외부 경로를 점검한다. | 승인된 권한 거부 사례에서 원문·검색·직접 요청을 모두 거부하고, 기존 서버 실행 시험 중 승인되지 않은 외부 모델·데이터 전송이 관측되면 배포를 보류한다. / TS-P20-HT05 |
| TS-P20-HN02 | 근거·실패 상태·복귀 / 원문 위치·버전·조회 시점을 표시하고 자료 실패와 실제 결과를 분리한다. | 삭제·접근 철회·변경된 자료가 탐지되면 해당 결과를 최신·확정으로 표시하지 않으며 오류 시 입력을 보존하고 기존 처리 경로를 제공한다. / TS-P20-HT06 |

## RFP 수행·검수 조항 초안

- 계약 대상: 공개 카탈로그 1개 분야·이용 절차 문서 2종, 원시 데이터 연계 0개
- 기존 납품분·추가 설정·추가 개발·업무 연계의 구분과 작업분해·견적 근거 제시
- 화면·데이터·인터페이스·권한 명세, 지식·규칙·프롬프트 버전, 시험 증거, 운영·복귀 문서 제출
- 정답·판정 책임·수정 이력을 가진 승인 평가셋 사용
- 자동 확정·권한 우회·상태 오표시를 해소한 뒤 인수 검토
- 기존 서버 사용. 신규 장비·클라우드 인프라 구매 제외

요구사항과 RFP 문안의 발주 검토 초안이다. 계약 심사·제품 인수 시험·현업 승인은 미완료다.
