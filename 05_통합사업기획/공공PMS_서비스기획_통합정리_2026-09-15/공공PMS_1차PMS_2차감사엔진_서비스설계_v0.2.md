# 1차 PMS와 2차 감사엔진 서비스 설계

2026년 9월 15일 · v0.2 · 사용자 단계 정정 반영 · **2026-09-21 추가: §8.1 신설 — N-08B_04·06·07(C트랙, 18번 §8.1 화해안 대상)의 요구사항ID·모듈·데이터객체·API를 AUD-F01~10에 매핑(실이식). 원 §8 표는 수정하지 않음, 근거는 §10 S07 참조.**

## 1 서비스 전략은 1차 PMS와 2차 감사엔진

1차는 PMS를 도입해 사업을 관리하고 공식 이행기록을 축적한다. 2차는 그 기록을 활용하는 CCK 감사엔진을 개발·적용한다. PMS의 현업 사용 가치와 감사엔진의 증거 기반 판단 가치를 각각 독립된 도입 목적과 완료조건으로 설계한다.

이 문서는 발주기관 기획자와 CCK 설계자가 서비스 범위·연결 관계·발주 분기를 검토하기 위한 설계안이다. 1차와 2차는 추진 단계이며 연차·기간·예산을 뜻하지 않는다. 실제 서비스 구현과 배포는 이번 작업 범위에 포함하지 않는다.

| 구분 | 1차 PMS | 2차 감사엔진 |
|---|---|---|
| 도입 목적 | 사업 진행·병목·산출물·책임을 관리 | 기준 대비 이행과 판단의 근거를 감사 |
| 주요 이용자 | 기관 담당자·수행사·업무 승인자·후임자 | 감사 담당자·전문 검토자·소명 주체·감사 승인자 |
| 핵심 산출물 | 공식 제출·보완·승인·변경·운영 이력 | 감사 증거·발견사항·소명·판단·조치·보고 |
| 완료의 의미 | 감사엔진 없이도 사업관리를 수행 | PMS의 기록을 원본과 연결해 감사 결과를 재현 |

### PMS가 감사엔진의 기반이 되는 이유

나중에 감사자료를 다시 모으는 비용을 줄이려면 1차부터 계약·요구·제출본·판단·조치의 식별자와 버전, 작성·승인 시각, 변경 사유를 남겨야 한다. 다만 감사계획·감사 기준팩·발견사항 판정은 2차의 기능으로 둔다.

NOA, 별도 대시보드, 기존 PMS 연계는 이 전략을 구현할 구성 대안이다. CCK의 감사엔진은 공통 기능과 업무별 기준팩으로 설계하며, 기존 NOA 제품에 이미 완성된 기능이 있다는 주장과 구분한다.

## 2 1차 PMS의 서비스 범위

기관이 사업공간을 개설하고 수행사가 산출물을 제출하면, 담당자는 검토·보완·승인을 처리한다. 대시보드는 해야 할 일, 대기 상대, 기한, 지연 사유, 유지관리 만료와 인수인계 사항을 보여 준다. 공식 업무 상태는 공동 기록에서 관리한다.

| 기능 묶음 | 1차에서 제공할 업무 | 남길 데이터 |
|---|---|---|
| 사업과 책임 | 서비스·사업·계약·참여 역할 연결 | 계약 범위·책임·변경 이력 |
| 일정과 병목 | WBS·선후행·기준/변경/예측/실제 일정 관리 | 대기 원인·기한·요청·회신 |
| 산출물과 검토 | 공식 접수·버전·검토 의견·보완·승인 | 원문·버전·행위자·사유·시각 |
| 회의와 의사결정 | 결정·쟁점·미결 과업 추적 | 회의 근거·결정자·후속 조치 |
| 인수인계와 운영 | 미결 책임 승계·유지관리 종류와 기간 확인 | 기산 근거·지원 범위·공백 위험 |
| 수행이력 | 확인된 이행 관측과 소명·정정 관리 | 평가 원자료·이견·정정 관계 |

### 1차의 AI와 감사 기능 경계

기존 NOA의 검색·초안 등 보조기능을 사용하더라도 PMS의 완료를 감사엔진 구축에 종속시키지 않는다. 자동 감사 판정, 감사 증거 분석, 발견사항 생성과 독립된 감사 종결은 2차 범위다. 단순 필수값·형식·기한 확인은 PMS 업무규칙으로 둔다.

### 1차 수용 시나리오 제안

시험결과서 한 종류를 계약 요구에 연결해 제출 → 접수 → 보완 → 재제출 → 승인 → 후임자 인계까지 수행한다. 감사엔진을 연결하지 않은 상태에서도 접수와 업무 처리가 가능해야 한다. 이전 제출본·판단·변경 이력을 보존하고 권한 없는 조회·승인을 차단한다.

수행사의 기본 제출·보완·소명 참여에 별도 유료 장벽을 두지 않는 도입안을 유지한다. 관측자료의 축적이 자동 기업등급·제재 또는 기관 간 공유로 이어지지는 않는다.

## 3 2차의 핵심 서비스는 CCK 감사엔진

감사엔진은 감사 대상과 기준을 정하고 증거를 연결해 누락·불일치·기준 위반 가능성을 찾아내며, 발견사항의 검토·소명·시정·재검증·감사보고를 관리하는 공통 업무 엔진이다. 감사가 진행되는 전체 절차와 결과의 근거를 추적하는 것이 핵심이다.

| 엔진 구성 | 2차에서 추가할 기능 |
|---|---|
| 계획과 기준 | 감사 ID·대상·기간·범위·권한, 업무별 기준팩·예외·개정 관리 |
| 증거와 검사 | PMS 및 허용된 외부 자료의 증거 묶음 고정, 규칙 검사·수치 비교·LLM 의미 분석 |
| 발견사항과 소명 | 기준·사실·근거·영향 후보 구조화, 소명·추가 증거·채택·기각·보류 |
| 판단과 시정 | 전문 검토·권한자 확정, 조치 책임·기한·완료조건·PMS 연결 |
| 재검증과 보고 | 새 증거로 해결 여부 확인, 미결·정정·종결, 감사보고서와 추적 이력 |

### 초기 적용과 확장 방향

초기 적용안은 공공 정보화사업의 계약이행·산출물·검토·변경에 대한 감사다. 이전 대화의 정보시스템 감리는 별도 업무팩으로 연결한다. 이후 내부감사·회계감사 등으로 확대할 때도 공통 엔진을 재사용하고 기준·증거 형식·권한·전문 판단은 업무별로 정한다. 첫 감사 유형의 정확한 범위는 후속 명세에서 확정한다.

감사엔진의 입력은 1차 PMS를 우선하되 다른 PMS·문서·구조화 자료도 허용된 연결 방식으로 수용하는 설계다. 데이터 출처가 다른 기관으로 바뀌었다는 이유로 접근권한이 자동 확대되지는 않는다.

### 감사 결과의 판단 책임

AI가 제시한 발견사항 후보와 사람이 확정한 감사 판단을 구분한다. 감사자·검토자·승인자의 역할을 분리하고 이해관계 및 접근권한을 확인한다. 감사·정보시스템 감리·회계감사의 법적 업무와 자격을 하나로 간주하지 않으며 적용 업무별 책임은 별도 검토한다.

## 4 NOA의 역할과 전체 아키텍처

논리 구성은 1차 PMS 업무화면·업무 로직·공식 원장과 2차 감사 화면·감사엔진·감사 기록으로 나눈다. NOA와 기존 로컬 LLM은 문서 작업·추론 등 확인된 공통 기능을 제공하는 재사용 후보다. 감사엔진의 기준·증거·판단·시정 상태는 명시적으로 설계한다.

| 구성 대안 | 적용 조건 | 추가 공수와 위험 |
|---|---|---|
| NOA 내부 확장 | 공유 권한·공식 기록 보존·화면·상태·확장 권리 확인 | 제품 확장·업데이트 영향과 장기 이력 검증 |
| 전용 업무화면과 NOA | NOA 연결이 가능하고 공동 업무를 별도 보완해야 함 | 업무 로직·화면·연계·운영 공수 산정 |
| 기존 PMS와 감사엔진 | 기관 PMS가 1차 요구를 충족하고 증거 연계가 가능 | 1차 개선분 + 2차 엔진·연계의 추가분 산정 |

배치 권고는 기존 PMS 충족 여부와 NOA 기능을 먼저 확인하고 부족한 업무만 추가하는 것이다. 내부 앱 또는 별도 화면을 지금 확정하지 않는다. 대시보드 자체로 공식 기록·감사 로직·권한이 충족되는 것은 아니다.

### 공동 기록과 개인 작업의 구분

기존 NOA 적합성 검토는 사용자 가이드 V1.0의 개인 공간·삭제 특성을 근거로 공동 원장의 별도 보존 책임을 요구했다. 현재 설치본·API·SDK·사용권을 실측한 결과는 아니다. 개인 초안이나 채팅 삭제가 공식 제출본과 감사 증거를 지우지 않도록 한다. [S02]

### 유지할 사업 제약

CCK 주관, 기존 로컬 LLM·기존 서버 활용, 신규 인프라 투자 0원을 유지한다. 신규 OCR·VLM·영상·음성 및 외부 클라우드 대체 호출은 포함하지 않는다. 기존 인프라의 용량·동시 처리 여력은 확인 전이다. 적용·개발·연계·시험·교육·운영·사용권 비용은 별도로 산정한다. [S04]

동일 계약 납품분과 공통 구성은 한 번만 계상한다. 1차와 2차가 같은 기반을 사용해도 각 단계의 데이터·권한·납품·검수 책임은 분리한다.

## 5 서비스와 데이터의 연결 규칙

1차 흐름은 기준·일정 확정 → 공식 제출 → 검토·보완 → 승인 → 유지관리·인수인계다. 2차 흐름은 감사계획·범위 확정 → 증거 확보 → 검사 → 발견사항 검토·소명 → 판단 → 시정조치 → 재검증·보고다.

| 전달 구간 | 필수 연결 정보 | 업무규칙 |
|---|---|---|
| PMS → 감사 증거 | 기관·사업·계약·요구·문서 ID, 원문·버전·행위·시각 | 허용 범위와 기준 시점을 고정. 조회·복제·반출 권한 확인 |
| 기준 → 검사 실행 | 감사 ID·기준 버전·점검 범위·입력·규칙·모델 버전 | 해당 시점에 적용한 기준을 재현. 충돌·미확정 표시 |
| 후보 → 사람 판단 | 관측 사실·증거 위치·추론·소명·판단 사유 | 후보와 확정 결론 분리. 미검사·판단 불가를 적합으로 처리하지 않음 |
| 감사 조치 → PMS | 확정 조치 ID·책임 역할·기한·완료조건 | 권한 있는 과업만 생성. 중복 요청 방지·실패 재처리 |
| PMS → 재검증 | 조치 ID·새 증거·버전·처리 결과 | 제출만으로 종결 금지. 기존 증거·판단을 덮어쓰지 않음 |

### 예외와 권한

감사엔진 장애 시 PMS 업무는 유지한다. 오래된 검사 결과는 대상 버전을 표시하고 새 제출본을 자동 승인하지 않는다. 소명으로 사실이 바뀌면 원결론·정정 사유·새 판단을 연결한다. 권한 회수 시 신규 자료 접근을 차단하고 이미 적법하게 보존 중인 기록은 기관의 보존 정책에 따라 처리한다.

증거 해시는 파일의 동일성을 확인하는 정보이며 내용의 진실성을 입증하지 않는다. 개인정보·비밀자료의 검사 범위와 보존·열람 주체는 감사 목적에 맞춰 제한한다. 엔진 출력이 PMS 승인·귀책·제재를 자동 변경하지 않도록 권한 경계를 둔다.

기관 간 확장은 공통 엔진의 재사용이다. 기관 데이터를 하나로 합칠 권한 확보와 구분한다. 실제 API 주소·필드·이벤트·응답 시간은 제품 확인과 상세 명세 단계에서 정한다.

## 6 요구사항과 공공 RFP를 단계별로 다시 배치

기존 RFP v0.1에는 PMS와 AI 검사 기능이 함께 들어 있다. 이번 정정 이후에는 52개 전체를 새 1차 PMS의 확정 범위라고 부르지 않는다. 아래 분류는 원 요구 ID를 유지한 재배치 제안이며, 원본 RFP의 정의·수용기준을 개정한 최종 발주 명세는 아니다. [S01]

| 재배치 제안 | 대상 | 수정 방향 |
|---|---|---|
| 1차 PMS 중심 13개 | SFR 중 아래 분리·이동 대상 외 | 현업 업무와 1차 독립 수용조건 유지 |
| 1차·2차 분리 8개 | SFR 005·006·011·012·017·018·021·022 | 업무 기준·보완·승인과 감사 증거·판단·재검증 분리 |
| 2차 중심 4개 | SFR 004·013·015·016 | AI 추출·사전검사·분석 상태·자동 검사 재정의 |
| 공통 기반 27개 | SIR·INR·DAR·PER·TER·SER·QUR·COR·PMR·PSR | 단계별 물량·검수·책임 분리, 공통 비용 중복 방지 |

13 + 8 + 4 + 27 = 52는 수정 전 원장에 대한 검토 분류다. 분리·통합 또는 감사 요구 추가 이후의 최종 요구 개수와 같지 않다. HTML 부록과 재배치 원장에서 모든 ID와 원문을 확인할 수 있다.

### 2차 감사엔진 요구사항 초안

AUD-F01 계획·범위, F02 기준팩, F03 증거 묶음, F04 검사 실행, F05 발견사항, F06 소명·판단, F07 시정조치, F08 재검증·종결, F09 보고·기록, F10 품질·재사용의 10개 묶음을 제안한다. 새 ID는 설계용이며 기존 RFP ID를 대체하지 않는다. HTML에 정의와 수용조건 초안을 수록한다.

### 테일러링과 발주 문서 개정

기존 단계·활동·작업·산출물·비고의 5열 양식을 재사용한다. 1차와 2차 각각의 적용·통합·조건부·제외 사유, 산출물, 검수 책임을 재작성한다. 기존 74개 코드의 적용 개수를 새 단계에 그대로 승계하지 않는다. 기존 PG 미확정 항목도 범위·일정·예산·환경이 정해진 후 다시 확인한다. [S03]

## 7 단계별 사업성과 후속 설계

| 구분 | 현재 문제 가설와 기대 변화 | 검증 지표 |
|---|---|---|
| 1차 PMS | 분산된 자료·연락·인계 → 공동 상태와 기록 | 탐색·보고·보완 추적·인계 시간, 지원 공백 |
| 2차 감사엔진 | 감사 때 증거 재수집·반복 대조 → 기준과 증거 연결 | 감사 준비·검토·재검증 시간, 누락·오탐·근거 추적 |
| 공공 가치 | 미결 책임·판단 근거 소실 → 서비스 연속성과 설명·소명 | 책임 누락·미해결 조치, 정정 경위, 사용자 수용성 |

단계별 연간 시간 편익 = Σ(업무별 처리 건수 × 실제 적용률 × 건당 순절감 시간). 순절감 시간은 현행 시간에서 도입 후 검토·오탐 정정·추가 입력·예외 처리까지 포함한 시간을 뺀다. 2차 편익은 1차 PMS가 운영되는 상태를 기준으로 추가 효과만 산정한다.

1차에서 줄어든 증거 취합 시간을 2차에 다시 더하지 않는다. 재작업·지연 회피비와 인건비도 중복 여부를 확인한다. 금액 환산 단가·기준연도·처리량·비용·개선율은 확보 전이며 감축 인원으로 환산하지 않는다. 신규 인프라 0원은 총사업비 0원을 뜻하지 않는다.

### 다음 설계의 순서와 통과 조건

| 순서 | 다음 산출물 | 완료조건 제안 |
|---|---|---|

| 2 | 감사 증거 인계 명세 | 표본의 원문·버전·판단 관계·권한을 모두 추적 |
| 3 | 2차 감사엔진 상세 요구·업무팩 | 정보화사업의 첫 감사 유형·기준·판단 권한 확정 |
