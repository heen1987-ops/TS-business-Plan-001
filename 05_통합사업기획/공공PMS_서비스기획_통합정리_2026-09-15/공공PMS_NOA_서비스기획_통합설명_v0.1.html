02

서비스모델과 NOA의 역할

가이드에 대한 기존 검토

개인 NOA 작업공간

2026.09.08 사용자 가이드 V1.0의 문서·양식·스킬 사용 흐름은 재사용 근거입니다. 개인 워크스페이스는 공유되지 않으며 삭제 시 내부 자료가 소실될 수 있어 공식 원장과 구분합니다. 현재 설치본 전체 기능을 단정하는 근거는 아닙니다. [S01]

API·SDK·실제 설치 버전·사용권·서버 여력은 확인 대기입니다. 별도 업무화면이 새 서버 구매를 의미하지 않습니다. [S01·S06]

기능 요구사항 SFR · 25개

SFR-001　기관·서비스·사업·계약의 연결 필수 · 원 요구 PMS-SFR-001

정의　시스템은 기관이 관리하는 서비스·시스템에 복수 사업과 계약을 연결하고 각 계약의 목적·범위·기간·수행 역할을 구분하여 조회할 수 있어야 한다.

업무규칙　동시 구축·운영·고도화를 허용한다. 신규 계약 등록으로 과거 계약·결정을 덮어쓰지 않는다.

입력　기관·서비스·사업·계약 식별정보와 관계

출력　서비스별 사업·계약 목록과 책임 관계

수용기준

  • Given 구축·운영 계약이 같은 서비스에 존재, When 고도화 계약 추가, Then 세 계약의 범위·기간을 구분해 조회할 수 있다.
  • Given 사업 종료, When 서비스 이력 조회, Then 종료된 사업의 결정과 후속 계약 관계가 보존된다.
SFR-002　참여 조직·역할·위임 관리 필수 · 원 요구 PMS-SFR-002

정의　시스템은 기관·수행사·컨소시엄·감리의 참여 역할과 적용 기간, 검토·승인 위임을 사업별로 관리해야 한다.

업무규칙　역할 변경은 과거 행위자를 변경하지 않는다. 수행사와 기술운영자에게 기관 승인·평가 확정 권한을 기본 부여하지 않는다.

입력　참여 조직·사용자·역할·기간·위임 범위

출력　참여 및 권한 이력

수용기준

  • Given 위임 기간 종료, When 승인 요청, Then 만료된 위임으로 승인할 수 없다.
  • Given 담당자 변경, When 과거 결정 조회, Then 과거 결정자와 현재 담당자가 각각 표시된다.
SFR-003　기준 원문 등록·적용 정보 관리 필수 · 원 요구 PMS-SFR-003

정의　시스템은 계약·RFP·지침 등의 원문, 버전, 출처 위치와 적용 시점·적용 여부를 관리해야 한다.

업무규칙　법적 의무·계약 의무·기관 규칙·권고를 구분한다. 출처 분류만으로 우선순위·적용성을 자동 확정하지 않는다.

입력　원문·출처·버전·시행 또는 적용일·확인자

출력　적용 기준 원장

수용기준

  • Given 원문 개정, When 새 버전 등록, Then 이전 적용본과 현재 후보를 구분해 조회할 수 있다.
  • Given 적용일·근거 미확인, When 기준 조회, Then 미확인 상태가 표시되고 확정 적용으로 표시되지 않는다.
SFR-004　요구·의무·완료조건 후보 추출 필수 · 원 요구 PMS-SFR-004

정의　시스템은 허용된 텍스트 원문에서 이행 요구·책임·기한·완료조건 후보를 추출하고 후보마다 근거 위치와 확인 필요사항을 제공해야 한다.

업무규칙　원문에 없는 수치·기한을 확정값으로 채우지 않는다. 추출 불가 구간과 사람의 추가 입력을 구분한다.

입력　기준 원문·텍스트 추출 결과

출력　원문과 연결된 요구 후보

수용기준

  • Given 기한이 명시되지 않은 과업, When 후보 추출, Then 기한을 임의 생성하지 않고 확인 필요로 제시한다.
  • Given 근거가 있는 후보, When 원문 확인, Then 해당 버전·위치를 열어 대조할 수 있다.
SFR-005　공동 기준 검토·확정 필수 · 원 요구 PMS-SFR-005

정의　시스템은 기관·수행사의 의견과 충돌 조정 결과를 연결하고 권한자가 사업 기준을 버전별로 확정할 수 있어야 한다.

업무규칙　필수 완료조건의 충돌이 남으면 해당 항목은 확정할 수 없다. 일부 범위 확정 시 제외 범위·사유·후속 책임을 명시한다.

입력　기준 후보·각 측 의견·해결 근거·승인 범위

출력　승인된 Baseline과 미확정 항목

수용기준

  • Given 필수 조건 충돌이 미해결, When 해당 항목 확정, Then 승인되지 않고 쟁점이 유지된다.
  • Given 쟁점 해결과 승인권자 확인, When 기준 확정, Then 버전·확정자·범위·근거가 함께 남는다.
SFR-006　기준·범위·일정 변경의 영향 관리 필수 · 원 요구 PMS-SFR-006

정의　시스템은 승인 후 변경 요청·영향 항목·의견·결정·효력 시점을 관리하고 승인 변경을 새 기준 버전으로 연결해야 한다.

업무규칙　제출본·검토·평가의 적용 기준을 보존한다. 변경 요청·예상일 수정만으로 승인 기한을 바꾸지 않는다.

입력　변경 사유·대상·영향·효력·승인 근거

출력　변경 전후 기준과 영향 목록

수용기준

  • Given 변경 요청만 등록, When 일정 조회, Then 현재 승인 기한은 유지된다.
  • Given 변경 승인, When 이전 제출 검토 기록 조회, Then 당시 기준과 변경 기준을 구분할 수 있다.
SFR-007　공동 WBS·네 종류 일정·선행조건 필수 · 원 요구 PMS-SFR-007

정의　시스템은 기관과 수행사의 과업·선행조건을 같은 일정에서 관리하고 초기 계획일·승인된 변경 기준일·최신 예상일·실제 완료일을 구분해야 한다.

업무규칙　기관의 자료 제공·검토·승인도 과업으로 포함한다. 작업 진척·제출·검토·승인을 구분하고 순환 선행관계는 확인 대상으로 차단한다.

입력　과업·관계·책임 역할·네 종류 날짜

출력　공동 일정·진행·대기 상태

수용기준

  • Given 기관 자료 제공이 선행조건, When 해당 자료 미제공, Then 후행 과업에 해당 대기 원인이 표시된다.
  • Given 최신 예상 완료일 변경, When 일정 저장, Then 초기 계획일·승인된 변경 기준일은 변경되지 않는다.
SFR-008　역할별 업무함·알림·상향 요청 필수 · 원 요구 PMS-SFR-008

정의　시스템은 사용자 역할에 맞는 제출·검토·회신·승인·기한 임박 업무와 다음 행동을 제공해야 한다.

업무규칙　수신 권한과 업무의 현재 담당을 확인한다. 전달 실패를 업무 완료로 처리하지 않으며 중복·과도한 알림의 설정 기준을 둔다.

입력　과업 상태·담당·기한·알림 및 상향 기준

출력　역할별 처리 목록·알림·전달 이력

수용기준

  • Given 검토 업무 발생, When 담당자가 업무함 조회, Then 대상·기한·근거·다음 행동이 표시된다.
  • Given 담당 교체 또는 권한 철회, When 알림 발송, Then 이전 담당자에게 비공개 내용이 전달되지 않는다.
SFR-009　자료 요청·회신·회의 결정 연결 필수 · 원 요구 PMS-SFR-009

정의　시스템은 자료 요청·회신·회의 결정에 관련 과업·책임·기한·원문·확정 상태를 연결해야 한다.

업무규칙　회의 초안과 확정 결정을 구분한다. AI 요약이나 수신 확인만으로 의무·결정을 새로 확정하지 않는다.

입력　요청·답변·회의 기록·결정 의견

출력　요청 회차·확정 결정·후속 과업

수용기준

  • Given 미확정 회의록, When AI가 요약, Then 후속 의무는 후보로만 표시된다.
  • Given 결정 확정, When 관련 과업 조회, Then 결정 원문·확정자·조치 기한을 확인할 수 있다.
SFR-010　이슈·위험·병목·책임 구분 필수 · 원 요구 PMS-SFR-010

정의　시스템은 실제 문제, 예상 위험, 대기 원인과 확인된 책임을 구분하고 처리 담당·기한·상태를 추적해야 한다.

업무규칙　기관·수행사·외부 선행조건을 구분한다. 신고·지연·대기만으로 귀책·벌점을 확정하지 않는다.

입력　이슈·위험 신고·대기 사건·원인·근거

출력　미결 원장·대기 원인·조치 목록

수용기준

  • Given 수행사가 위험을 자발적으로 신고, When 이력 반영, Then 신고 자체가 감점으로 전환되지 않는다.
  • Given 기관 검토 대기, When 병목 조회, Then 수행사 지연과 구분하고 책임 미확정은 별도로 표시한다.
SFR-011　산출물·요구사항·검증증거 대응 필수 · 원 요구 PMS-SFR-011

정의　시스템은 산출물별 대상 요구·과업·담당·제출기한·검토자·완료조건·필요 증거를 연결해야 한다.

업무규칙　하나의 산출물이 여러 요구에 대응할 수 있다. 대응하지 않은 요구와 미확정 연결을 숨기지 않는다.

입력　승인 기준·산출물 목록·과업·검증조건

출력　요구별 산출물 및 증거 대응표

수용기준

  • Given 요구에 산출물 연결 없음, When 대응표 조회, Then 미연결 항목이 표시된다.
  • Given 하나의 결과서가 여러 요구를 검증, When 제출, Then 각 요구의 증거 위치·확인 상태를 구분할 수 있다.
SFR-012　증거 등록·출처·확인 상태 필수 · 원 요구 PMS-SFR-012

정의　시스템은 문서·시험 결과·확정 기록의 원본·버전·출처·발생/수집 시각·위치·접근 범위·확인 상태를 관리해야 한다.

업무규칙　파일 무결성은 내용의 사실성을 보장하지 않는다. 미확보·미추출·권한 제한과 부적합을 구분한다.

입력　증거 원본·생성 맥락·출처·요구 연결

출력　Evidence 목록과 추출·확인 범위

수용기준

  • Given 원본의 일부 구간 추출 실패, When 증거 조회, Then 확인 구간과 미추출 구간이 구분된다.
  • Given 권한 없는 연결 증거, When 조회, Then 원문·비공개 요약이 노출되지 않는다.
SFR-013　수행사 제출 전 자체점검 필수 · 원 요구 PMS-SFR-013

정의　시스템은 수행사가 승인 기준에 따라 작성 중 자료의 필수 항목·증빙 누락 후보를 제출 전에 확인할 수 있게 해야 한다.

업무규칙　결과를 공식 승인·공식 기업평가에 자동 편입하지 않는다. 점검 실패를 이유로 권한 있는 공식 제출 경로를 막지 않는다.

입력　수행사 초안·승인 기준·연결 증거

출력　비공개 자체점검 결과

수용기준

  • Given 수행사 미제출 초안 점검, When 기관이 일반 제출 목록 조회, Then 초안·자체점검 결과가 공개되지 않는다.
  • Given 자체점검 서비스 실패, When 정상 형식 자료 제출, Then 공식 제출을 진행할 수 있다.
SFR-014　공식 제출·접수증·버전 고정 필수 · 원 요구 PMS-SFR-014

정의　시스템은 제출 권한·대상·필수 형식을 확인한 자료의 원본·버전·기준 버전·접수 시각을 고정하고 접수증을 제공해야 한다.

업무규칙　원본과 접수 기록의 저장이 확인되기 전에 접수 성공을 표시하지 않는다. 같은 제출 재시도는 중복 접수·검토 업무를 만들지 않는다.

입력　산출물·증거·제출자·대상 기준

출력　접수증·고정 제출본·검토 요청

수용기준

  • Given 원본 저장 실패, When 제출, Then 접수 성공이 표시되지 않고 복구·재시도 경로가 안내된다.
  • Given 접수 성공 후 같은 요청 재전송, When 처리, Then 최초 접수증과 원본 시각을 유지한다.
SFR-015　분석 상태 분리·실패 복구 필수 · 원 요구 PMS-SFR-015

정의　시스템은 업무 접수 상태와 AI 분석 상태를 구분하고 분석 지연·일부 성공·실패 시 재시도 또는 수동 검토를 제공해야 한다.

업무규칙　정상 접수를 분석 장애로 미제출 처리하지 않는다. 오래된 결과가 최신 제출본의 상태를 덮지 않도록 한다.

입력　접수 기록·분석 범위·오류·재시도 요청

출력　분석 상태·실패 범위·대체 경로

수용기준

  • Given 접수 후 AI 실패, When 상태 조회, Then 접수 성공과 분석 실패가 동시에 정확히 표시된다.
  • Given 새 버전 제출 뒤 구버전 분석 도착, When 반영, Then 과거 버전 결과로 연결되고 최신본 승인이 바뀌지 않는다.
SFR-016　기초 검토 후보·근거 제공 필수 · 원 요구 PMS-SFR-016

정의　시스템은 제출자료와 승인 요구의 기초 대조 결과를 후보·근거·미확인 범위로 제시하고 담당자가 검토 상태를 기록할 수 있어야 한다.

업무규칙　찾지 못함은 부적합과 다르다. AI 확신도와 담당자의 확정 판단을 구분한다. 전문 감리 검사의 범위는 후속 감리 범위에서 확장한다.

입력　고정 기준·제출본·읽을 수 있는 증거

출력　요구별 검토 후보·근거 위치·검토 상태

수용기준

  • Given 시험 로그 미확보, When 기초 검토, Then 증거 요청 후보가 제시되고 시험 실패로 자동 확정되지 않는다.
  • Given 분석하지 못한 요구, When 검토 요약, Then 검토 완료 항목으로 집계되지 않는다.
SFR-017　보완 요청·소명·의견 차이 관리 필수 · 원 요구 PMS-SFR-017

정의　시스템은 검토 지적별 보완 요청·기한·책임·응답·추가 근거·소명과 의견 차이를 연결해야 한다.

업무규칙　정당한 이견·적용 제외·변경 요청을 구분한다. 응답 접수만으로 원 지적을 해결 처리하지 않는다.

입력　사람이 확인한 지적·요청·보완 또는 소명

출력　지적과 연결된 공식 요청·응답 회차

수용기준

  • Given 다른 첨부의 증거로 소명, When 수행사 응답, Then 해당 원문과 소명 사유가 지적에 연결된다.
  • Given 보완 답변만 제출, When 상태 조회, Then 재검증 전까지 해결 확정으로 표시되지 않는다.
SFR-018　현재 버전 재검증·확정·철회 필수 · 원 요구 PMS-SFR-018

정의　시스템은 현재 대상 버전의 보완·소명 근거로 해결·미해결·철회·유보를 기록하고 권한자의 업무상 확정과 공식 계약 절차를 구분해야 한다.

업무규칙　구버전 결과로 최신본을 승인하지 않는다. 철회·정정은 후속 이력에 반영하되 원래 판단과 변경 사유를 보존한다.

입력　지적·응답·현재 자료·검토·승인 권한

출력　재검증 결과·확정자·결정 근거·후속 미결

수용기준

  • Given 최신본과 재검증 대상 불일치, When 종결 요청, Then 불일치를 알리고 최신본 종결을 막는다.
  • Given 지적 철회 확정, When 수행이력 조회, Then 철회 상태·사유가 반영되고 미해결 결함으로 집계되지 않는다.
SFR-019　주기적 다면평가 계획·배정 필수 · 원 요구 PMS-SFR-023

업무규칙　담당자·검토자·중간관리자·최종 결재자·업무부서·사용자·전문가의 관찰 영역을 구분한다. 변경 기준을 과거 회차에 몰래 소급하지 않는다.

  • Given 계획 변경, When 과거 응답 조회, Then 당시 질문·대상·기준으로 확인된다.
SFR-020　역할별 응답·관찰 불가·중복 처리 필수 · 원 요구 PMS-SFR-024

정의　시스템은 배정된 평가자가 관찰 범위에 맞춰 응답·근거·관찰 불가를 기록하고 미응답과 유효 응답을 구분해야 한다.

업무규칙　동일 사건·회차의 응답 수정과 중복 제출을 구분한다. 관찰 불가·미응답을 0점으로 변환하지 않으며 다른 역할의 질문을 무조건 강제하지 않는다.

입력　평가 회차·배정·관찰 범위·응답·근거

출력　역할·기간별 응답과 응답 상태

수용기준

  • Given 관찰 불가 응답, When 집계 대상 확인, Then 0점으로 포함되지 않고 미응답·유효 응답과 구별된다.

수용기준

  • Given 지적 철회 또는 우수 성과 확정, When 이력 조회, Then 현재 상태와 확인 근거를 함께 볼 수 있다.
SFR-022　평가 고지·소명·재검토·정정 반영 필수 · 원 요구 PMS-SFR-026

정의　시스템은 허용된 범위의 평가 결과를 당사자에게 알리고 소명·재검토·확정·정정 이력을 관리해야 한다.

입력　결과 고지·소명·추가 근거·재검토 담당·결정

출력　통지·소명 처리·정정된 이력

수용기준

  • Given 잘못된 평가가 정정 확정, When 관련 이력·집계 조회, Then 정정 상태가 반영되거나 갱신 대기임이 명시된다.

정의　시스템은 후임자에게 사업 목적·계약·주요 결정·현재 미결·다음 행동·지원 책임을 원문과 연결해 제공해야 한다.

출력　종류별 지원기간·책임·미결 목록
