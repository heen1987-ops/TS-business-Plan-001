# 공공 PMS 서비스모델과 설계현황 통합정리

2026년 9월 15일 · v0.1

## 1 서비스 목적과 현재 기획 방향

공공 PMS는 정보화사업의 계약 기준과 실제 이행자료를 연결하여 누락·지연·보완 사항을 조기에 확인하고, 담당자가 바뀌어도 공공서비스의 운영 책임이 이어지도록 지원하는 서비스다. CCK의 검사·검증 기능을 업무에 적용하고, NOA의 문서 작업 기능과 공동 사업기록을 연결하는 모델로 기획한다.

검토 대상은 발주기관 기획자·사업 담당자와 CCK 서비스 설계자다. 이 문서는 2026년 9월 11일까지의 공공 PMS 설계를 정리하고 9월 15일의 기존 시스템 추가 적용 기준을 반영한다. 요구사항·RFP의 세부 내용은 자료목록에 연결한 원장을 기준으로 읽는다.

| 항목 | 현재 기준 |
|---|---|
| 도입 목적 | 검토 부담 완화, 이행 품질 확보, 서비스 연속성 및 근거 있는 판단 지원 |
| 구매자와 사용자 | 기관이 도입하고 담당자·승인자·수행사가 역할별로 사용. 공급사 기본 제출·보완·소명에 별도 유료 장벽을 두지 않는 안 |
| 서비스 구성 | NOA 개인 문서·검사 지원과 공동 사업 원장의 논리적 분리 |
| 핵심 관리 흐름 | 기준 확정 → 제출 → 검사 후보 → 사람 검토 → 보완 → 재검토 → 승인·이력 |
| 최초 검증 단위 | 시험결과서 한 종류의 제출·보완 종결 흐름. 전체 1차 요구사항을 축소한다는 뜻은 아님 |
| 현재 단계 | 기획·설계와 발주 검토. 실제 제품 적합성·구현·기관 승인은 별도 확인 |

### 기존 시스템을 활용하는 사업 범위

기구축 PMS·NOA·기존 AI가 있어도 새로운 업무 적용과 기능 개선을 기획할 수 있다. 기존 계약의 동일 납품분은 재사용 또는 계약 이행으로 구분하고, 새 규칙·지식·설정·연계·검증에 필요한 추가 수행분을 산정한다. 공공 PMS의 예산은 다른 TS 기획의 1차 7억·2차 5억 상한과 별개다. [S07]

CCK 주관, 기존 로컬 LLM과 서버 활용, 신규 인프라 투자 0원을 유지한다. 입력은 텍스트가 있는 전자문서와 구조화 자료로 한정하며 신규 OCR·VLM·영상·음성 처리와 외부 클라우드 대체 호출을 포함하지 않는다.

## 2 NOA 재사용과 공동 업무의 분담

9월 11일 적합성 검토는 9월 8일자 NOA 사용자 가이드 V1.0의 개인 워크스페이스 비공유 및 삭제 특성을 근거로 한다. 이 검토에 따라 개인 작업공간을 공식 사업 원장으로 바로 쓰는 가정을 수정했다. 이 내용은 해당 가이드에 대한 기존 검토 결과이며 현재 설치본의 실행 성능이나 모든 제품 버전의 기능을 단정하는 근거는 아니다. [S01]

| 구성 대안 | 선택 조건 | 설계에서 남길 책임 |
|---|---|---|
| NOA 내부 공동 앱 | 공유 권한·기록 보존·화면 확장·장기 상태 기능과 사용권 확인 | 개인 작업과 공식 업무의 상태·식별자 분리 |
| 별도 업무화면과 NOA | 문서·검사 연계는 가능하나 공동 업무 기능 보완 필요 | 공동 원장·처리 로직·권한을 업무 계층에서 집행 |
| 기존 PMS와 NOA 연계 | 기관 PMS가 공동 기록·제출·승인을 이미 제공 | PMS를 공식 원장으로 유지하고 검사 기능 연결 |
| 개인 문서 지원부터 적용 | 자동 API 연계 전 제한적 활용 검토 | 수동 등록 비용 포함. 전체 PMS 제공과 구분 |

권고안은 공동 업무 책임을 먼저 정하고 실제 확장·연계 기능에 맞춰 화면 위치를 선택하는 것이다. 대시보드는 해야 할 일과 병목을 보여주는 창구이며, 제출본·승인·보존을 관리하는 업무 로직이 함께 필요하다. 별도 화면을 선택해도 새 서버 구입을 전제하지 않는다.

### 기능 분류와 책임

기존 기능 원장은 16개 묶음을 재사용 후보 6개, 설정·확장 2개, 전용 업무 설계 6개, 연계 1개, 기술·계약 확인 1개로 분류한다. 이는 설계 작업 분류이며 NOA의 충족률 또는 개발 완료율이 아니다. [S02]

NOA는 자료 선택·항목 추출·양식 작성·검토 후보와 근거 제시를 지원한다. 공동 업무 계층은 사업별 접근권한, 공식 접수, 문서 버전, 상태 전이와 보존을 집행한다. 담당자와 승인자가 후보 채택·기각·소명·최종 승인을 판단한다.

기관 계약·결재 기록 → 공동 사업 원장의 기준·제출본 → NOA 검사 작업 → 사람의 검토 → 공동 원장의 보완·승인 → 유지관리·인수인계로 연결한다. 개인 대화나 작업 파일을 삭제해도 공식 기록이 사라지지 않도록 설계한다.

## 3 요구사항과 공공 RFP의 기준선

9월 10일 요구사항 58개에서 1차 범위 46개를 공공 RFP로 전환하고, 시험·산출물·테일러링 관리 6개를 보강해 52개를 구성했다. 필수 50개와 조건부 기관 연계 2개이며, 후속 12개는 이번 가격·검수 범위와 구분한다. 이번 정리는 요구사항 ID·정의·수용기준을 변경하지 않는다. [S03·S04]

| 원장 또는 문서 | 읽는 목적 | 현재 범위 |
|---|---|---|
| 요구사항 분석서와 명세서 | 전체 서비스 요구와 원래 추적 관계 | 전체 구상 58개 |
| 1차 범위와 미확정 검토표 | 초기 구축·후속 기능 및 확인 항목 구분 | RFP 분기의 범위 근거 |
| 공공 RFP와 추적 원장 | 발주 요구·검수·납품 조건 검토 | 52개 요구, PG 15개 미확정 |
| 테일러링 내역서 | 표준 작업·산출물의 적용 범위 결정 | 기존 코드 74개와 별도 보완 |

### 상세 설계에서 유지할 업무규칙

서비스 하나에 구축·운영·고도화 계약을 동시에 연결한다. 기준 일정과 변경 이력, 실제 처리·대기 기록을 보존하고 지연 사유와 책임은 확인 절차를 거쳐 기록한다. 사업 종료와 유지관리 종료를 구분한다.

공식 접수는 AI 검사가 실패해도 유지한다. AI 지적은 검토 후보로 저장하고 수행사 귀책이나 평가 감점으로 즉시 전환하지 않는다. 소명·보완·철회·재검토의 근거와 판단자를 남긴다. 새 제출본이 생기면 이전 검사 결과가 어느 버전을 대상으로 했는지 구분한다.

### 테일러링과 후속 모듈

원본의 단계·활동·작업·산출물·비고 5열과 74개 코드를 유지한다. 적용 50개, 통합 17개, 조건부 5개, 제외 2개이며 코드 없는 기초 문서 4개와 보완 항목 7개를 별도 관리한다. 기관·기간·납품 범위가 정해지면 적용 사유와 검토 책임을 갱신한다. [S05]

정보시스템 감리, 고도화된 기업 평가, 성과·만족도, 차기 RFP 환류·컨소시엄·기관 간 확장은 후속 범위와 연결한다. 초기 다면 관측·정정과 유지관리 요구까지 후속으로 밀어내지 않는다. 원 PMS ID와 분기 RFP ID는 서로 다른 코드 체계이므로 번호만으로 의미를 추정하지 않는다.

## 4 도입 편익과 비용의 검증 방식

도입 필요성은 담당자가 기준·자료·상태를 다시 찾는 부담, 반복 보완, 인수인계 누락과 유지관리 공백의 문제 가설로 설명한다. 현재 기관의 실제 시간·오류·비용을 측정한 값은 아직 확보되지 않았으므로 기존 대화의 시장 규모나 AI 개선율을 공공 PMS의 확정 편익으로 사용하지 않는다.

| 현행 문제 가설 | 도입 후 기대 변화 | 측정할 값 |
|---|---|---|
| 계약과 증빙을 반복 검색 | 기준·제출본·원문 위치를 연결 | 건당 탐색·검토·정정 시간 |
| 보완 상태를 전화·메일로 확인 | 책임·기한·미결 사항을 함께 조회 | 재보완 횟수, 미처리 체류 시간 |
| 담당자 교체 때 과거 경위 재구성 | 결정과 미결 책임을 상시 승계 | 인수인계 준비·재파악 시간 |
| 계약 종료와 지원 범위 누락 | 유지관리 기산·종료·후속 계약 연결 | 지원 공백 일수, 누락 건수 |
| 주관적 평가와 설명 부담 | 확인된 이행기록 및 소명 보존 | 평가 정정, 근거 열람, 이의 처리 |

### 정량 산출에 필요한 자료

연간 시간 편익은 업무별 처리 건수에 건당 순절감 시간과 실제 적용률을 곱해 합산한다. 순절감 시간에는 AI 결과 검토·오탐 정정·이중 등록 시간을 포함한 도입 후 전체 작업시간을 차감한다. 금액 환산은 직무별 적용 단가의 출처·기준연도와 함께 제시하며 현금 지출 절감과 업무 여력 확보를 구분한다.

재작업·지연 회피 편익은 확인된 사건 감소량과 사건당 추가 비용으로 산정하되, 시간 편익에 이미 포함된 인건비를 다시 더하지 않는다. 현행 방식, 규칙 기반 SI, AI 결합 방식에서 같은 종류의 사례를 비교하고 검토 품질과 예외 처리 부담을 함께 측정한다.

### 비용과 사회적 가치

비용은 공통 구성 1회분, 업무별 추가 설정·지식·연계·시험, 교육·운영·사용권의 증분으로 나눈다. 신규 인프라 투자 0원과 총사업비 0원을 구별한다. 기간·물량·권리·서버 여력 확인 전에는 가격과 투자 회수기간을 확정하지 않는다.

사회적 편익은 공공서비스 중단 위험 감소, 처리 품질, 설명·소명 기회와 조직기억의 유지로 검증한다. 업무시간을 감축 인원으로 환산하지 않고 확보한 시간의 검토·품질 개선 활용과 직무 영향을 함께 확인한다.

TS 22개 업무별 기획 및 P23 정책·예산·발주 기획지원은 관련 사업 구상이지만 공공 PMS와 동일 사업으로 합산하지 않는다. 공통 엔진 재사용 가능성과 대상 업무·납품 범위·예산의 통합 여부는 별도로 검토한다.

## 6 다음 설계와 의사결정 사항

후속 작업은 제품 구현 없이 업무 모델을 명세하는 순서로 진행한다. NOA 제품 확인과 기관 조건을 병행 확보하되, 확인 전에도 사용자 역할·기록 책임·예외 흐름의 논리 설계는 진행할 수 있다.

| 순서 | 설계 산출물 | 완료 판단 기준 |
|---|---|---|
| 1 | 역할과 업무 시나리오 | 기관·수행사·검토자·승인자·후임자의 성공·예외 흐름과 권한 구분 |
| 2 | 상태와 기록 책임 명세 | 접수·검사·보완·소명·승인의 전이, 버전과 보존 책임 정의 |
| 3 | 화면정의서와 정보구조 | 공동 업무와 NOA 진입점, 대기·빈 화면·오류·권한·접근성 정의 |
| 4 | NOA 적합성 확인표 | C01~C08에 실제 문서·시연·권리 증거를 연결. 미확인은 유지 |
| 5 | 연계 및 데이터 계약 | 식별자·전달 범위·중복·실패·재시도·반출 조건 정의 |
| 6 | 편익 및 공수 산정표 | 현행 측정값·순편익·공통/추가 공수·증분 운영비 구분 |
| 7 | RFP와 테일러링 개정안 | PG-01~PG-15와 변경 요구를 추적하고 기관 검토로 연결 |

### 구성 선택 전에 확인할 사항

C01 공동 권한, C02 개인 삭제와 공식 기록 보존, C03 스킬 작성·배포, C04 화면 확장, C05 실제 API, C06 장기 상태·실패 복구, C07 로컬 모델·자원, C08 재사용 권리·종료 인계를 확인한다. 확인 결과에 따라 NOA 내부 앱, 별도 업무화면 또는 기존 PMS 연계를 선택한다. [S01]

기관명·계약 당사자·예산·기간·대상 사업 수·문서량·연계 범위·품질 목표·보안·접근성·운영 인수 조건은 RFP의 PG 항목으로 관리한다. 실제 담당 부서와 승인자를 확정하기 전에는 내부 검토용 책임 역할로만 표시한다.

### 현재 판정

통합 문서는 설계 검토의 출발점으로 사용한다. 요구사항 추적과 자료 정리 완료가 NOA 제품 적합성, 경제성 입증 또는 발주·구현 승인으로 이어지는 것은 아니다. 미확정 항목은 후속 설계 작업목록에서 증거와 결정 상태를 갱신한다.
