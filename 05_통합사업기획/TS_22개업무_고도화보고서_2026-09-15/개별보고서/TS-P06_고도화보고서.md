## 2. 현행 기반과 고도화 목표

철도 자율보고 접수·분석·전파 절차을 이용하는 업무에 철도 분류체계·보호 설정·의미 보존/재식별 평가 항목을 추가한다. 현행 내부 화면·소요시간·API를 직접 시험한 것은 아니다. 아래 흐름과 오류 처리는 **제안 설계**이며 현업 워크숍에서 실제 절차와 대조한다.

대표 상황: 작은 역의 특정 근무시간과 직무를 그대로 쓰면 이름을 지워도 신고자를 추정할 수 있는 상황

| 현행 기반 활용 | 고도화할 처리 | 유지할 공식 책임 |
| --- | --- | --- |
| 철도 자율보고 접수·분석·전파 절차 | 철도 자율보고 원본을 보호하면서 검토용 분석과 전파용 사례 초안을 분리하는 업무 지원 | 기존 업무의 자격·검사·예약·지급·공개·안전 판단 권한 |
| 정형 보고양식·전문 분류체계·수동 비식별 템플릿 | 사건 구조화, 핵심 맥락을 보존한 요약, 검토용·전파용 초안 | 원천 데이터·적용 기준의 승인과 검토자 확인 |


국민에게 기대하는 가치는 정확한 다음 행동과 보완 필요를 더 빨리 이해하거나, 담당자의 검토 누락을 줄이는 것이다. 다음 지표를 측정해 확인한다: 안전 핵심 사실의 의미 손실·식별 위험 누락·전문가 수정 부담. 업무시간 절감을 감축 인원으로 환산하지 않는다. 사고 감소·무사고를 이 기능만으로 입증했다고 주장하지 않는다.

공개 NOA 소개와 내부 TA-01·02·03·20 기록은 재사용 후보의 근거다. 실제 납품 버전의 구현·성능·사용권 증명이 아니며 부족한 업무 기능은 CCK의 설정·개발·시험 과업으로 산정한다. TA-23 NL2SQL·Evidence Trail은 계획 기능이므로 현재 보유 기능으로 계상하지 않는다. 상세 기술 근거는 공통 보고서에 연결했다.

## 4. 처리 흐름과 화면

제한 접수 → 내부 구조화 → 검토용 초안 → 전파용 별도 작성 → 보호·의미 검토 → 승인 또는 반려. 승인 전 검색·배포 대상에 넣지 않는다.

| 순서 | 사용자·시스템 동작 | 처리 책임 |
| --- | --- | --- |
| 1 | 원본·검토본·전파본의 저장·검색 권한을 별도로 적용한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 2 | 사건 순서·조건·불확실성을 함께 요약한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 3 | 이름 제거 외에 시각·장소·희귀 역할의 결합 위험을 검토 목록으로 표시한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 4 | 보호 검토와 의미 검토를 통과한 버전만 전파 후보에 둔다. | 사용자/현업 확인 후 공식 시스템의 권한 유지 |


화면 TS-P06-S01은 **입력·조건 → 근거를 포함한 결과 → 사용자/담당자 확인 → 다음 처리** 순서로 구성한다. 원문 위치와 적용본은 결과 옆에서 확인하고, 확인 전 초안과 확정된 원천 상태를 구분한다. 모바일은 입력·결과·확인을 세로로 배치하며 조건을 잃지 않는다.

| 화면 상태 | 필수 동작 |
| --- | --- |
| 대기·조회 중 | 입력을 보존하고 진행 단계 표시; 확정 버튼 중복 실행 방지 |
| 자료 없음·일부만 확인 | 없는 항목과 미확인 사유, 가능한 다음 행동 표시 |
| 권한 거부 | 자료 내용을 노출하지 않고 권한 요청 또는 기존 창구 안내 |
| 오류·시간 초과 | 현재 처리 결과를 확정하지 않음; 원 상태 재조회 후 재시도 |
| 정상 결과·확인 대기 | 근거·적용본·한계를 읽고 사용자가 선택 또는 담당자가 수정 |
| 이관·확정·반려 | 공식 응답이나 담당자 결정 이력으로 상태 구분 |


화면 상세 디자인과 API 실주소는 별도 구현 단계에서 확정한다. 키보드 입력·오류 초점·상태 읽기와 모바일 조건 유지가 제품 인수 시험 대상이다.

## 5. 데이터·출력 계약

아래 필드명은 **논리 설계 예시**다. 실제 원 시스템 필드·API가 존재한다는 뜻이 아니다. 필드별 필수 여부·보존기간·마스킹·추출 가능성을 원천 담당자와 매핑표로 확정한다.

| 입력 논리 항목 | 연결·검증 규칙 |
| --- | --- |
| report_id / access_domain | 보고서키와 제한된 원본 영역 |
| event_order / context | 사건 순서·관련 운영 조건 |
| direct_identifiers | 이름·연락처 등 별도 접근 항목 |
| indirect_identifiers | 희귀 장소·시각·직무의 조합 |
| hazard_tags / evidence_ref | 위해요인 후보와 근거 |
| release_version / approval | 전파용 버전·검토 및 승인 상태 |


출력은 다음 항목을 묶고 각 항목에 원문 참조·버전·확인 상태를 붙인다.

- 권한이 제한된 사건 구조화표
- 위해요인과 불확실성
- 검토용 상세본
- 식별 단서를 조정한 전파용 초안
- 의미 보존·재식별 검토 기록

공통 메타데이터: case_id, source_refs, source_version, retrieved_at, rule_version, model_config_version, review_status, reviewer_action. 여기의 review_status는 제안 기능의 상태이며 법정·업무 처분 상태를 대신하지 않는다.

원본 접수 시스템의 허용된 읽기 또는 승인된 비식별 자료 반입만 협의한다. 공개 전파 쓰기는 초기 범위에 포함하지 않는다. P08과 처리 코드만 공유하고 원본 인덱스·권한은 분리한다.

자료가 없으면 승인된 파일 반입·공개 지식만으로 가능한 1단계까지 수행한다. 개인 데이터 조회·쓰기 연계가 필요한 후속 단계는 실제 인터페이스와 권한이 확인돼야 개발 범위를 확정한다.

## 8. 데이터 주권·안전·운영

표면적 비식별 처리 후 재식별 또는 안전 의미 손실 가능성. 자동 비식별 완료를 보장하지 않고 전문가 이중 검토를 요구한다.

- 자료 원본·검색 인덱스·모델 호출·로그·백업·라이선스 경로를 기존 서버 환경에서 점검한다. 로컬 배치라는 이유만으로 외부 전송이 없거나 보안이 충족됐다고 단정하지 않는다.
- 문서 안의 명령·외부 링크는 근거 데이터로 취급하고 실행 지시로 사용하지 않는다. 인용 권한은 검색과 원문 열람 모두에서 검증한다.
- 기준·문서 변경과 접근 철회 시 결과를 재확인 대상으로 전환하고 인덱스 갱신·삭제 전파 방법을 검증한다. 보존기간과 삭제 권한은 TS 정책 확인 후 설정한다.
- 기존 업무 화면을 복귀 경로로 보존하고 AI 기능만 비활성화할 수 있게 한다. 쓰기 도입 시 요청 식별자·상태 재조회·승인·중복 방지·복구 담당을 계약에 명시한다.

법정업무 확인 범위: 공식 안내의 철도안전법 제61조의3 및 신고자 보호 원칙 확인. 새 AI 이용 목적의 허용 여부는 별도. 실제 현행 조문·위탁 관계·개인정보 처리 근거의 최종 적용 검토는 착수 전 확인 항목이다.
