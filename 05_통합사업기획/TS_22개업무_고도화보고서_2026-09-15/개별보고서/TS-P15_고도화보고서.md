## 2. 현행 기반과 고도화 목표

마이배터리 및 제작사별 식별정보 안내을 이용하는 업무에 공식 안내 지식팩·질문 유형·링크 갱신·오안내 평가 항목을 추가한다. 현행 내부 화면·소요시간·API를 직접 시험한 것은 아니다. 아래 흐름과 오류 처리는 **제안 설계**이며 현업 워크숍에서 실제 절차와 대조한다.

대표 상황: 소유자가 배터리 정보를 TS에 새로 등록해야 하는지 제작사 앱에서 확인하면 되는지 혼동하는 상황

| 현행 기반 활용 | 고도화할 처리 | 유지할 공식 책임 |
| --- | --- | --- |
| 마이배터리 및 제작사별 식별정보 안내 | 배터리 식별정보를 찾으려는 국민에게 제작사별 공식 확인 절차를 쉽게 설명하는 기존 상담 AI의 지식 확장 | 기존 업무의 자격·검사·예약·지급·공개·안전 판단 권한 |
| 제작사별 링크·짧은 문진형 안내 페이지 | 질문 의도·제작사·확인 목적을 이해한 근거 안내와 예외 질문 | 원천 데이터·적용 기준의 승인과 검토자 확인 |


국민에게 기대하는 가치는 정확한 다음 행동과 보완 필요를 더 빨리 이해하거나, 담당자의 검토 누락을 줄이는 것이다. 다음 지표를 측정해 확인한다: 잘못된 확인 경로·완료까지 탐색시간·불필요한 문의. 업무시간 절감을 감축 인원으로 환산하지 않는다. 사고 감소·무사고를 이 기능만으로 입증했다고 주장하지 않는다.

## 4. 처리 흐름과 화면

목적·제작사 확인 → 공식 안내 검색 → 경로 설명 → 사용자 선택 → 외부 공식 경로 안내. 실제 배터리 상태 확인이나 민감정보 수집은 하지 않는다.

| 순서 | 사용자·시스템 동작 | 처리 책임 |
| --- | --- | --- |
| 1 | 제작사와 질문 목적에 맞는 승인 안내만 사용한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 2 | 안내 링크·메뉴의 확인일과 갱신 필요 상태를 관리한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 3 | 식별번호의 목적만 공식 자료 범위에서 설명한다. | LLM은 제안·설명, 규칙·권한·원천 상태는 응용 계층에서 검증 |
| 4 | 공개 절차 설명에 필요 없는 개인 차량정보는 요구하지 않는다. | 사용자/현업 확인 후 공식 시스템의 권한 유지 |


화면 TS-P15-S01은 **입력·조건 → 근거를 포함한 결과 → 사용자/담당자 확인 → 다음 처리** 순서로 구성한다. 원문 위치와 적용본은 결과 옆에서 확인하고, 확인 전 초안과 확정된 원천 상태를 구분한다. 모바일은 입력·결과·확인을 세로로 배치하며 조건을 잃지 않는다.

| 화면 상태 | 필수 동작 |
| --- | --- |
| 대기·조회 중 | 입력을 보존하고 진행 단계 표시; 확정 버튼 중복 실행 방지 |
| 자료 없음·일부만 확인 | 없는 항목과 미확인 사유, 가능한 다음 행동 표시 |
| 권한 거부 | 자료 내용을 노출하지 않고 권한 요청 또는 기존 창구 안내 |
| 오류·시간 초과 | 현재 처리 결과를 확정하지 않음; 원 상태 재조회 후 재시도 |
| 정상 결과·확인 대기 | 근거·적용본·한계를 읽고 사용자가 선택 또는 담당자가 수정 |
| 이관·확정·반려 | 공식 응답이나 담당자 결정 이력으로 상태 구분 |


화면 상세 디자인과 API 실주소는 별도 구현 단계에서 확정한다. 키보드 입력·오류 초점·상태 읽기와 모바일 조건 유지가 제품 인수 시험 대상이다.

## 5. 데이터·출력 계약

아래 필드명은 **논리 설계 예시**다. 실제 원 시스템 필드·API가 존재한다는 뜻이 아니다. 필드별 필수 여부·보존기간·마스킹·추출 가능성을 원천 담당자와 매핑표로 확정한다.

| 입력 논리 항목 | 연결·검증 규칙 |
| --- | --- |
| maker / model_family | 초기 제작사 1곳·확인된 모델 범위 |
| requested_information | 식별번호·확인 경로 등 질문 목적 |
| guide_ref / revision | 공식 안내 원문·갱신일 |
| channel / availability | 앱·콜센터 등 공식 확인 경로 |
| unresolved_reason | 정보 없음·모델 불명·링크 오류 |
| user_selected_next_step | 이용자가 선택한 다음 행동; 개인정보 조회 없음 |


출력은 다음 항목을 묶고 각 항목에 원문 참조·버전·확인 상태를 붙인다.

- 제작사·질문에 맞는 확인 경로
- 정보 확인에 필요한 항목
- 식별정보의 의미와 해석 한계
- 공식 안내 근거·확인일
- 찾을 수 없을 때 담당 창구

공통 메타데이터: case_id, source_refs, source_version, retrieved_at, rule_version, model_config_version, review_status, reviewer_action. 여기의 review_status는 제안 기능의 상태이며 법정·업무 처분 상태를 대신하지 않는다.

공개 안내 지식팩만 추가한다. 개인 배터리 데이터·제작사 앱 로그인·진단 연계는 0개다. 공통 상담 플랫폼의 지식 갱신·근거 표시 기능을 사용한다.

자료가 없으면 승인된 파일 반입·공개 지식만으로 가능한 1단계까지 수행한다. 개인 데이터 조회·쓰기 연계가 필요한 후속 단계는 실제 인터페이스와 권한이 확인돼야 개발 범위를 확정한다.

- 기존 업무 화면을 복귀 경로로 보존하고 AI 기능만 비활성화할 수 있게 한다. 쓰기 도입 시 요청 식별자·상태 재조회·승인·중복 방지·복구 담당을 계약에 명시한다.

법정업무 확인 범위: TS 마이배터리 공식 안내의 식별번호 제공·소유자 직접 관리 확인. 제작사 데이터 이용권 별도. 실제 현행 조문·위탁 관계·개인정보 처리 근거의 최종 적용 검토는 착수 전 확인 항목이다.
