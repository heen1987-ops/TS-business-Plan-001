# 한글 문서 호환 복구·검증 기록

- 대상: 39개 처의 현재 문서 117개와 이전 계획서 39개, 총 156개 HWPX
- 사용자 문제: 계획서·대가산정서 다운로드 후 한글에서 손상·변조 가능성 경고 및 열람 실패
- 수용기준: 보안 설정 변경이나 강제 열기 없이 실제 한글에서 열리고 본문을 읽을 수 있는 게시본 제공
- 검증 환경: Windows, 한컴오피스 한글 2024, 전용 숨김 COM 인스턴스
- 콘텐츠 판본: 현재 계획서 v0.5, 이전 계획서 v0.4, 대가산정서·도식집 v0.3 유지

## 원인과 재현

공개 배포 과정에서 개인 PC 경로를 파일명으로 치환하면서 일부 본문이 짧아졌으나, 변경 전의 `hp:linesegarray` 줄 배치 정보를 그대로 보존했다. 현재·이전 계획서 78개 모두에서 본문 길이 밖을 가리키는 배치 정보가 발견됐다. 대표 MR 계획서는 일반 `Open`에서 실패했고, 선택적 배치 정보만 제거한 시험본은 같은 한글 환경에서 성공했다.

한컴 개발자 포럼의 공식 답변도 `hp:t` 본문을 수정할 때 이전 `hp:linesegarray`가 유효하지 않게 되어 해당 경고가 발생할 수 있고, 선택적 배치 정보를 제거할 수 있다고 설명한다. [한컴 공식 개발자 포럼: HWPX section0.xml 수정](https://forum.developer.hancom.com/t/hwpx-section0-xml/2414)

대가산정서·도식집 78개에서는 위 배치 오류가 발견되지 않았으며 대표 파일의 경고도 재현되지 않았다. 이 파일들은 불필요하게 재작성하지 않고 실제 일반 열기 검사를 전체에 적용했다.

과거의 ZIP·HTTP·해시 검사와 `forceopen:true`를 사용한 검사는 일반 보안 설정에서 열람 가능한지를 보장하지 못했다. 이번 검증에는 강제 열기 옵션을 사용하지 않았다.

## 수정 범위와 보존

| 항목 | 처리 |
| --- | --- |
| 현재 계획서 39개 | section XML의 선택적 줄 배치 캐시 제거 |
| 이전 계획서 39개 | 같은 호환 수정 적용, 이전 콘텐츠 판본 유지 |
| 대가산정서 39개 | 파일 바이트 그대로 보존 |
| 도식집 39개 | 파일 바이트 그대로 보존 |
| 계획서 본문·표·금액·근거 | 배치 캐시 이외의 의미 구조 보존 |
| 내장 그림·미리보기·패키지 설정 | ZIP 항목별 바이트 보존 |
| 원본 이력 | Git의 이전 커밋 및 복구 전 SHA-256 보존 |
| 게시 메타데이터 | 수정본 크기·SHA-256·복구 날짜·제거 캐시 수 갱신 |

제거한 선택적 배치 캐시는 총 105,466개. 한글이 본문을 열 때 배치를 다시 계산하도록 하는 호환 수정이며 사업내용·대가 재산정이나 새 콘텐츠 버전 작성과 구분한다.

## 실제 한글 검증

1. 작업 전용 한글 인스턴스에서 `Open(path, 'HWPX', 'lock:false')` 실행.
2. 허용된 시험 문서만 파일 접근 승인. 기존 사용자의 한글 창이나 문서에 접근하지 않음.
3. 손상 경고는 별도 이벤트로 기록. 게시 조건은 해당 경고 0건.
4. 일반 열기 성공 후 `InitScan`·`GetText`로 본문 스캔.
5. XML에 있는 모든 비어 있지 않은 문단의 텍스트가 실제 스캔 결과에 포함되는지 공백을 정규화하여 대조.
6. 처명·페이지 수·문단 수 확인. 문서별 결과에 실제 검사한 SHA-256 기록.
7. 156개 결과와 작업 목록·공개 목록의 경로 집합 및 SHA-256을 먼저 대조한 뒤 파일 교체.

결과 정본은 [한글 호환 검증 기록](../src/hwpx-compatibility-20261006.json). 이 기록의 성공값과 SHA-256이 실제 게시 파일에 일치해야 자동 검사를 통과한다. 새로 변경한 파일에는 새 일반 열기 검증이 필요하다.

| 완료한 검사 | 실행 결과 |
| --- | --- |
| 실제 한글 일반 열기·문단 대조 | 156/156 성공 · 비어 있지 않은 문단 109,665개 대조 · 손상 경고 0건 |
| 독립 내용 보존 대조 | 복구 계획서 78개 의미 구조 동일 · 비section ZIP 항목 1,536개 바이트 동일 · 오류 0건 |
| 최종 `npm ci`·`npm test` | 성공 · 73개 React 경로와 전체 검사 통과 |
| 한글 파일 자동 검사 | 30,911조건 통과 · 156개 파일 SHA·CRC·판본·실제 열기 기록 대조 |
| 39처 다운로드 브라우저 검사 | 297조건 통과 · 현재 링크 117개·HTTP 해시 3개 확인 |
| 사용자 클릭 다운로드 검사 | 339조건 통과 · 현재 3종과 이전판, 실제 다운로드 4건 SHA 일치 |
| 통합 본문 브라우저 회귀 | 384조건 통과 · 모바일·키보드·탐색·문서 다운로드 확인 |

위 표는 로컬에서 실행한 결과. 공개 배포의 Actions 성공 및 HTTP 대조는 배포 후 별도로 확인하는 단계이며, 로컬 결과를 배포 완료 근거로 대신하지 않는다.

## 다운로드와 회귀 방지

- 문서 링크에 실제 파일의 SHA-256 앞 12자리를 판본 쿼리로 부여. 기존 손상 파일을 브라우저 캐시에서 재사용하는 문제 예방.
- 자료실·처별 제안·PMS·검색의 공통 링크 컴포넌트에 동일 처리 적용.
- ZIP CRC 검사 추가. 이미지와 미리보기 등 본문 외 ZIP 항목도 포함.
- 복구 계획서에 이전 줄 배치 캐시가 다시 들어오면 검사 실패.
- 잘못된 배치 캐시·CRC 변조를 거부하는 회귀 사례 추가.
- 문서별 원본 보존 기록과 156개 실제 일반 열기 결과를 자동 빌드에서 대조.
- 공개 배포 후 156개 전체의 HTTP 수신 바이트·SHA-256 확인. 사용자 클릭 다운로드도 별도 확인.

## 검증의 한계와 롤백

검증 환경은 설치된 한글 2024이며 모든 구버전·다른 운영체제의 호환성을 입증한 것은 아니다. 본문 스캔과 그림 바이트 보존은 모든 페이지의 시각 배치 품질을 대신하지 않는다. 계획서·대가의 사업 타당성, 확정 예산 및 현업 수락 여부도 이번 호환 검증의 범위 밖이다.

문제 발생 시 이번 커밋의 변경을 되돌려 직전 게시본·원장을 함께 복원할 수 있다. 다만 직전 계획서에는 확인된 열람 오류가 있으므로 단순 롤백보다 해당 파일의 추가 호환 수정과 일반 열기 재검증을 우선한다. 이미 내려받은 손상 파일은 자동으로 수정되지 않으므로 새 링크에서 다시 다운로드해야 한다.
