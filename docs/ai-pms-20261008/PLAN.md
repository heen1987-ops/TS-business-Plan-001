## 문제와 범위

국토부 PMS의 보고 구조를 참고한 TS 자체 업무추적 PMS 설계와, 기구축 TS AI 플랫폼에서 사용할 감리 지원엔진의 별도 R&D·이식 계획 작성.

- 현재 국토부 PMS 사용은 사용자 현장 확인. 참조 시스템은 RealPMS로 잠정 설정하며 정확한 시스템·TS 이용범위·연계권한 추가 확인
- 기존 스킬형 PMS v0.3의 공동 코어·스킬·권한·문서 연결 재사용. 새로운 계획은 별도 TS-AIPMS-2027 v0.1로 보존
- 2027 정보화사업 일정, 공고·협약 미확정 R&D 시간축, 독립 감리 역할·대가의 구분
- 운영 서버·TS API·실제 감리 성능 구현은 이번 정적 기획 사이트 반영 범위 밖
- 최근 사용자의 독립 R&D 요청은 이번 감리엔진에 적용. 과거 일반 기획의 독립 R&D 제외를 모든 사업에 전역 변경하지 않음

## 변경·위험·롤백

- canonical: src/ts-ai-pms.cjs · render: TsAiPmsPlan.jsx/CSS
- 기존 IntegratedReader 공통 플랫폼 본문에 삽입, 사이드 목차에 같은 페이지 앵커. SkillPms 공통 화면 첫 상세안에 삽입. 별도 페이지 신설 없음
- Markdown·JSON·CSV는 canonical에서 빌드 생성, 사이트 상대경로·공식 원문 링크만 제공
- 기존 업무/산출물·재사용 제품 구현으로 오인할 위험: 상태·판본·권한·설치본 확인을 별도 명시
- 공개 사이트는 자료 열람용. 외부 API·인증·PMS 상태 변경 기능 추가 없음
- 롤백: 이번 변경 이전 72cd218 커밋의 사이트 소스로 되돌려 새 정상 커밋·Actions 배포. 기존 문서/브랜치 삭제·이력 재작성 없음

## 독립 검토

RealPMS 조사자와 감리·연구 조사자에게 canonical/React의 읽기 전용 검토 요청. 이 검토는 실제 현업 인터뷰·법률 자문·공식 감리와 구분.

## 공개 범위

신규 기획·자체 이미지·구조화 데이터·산정 입력만 배포. 공식 매뉴얼/가이드 원본은 로컬 조사 폴더에 보존하고 사이트에서 공식 다운로드 링크 제공. CCK 내부 원본 PDF·개인 로컬 경로·자격증명 게시 없음.

## v0.2 · 사용자 정정에 따른 적용 구조

2026-10-08 · 기존 기획 수정 · M / Medium. Stage-Gate·요구사항 추적·관련 회귀 검증 적용. 새로운 백엔드·페이지·승인절차 신설 없음.

- 공통 기반: TS 자체 NOA 업무 가이딩·과업·검토·후속조치 관리. RealPMS 계정이나 외부 보고를 모든 업무의 전제로 두지 않음
- 조건부 보고: 동일 사업에서도 과업/보고 단위로 필요·불필요·확인 중, 근거·주기·제출자·효력시점 분리. 미확정 상태의 외부 제출 차단
- 완료·권한: TS 내부 완료와 해당 과업의 외부 보고 완료 구분. 보고 불필요 업무는 TS 완료조건으로 종료, 보고 필수 업무는 필수 외부 완료조건 확인
- 프로젝트·일상업무: WBS·계약·감리·인수는 해당 업무유형에만 적용. 일상업무에는 목적·자료·순서·검토·후속조치 가이드 사용
- 향후 국토부 확대: 공통 코어·스킬 형식 재사용, 기관 기준팩·권한·자료·어댑터·운영·사업비 별도 구성. 국토부 도입 확정·TS 데이터 자동 공유 없음
- 측정·대가: 공통 업무시간과 보고 대상의 보고시간 별도 분모. 비대상 0분 평균 혼입 금지. 선택형 보고 어댑터·기관 추가공수의 중복 제외
- 그림: architecture-v1 원본 보존, architecture-v2 신규 생성. 기존 연구·이식 그림은 동일 연구 경계로 유지

수용기준: 3개 보고 적용 프로필·혼합 사업·별도 제출권한·필수 외부 실패·업무유형·측정 분모·후속 확대의 본문/요구/다운로드 일치, 13개 연속 절·기존 처 탐색 유지, 신규 그림의 정확한 한글·연결 방향 확인. 연구 성능·현업 수요의 실증 판정은 이번 사이트 검증 범위 밖.

## v0.3 · 계약 전 선정·대금·업체 아카이브 확장

2026-10-08 · 기존 기획 확장 · M / Medium. 요구사항 추적·공식 원문 대조·독립 사전검토·관련 브라우저 회귀 적용. 실제 입찰·평가·전자서명·송금·업체 정보 공개 기능은 신설하지 않음.

- 목적: 입찰 후보·평가기준·위원 점수·선정·협상·계약 약속을 수행·검사·청구·선금정산·실제 지급·업체별 이력까지 연결
- 전제: 실제 사업 RFP·평가배점·점수·계약·지급조건·참가업체는 미확보. 기본 점수·고정 지급비율·가상 업체 생성 없음
- 적용: TS 계약 담당·사업 담당·재정/회계 담당·평가위원의 책임 분리, 업체 간 제안서·위원 평가·계좌·수행사 미제출 자료 격리. 기존 RealPMS 조건부 보고 유지
- 기술: 기존 코어·권한·판본·NOA 스킬 재사용, 공고/참가단위·평가 기준팩·계약·지급회차·정산·아카이브 관계 추가. 실제 지급은 승인된 ERP/재정 원장과 결과 대조
- 공개: 기획안·모델 도식·빈 입력양식만 게시. 실제 제안서·위원 신원/점수·계좌·증빙을 수집·공개하는 행위 없음
- 대가: 공통코어 기능과 평가·지급·업체이력의 신규 기능 경계, 통상 분석·설계·시험 및 어댑터 공수 중복 제외. 새 연구성과로 재분류하지 않음
- 버전: v0.2 로컬 5종 보존, 신규 v0.3 산출물 누적. 기존 13절을 16절로 확장, 요구8→12, 연구4·지표5·기존 경로 유지

수용기준: 공고·접수본/평가/선정·협상·계약의 판본과 상태 분리, 평가점수의 null/실제0 구분·공고별 집계/동점/정정 근거, 참가단위/공동수급 역할, 선금과 기성 gross/net·정산/실제지급·취소/환급의 분리, 업체별 입찰 이력과 계약 이력의 별도 보존, 개인정보·영업비밀·보존정책, 3개 빈 CSV·본문/JSON·그림 일치. TS 현행 내부규정·제품 API·정답/성과·지급 계산 성능은 실제 구축 전 확인 조건.
