## 목적과 범위

- 기후탄소물류처 안전운임 신고 처리 지원과 택시·DRT 지원금 검증의 데이터 흐름·서비스 흐름·세부 실행 구조를 각각 이미지 모델로 제작.
- 사용자는 두 제안 모두 적용하도록 답변. 기존 컨셉도·전체 구성도 및 근거·명세·상태모델 유지.
- M 규모·낮은 운영 위험의 정적 사이트 변경. 영향분석·행동 검증·독립 시각/코드 리뷰를 거쳐 기존 Actions 경로로 배포.
- 새 API·개인정보 수집·운영계 실행 없음. 실제 CCK 제품 동작·기관 연계·정량효과는 별도 검증 대상.

## 읽기·책임 경계

- 그림 바로 아래에 대체 설명을 펼쳐 제공. 작은 화면에서는 비율 유지·원본 확대·HTML 설명으로 열람.
- 데이터 흐름은 원천·사건키·판본·승인기록·공식 결과 중심, 서비스 흐름은 역할과 보완 절차 중심, 실행 구조는 계획·도구·검증·승인·어댑터·대사·복구 중심.
- CL: LLM 금액 계산·독자 위반 확정·과태료 부과 제외. 통보 준비·전송·관할 수신·처분의 상태 구분.
- DRT: 반복 이용만으로 부정 판단 금지. 검토 대기와 지급 보류 구분. 개인정보 분리·가명키 연결·지자체별 권한 구분.
- 실행 그림의 번호는 변경행위 경로. 읽기 조회는 사건별 권한에 따라 수행. 공유 도구선은 검증 지원이며 사람의 판단을 자동화하는 의미가 아님.
- 기존 공식 시스템 상자는 논리 참조. 원장 물리 통합·API 확보·현재 제품 구현의 사실을 주장하지 않음.
- 응답 유실은 상태 조회 후 재처리 판단·담당자 인계. 새 근거·불일치는 잔여 과업 재계획으로 연결.
