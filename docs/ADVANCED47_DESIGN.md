## 1. 문제·범위·수용기준

- 문제: 요구사항·검수·지표는 연결되었으나, 변화하는 근거에 따른 과업계획·도구 수행·결과 검증·재계획의 구체적인 실행 구조 설명 부족.
- 사용자: TS 처별 현업·정보화 검토자와 CCK 기획·설계 담당자.
- 범위: 기존 13개 처의 제4장에 고도화 실행 설계 추가. 6개 큰 장의 연속 스크롤·기존 링크·근거·측정 원장 보존.
- 제약: CCK 주관, 로컬 LLM, 기존 서버 활용, 신규 장비·비전·차량 제어 제외.
- 수용기준: 처별 목표·업무키·AI/규칙 역할·재계획·완료 증거의 구분, 구성요소·서비스 계약·예외 경로 명세, 정상/금지 전이 재현, 기존 요구·지표 추적, 모바일·키보드·도식 글자영역 확인.
- 실제 제품 기능과 설계안의 구분 유지. API·쓰기권한·성능·개선효과의 구현 완료 주장 금지.

## 2. 방법론·설계 결정

- 유형/규모/위험: 기존 제안 사이트의 내용·동작 고도화 / L / Medium.
- 방법론: 업무 경계 분석 + 요구사항 추적 + 상태 반례시험 + 독립 검토.
- Discovery: 기존 13개 처의 목표·근거·요구사항·39개 측정 수집계약 대조.
- 대안: 고정 규칙 처리 / 단일 LLM 응답 / 제약된 계획·수행·검증 결합.
- 선택: 정형 계산·공식 상태는 규칙·원천에 두고, AI는 사건의 확인질문·근거 관계·과업계획을 제안. 변경행위는 기관 승인·도구 통제·원천 대사 조건으로 제한.
- UI 결정: 새 하위 페이지를 늘리지 않고 제4장의 연결된 설명으로 제공. 표와 확대 가능한 SVG, 8개 가상 예시 제공.
- 논리 구성요소를 서버 대수 또는 현재 CCK 제품의 구현 기능으로 해석하지 않도록 표시.
- 별도 신규 사업비·인월·정량 개선 목표 설정 없음. 원천 접근·제품 재사용·기준선 검증 후 확정할 항목.

## 4. 구체적인 업무 변경

- MR: 제품·배포판·할증조건·시험증거의 변경에 따른 확인질문과 검정 경로의 영향 검토.
- DF: 위험 신호와 자료 제출 감소를 구분하고 권한 있는 주체의 실제 조치·미시행 사유 확인.
- SA: 계획서 제출과 조치 실시·해소 증거를 구분하여 종결 또는 계속관리 판단 준비.
- QE: 학습·이해 확인과 개인의 자격·운행 적합 판정을 구분.
- CL: 자료 해석과 규칙 계산·공식 거래 결과의 불일치 확인.
- PS: DRT 대상·이동 취약성·정책대안 근거 비교. AI의 전국 재원 자동 배분·배차 확정 제외.
- RI: 실증조건·보험·운영변경의 영향과 잔여 입증 과업 연결.
- DV: 현장 경계·개선 권한·재원·실제 개선 증거에 따른 검토·후속 확인.
- IP: 표본·노출량·기관별 조건과 독립 현장 확인을 함께 검토.
- SI: 검사대상 기기의 동일성·증거·재검사·공식 조치 연결.
- PK: 보수 실시, 검사 결과, 재개 허용을 별도 상태로 검토.
- AD: 차량·장치·프로그램별 적용범위와 진단 근거의 유효성 확인.
- RD: 실험·측정 조건과 법정 기준의 구분, 보류 근거 및 후속 실험계획 연결.

각 적용은 기획 가설. 현업의 실제 수요·전결·자료·연계권한·제품 기능을 확보했다는 의미 아님.

## 5. 예외·데이터 불변식

1. 사건 기록판본(recordVersion)과 근거판본(revision)을 분리. 모든 수락 갱신의 기록판본 증가, 원천/정책 변경의 근거판본 갱신.
2. 가상 이벤트 expectedRevision은 기록판본 대조값. 논리 계약의 expected_revision과 대응.
3. 승인범위에 대상 항목·인자·근거/계획판본·유효기간 결합. 실행 직전 재확인.
4. 동일행위 키에 다른 인자 또는 원 요청 사용 차단. 미반영 공식 대사·유효 승인·재시도 허용기록을 갖춘 동일 요청만 재시도.
5. 부분 반영은 승인 항목 전체를 완료·잔여로 분할한 스냅샷. 중복·범위 밖 항목·이전 완료분 삭제 차단.
6. 동일 판본에서도 partial_reconciled로 완료분을 보존한 뒤 잔여계획 편성 가능. 완료분 포함 재승인 차단.
7. 진행 중 원천 변경·보류는 전송 취소로 간주하지 않음. 이전 요청의 대사를 선행하고 EVIDENCE 또는 HOLD로 복귀.
8. 보류는 ID·사유·발생판본별 누적. 이미 HOLD인 경우도 추가 보류 수신. 미해소 보류가 하나라도 남으면 재개 차단.
9. 대사 완료 및 정상 종결 요청의 추가 결과도 이전 요청에 보존. 현재 진행 요청을 덮어쓰지 않고 정정 검토로 보류.
10. 같은 불변 공식 결과 참조의 재수신은 중복으로 제외. 결과의 새 판본은 새 참조로 수신하는 계약 필요.
11. 업무 종결과 후속 관측 상태 분리. 종결을 무재발·효과 입증으로 계산하지 않음.
12. 조회·분석 인계(A)와 변경행위 승인(B)은 대안 경로. 정상/부분/늦은 결과 또한 대안 분기이며 순차 실행 목록 아님.

## 6. 구현 전·후 독립 검토

- 사전 검토: 승인과 실행 분리, 근거 변경과 늦은 결과, 부분 반영, 권한 보류에 대한 반례 우선 설정.
- 독립 재검토에서 발견: 대사 후 복귀 누락, 시퀀스 상충, 과업 실행·재계획 연결 누락, 멱등키 충돌, SVG 노드 높이 부족, 중첩 보류와 부분 반영 불변식, 과거 정상 요청의 추가 결과 누락.
- 조치: 명시 전이·보류 배열·행위 원장·완료/잔여 분할·이전 요청 이력·환류 선·분기 시퀀스 추가 및 회귀시험 편입.
- 최종 독립 판정: 합격. 기획용 실행 설계·가상 상태모델 범위에서 필수 보완사항 없음.
- 실제 TS·제품 API·권한·운영 성능의 독립 검증을 의미하지 않음.

## 8. 한계·후속 확정·복구

- 현재 예시는 단일 활성행위 모델. 실제 다중 작업큐, 분산 트랜잭션, 서명·인증·권한 검증, 스케줄러·LLM·ERP 연계 구현 아님.
- 가상 플래그는 권한자/원천 확인 결과를 설명하기 위한 입력. 실제 기관 승인 근거의 대체 수단 아님.
- 실제 데이터 접수의 영속 저장·동시처리·이벤트 역순·보안 공격·장애 복구는 구현 후 별도 계약/통합시험 필요.
- 완료 기록의 취소·되돌림은 이 예시에서 자동 실행하지 않음. 새 공식 정정 과업과 원천별 취소·보상 계약의 상세화 필요.
- 동시성·시간제한·재계획 횟수·보존기간·RTO/RPO 등 8개 운영값은 null 유지. 근거 없는 수치 보장 없음.
- 후속 확정: 업무별 정상·보완·변경 사례 → 실제 API/권한·제품 기능 대조 → 기준선·규칙 비교군 확보 → 허용 실행범위 합의 → 기관 시험환경에서 인수 검증.
- 롤백: 이번 로컬 커밋만 git revert 후 npm test. 원본 기획/법령/측정 원장은 유지. 공개 배포 재개는 별도 명시 요청 전 수행하지 않음.
