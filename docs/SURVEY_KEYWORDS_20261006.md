## 읽기 구조와 수용기준

`내 처 선택 → 이번 검토의 목적 → 짧은 핵심 과제명·얻으려는 결과 → 목적과 근거 / 해결방법 / 효과 검증 → 상세 설명·현업 의견`

| 개선 항목 | 수용기준 | 연결 파일 |
|---|---|---|
| 처 첫 화면 | 검토 목적 한 문장과 핵심 과제명·결과 먼저 표시. 내부 용어·데이터명을 개요에 중복 나열하지 않음 | survey-reading / SurveyDesign |
| 주제명 | 읽기용 짧은 이름 사용. 원래 상세 기획명은 식별자와 함께 본문에 한 번 보존 | survey-reading / survey-design / export-survey-design |
| 세부 처리 | 기존 모든 단계를 최대 세 묶음에 한 번씩 연결. 입력·처리·출력 상세 보존 | SurveyDesign / 설문 정적·브라우저 검사 |
| 시간순서·역할 | 순차 업무는 흐름으로, QE-H01은 세 역할 영역으로 표시. 역할 목록을 의료 판단의 시간순서로 표현하지 않음 | survey-reading / SurveyDesign / CSS |
| 본문 탐색 | 목적·해결방법·효과 검증의 세 개 주요 이동. 기존 여섯 절과 직접 링크 보존 | survey-design / 브라우저 해시·포커스 검사 |
| 질문 | 주제별 01~15 연속 번호. 질문 앞의 설명과 동일한 긴 용어·기술목록 반복 제거 | SurveyDesign / 브라우저 검사 |

## 모빌리티연구처 적용 예

- 이번 검토의 목적: 검정 준비와 DRT 운영에서 필요한 확인·조정을 정확하게 연결하기 위한 검토.
- 핵심 과제 1: **앱미터 변경 신고·수리검정**. 변경내용 파악 → 검정 준비 → 결과 확인.
- 핵심 과제 2: **DRT 전화 접수·배차 운영**. 접수 확인 → 배차 처리 → 운영계획 개선.
- 위 이름은 설명용 표현. 공식 과제명·직무분장·확정 부서 목표로 승격하지 않음.
