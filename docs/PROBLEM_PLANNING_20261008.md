# 문제 중심 2027년 TS AX 통합기획

## 변경 목적

- 사용자 피드백: 처별 솔루션의 과도한 분산, 사업의 핵심 문제와 필요성 파악 곤란
- 개선 방향: 문제·필요성을 먼저 설명하는 통합기획 추가, 기존 처별 상세설계와 상호 연결
- 산출물: `index.html?view=problems`, 전체 본문 MD·JSON, 정적 검사 및 브라우저 회귀검사
- 대상: TS 사업·현업·정보화 검토자, CCK 기획·개발 담당자
- 범위: 2027년 후속사업의 문제·전환목적·초기 검증범위 구조화. 확정 예산·계약·기관 수요·구현 완료의 주장과 구분
- 방법론: 공공사업 Stage-Gate·요구사항 추적, 기존 UI의 점진 개선, BDD 방식의 사용자 흐름 검증

## 읽기 구조와 기술 적용

- 첫 화면: 통합 목적·목표·수단 → 다섯 꼭지 비교 → 문제별 상세 설명
- 각 꼭지: 문제·대상 → 필요성 세 가지 → 공개 확인 업무·출처·확인일 → 대표 흐름 → 현업 검증 가설 → 목적·목표·수단 → 구체적 개선 흐름 두 가지 → 첫 적용 후보 → 효과지표 세 가지 → 관련 처·기존 설계
- 주요 본문: 기본 펼침·연속 스크롤. 54개 개별 매핑만 보조 펼침 목록으로 제공
- 공통 기반: 기존 업무시스템·허용 데이터 → aRDa/기존 저장소 → NOA 업무 스킬 → 전문 도구·담당자 판단 → 기존 시스템 처리 → 결과 검증
- Grantee: 증빙 대사 적용 후보. TS 설치본의 기능·API·사용권·성능 확인 전 적용 완료로 표현하지 않는 기준
- 플랫폼 비용: 기존 계약 동일 납품분과 공통 기반·업무별 증분 개발을 구분. 본 변경에서 금액 새 산정 없음

## 근거와 측정의 경계

- 공식 TS DRT 안내에서 기존 콜·정산·앱 배차 기능과 지자체·TS 역할 확인. 시스템 부재를 신규 필요성으로 사용하지 않는 기준
- 사용자 제공 수동 접수·기사 배정 의견은 현장 의견으로 표시. 모든 지역의 현행 상태로 일반화하지 않는 기준
- KATRI 기술검토 안내의 조건별 제출자료와 기존 자동화 프로그램을 적용 기반으로 활용
- 제작결함조사·철도 정기검사의 기존 업무와 공식 권한을 유지. 내부 실제 처리순서는 현업 확인 대상으로 표시
- 중요한 누락·반복 보완·재연락·조치 확인의 발생규모와 AI 성과는 미측정. 확정 개선율·단가를 넣지 않는 기준
- DRT 이용 완료율의 분모는 사전 정의한 전체 유효 이동요청. 배정률·배정 후 완료율 및 미배정 대기를 별도 병기하여 선택 편향 방지
- 비교 구성: 동일 사례·난도·자료·조건의 현행 / 규칙·SI 개선 / AI 결합. 독립 전문가와 업무 책임자가 판정·기간·수락 기준 확정
- 감리·보조금 감사·질병정보 연계·공식 판정은 업무별 근거와 권한 검증 필요. 초기 DRT 운영 고도화와 혼합하지 않는 기준
