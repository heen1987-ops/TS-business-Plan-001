# 2027 처별 제안 · 제품 연계 도식

## 범위와 상태

- 기존 기획 39개 처의 42개 후보에 전체 아키텍처·서비스 흐름·데이터 흐름·요구환경 각 1장, 총 168장 삽입.
- 미기획 KATRI 12개 부서는 임의 사업이나 도식 생성 대상에서 제외.
- 기존 TS AI 공통플랫폼의 재사용과 업무별 스킬·연계·검증 확장에 관한 논리 설계. 실제 설치·호출·권한·성능·효과의 검증 완료를 의미하지 않음.
- 생성 원본 PNG 그대로 사용. 파일별 SHA-256·해상도·바이트·생성기를 공개 자산 원장에 기록. 과제별 실제 입력·완료조건은 기존 목적·목표·수단 원장에서 참조.

## 제품 역할과 End-To-End

1. 기존 플랫폼의 인증·접근통제 아래 요청과 사건ID 구성.
2. aRDa 후보로 허용 원문·판본·적용시점·근거 위치 조회.
3. NOA에서 목표·확인질문·과업 계획 구성.
4. Argus·Keeper 후보로 과업 상태·제한된 도구 실행의 기록 연결.
5. Grantee 후보에서 기준·증거·공식기록 대사, 근거·상충·미확인 반환.
6. 기존 전문도구에서 운임 계산·배차 최적화·통계·정형 조회 수행. Grantee와 LLM의 자유계산으로 대체하지 않음.
7. 지정 담당자·전문가·권한자가 해석·예외·확정·공식 인계 판단.
8. 허용된 기존 절차의 실제 결과를 독립 원천에서 재조회하여 승인안·실제 결과 대조.
9. 근거·정정·실행·미완료 상태를 재축적하고 NOA 계획 갱신.

Nexus는 기존 로컬 모델 연계 후보이며, 이미 설치된 모델 게이트웨이를 우선 재사용 검토. 제품 설치본·버전·사용권·실제 API·동시성·복구 목표는 확인 대상.

## 권한과 과제별 차이

- MR-02: 전화 접수·조합의 수동 배차 고도화·예외 대응·운영계획 검토. 최적화는 기존 전문 도구. 감사·부정수급 판단·환수·전국 예산배분 제외.
- EX05-01: 실제 설정·복구 실행은 운영 승인과 허용 도구 범위 확인 후. 승인 전 조회·시험계획과 실제 변경 구분.
- EX11-01: 승인 초안 인계가 기본. 별도 쓰기권한·연계·멱등·결과 조회 검증 후 제한된 ERP 초안 등록 후보. 지급·마감·취소 자동실행 제외.
- 나머지 39개 후보: 기존 절차 인계·결과 참조가 기본이며, 문서작성 완료를 공식 업무 완료로 취급하지 않음.
- EX21-01·EX22-01: 수요·국내 요건 또는 자료권한·보호검수 확인 전 운영 적용 보류(HOLD).
- QE-01: 수검자는 이해·협의·활동 이행 참여자. 공식 소견·판정 확정은 지정 검사요원·기관 권한자.

## 육안 검수와 릴리즈 기준

최초 168종을 14개 과제씩 세 명의 읽기 전용 검수자가 나누어 원본/원본 해상도 연락판으로 확인. 제품 역할 혼동, 입력·반환 역전, 사람 확정 우회, ERP 등록·재조회 순서, TS 담당자의 공무원 신분 추정은 필수 수정 대상으로 분류.

수정 원본은 같은 과제/type에 재매핑하고 재검수. 기존 도식은 이전 상세설계 접힘 영역에 보존하며, 본문은 새 4종과 정확한 텍스트 명세 중심으로 구성. 실제 인수·권한·효과 검증을 대신하는 그림으로 사용하지 않음.

릴리즈 조건: 38개 정적 검증 통과, 주요 브라우저 회귀 검사 통과, 수정 이미지의 필수 의미 결함 해소, 배포 Actions 성공 및 공개 자산 확인. 로컬 최종 실행·독립 판정·검증 범위는 [QA_20261007.md](QA_20261007.md)에 기재. 이전 배포 커밋 `69a3d8d67065e2652e4b569ca572a2e8003b7c9f`로 복구 가능.
