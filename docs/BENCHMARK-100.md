# 벤치마킹 100건 운영 기준

정리일: 2026-10-20. 분석 근거 대조일: 2026-10-19.

- 정본: `src/benchmark-100.json`. 플랫폼 34건, 업무·전략 66건, 합계 100건.
- 사례 식별: BM-001~BM-101 중 BM-055 제외. 동일 MOT 사례의 BM-054 통합 및 OneService BM-101 추가. 두 사례집의 전체 필터는 같은 100건을 조회하며 별도 합산 금지.
- 분석 순서: AS-IS → TO-BE·기대효과 → 확인된 실제 성과 → 성립 조건·실패/병목 → CCK 시사점 → TS 업무·재사용·추가 개발·검수.
- 사실과 해석: 원문 성과, 기관·공급사 자기보고, 시범평가, RFP 목표, 계획, CCK 설계 가설의 분리. 종료만으로 실패 원인을 확정하지 않음. 모델카드 성능·도입 인원·목표 절감률의 현장 성과 전용 금지.
- 근거 수준: 정부·기관·공급사 원문과 공개 보도·공고 구분. 원문/RFP가 확보되지 않은 사례도 분석 대상에 포함하되 검증 공백과 설계 추론 표시. 100건 분석 완료는 100건 모두의 운영 성공 검증을 의미하지 않음.
- 조직 연결: `ts-organization-rules.cjs`의 공식 조직코드·직제시행세칙 업무 근거 사용. 사례의 TS 적용 부서는 제안이며 법적 권한 이전을 뜻하지 않음.
- 재사용: CCK 기능은 후보 범위. 현행 TS 설치본·계약·API·성능을 대조한 후 확정.
- UI: 플랫폼 사례집·전략과제 사례집의 공통 `Benchmark100` 뷰. 좌측 메뉴와 공유 Pretendard·글씨 크기 유지. 기존 ID 링크 해석. 기존 도면·RFP는 선택 사례에서 펼침.
- 기존 자산: 57건 설계 자료와 31건/26건 PPT 보존. 다운로드 이름에 기존 설계 범위 표시. 새 100건은 Markdown·CSV·JSON으로 동일 데이터 제공.
- 수집 목록: 기존 2,637건 탐색 원장과 100건 심층 분석은 별도 범위. 수집 목록의 항목 수를 검증된 사례 수로 사용하지 않음.
- 검증: `npm test`에 100건 스키마·중복·전략·공식 조직·주요 수치 해석·공개 경계·웹/다운로드 일치 검사를 추가. 브라우저에서 필터·사례 전환·원문 도면·내부 링크·모바일 점검.
