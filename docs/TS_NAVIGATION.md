# TS 홈페이지 기반 내비게이션·메뉴·자료 등록 구조

기준일: 2026-09-23. 기존 React 사이트의 탐색 개선(M 규모). 기존 조직 연결지도·처별 문서·슬라이드 보기 보존.

## 목적·적용 기준

- 목적: 기관 이해 → 전략 → 조직·업무 → 처별 AX 제안·근거로 이어지는 탐색 경로의 명확화.
- 참고: [한국교통안전공단 공식 홈페이지](https://main.kotsa.or.kr/main.do), 2026-09-23 브라우저 열람 및 화면 확인.
- 반영 요소: 흰색 상단, 청색·청록색 중심 색상, 보조 금색, 펼침형 대메뉴, 청색 현재 위치 표시, 왼쪽 세부 메뉴, 자주 찾는 메뉴.
- 기획자료의 6개 분류 적용. 공식 홈페이지 메뉴 전체 복제나 공식 서비스 운영상태를 의미하지 않음.
- 화면에 CCK 제안·검토자료와 공식 누리집의 구분 표시. 공식 로고 자산·회원가입·민원처리 기능의 신규 도입 없음.

## 메뉴 구조

| 대메뉴 | 주요 하위 분류 |
|---|---|
| 공단 이해 | 기관의 존재 의의, 법정·수탁업무, 법령 근거 |
| 중장기 전략 | 2026–2030 경영목표·전략과제 |
| 조직·업무 | 조직 연결지도, 조직도·수행업무, ARS 업무지도 |
| AX 전환 제안 | 13개 처, KATRI, 컨셉·흐름·아키텍처·근거·측정명세 |
| 공식 서비스 | 처별 공식 홈페이지·시스템, 담당 처 확인 대기 |
| 자료실 | 자료 안내, 추가 설계, 업무 전환 후보, 자료 등록 원장 |

상단 메뉴는 클릭·키보드 아래 화살표로 펼침. Escape·닫기·바깥 클릭으로 닫기. 검색과 전체메뉴는 대화상자로 제공, 닫을 때 원래 버튼으로 초점 복귀. 경로 변경 시 본문으로 이동.

왼쪽 메뉴는 현재 대분류의 폴더만 표시. 검색어 입력 시 전체 분류 검색. 모바일에서는 상단 전체메뉴와 접이식 세부 메뉴 사용. 701px 이상 슬라이드 보기에서는 실제 상단 높이를 측정해 본문·이전·다음 버튼의 사용 공간 확보.

## 등록구조의 해석과 범위

사용자 확인 대기 중 적용한 가정: ‘등록구조’는 메뉴·조직·자료·공개 경로의 등록·분류체계. 현재 화면은 읽기 전용 원장이며 파일 업로드·서버 저장·관리자 수정 기능은 미구현.

원장: `src/navigation.cjs`. 상단·현재 위치·왼쪽 메뉴·검색·전체메뉴·등록자료 목록의 공통 기준.

- `id`: 고유 등록 식별자
- `title`, `route`: 제목과 실제 자료 보기 경로
- `menuId`, `menu`, `parentId`, `breadcrumb`: 상위 메뉴와 계층
- `organization`, `kind`: 관련 조직 코드와 자료 유형
- `sourceFiles`: 해당 화면의 구현·참조 데이터 파일. 본문의 모든 주장을 입증하는 외부 원문 목록은 아님
- `status`: 등록 경로·분류 확인 상태. 내용 확정 여부는 개별 원문에서 확인
- `registeredAt`: 등록 분류 기준일. 외부 근거의 발행일·효력일과 구분

239개는 동일 화면의 아키텍처 탭·측정명세 등 세부 보기를 포함한 메뉴 등록 항목 수. TS 업무 수나 신규사업 수가 아님. HTML 진입 경로는 66개이며 이번 변경으로 `registry.html` 1개 추가(65→66).

갱신 순서: 자료 원본 확인 → 공개용 내용·화면 반영 → 등록 ID·분류·경로 연결 → 신규 진입점만 `site-routes.json` 추가 → 빌드·링크·원장·화면 검증 → 검토 후 커밋·배포. 내려받기 JSON은 빌드에서 공통 원장으로 생성하여 별도 수작업 복사 배제.

## 구현 파일

- `src/SiteNavigation.jsx`: 상단·대메뉴·검색·사이트맵·현재 위치·빠른 메뉴.
- `src/DocumentNav.jsx`: 공통 분류 원장을 이용하는 문맥별 폴더 탐색.
- `src/Registry.jsx`: 등록 목록·검색·필터·JSON 내려받기.
- `src/ts-navigation.css`: 공식 사이트에서 참고한 색상·배치, 반응형·초점·슬라이드 높이.
- `src/App.jsx`, `src/core.jsx`: 경로 연결·슬라이드 예외·상단 높이 측정.
- `scripts/build.cjs`, `site-routes.json`: 등록 원장 진입점 및 JSON 출력.

외부 API·서버·LLM·새 인증권한·개인정보 저장의 추가 없음. 관련 없는 기획 데이터·금액·기존 원본 문서의 변경 없음.

## 배포·운영

기존 승인 범위의 GitHub Actions Pages 배포 사용. 배포 이후 `version.json`의 커밋과 메뉴·원장 JSON 경로 확인. 저장소 공개범위·Pages 설정·빌드 방식 변경 없음.

롤백: 이 내비게이션 변경 커밋을 revert하여 이전 화면으로 복원한 뒤 기존 검증·배포 경로 사용. 기존 진입 경로는 유지하므로 분류 원장의 갱신만으로 이전 외부 링크를 변경하지 않음.

잔여 확인: ‘등록’이 실제 관리자 작성 화면을 뜻하는 경우 사용자 답변에 따라 별도 저장·인증·공개 승인 흐름 설계 필요.
