# TS 실제 업무 적용 시나리오

기준일: 2026-10-20 / 직제 업무 기반 적용 설계

## 범위

- SC-AI-01: AI혁신처 AI 서비스 변경 검토. 디지털기획처·정보보안처 및 예산/계약 영향 시 소관 협의.
- SC-BU-01: 예산처 예산 집행·차이 검토. 사업 소관의 차이 사유와 재정회계처의 집계·전표 확인 분리.
- SC-HR-01: 인재개발처 전보·미결 업무 인계. 발령 효력·인수 배정·권한·수락·원천 책임 변경 연결.
- 각 8단계·5개 자료·3개 검수 시나리오. 합성 업무건·역할 사용, 실제 직원·사업·증빙 및 계정정보 미사용.

## 근거와 경계

- `ts-org-rule-20260630.json` 및 `ts-organization-rules.cjs`의 원문 항목·표/행 좌표 그대로 대조. AI혁신처 RULE-T37-3, 디지털기획처 RULE-T37-2, 정보보안처 RULE-T37-5, 예산처 RULE-T36-4, 인재개발처 RULE-T38-3, 재정회계처 RULE-T38-4.
- [TS 공식 조직도](https://main.kotsa.or.kr/portal/contents.do?menuCode=06020400)에서 관련 부서 명칭·상하위 관계 재확인(2026-10-20). 현행 전결·개인 배정·업무 API 확인으로 확대하지 않음.
- CCK 아카이브 README·현재 정정·사업/기술 근거 문서의 해당 주장을 검토. E09 재편집 사용자 매뉴얼 PDF 6~8·15~17쪽 추출문, PG18 카탈로그 정의, PG24 Epic 색인, PG34 2026-08-03 로드맵 §1~2 직접 대조.
- NOA는 문서·양식·개인 작업공간의 매뉴얼 근거. 부서 공동 사건·협업 수락·공식 승인 엔진으로 현재 제공된다고 표시하지 않음. T2 카탈로그/설계·과거 실장, T3 특정 시험 근거는 현재 TS 설치본 검증과 구분.
- 실제 전결선, 자료 목록, 협업 조건, 인수 정답은 소관 확인이 필요한 적용 설계. 기본 SSO·IAM·ETL·결재·로그 및 미완료 기존 의무의 재계상 제외. 추가분은 사건·근거·판본·협업·변경 영향의 연결.

## 구현

- 정본 `src/ts-org-scenarios.json`, 표시 `src/OrgWorkScenarios.jsx`, 공통 폰트 상속 `src/ts-org-scenarios.css`.
- 기존 상세설계 03절에 단일 시나리오 선택 UI. 이전 2개 요약 예시의 화면 중복 제거; 원 문헌 설계 다운로드의 요약은 보존하고 세부 명세로 연결.
- 최초 화면은 누락자료 요청 단계. 3업무·24단계의 응답, 입력, 담당, 상태, 예외, 재사용, 순증, 기존 과업·검수 연결.
- 5영역 아키텍처, 업무별 6개 흐름 노드·3개 예외 복귀 경로와 14개 데이터 연결. 자료·근거·검수는 선택 펼침. 좌측 메뉴 유지·동일 SPA·별도 전역 메뉴 없음.
- 해시 `#org-work-scenarios` 직접 진입 시 해당 상세 펼침. 업무별 조직 화면 왕복·원문·구축/검수 연결.
- MD/JSON 다운로드는 동일 원장 생성. MD에는 업무별 Mermaid 아키텍처 포함.
- 홈페이지는 설계 시연이며 실제 업무 조회·발송·상신·승인 API 미호출.
