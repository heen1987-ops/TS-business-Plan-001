# 사례 기반 AS-IS → TO-BE 사업기회 v1.2

2026-11-03 · 기획 제안, 현장 검증 전

## 변경 내용

- `src/asis-tobe-v12.cjs`: 3영역 사례별 확인 사실, 미확인 현황, 문제 가설, TS 적용 시나리오, TO-BE 처리·결과·예외, 고도화·신규·연계·차세대, 검증과 공개 출처를 관리.
- TS의 2025년 공통 플랫폼 추진, 검사 보험 전산확인, 이륜차검사 카카오 전자문서 및 SMS 리콜알리미 등 확인된 기존 서비스를 명시. 기존 기능이 없다는 진단이나 최초 도입으로 표현하지 않음.
- 제공된 기존 TS25·TS26·INS26 요구 대조 문서는 2차 근거로 표기. 이번에 공고 원문을 재열람하지 못했고 계약·납품·검수·운영 범위는 미확인.
- 실제 기관 운영·시험, 연구·설계 중인 사례, 제3자 재구성과 TS 적용 시나리오를 구분. 해외 실증·다른 기관 성과를 TS의 효과로 환산하지 않음.
- `src/concepts/컨셉명.md`: 각 기회를 AS-IS와 TO-BE의 상세 업무 흐름 및 3영역별 사업화 경로로 보강.
- `AsisTobeCases.jsx`는 기존 홈페이지 사업기회 화면 안에서 사업 유형 기준, TS 기존 요구 경계, 사례별 현행·목표와 세부 절차를 제공. 기존 75개 경로와 8개 주 메뉴는 유지.
- `scripts/export-asis-tobe-v12.cjs`가 동일 원장에서 상세 Markdown을 생성. `scripts/check-opportunities.cjs`가 사례의 필수 항목·출처·컨셉 연결 및 기존 검사와 다운로드 무결성을 확인.

## 적용 기준

고도화는 기존 범위의 실제 미충족분, 신규 구축은 기존 범위로 충족되지 않는 별도 업무·기능, 차세대는 선행 실증 후 여러 업무를 묶는 조건부 신규 사업으로 구분한다. 연계는 세 사업 유형을 가로지르는 수행 방식이다. 실제 인수·권한·수요·예산을 확인하기 전에는 순증과 효과를 확정하지 않는다.

동일 업무에서 기존 이행·하자·유지관리와 추가 개발을 이중 산정하지 않는다. 개인정보 수신과 고위험 업무 쓰기는 권한·동의·공식 결과·예외 복구가 확인될 때만 검토한다. 야간 품질평가는 실시간 안전 통제를 대신하지 않으며 평가 점수는 현업의 확정 판정이 아니다.
