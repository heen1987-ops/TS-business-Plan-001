## 1. 방법과 검증

### 1.1 조사 설계

- 처별 조사원 13명 + 교차검증 조사원 1명(조직 실체·기존 과제 중복)
- 공통 지시서(`00_공통지시.md` 요지): A 법·제도, B 5개년 실적 수치, C 문제 증거(국감·감사·민원·언론·판례), D 현행 시스템·계약·예산, E 선례·대안(해외 동등기관·논문·비AI 대안), F 데이터 가용성·권한, G 이해관계자. 범주별 시도·실패를 조사 로그에 기록
- 증거 등급: CONFIRMED(원문 직접 확인) / PLAUSIBLE(신뢰 가능한 2차 출처·부분 확인) / INFERRED(추론, 과정 명시) / UNKNOWN(못 찾음, 경로 기록)
- 설계 원칙: 최종 판정·처분은 사람, 비전 자동판정 주축 금지, 기존 계약 납품분 중복 금지, 인력 감축 환산 금지, 기준선 없는 목표 수치 금지
- 금지: 외부 기관 접촉·양식 제출·정보공개청구 일체, 브라우저 공용 창 사용, 프로젝트 파일 수정. 로그인·대용량 파일 내려받기는 사용자 승인 대상으로 남김

### 3.2 설계 함의

- 13개 처가 따로 13개 AI를 만드는 구조보다, **공통 "후속조치 사건 원장" 엔진 1개 + 처별 규칙표·데이터 연계**가 증거에 맞음. 프로젝트 기획 기준 5(공통 기능과 기관별 규칙 분리)와 일치
- 공통 엔진 구성
  - 사건 ID(원 판정 1건 = 사건 1건), 원 판정 판본, 조치 권한자, 기한
  - 지적 유형별 **허용 증거 규칙표**(aRDa로 판본 관리, 폴리스로 조문 근거 연결)
  - 상태 분류(미착수·조치 중·증거 제출·확인 완료·기한 도과·기록 모순)와 월별 목록
  - 재발 관측창(90일·12개월 등 처별)과 비교군 설계
  - LLM(NOA) 역할: 비정형 조치결과서·사유 자유기술 정규화, 주소·명칭 매칭, 통보·보완요청 초안, 증거 부족 시 확인 과업 재계획. 판정·종결 결정은 사람
- 처별로 다른 것: 법적 권한자, 규칙표, 원천 시스템(mpis·특수검사정보관리·TMACS·ETAS/COSAS·STFS·샌드박스 시스템·VIMS)
- 이 해석의 한계: 공백의 **구조**는 법령·지침 원문으로 입증. **규모**는 PK·SI·RI만 실측, 나머지는 과거 수치·보도 또는 미실측. "모든 처에 공백이 크다"로 일반화 금지
