## 3. 반영 방식

1. `solutions-47.public.json`을 `src/solutions-47.json`으로 복사해 읽는다. `data.json`·`impact.json`·`proposal-profiles.json`의 기존 필드는 덮어쓰지 않는다(원장 보존). 표시 계층에서 새 요약을 우선 적용한다
2. 처별 제안 화면 첫머리에 "근거 재검증 결과(2026-09-25)" 블록을 둔다
   - 판정 배지(수정/재설계), 새 제목, 한 줄 요약
   - 입증된 사실 2~3개. 사실마다 근거 ID 링크, 등급 배지(CONFIRMED·PLAUSIBLE·INFERRED·UNKNOWN), `source_level`이 "2차"면 "보도 인용" 표시
   - 사람이 결정하는 지점, 기준선 상태, 제외 범위
   - 근거 건수(전체·등급별·공개)
3. 재설계 8개 처: 기존 컨셉 제목·상세기획 절을 접힘 영역 "이전 가설(2026-09-24)"로 옮긴다. 삭제하지 않는다. 기존 경로·앵커는 유지한다
4. 수정 5개 처: 기존 상세기획은 유지하되, 문제·지표 문구 옆에 새 요약을 우선 표시한다
5. 예시 기준선: 13개 처 화면에서 `exampleBaseline` 값 표시를 없애고 `baseline` 문구로 대체한다. 실측 수치는 기준일·분모와 함께 표시한다. 측정명세(39개 지표)의 목표 수치도 "기준선 확보 전 목표 미설정"으로 표시한다
6. 근거 목록 화면: `evidence` 배열을 처별로 표시한다. 유형·등급·출처 필터, 원문 링크(`url`), 열람일. 공개 파일에 없는 근거는 표시하지 않는다
7. 공통 발견: 홈 또는 AX 서비스 개요에 `commonFinding` 블록 1개
8. 내려받기: 공개 파일을 MD·JSON으로 내려받게 하는 기존 방식(export 스크립트)을 따른다

## 4. 금지

- `internal/*.md`의 문장·수치를 공개 화면에 옮기지 않는다
- CCK, 사업 차수(1차·2차), 계약 관계·수주, 내부 회의 자료를 공개 화면에 쓰지 않는다
- TS 기존 시스템·기존 AI를 "중복", "부족", "대체"로 평가하는 표현을 쓰지 않는다. "기존 서비스와 역할 구분"처럼 중립으로 쓴다
- 새 금액·공수를 추가하지 않는다. 재설계 처의 공수·인건비는 산정 전 "미산정"으로 둔다
- 개인 성명·연락처를 표시하지 않는다
