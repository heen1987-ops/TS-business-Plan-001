TS 진입점 2개와 업무 스킬 7개, 기관 확장팩의 공유 방법론 1개를 아래에 연결한다. 호환 호출은 별도 업무 기능으로 중복 산정하지 않는다.

## 공통 처리 흐름

1. 사용자·기관·사업·업무 목적과 허용 자료 범위를 확인한다. 공식 ID와 권한 연결은 추가 개발·검수 대상이다.
2. 사업 자료와 가이드를 읽고 출처·판본·위치·확인 범위를 근거 팩으로 묶는다.
3. 기관 표준과 해당 사업의 산출물 목록·테일러링·양식·기한 근거를 구분한다.
4. 근거가 있는 값으로 일정과 초안을 만들고 미확인·충돌·가정은 표시한다.
5. 이슈와 일정·산출물의 연결을 점검하고 변경안은 승인 전 제안으로 유지한다.
6. 제출·승인 증적과 상태 변경을 기록하고 다음 담당자에게 근거와 미해결 사항을 인계한다.

## 이번 반영과 추가 개발

- 원본 스킬의 이름·목적·입출력·절차 요약과 고정 커밋 출처

- 설치·앱 발견·운영 실행을 수행하지 않았다는 상태

포함하지 않은 자료와 실행:

- 비공개 사업 카탈로그 전체·양식 구조 전체·내부 제도 발췌·실제 원문
- 인사·환자 자료, 원장·캐시·사용자 설정·자격증명
- 스킬 자동 설치·MCP 등록·원격 배포·운영 시스템 변경

통합 시 추가할 기능:

- GAI-R01~R03: 공식 사용자 ID, 유효기간이 있는 소속·직무·위임, 원천 동기화와 변경 대사

- GAI-R05~R10: 조직·직무별 스킬 선택, 근거·상태 인계, 승인·업무 원장 대사와 기관별 분야 팩
