# TS 정의에서 사업 제안까지 이어지는 읽기 구조

기준일: 2026-09-24. 사용자 피드백: 세부 항목이 너무 많아 기관의 정의와 사업 제안의 맥락을 이해하기 어려운 문제.

## 변경 목적과 범위

- 첫 방문자가 TS의 존재 목적, 법정 책임, 중장기 방향, 조직의 일, AX 제안의 이유를 차례로 이해하는 구성.
- 홈을 조직 연결지도에서 기관 설명으로 변경. 연결지도는 별도 탐색 도구로 유지.
- 전체 자료 원장과 화면 메뉴의 분리. 자료의 세밀한 등록 단위는 검색에 유지하되 메뉴에는 큰 주제만 표시.
- 새 업무·권한·실측효과 확정이나 예산 산정 없이 설명과 탐색 구조의 개선.

## 읽는 순서

1. TS는 어떤 기관이며 왜 필요한가: 설립 목적·기관 유형·국민과 기업에게 제공하는 가치.
2. 어떤 법에 따라 어떤 책임을 수행하는가: 설립법, 업무별 근거, 위탁·대행·지정, 공식 판단과 지원의 구분.
3. 2026–2030년에 무엇을 달성하려는가: 공식 미션·비전, 4개 목표와 12개 전략과제, 기획에서 검토할 질문.
4. 조직은 어떤 일을 수행하는가: 본사·자동차안전연구원·지역 현장의 관계와 업무 흐름.
5. 그래서 어떤 AX 전환을 제안하는가: 국민 편익 → 기관 목표 → 업무 한계 → 전환 방식 → 검증의 연결.

홈과 기관 소개는 같은 설명 원본을 사용. 13개 처는 현재 상세 기획 범위이며 TS 전체 조직이나 전체 법정업무의 완전 목록을 의미하지 않음.

2026-09-24 공식 페이지 확인 결과 반영.

- 국토교통부 기관 안내: https://www.molit.go.kr/USR/WPGE0201/m_19475/DTL.jsp
- ALIO 기관 현황: https://www.alioplus.go.kr/organization/organHeadDetail.do?apbaId=C0019&typ=region

기관 유형만으로 개별 사무의 권한을 추정하지 않음. 세부 법령의 조문·시행일·위임·위탁·전결은 기존 법령 원장의 확인 범위를 유지. 이번 기관 소개 확인을 전체 법령 전문의 최신성 검증으로 확대하지 않음. 공식 목표와 기획용 해석을 구분하고 실측 편익을 새로 주장하지 않음.

## 부서별 본문

6개 큰 장 안에서 자연스럽게 이어지는 연속 문서.

- 업무와 사업의 목적
- 현행 한계와 전환 방향
- 사용자와 업무의 흐름
- 시스템과 데이터 설계
- 개인정보·책임·운영
- 도입 범위와 효과 검증

13개 처의 본문을 각각 44개 절에서 24개 설명 단위로 통합. 목적·한계·구현·효과의 중복 설명을 대응 절에 합치고, 지표별 측정 4개 조각을 하나의 지표 설명에 배치. 문장·글머리표·상태·근거 링크·표·그림은 보존하고 기존 절 주소는 통합된 위치로 연결.

법정업무 전체와 제안 목록은 개수로 균등 분할하지 않고 실제 분야·업무계통으로 묶음. 별도 근거 없는 문서에는 임의 장 구분을 추가하지 않음.

## 화면·상호작용

- 왼쪽: 기관 이해의 5단계, 현재 부서의 6개 장, 자료 검색. 다른 부서는 필요할 때 펼치는 목록.
- 본문: 설명과 근거의 연속 표시, 상단 목차의 장 이동, 넓은 읽기 공간.
- 오른쪽 고정 목차 제거. 도식·표의 본문 폭 확보.
- 전체 원장 319항목을 검색·등록자료에서 유지. 메뉴에 모든 세부 항목을 노출하지 않음.
- 작은 화면: 목차 열기·닫기, 이동 후 초점 및 헤더 아래 위치 확인.
- 큰 장 H2 → 상세 설명 H3 → 카드 H4 위계. 도식 확대·Esc 닫기·초점 복귀 유지.
- 기존 hash, slide, metric, store, contract 직접 링크와 뒤로/앞으로 이동 보존.
- 외부 API·입력정보 저장·AI 실제 실행 추가 없음. 정적 기획자료의 공개 범위 유지.

## 배포·복구

기존 main → Actions → Pages 경로 사용. 배포 전 npm ci 및 npm test, 관련 브라우저 검사 수행. 배포 후 version.json의 commit, 홈의 기관 소개, 부서의 6개 장, 법령 매핑 서두 확인. 오류 시 이번 커밋 revert 후 동일 검증·배포. 조직지도와 기존 세부 문서 경로를 삭제하지 않아 직접 링크 호환 유지.

화면 캡처와 실행 결과는 qa-output에 보관하며 배포 대상에서 제외.
