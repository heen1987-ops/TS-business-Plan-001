# 통합 본문 UI/UX 재구성 · 2026-10-06

## 문제와 범위

처별 본문·기술설계·설문·한글 문서가 여러 진입점으로 나뉘고, 상단 메뉴와 작업공간 메뉴가 겹쳐 내용의 연결을 파악하기 어려웠다. 기본 홈페이지를 하나의 연속 본문으로 구성하고, 같은 화면에서 담당 처와 과제를 바꾸어 상세 제안부터 의견·문서까지 이어 읽도록 변경했다.

- 대상: 2027년 TS 후속사업을 검토하는 현업·기획·CCK 담당자.
- 성공기준: 반복 메뉴 제거, 일반 페이지 스크롤, 선택 처·과제와 설명·의견·문서 일치, 기존 상세 경로 보존, 모바일 탐색 가능.
- 제약: 기존 근거·설계·도식·한글 파일 재사용. 실제 업무분장·수요·권한·효과·가격을 새로 확정하지 않음. 원장과 과거 판본 삭제·덮어쓰기 없음.
- 방법론: 기존 기능 개선의 영향분석·BDD·독립 검토. 쓰기 실행자는 한 명, 데이터와 화면 검토는 읽기 전용 역할로 분리.

## 정보구조와 사용 흐름

기본 진입점은 `index.html`의 통합 본문이다. 헤더의 처별 제안·공통 기술·한글 문서와 좌측 목차는 같은 본문 안의 위치로 이동한다. 스크롤에 따라 현재 장을 표시한다.

1. 기관 이해: TS의 존재 의의·설립 근거·법정업무·2026~2030 전략·조직.
2. 2027년 기획 방향: 현재 적용 프로젝트와 추가 제안의 경계.
3. 처별 상세 제안: 처 선택 → 목적·근거·현행 한계 → 최신 해결안·도식·측정방법 → 현재 구현·편성 조건.
4. 공통 기술: NOA·조직지식·스킬형 PMS와 기존 시스템 연계.
5. 추진조건: ISP·RFP·대가·착수·보안·개인정보·AI 윤리 검토.
6. 의견과 문서: 같은 처의 상세 질문·추가 의견 → 최신 한글 문서 → 출처와 접힌 보존 자료실.

기관부터 문서까지 본문을 연속 표시한다. 처별 제안만 선택에 따라 교체하고 공통 설명은 유지한다. 새로고침·뒤로·앞으로 이동에도 URL의 `dept`, `project`, `topic`으로 선택을 복원한다. MR-02 DRT와 QE-H01 고령자 평가 의견도 각각의 맥락을 유지한다.

법령별 세부 매핑과 이전 상세 아키텍처처럼 동일한 내용이 통합 본문에 없는 경로는 원래 상세 문서로 연결한다. 단순히 비슷한 제목의 장으로 보내 원문을 숨기지 않는다. 이전 홈은 `index.html?view=overview`, 조직 연결지도는 `?view=map`으로 보존한다.

## 데이터·화면 경계

- 조사 대상 조직 51개, 기획 과제 42개, 설문 주제 55개 유지. TS 전체 공식 업무분장 조사 완료를 뜻하는 수치가 아님.
- 39개 처의 최신 한글 117개 유지. 계획서가 없는 12개 조직은 수요 탐색 설명과 의견을 표시하고 미작성 상태를 알림.
- 기획 과제가 둘인 처는 과제별 본문과 의견을 동기화. 한글 문서는 기존 처별 작성본 연결을 유지.
- 기준선·목표·최종 가격의 미확정 값 유지. 미산정 값을 0 또는 실증 성과로 변경하지 않음.
- 다운로드는 본문 끝으로 이동. 뉴스·이전 판본·전체 원장은 접힌 자료실 안에서 보조 자료로 접근.
- 입력은 처 검색·선택·목차 이동만 수행. 설문 제출이나 TS 운영 시스템 변경 기능 없음.

새 서버·API·계정·개인정보 저장·외부 모델 호출 없음. 기존 파일의 공개 범위와 사실 판단 상태 유지. 한글 문서와 공식 출처는 기존 자료의 경로를 사용한다.

- 독립 데이터 검토: 51/42/55/117 관계·미확정 값·실제 문서 연결 보존 판정.
- 독립 화면 검토: 실제 51개 조직 전환, PC/390px, DRT·QE 추가 주제·뒤로/앞으로·다운로드 통과. 모바일 버튼 Escape 권고를 구현에 반영.

위 검사는 구현과 연결의 품질 검증이다. 실제 TS 사용자 인터뷰·현업 수요 확인·법적 전결 확정·도입 성과 검증을 대체하지 않는다. 전면 접근성 인증을 수행한 것으로 표시하지 않는다. 스크린샷과 브라우저 결과는 제외 경로 `qa-output/integrated/`에 보관한다.

기존 브라우저 테스트에서 이전 홈의 계약은 `?view=overview` 또는 `?view=guide`에 유지하고 기존 단언을 보존했다. 새 기본 홈 계약은 별도 모델·브라우저 검사로 추가했다.

## 배포·롤백

`npm test` 및 최종 diff 검증 후 main 커밋·푸시, GitHub Actions 성공, 공개 `version.json`의 커밋 일치와 실제 통합 화면 응답을 확인한다. 배포 확인 전에는 공개 반영 완료로 보고하지 않는다.

배포 오류가 생기면 해당 커밋의 영향만 되돌려 기존 파일·자료를 보존한다. 전체 Git 이력이나 자료를 재작성하지 않는다. 이번 변경은 기존 경로·데이터·다운로드를 제거하지 않으므로 통합 홈을 되돌려도 원래 문서를 계속 사용할 수 있다.
