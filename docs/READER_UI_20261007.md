# 전체 읽기 UI 재구성 및 법령·현행 업무 근거 반영

작성일: 2026-10-07 / 적용 대상: GitHub main 사이트

## 1. 문제와 완료 기준

사용자 문제는 과제별 설명의 분량보다 탐색 구조의 혼재에 있음. 중복 상단 메뉴·복귀 링크·내부 목차, 즉시 변경되는 선택값, 흩어진 상세 페이지, 검색을 해제해도 되살아나는 이전 필터 때문에 같은 처의 목적·근거·설계·자료를 이어 읽기 어려운 상태.

완료 기준: 공통 상단 메뉴 4개, 현재 처·과제 맥락 보존, 명시적 선택 적용, 현재 페이지에 대응하는 단일 목차, 상세 본문 연속 스크롤, 기존 링크·도식·한글 문서 유지. 검색 빈 상태·초기화·뒤로가기·모바일·키보드 초점까지 검증.

방법론: 기존 UI 개선의 BDD·영향분석·회귀검증, 공공 제안 내용의 근거·요구사항 추적, 독립 QA. 전체 페이지 재작성 대신 공유 탐색 계층을 교체하여 기존 상세 자료를 보존.

## 2. 정보구조

| 상단 메뉴 | 읽는 내용 | 선택 맥락 |
|---|---|---|
| TS 이해 | 존재 의의·법정 역할·2026–2030 방향·현재 기획 범위 | 선택 처·과제 유지 |
| 법령·현행 업무 | 중앙부처·원 권한자·TS 수행조직·공개 처리방식·CCK 추가범위 | 기획 과제는 해당 과제 연결, 미작성 조직은 전체 법령표 |
| 처별 사업기획 | 목적·근거·문제·기술적 HOW·도식·정량 측정·요구사항·실행 조건 | 선택 과제의 통합 본문 |
| 의견·한글 문서 | 병목 가설의 타당성·별도 의견·추가 수요·한글 문서 내려받기 | 같은 처·과제의 의견·문서 |

첫 화면에서 처·과제를 탐색하고 '선택 적용'을 눌러 본문 갱신. 선택 상자 탐색 자체는 현재 읽고 있는 본문을 바꾸지 않음. 과제명 아래 대상 편익을 먼저 표시하고, 목적·목표·수단의 상세 구분은 본문에 유지.

통합 본문은 기관 이해 → 선택 과제의 법령·현행 업무 → 상세 제안 → 공통 플랫폼·실행 조건 → 현업 의견 → 한글 문서의 순서. 본문을 작은 슬라이드 페이지로 나누지 않음. 이전 상세 URL과 자료는 계속 접근 가능.

## 3. 화면·상태·주소 계약

| 화면 | 사용자 목표 | 상태·검증 |
|---|---|---|
| 통합 첫 화면 | 처·과제 선택 후 제안 전체 읽기 | 미적용 선택, 명시적 적용, 미작성 조직, 직접 URL, 뒤로·앞으로·새로고침 |
| 처별 제안 목록 | 조직·과제 검색 후 상세 본문 진입 | 전체 51조직·42과제, 미작성 12조직, 빈 검색, 초기화, 필터 유지 |
| 법령 매핑 | 담당·위탁 관계와 목적·솔루션 연결 확인 | 선택 과제, 전체 법령표, 검색·분야 필터, 미연결의 추가 확인 표시 |
| 자료·한글 문서 | 현재 과제의 파일 찾기 | 공개 downloads 경로, 파일 응답·ZIP 서명·기존 무결성 |
| 공통 목차·검색 | 원하는 절로 이동·자료 찾기 | 현재 본문에만 연결, 열린/닫힌 모바일 목차, Escape 초점 복귀, 동적 필터 재구성 |

주소 우선순위: 명시적인 dept/project 질의 → 기존 처별·상세제안 주소의 조직/과제 식별 → 검증된 기본 선택. rail-license·rail-type의 두 번째 과제는 view=evidence 같은 부가 질의가 있어도 유지.

목차 ID는 조직 고유 키 또는 내용 기반 ID 사용. 검색 결과의 순번을 앵커로 사용하지 않음. 동일 페이지 목차는 클릭 당시의 검색 질의를 보존. 필터 변경 이벤트와 DOM 변경을 모두 반영하며, 입력 중 포커스·스크롤을 다시 빼앗지 않음.

## 4. 기술 변경

- reader-ui.cjs: 메뉴·선택 맥락·이동 주소의 공통 규칙.
- SiteNavigation.jsx·IntegratedReader.jsx: 공통 4메뉴, 현재 선택, 명시적 적용, 통합 본문.
- DocumentNav.jsx: 단일 로컬 목차, 유효 앵커, 필터 동기화·모바일 초점.
- DocumentReader.jsx: 중복 내부 outline 제거, 상세 내용·그림 확대·이전 주소 보존.
- DepartmentDirectory.jsx: 조직별 밀도 조정, 과제당 편익과 단일 본문 진입 링크.
- reader-ui.css: 260px 목차·자연 스크롤·여백 축소·390/768/1280/1600 반응형. 실제 헤더 높이를 모든 본문 ID의 scroll-margin에 반영.
- mandate-workflows.cjs·MandateWorkContext.jsx: 사실과 제안 분리, 출처·현행 업무·해외 적용·측정 근거 연결.

권한·API·기관 데이터 스키마 변경 없음. 공개 정적 자료의 클라이언트 탐색 변경이며, 원 시스템 조회·ERP 변경·의견 외부 전송을 실행하지 않음. 실제 업무 연계는 별도 접근권한과 인수 명세가 필요한 설계안.

## 5. 근거 반영 범위와 한계

공식 출처 37개, 국내 공개 처리방식 13개, 해외 운영사례 7개. 기존 대표 법정업무 27개·하위 관계 36개 보존. 최신 과제 21개와 법정업무의 명시적 관계 24개 연결. 나머지 21개 과제는 추가 법령·분장·사규·협약 근거 확보 대상으로 표시.

중앙부처의 제도 소관, 위탁·지정·의뢰 원 권한, TS 수행조직, 최종 결정은 구분. 공개 절차가 내부 병목 발생률·대기시간·전결·API 권한을 입증하지 않음. 해외의 제도·예산·성과를 국내 기대효과로 전용하지 않음. 현업 피드백은 미수령이며 독립 UI 검토가 이를 대체하지 않음.

DRT는 이미 있는 콜센터·자동배차·최적경로·정산 기능을 기반으로 지역 택시조합의 수동 접수·배정과 운영계획의 실제 잔존 구간을 확인하는 안. 보조금 처분·자동 환수·전국 예산 배분 권한으로 확대하지 않음. 고령자 건강정보 자동 연계 역시 확보된 권한으로 표시하지 않음.

정량 지표는 측정식·원자료·책임·비교 조건을 제시하되 실제 기준선과 수치 목표 미확정 유지. NOA·aRDa 및 전문 규칙·도구·사람 판단의 추가범위는 설계 가정이며 제품 실제 성능·TS 구현 완료를 주장하지 않음.

## 6. 보존·배포·롤백

73개 기존 React 경로, 156개 HWPX, 168개 과제 도식 유지. 버전별 한글 문서 원본을 덮어쓰지 않음. 다운로드는 PC 경로가 아닌 공개 downloads 주소 사용. 생성 이미지·한글 문서를 새로 만든 것으로 보고하지 않음.
