# 처별 육하원칙·상세 설계 보강

작성일: 2026-09-24. 대상: 사이트에 등록된 13개 처의 대표 제안. 전체 TS 업무분장 또는 확정 RFP와 구분.

## 요청·성공기준

- 기존 요약의 문제: 필요성·현행 한계·해결 방법과 도식의 연결이 부족하고 처별 차이가 드러나지 않음.
- 성공기준: 처별 육하원칙, 필요성의 인과관계, 현행 기반과 한계 가설, 정상·예외 사례, 5종 도식, 데이터·개인정보 처리, 요구·인수기준의 연결.
- 읽기 방식: 연속 스크롤 유지. 목차는 본문 위치 이동. 도식을 보기 위해 별도 페이지 전환을 요구하지 않음.
- 산출물: 데이터 기반 상세 문서, SVG 도식·텍스트 설명, 내려받기 자료, 회귀검사.

## 가정·경계

- 공식 업무안내는 현행 업무 존재의 근거. 반복 보완·지연·미해소의 실제 빈도는 현장 진단 필요.
- 기존 조직 축·법령 원장을 유지. 업무분장·전결·API 접근·개인정보 처리 근거 미확정 사항은 확인 대상으로 표시.
- NOA·aRDa와 기존 로컬 LLM·서버 재사용 전제. Agentic OS는 기존 계약 미포함이라는 사용자 확인을 반영한 별도 과업 후보.
- 신규 인프라 구매·비전·장비 제어 제외. 기존 제품의 재사용 가능성과 실제 적용 완료를 구별.
- 공고 미매핑 기획 초안. 일정·예산·효과를 확정하거나 새로운 금액·내부 계약정보를 공개하지 않음.

## 설계·검증

- 컨셉도: 수혜자·업무목적·기관 역할·제공 가치 관계.
- 전체 아키텍처: 외부/기관 경계, 공통 기능, 처별 모듈, 기존 서버·저장소·연계.
- 서비스 아키텍처: 역할별 수행 순서, 승인 관문, 공식 결과 대사, 실패·보완·재계획.
- 데이터 흐름도: 입력·변환·색인·계획·승인·실행·대사·관측의 객체와 계보.
- 개인정보 처리도: 목적·근거, 최소수집, 식별정보 분리, 접근통제, 모델 입력·출력, 제공/위탁, 보관·파기·권리행사.
- 모든 도식은 논리 설계안. 실제 TS 시스템 구축도나 보안 인증 결과와 구분.
- UI: 키보드 목차·도식 확대·Esc·초점 복귀, 모바일 넘침, 전체 본문 찾기·인쇄 검증. 외부 API 호출 없음.
- 원문 보존, 기존 주소, 13처·104요구·16아키텍처, 신규 도식 구성요소·참조 ID·공개 경계 검사.
