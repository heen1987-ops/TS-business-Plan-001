# 처별 의견 확인 화면·구성 재정리

- 요청: 전체 구성이 뒤섞여 읽기 어려운 문제 개선.
- 시간축: 2027년 후속사업 기획을 위한 현업 의견 확인. 설문 문항·사업 가설의 변경 없이 진입·읽기·참고자료 흐름 개선.
- 작업 규모 M / 위험도 Medium. 사용자 흐름·정보구조 분석, 최소 변경, BDD 회귀검증, 독립 코드 검토 적용.
- 대상: TS 현업 담당자, 처별 기획 검토자, 설문 작성 담당자.
- 가정: 별도 현업 피드백은 아직 없음. 기존 조사 내용은 확인할 가설이며 실제 수요·도입·효과를 확정하지 않음.

## 확인한 혼란과 변경

| 기존 화면에서 확인한 문제 | 이번 변경 | 수용기준 |
|---|---|---|
| ISP·비용·구현 검토 아래에 설문 본문 혼재 | `research-library.html?view=survey`에 의견 확인 전용 화면 제공 | 홈·상단 2027 메뉴·처별 제안·검색에서 직접 진입 |
| 51처 목록과 본문을 모두 나열하여 원하는 처 찾기 부담 | 상위 조직별 처 선택, 선택한 처 하나만 표시 | 51처 모두 선택 가능, 기본 미선택, 다른 처 본문 숨김 |
| 응답 역할·병목 설명·공통 판단 문항이 떨어져 있음 | 응답 배경 → 해당 병목 → 해당 질문 순서 | 각 주제의 15문항 또는 발견 3문항 누락·중복 없음 |
| 이전 인터뷰와 구조화 정의파일이 현재 응답 흐름과 혼재 | 최신 설문을 기본 제공, 이전 자료·전체 CSV/JSON은 참고 영역 | 최신 설문 158파일과 v0.1·한글 계획서 링크 보존 |
| 처별 직접 링크에서 현재 단계 표시 부족 | 처 직접 링크에 ‘내 처의 병목·질문’ 목차 활성 표시 | 제목·breadcrumb·목차·본문 역할 일치 |
| 처 선택 후 일반 절 이동·뒤로가기에 선택 상태 혼선 | 브라우저 이력에 선택한 처 식별자만 기록 | 초기 미선택 및 선택·해제 Back/Forward 복원 |

기존 공개 화면의 1440px 데스크톱 초기 레이아웃을 확인한 결과, 기획 본문 전체 약 39,758px, 그 안의 설문 영역 약 13,853px이며 처 선택 영역 약 6,441px에 목록과 요약이 중복 노출됨. 새 전용 화면의 미선택 초기 설문 영역은 약 3,326px, 처 선택 영역은 약 449px. 이는 브라우저 레이아웃 관찰값이며, 선택한 처의 상세내용 길이나 실제 사용시간·만족도·업무효과 측정 결과가 아님.

## 읽기 순서

1. **프로젝트·NOA 설명**: 조사 목적 → 현재 프로젝트 배경 → 제품 역할 → AX 확대 방향. 파생 문서·공급사 설명·계약 미포함 회신의 확인 수준 함께 표시.
2. **내 처의 병목·질문**: 담당 처 선택 → 응답 역할/범위/현재 사용 3문항 → 업무·목적·병목·HOW·조건·판단 경계 → 질문 4묶음. 기대 결과·측정방법·출처는 같은 주제 안에서 펼쳐 확인.
3. **별도 의견**: 현업 불편·대국민/기업 서비스·누락 문제·AX 확대·제외 범위 5문항. 선택 처나 병목 동의 여부와 무관하게 열람.
4. **설문지·참고자료**: 선택 처의 최신 MD·정의 CSV·빈 회신 CSV. 이전 한글 계획서·인터뷰 v0.1, 전체 JSON·공통 필드 정의·해석 기준은 참고 펼침.

병목별 15문항은 `업무와 병목 확인 3 → 판단 이유·실제 근거 4 → 개선 방법·조건 4 → 기대 결과·우선순위 4`로 묶음. 문항ID·선택지·분기·근거·해석 경계는 기존 v0.2와 동일. UX 변경만으로 새 문항 버전이나 확인된 수요를 만들지 않음.

## 정보구조·상태·보안

- 전용 view는 기존 물리 경로를 재사용. 사이트 73개 경로 유지.
- 52개 설문 검색 결과와 처별 본문 링크를 새 view에 연결. 이전 `view=planning#implementation-survey-*` 링크는 접힘 영역 자동 펼침으로 보존.
- 기본 미선택, 처 선택, 일반 절 이동, 직접 링크, Back/Forward, 선택 해제, 모바일 목차, 키보드 선택/펼침 검증.
- 처 식별자만 현재 탭의 브라우저 이력에 기록. 실제 응답 입력·제출·업로드·서버 저장 기능 없음.
- 실제 회신·개인정보·건강정보·원문 사건은 공개 저장소 자동 배포 대상 아님. 기존 법정 판단·제품 구현·계약·실측 상태 유지.
- WCAG 2.2 AA 목표에 맞춰 native select, label, status, heading, focus-visible와 앵커 포커스 사용. 스크린리더 전수검사·실사용자 연구는 미실시.

## 검증·보완 기록

- `npm test`: 빌드와 35개 정적·콘텐츠 검사 통과. 73개 경로, 내부 깨진 링크 0, 설문 검사 447개 통과.
- 새 UX 브라우저 검사 190개 통과. 51처 선택, 55주제 질문 배치, 최신/이전 자료 분리, 4목차 활성, 홈 직접 진입, 기존 공유 링크, 1440/768/390px, 가로 넘침·본문 내부 세로스크롤·JS 오류 0 확인.
- 첫 UX 검사에서 추가 의견으로 이동 후 선택 해제/Back 복원 실패. 일반 절 이력에도 선택 처를 보존하도록 보완하고 같은 검사 전체 재실행 통과.
- 기존 설문 검사에서 숨긴 QE의 summary에 바로 포커스하던 전제 실패. QE 직접 링크로 해당 처를 표시한 뒤 동일 키보드 접기·펼치기 검사. 기존 설문 234개 통과, 158 파일 HTTP 응답·본문 확인.
- 홈 검사 초기 실행은 미리보기 포트 환경 변수 오설정으로 연결 거부. 현재 서버 주소를 `SITE_URL`에 지정해 동일 검사 재실행, 홈 229개 통과. 코드 오류로 일반화하지 않음.
- 기존 인터뷰 v0.1 브라우저 184개, 기획 검토·검색 154개, 전체 공통 UX 431개 통과. 새 UX 190 + 기존 설문 234 + 인터뷰 184 + 홈 229 + 기획 검토 154 + 공통 UX 431, 합계 1,422개 브라우저 조건 통과.
- 독립 정보구조·메뉴 검토: 합격, 필수보완 없음. 독립 이력 복원·문항 배치 검토: 합격, 필수보완 없음. 실제 현업 조사 결과와 구분.
- 화면 증거: `qa-output/survey-ux/after-desktop.png`, `after-mr-questions.png`, `after-mr-1440.png`, `after-mr-768.png`, `after-mr-390.png`. 생성 이미지 없음, 실제 UI 캡처.

- 잔여 확인: 실제 리서치베이 서비스·가져오기 규격·등록·발송·회신, 현업 사용성 조사, TS 설치본·원본 계약·제품 성능 미검증.
- 다음 입력: 담당자에게 새 전용 view와 자신의 처 링크 제공 후 설명 이해도, 병목 정합성, 문항 부담, 누락 업무에 대한 회신 확보. 회신 확정 전 비용·도입효과·사업채택을 자동 확정하지 않음.
